## 确认仍有优化空间的四类面板

> **过时段落提示（2026-11-06）：**下面四类的原问题已完成或被聊天卡片方案替代，不再按此节重做；仅“第三批：细节复核”继续作为后续低优先级检查。

### 1. 批注详情与未保存草稿：第一优先

实际入口：`BrowserTabPanel.vue` 的批注按钮 → `BrowserAnnotationsPanel.vue`。

- [BrowserAnnotationsPanel.vue:27](../src/components/BrowserAnnotationsPanel.vue#L27)：意见区域只根据窗口高度计算，普通窗口下短意见也分配约 190 高的滚动区。
- [BrowserAnnotationsPanel.vue:30](../src/components/BrowserAnnotationsPanel.vue#L30)：编辑、定位、加入对话、检查位置、查看证据、状态操作使用两排同级默认按钮；恢复副本、删除确认会继续增加控件。
- [BrowserAnnotationsPanel.vue:42](../src/components/BrowserAnnotationsPanel.vue#L42)：未保存草稿仍是文字按钮；底部另有整行“收起”。

目标：标题行放返回／关闭；意见按内容增长并设上限；“编辑／加入对话”形成清晰主次，定位用独立图标；低频操作收进次级区域。草稿和冲突副本使用与下载相近的平铺行，显示简短内容、状态和明确恢复操作。保留删除确认、跨窗口草稿及证据关联，不将样式修改变成数据迁移。

批注输入编辑器已经具备文字测量、随内容增高、原生多行及草稿保护，单独保留，不能与尚待收紧的批注详情混为一项。

### 2. 对话搜索：第一批

实际入口：`ChatPage.vue` 搜索对话 → `NativePanelDialog` → `chatSearchPanel()`。

[native-dialog-panels.ts:15](../shared/native-dialog-panels.ts#L15) 的结果列表固定高 380，零条或一条结果也保留该高度；时间另占一行。面板默认宽 580。

目标：空结果只保留搜索框与提示；少量结果按内容收缩，较多结果才滚动；标题与时间同排，摘要保留一行。输入焦点、中文输入法、Enter 选中、当前聊天标识和切换保护不变。

### 3. 引用来源：第一批

实际入口：回答中的来源按钮 → `readSourcesPanel()`。

[native-dialog-panels.ts:26](../shared/native-dialog-panels.ts#L26) 在缺少标题和摘要时可能重复展示域名、域名、网址；列表固定高 360，默认宽 520。正常来源摘要已有截断，问题主要是重复与层次，不是普遍存在超长正文。

目标：网站名／域名只出现一次，标题突出，摘要最多两行；少量来源收缩列表，保留来源数量、分页及完整网址提示。点击只打开当前可见且仍有效的来源。

### 4. 工作区文件选择器：第一批

实际入口：应用菜单／文件工作区“打开对话文件” → `WorkspaceFilePickerDialog` → `workspacePickerPanel()`。

- [native-dialog-panels.ts:46](../shared/native-dialog-panels.ts#L46)：空列表仍保留 300 高结果区。
- [native-dialog-panels.ts:44](../shared/native-dialog-panels.ts#L44) 与后面的重试分支：顶部刷新、部分目录重试、错误重试可能同时出现。

目标：文件图标、文件名、路径和定位操作按行排列；空态缩短，结果随条数增长；加载、部分不可读和读取失败使用一处状态区，按实际情况提供一个主要刷新／重试入口。部分成功时保留已读文件，不把部分目录失败表现成整个列表不可用。

## 四类面板共同处理的布局问题

[NativePanelDialog.vue:18](../src/components/NativePanelDialog.vue#L18) 的可用宽度目前主要用于计算锚点；显示时传入的内容树仍保留原始宽度。`max-width` 属性主要约束备用 HTML 对话框，不能据此认为原生内容已经随窗口收缩。

第一批需要一起调整实际内容宽度与行内文字预算，并按内容计算列表高度。不能只移动弹层位置，也不通过缩小字体来塞入长内容。窄窗是否实际越出预期范围，应在真实原生窗口中确认，不能将静态尺寸直接写成已复现的裁切故障。

样式沿用现有主题及下载卡片：一次外层留白、13–14 的标题、12–13 的正文、11–12 的辅助信息、轻量图标按钮。小卡片通常控制在 300–380 CSS px；搜索与文件选择可保留较宽桌面尺寸，但必须随可用空间调整。使用现有 Fluent 图标，所有纯图标操作有可访问名称和提示。

## 另外确认的两处弹窗问题

### 技能／插件通用弹窗的暗色表头和底栏：第一批收口

[SkillDialogShell.vue:135](../src/components/skills/SkillDialogShell.vue#L135) 的表头固定白色，底栏也使用固定浅色；[postpile-theme.css:527](../src/styles/postpile-theme.css#L527) 和后面的底栏规则继续显式指定白底。现有暗色规则主要覆盖外层卡片，不能覆盖这些独立子区域。

目标：仅将表头、底栏、文字、边框和关闭按钮统一到现有主题变量，保留当前尺寸、滚动及操作结构。检查所有复用该外壳的技能、插件和商店弹窗；用浅色／暗色截图确认，不另建一套主题。

### 插件安装确认卡的信息密度：后续一批

[PluginImportDialog.vue:56](../src/components/plugins/PluginImportDialog.vue#L56) 常驻完整描述，以及方式、来源、大小、标识、套件等元信息；描述没有行数限制。

目标：名称／版本和两行描述作为摘要，完整来源与标识折入可展开详情，安装操作保持明确。覆盖已有插件、套件冲突及其他影响安装决定的警告继续常驻，不能为精简视觉而隐藏。

## 第二批：全局面板与实时网页

明确存在的结构残留：

- [ChatPage.vue:1128](../src/pages/ChatPage.vue#L1128) 起的删除聊天、关闭 Session、退出确认使用全窗遮罩。
- [SettingsDialog.vue:2](../src/components/SettingsDialog.vue#L2)、[DocsDialog.vue:2](../src/components/DocsDialog.vue#L2) 仍是全局 HTML 对话框。
- DOM 覆盖相交后，[BrowserTabPanel.vue:407](../src/components/BrowserTabPanel.vue#L407) 的检测会进入 preview 截图和 `layout(null)` 路径，隐藏网页 View。这适用于当前 `.9`，并非仅限旧环境。

实施方向：简单破坏性确认评估使用真正的原生模态对话框，保留默认取消、明确目标、重复提交保护和窗口阻断；不能用当前非模态 `NativePanelDialog` 直接替换。设置与帮助内容复杂，优先复用停靠页面或独立窗口，避免为了统一卡片而重建整套原生控件。

浮动侧栏及聊天输入浮层按实际相交检查。先实现布局避让或合适的承载方式，再逐处收紧截图回退；不能直接删除截图和隐藏代码，否则网页 View 会盖住 HTML 浮层。保留正常标签切换、转移窗口、显式隐藏和失效布局的 View 生命周期，以及用户主动截图、批注证据和远程画面。

## 第三批：细节复核，不先认定为未完成

- 标签溢出列表已经具备原生平铺行、搜索及按可用空间计算高度，不属于固定 380 高空白问题。可进一步复核窄窗文字预算、固定标记和资源类型图标的关系。
- 标签悬停提示的标题使用固定 40 高区域，可复核短标题留白及长标题省略；优先级低于前四类。
- 文件行的下载状态、错误提示和辅助颜色可与新下载卡片统一；需考虑全局主题覆盖，不能只发现局部硬编码颜色就认定当前暗色必然出错。
- 远程连接页面 [RemoteBridgePage.vue:69](../src/pages/RemoteBridgePage.vue#L69) 将同一错误详情用于顶部状态与中央空状态。可改为简短状态、一次原因说明和就地恢复入口，技术详情折叠；保留现有连接和鉴权逻辑。该项使用频率较低，排在本地面板后面。

## 实施顺序与验收

1. 先做批注详情和三个通用选择器，同时完成原生内容尺寸适配，并收口技能／插件通用弹窗的主题。使用临时资料准备空、单项、长列表、超长名称、加载／失败、批注冲突等状态。
2. 生成真实原生窗口的浅色、暗色及窄窗截图，验证图标独立操作、分页、键盘、焦点、IME、草稿恢复、作用域与异步旧回执拒绝。下载卡片现有样式作为一致性参照，不以 HTML 重绘冒充原生截图。
3. 单独实施全局确认／帮助／设置的承载调整，验证模态语义、取消与退出行为；迁移后的入口检查 preview 请求、网页隐藏调用、View 尺寸、WebContents 身份和 RAF 持续绘制。
4. 插件确认卡密度和第三批细节按使用频率处理，再决定发行范围。规划不提前指定版本号，也不将尚未实现的效果计入已发布 0.4.6。

本次没有新增运行测试或修改产品代码；当前发现依据生产调用链和布局定义。后续通过项须以实际实施后的截图及检查记录为准。
