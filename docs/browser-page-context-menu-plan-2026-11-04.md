目标是在真实网页内容上右键时提供常用浏览器操作，包含返回、前进、重新加载、批注和检查元素。此菜单与标签右键、地址栏编辑菜单、聊天输入菜单分别处理；沿已有原生 Menu 外观和业务逻辑，不以 HTML 弹层或截图背景实现。

## 1. 入口与范围

在实际 BrowserPage 的 WebContents 监听 `context-menu`，由主进程按命中的页面、frame 和内容类型构造菜单。工作区、展开工作区及独立浏览器共用定义；页面移窗后跟随实际宿主，不重复绑定监听。

支持鼠标右键及可用的键盘菜单键／Shift+F10；触摸长按按原生 menuSourceType 核对，不模拟一次额外右键。网页阻止上下文菜单、原生输入保护或特殊页面未发出事件时，按真实能力处理，不注入全站脚本强行取消网站自己的行为。

普通页提供页面菜单，链接／图片／选区／输入框增加对应项目；可复合命中时按上下文组合并去重。无关项隐藏，暂不可执行的基本项禁用；禁用状态根据当前页实时能力复核。

## 2. 常规页面菜单

基础分组建议为：

- **页面控制**：返回、前进、重新加载；加载中提供“停止加载”，清缓存重新加载作为次级项。没有前后历史时禁用对应按钮。
- **页面操作**：复制当前网址、在此网页中查找；查找指向网页查找，不误打开当前聊天查找。
- **批注**：只提供“批注”，点击直接打开右键目标的原生填写面板；不提供查看列表或数量入口。
- **开发工具**：检查元素、打开开发者工具，放在底部与常用动作分隔。

初版保持常用项易扫读，低频功能放更多／子菜单。打印、另存页面、查看源码、媒体播放控制等作为后续扩展，只有接通真实业务后才显示，不在首版放无效占位按钮。网页更多菜单已有的下载、浏览器设置和移窗等不必全部重复进页面右键。

## 3. 按命中内容补充

### 3.1 链接

提供“在新标签页打开链接”“复制链接地址”；移至新窗口等低频项可放子菜单。新标签继承来源页面的真实会话和所属对话，沿标签服务的排序／后台打开规则，不因公共默认会话改为另一个账号。

新建／导航复用 URL 白名单和协议校验。javascript、内部或本地文件等特殊链接不直接套普通 HTTP 打开，外部协议继续遵循既有外部打开策略。链接文字、URL 来自网页，不因此获得宿主命令权限。

### 3.2 图片

在真实图片上下文提供“复制图片”“复制图片地址”“在新标签页打开图片”；没有图片内容或无有效地址时分别禁用／隐藏。图片和链接复合命中时保留各自动作，避免同名项重复。

“保存图片”需接入现有下载／文件保存与权限流程，不能在菜单里绕过下载服务直接写路径。首批可先提供复制与打开，保存接通后再显示；canvas、blob 和跨域媒体需分别验证，不承诺任意内容都能按 URL 下载。

### 3.3 选中文字

提供复制、使用当前搜索方式搜索，以及为选区添加批注。菜单只显示精简短标签，全文不塞进菜单，不在日志记录选区内容。

只有用户实际选择搜索才打开新结果页，正确编码查询词并沿来源会话。密码等敏感输入控件不提供选区搜索／复制派生动作；不为了组菜单读取或序列化表单的 value。

### 3.4 输入框／可编辑区域

按 `isEditable`、控件类型和 `editFlags` 提供撤销、重做、剪切、复制、粘贴、粘贴为纯文本、删除、全选；保留网站内容中的输入位置和选择，不操作聊天编辑器或地址栏。

保存触发 frame 的身份和焦点。现有 editState 只读顶层 activeElement，不能直接用于 iframe 菜单；也不存在可随意调用的 WebFrameMain.copy／paste。应用应显式绑定 guest 的原生编辑动作，并验证焦点仍属于原 frame；能力不能确认或 frame 已导航／销毁时不执行旧命令，不用脚本读取正文代替原生复制。

## 4. 批注入口的具体行为

“批注”保存右键时的来源页、文档、frame 和位置上下文，关闭菜单后通过统一批注服务直接建立目标并打开编辑。有效目标能够解析时直接为该位置建立临时目标并打开[.7 多行评论面板](./已完成/native-annotation-multiline-panel-plan-2026-11-04.md)，不需要用户再找一次原位置。

命中选区时尽量保留真实文字／几何证据；没有可靠锚点、跨 frame 暂不支持时禁用并说明；页面或目标已经变化时拒绝旧动作，不退回“进入批注模式”，也不将旧坐标当成已定位元素。不要通过合成网页点击建立批注，以免激活链接或表单。

保留正常导航／地址栏与工具栏点选模式；数量入口及原生批注列表按本轮用户要求移除。右键直接填写、保存后在所属对话中显示批注卡片，不自动发消息或调用 Agent；显式“加入输入框”才建立引用。原草稿、目标、revision 和证据机制保持。

已在目标编辑或 NativePanel 文本输入上右键时，由该编辑控件处理；不能穿透成底层网页菜单。已有草稿先保留再切目标，旧关闭回调不清除新编辑器。

## 5. 检查元素与开发者工具

“检查元素”调用真实网页 `page.webContents.inspectElement()`，使用同一 guest 的原始上下文坐标，不检查宿主 window.webContents，也不检查聊天界面。键盘调用缺少可靠目标位置时提供“打开开发者工具”，不默认检查左上角。

优先使用独立 DevTools 窗口，避免停靠导致网页宽高突然改变；显式选择停靠模式时按真实几何变化处理。用户关闭后释放相应资源，重复检查复用现有 DevTools。

DevTools 不是只读提示：它允许执行脚本／修改 DOM，并可能导致已附着 debugger 断开。Agent 活跃、原生输入未收敛或调试连接冲突时，禁用并说明或沿既有明确接管流程协调；不强行 detach／重连，不自动停止再重放任务。仅打开右键菜单不 attach debugger，不打开 DevTools。

调试窗口可能产生额外 WebContents，计作用户明确打开的开发工具；普通右键菜单自身仍不创建 renderer。DevTools 不获得 Navora 应用 IPC 或新的 Agent 授权。

## 6. 原生菜单、状态与控制权

沿 `Menu.buildFromTemplate`／`Menu.popup` 和现有 `.6` 应用菜单 appearance，统一图标、分组、禁用、快捷键及焦点。实际监听和动作在主进程绑定注册页面，不向远程 guest 暴露当前只给应用宿主的 native-ui／workspace IPC。

菜单快照带 pageId、真实宿主、文档／frame 身份和请求代次，执行前复核。切标签、导航、销毁或移窗后取消旧菜单；坐标相关动作还需确认滚动／缩放／布局未使目标失效。复制、打开、导航和批注不能使用“目前活动标签”替代原触发页。

菜单定位与 inspect 使用不同空间：检查元素沿同一 guest 的 params.x/y；原生菜单位置经已验证的宿主内容区／WebContentsView 偏移转换。选择框、页面坐标、宿主 DIP 与屏幕坐标分开，不盲乘 deviceScaleFactor，也不对 iframe 再重复加偏移；跨缩放和独立窗口以真实命中验收。

Agent 控制租约的原生 pointer／keyboard 保护可能让 guest 根本不产生右键事件。打开／悬停／关闭菜单不得自动解除保护或调用 takeControl；需要人工操作时沿现有宿主接管入口，不能为菜单可见性合成或重放右键。以后若要求保护期间也能出现受控菜单，另核对内核通知能力，不假定已有。

导航、刷新、编辑和批注等实际动作共用现有协调、授权及忙碌规则；未收敛时禁用或提示先接管，不绕过 owner／epoch。关菜单恢复正确焦点，不能把真实输入重新派给错误 frame。当前菜单与批注面板／IME 候选的关闭顺序也需明确。

## 7. 依赖与实施顺序

基础右键菜单、导航和检查可用现有 Electron API，不要求为这些项目等待新内核。`.7` 已发布多行 textarea，批注菜单项接统一原生批注入口；随内容自动增高仍缺原生尺寸契约，不能由固定 height 推定已满足。当前实施顺序见[.7 总规划](./electron-7-readiness-and-implementation-plan-2026-11-04.md)，本轮未接入应用。

实施建议：先接可信页面事件与菜单上下文，再接导航／复制／查找及检查；随后接链接、图片、frame 编辑和批注，最后扩展下载／打印／源码等。每批复用现有服务，不重复实现另一套浏览器控制器。

源码落点包括 browser-host／browser-registry 的页面注册、统一菜单服务、browser-workspace 现有命令及批注服务。当前只读检索未见这些网页模块注册页面 context-menu／inspectElement；这不等于所有系统默认菜单均不存在，也不将应用调试环境变量打开 DevTools 当成正式入口。

## 8. 验收

- 页面空白、链接、链接图片、选区、普通／密码输入框、contenteditable、同源及跨域 iframe 的菜单项目与可用状态正确。
- 无历史时返回／前进禁用，加载中停止可用，网页查找不误开聊天查找；动作仍作用于原页。
- 链接继承真实会话／对话，下载沿原服务；输入编辑不误切到宿主或另一 frame。
- 右键批注正确定位或明确要求重选，草稿／全文／证据不丢，DevTools 检查实际网页并处理调试冲突。
- 鼠标、键盘菜单、多 DPI、应用 zoom、页面滚动、独立窗口和移窗后坐标正确；菜单未选动作关闭时不误触网页。
- AI 保护、等待、忙碌、暂停和显式接管路径准确，不因菜单自动交还；导航／移窗后迟到动作被拒绝。
- 菜单叠加时网页视频／动画和 Agent 实例保持，背景截图为零；显式 DevTools 实例与原生菜单资源分别统计。

API 依据：[Electron context-menu 事件](https://www.electronjs.org/docs/latest/api/web-contents#event-context-menu)、[inspectElement](https://www.electronjs.org/docs/latest/api/web-contents#contentsinspectelementx-y)、[Debugger](https://www.electronjs.org/docs/latest/api/debugger)。实现同时核对锁定 `.7` 的公开类型。

## 9. 当前实现与专项验证

[页面菜单服务](../electron/modules/browser-page-context-menu.ts)已接基础导航、加载停止、网址／链接／图片复制及来源会话内新标签、选区搜索、原生编辑、网页查找和独立 DevTools／检查元素。来源页、宿主、文档、控制代次、frame 与实时可用状态在动作前复核；菜单互斥沿现有 native-ui 服务，不向 guest 暴露宿主 IPC，不新增截图替换。

主 frame 编辑在隔离世界保留实际焦点控件与选区，只核对身份、选择及控件状态，不读取表单 value；不匹配时拒绝，不向另一个控件重派。坐标动作保留原始原生点，核对可观察命中节点、矩形与视口，并穿入开放 shadow root。键盘来源不猜左上角目标。

独立复查发现子 frame 的主世界凭据可被网页伪造、外层 iframe 不能证明内部命中节点未变，因此当前子 frame 不开放编辑和坐标检查／复制图片，保留来自原生 params 的显式文字复制和其它页面动作。封闭 shadow 的内部目标及完整 frame 编辑仍需可信原生上下文能力，不冒称 DOM 可观察检查覆盖全部情况；公开契约需求见[定制规范第 7 节](./electron-native-panels-customization-spec-2026-11.md#7-网页右键的-frame-目标与编辑凭据待公开能力)。已有 debugger 或实际 Agent 输入租约时禁用冲突动作，不强制断开或自动交还。

本轮右键菜单已改为“批注”，在隔离世界保留并核对真实命中节点、几何、视口和文档代次，直接建立目标并弹出原生填写面板，不合成业务点击。保存后显示对话卡片，右键这次编辑关闭后退出单次批注会话。跨域子 frame 只批注外层框架容器，不冒称已取得内部可信节点。主侧真实菜单专项通过 24 项，完整界面链路见[本轮实施记录](./panel-density-and-annotation-chat-implementation-2026-11-05.md)。

[隔离检查脚本](../scripts/browser-page-menu-smoke.mjs)使用真实 `.7` 网页右键事件和跨源 frame，最终 19 项检查通过，覆盖基础禁用状态、锚点偏移、真实历史返回、停止加载不误刷新、链接会话／对话继承、密码排除、跨 frame 拒绝伪造与错误目标、开放 shadow 隔离凭据、100／150／200% 网页缩放、焦点切换、坐标目标替换、菜单关闭／切页／移窗后旧动作拒绝及 debugger／Agent 冲突。Menu 对象与回调为真实 Electron 对象；OS popup 绘制、剪贴板和 DevTools 打开动作在该脚本中隔离记录，不能将其宣称为物理菜单键盘、混合 DPI 或 DevTools 视觉实机验收。脚本只访问本地网页与临时资料，不读写安装版用户数据。
