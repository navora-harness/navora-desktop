## 1 材质范围和窗口覆盖

- **主窗口**：标题栏、菜单所在框架及最左图标栏露出系统 Acrylic；按钮和标签的交互状态保持清楚，文字不随背景一起透明。
- **停靠资源侧栏**：以低饱和、带透明度的主题底色覆盖系统底材，保留文字对比度；搜索、选中行等必要控件可有独立底色。主内容区继续不透明。
- **独立浏览器窗口**：标题栏／标签条的空白框架显示 Acrylic，标签仍沿用工作区的主题、选中、悬停和失焦规范；地址工具行及网页不在本次透明范围内。
- **独立文件窗口**：标题栏／标签条采用与独立浏览器相同的透明规则；文件内容及预览区域保持原有不透明表面。
- **设置、欢迎及其它应用路由**：它们目前在主窗口中显示，不为材质另建窗口。应继续保留外层原生标题栏效果，页面正文保持清楚；页面自己的内容标题不自动变成玻璃层。
- **隐藏定位辅助窗口**：`electron/modules/geolocation.ts` 创建的隐藏窗口不纳入视觉改版。
- **系统文件对话框、DevTools、原生菜单、NativePanel、网站信息与证书窗口**：不把 BrowserWindow 的设置批量套入这些窗口；各自保持所属平台／内核的展示规则，网站信息仍保留既有入口和语义。

“其它窗口标题栏”在此指应用管理的可见独立窗口标题栏；新增窗口类型应经过同一窗口策略登记，不能遍历全部 Electron 窗口后无差别改造。

## 2 原生底材与页面绘制的边界

Electron 的 `backgroundMaterial` 构造参数或 `win.setBackgroundMaterial('acrylic')` 设置的是 **整个窗口的系统绘制底材**，包括非客户区。它不是对某一条 DOM 元素施加 CSS 模糊，也不提供“只在某个矩形中开启 Acrylic”的区域接口。目标范围由应用自身哪些区域透明、哪些区域继续不透明共同决定。

采用条件化透明表面让底材透出，不能只在构造参数中增加一个字段。根文档、Vuetify 包装和父容器仍画实色时，标题栏或侧栏即使设置为透明也只会露出上一层实色。

采用系统材质不等于必须开启 `transparent: true`。本规划保留现有原生窗框、系统窗口按钮与命中机制，不使用全窗透明、降低窗口 opacity、黑底补偿或特殊显卡参数拼出效果。用于 WebContents 清屏的背景值与材质更新顺序应在接入时以实际透明合成结果确定，不能把“字符串设置成功”当成底材可见的证明。

不得通过 `filter: blur()` 模糊文字和子元素；`backdrop-filter` 只能处理可合成的网页层，不能用来宣称已模糊原生 WebContentsView 中的网页。正常 Acrylic 展示不采集桌面／网页截图，不显示静态背景替代实时内容。

## 3 现有实现中的阻挡层与改造落点

以下保留实施前的阻挡层定位，便于解释改动动机；当前接入点及实际验证范围见第 9 节，不能将这些基线描述当作现状。

### 3.1 原生窗口和主题同步

- `electron/main.ts:createWindow()` 使用 `mainWindowChrome()`，但另设 `backgroundColor: '#ffffff'`。
- `electron/modules/browser-host.ts:newDetached()` 同样设白色窗口背景，并复用 `detachedWindowChrome()`。
- `electron/modules/file-windows.ts:newHost()` 设置 `backgroundColor: '#fff'`，也复用上述独立窗口框架。
- `electron/modules/window-chrome.ts` 的 Windows 分支目前使用原生 frame、隐藏标题栏和透明 `titleBarOverlay.color`，可以作为统一策略入口；不能改掉平台拖动、缩放和系统按钮行为。
- `electron/main.ts:updateWindowAppearance()` 每次主题更新会执行 `win.setBackgroundColor(theme.shell)`，并将 `titleBarOverlay.color` 重新设为实色 `theme.shell`。即使构造时已透明，后续主题同步也会重新遮住效果。必须让构造、首次显示、配置变更和系统主题变更使用同一套材质决策。
- `.7` 的 `BrowserWindow::SetBackgroundMaterial()` 在设置 `acrylic` 后自动将宿主窗口及其 WebContents 背景设为透明，在设置 `none` 后自动设为纯白；因此不能先恢复深色背景再调用 `none`，否则恢复色会再次被白色覆盖。回退顺序必须是先 `none`，再立即设置当前主题的不透明背景，并同步 DOM 表面与标题栏按钮颜色。不能把“关闭材质会自动恢复原主题色”作为假设。
- 底层 `NativeWindowViews::SetBackgroundMaterial()` 遇到 DWM 设置失败仅记录警告，没有向 JS 抛出这一失败。支持条件预检和可观察的接口异常仍须处理，但不能只用 `try/catch` 就声称捕获全部原生材质失败；当前公开接口的观测限制见第 4.3 节。
- `pushConfigChanged()` 已向同应用文档的可见宿主窗口发送配置；新窗口首帧也应直接采用当前策略，不能等待用户切换主题后才生效。

### 3.2 根容器和主题覆盖

- `src/App.vue` 的 `body` 当前画白色背景；`src/main.ts` 引入的 Vuetify／Postpile 样式与应用包装也需检查最终计算背景。
- `src/styles/appearance-themes.css` 把 `.navora-app`、`.shell.main-shell`、`.window-titlebar` 和 `.activity-rail` 设为实色，且使用 `!important`。深色模式另有 `body` 实色规则。只改某个组件的 scoped 样式不足以穿过这些层。
- `src/styles/main-window-layout.css` 的 `.content-surface` 整体实色包住侧栏和正文。若仅把 `aside.sidebar` 改为半透明，底下仍是这块实色；应将可露底材的父层与正文自己的不透明表面明确分开，同时保持现有网格、裁切和圆角命中。
- `src/styles/interface-followup.css` 的悬浮侧栏规则又单独覆盖背景；需要与停靠状态分别核对，不能误把浮动侧栏归为系统材质的自动继承者。
- `DetachedWindowBar.vue`、`BrowserHostPage.vue`、`FileHostPage.vue` 的外层和标题条背景，加上 `appearance-themes.css` 的独立窗口规则，都会挡住标题栏底材。独立窗口根表面需允许标题区域露底，同时让工具行和内容区保持实色。

规划使用一个明确的宿主材质标记，仅控制主窗口和独立窗口的指定框架表面，而不是全局把 `--appearance-surface` 改成透明。只在停靠资源侧栏启用对应半透明 token；悬浮侧栏、NativePanel 的主题与子控件、菜单、正文和网页层不继承这些透明 token。普通面板保持原有不透明主题；也不能通过整体 `opacity` 连带降低文字、图标、焦点框或系统按钮的对比度。

## 4 设置、主题与支持条件

### 4.1 设置与生效状态

在“设置 → 外观”规划一个“窗口透明与模糊”开关，支持环境默认开启；关闭后回到现有不透明主题。这里只新增展示偏好，不改变主题选择、网页透明度或浏览器缩放。

实际状态区分用户偏好和系统能否生效：用户选择开启但系统不支持时保留偏好，并使用不透明表面。已有及后续创建的主窗口、独立浏览器和独立文件 BrowserWindow 一致响应；NativePanel 不参加此开关，保持普通不透明表面。设置保存失败不得造成不同宿主窗口长时间各用一套样式。

设置开关按可信宿主 IPC 发布的 `supported`／`supportReason` 判断能否操作；平台支持由共享策略检查平台、系统构建与公开 API，独立于 `requested` 和当前 `mode`。未知、远程或平台不支持时开关灰显并简短说明，保留原保存值，不代用户改成 false；支持平台即使当前已关闭或因高对比、减少透明度、应用色调等暂时使用实色，也可继续修改偏好，避免关闭后无法再开启。

### 4.2 系统范围与回退

该系统材质接口仅支持 **Windows 11 22H2 及以后版本**。Windows 10、旧 Windows 11、非 Windows、远程网页客户端，以及能够观测到的接口异常或系统透明限制，使用现有主题实色，不模拟截图模糊，不要求升级内核来伪造支持。DWM 仅记日志或系统静默降级的部分不能据此承诺已被自动检测。

系统高对比／强制颜色模式优先采用清晰的不透明表面；系统“减少透明度”开启时同样回退。接入时核对实际版本的 `nativeTheme.shouldUseHighContrastColors`、`nativeTheme.prefersReducedTransparency` 和 `updated` 通知，并覆盖 CSS 强制颜色边界。接口或系统策略不能观测的部分应明确记录限制，不能虚构一个“当前底材已经生效”的系统 getter。

### 4.3 不支持时同时取消透明配色

原生材质与额外的透明配色使用同一份窗口策略，不能出现“系统不支持 Acrylic，但标题栏、图标栏和侧栏仍套用透明颜色”的半启用状态。

- **先判断可用条件**：检查平台、系统版本／构建号、实际运行时是否提供材质接口、用户外观偏好，以及可观测的系统透明度和辅助功能设置。Windows 11 的系统版本号可能仍以 `10.0` 开头，不能仅靠主版本号等于 `11` 判断。版本无法解析、接口缺失或条件不明时，保守使用实色。
- **统一决定有效模式**：区分“用户希望开启”和“当前窗口获准请求材质”。只有支持条件通过且没有观测到接口异常时，才给宿主文档启用材质专用标记和半透明配色；这表示应用按当前可观察条件完成请求，不证明 DWM 调用全部成功或系统合成器确实呈现模糊。应用与系统外观不同时保留底材，由宿主自身的主题半透明覆盖色保证可读性，不再仅因色调不同就关闭 Acrylic。
- **同步撤销整套效果**：不满足条件、用户关闭或观测到接口异常时，在接口可用的情况下先将原生底材设为 `none`，紧接着调用 `setBackgroundColor()` 恢复当前主题的不透明背景，不能保留 `none` 自动写入的纯白。与此同步移除材质标记，恢复根背景、标题栏、最左图标栏、停靠资源侧栏及 `titleBarOverlay` 的原有不透明主题色，并重新计算文字和系统按钮颜色。不能先设主题背景再调用 `none`，也不能只关闭原生材质或只调整某个组件；正文原有不透明表面继续保留。
- **响应系统变化**：结合实际版本的 `nativeTheme.prefersReducedTransparency`、`inForcedColorsMode`、`shouldUseHighContrastColors` 及 `updated` 通知重新评估；属性不存在或无法可靠观测的条件按兼容策略处理。用户偏好不被系统临时回退覆盖，系统重新允许后可按同一策略恢复。主窗口和已有独立窗口同步处理，新窗口首帧先保证实色可读，再按已确认的条件启用。

现有 `setBackgroundMaterial()` 返回 `void`，没有可可靠证明“当前 Acrylic 已被系统实际绘制”的公开 getter；DWM 调用失败可能只在原生日志中记录，JS 的 `try/catch` 不能完整判定。`.7` NativePanel 的公开接口也没有材质生效状态或状态变更事件；`NativePanel.isSupported()` 只说明原生面板可用，不能证明系统支持 Acrylic。源码与发行测试使用的 `_getState()` 属于未列入公开类型的私有诊断入口，不能将其中的 DWM 属性或请求应用结果包装为生产环境的“实际模糊已显示”。远程会话、失焦或系统合成策略可能静默减弱效果，因此不能承诺识别所有视觉降级，也不能把调用未抛错当成模糊已显示。不增加截图轮询或虚构 `isAcrylicSupported` 接口；暂时无法观测的情形保留手动关闭入口。如后续定制内核提供明确的公开材质状态通知，再接入统一策略；此可选增强不列入消除网页截图替换的门槛。

### 4.4 主题、失焦与首帧

浅色、深色和跟随系统模式分别定义侧栏覆盖色、文字和细边界；主题切换不改变网页本身主题。标题栏系统按钮颜色继续同步，以免透明背景上出现看不清的关闭／最大化符号。

当前应用的 `appearance_mode` 主要改变宿主 CSS 与配色，而内核的 DWM 浅深色跟随 NativeTheme；两者不是自动绑定的同一状态。系统浅色／应用深色及反向组合可能出现材质色调与文字不匹配，必须按主窗口、独立浏览器和独立文件窗口分别核验。不能为匹配宿主材质而直接改全局 `nativeTheme.themeSource`，以免同时改变真实网页的系统主题媒体查询。

本轮保留用户选择的应用主题，逐窗口检查文字、图标、系统按钮和焦点对比度。标题栏、左侧图标栏与停靠侧栏使用应用主题的半透明覆盖色：同色调时覆盖较轻，相反色调时加深覆盖以保持可读，底下仍是实时系统 Acrylic。该方案没有调用逐窗口 DWM 色调接口，也没有全局更改 `nativeTheme.themeSource`。辅助功能限制、不支持或可观察 API 异常仍回退当前主题实色。以后如确需独立设置每个宿主窗口的 DWM 原生浅深色，再确认公开内核契约；不借用 NativePanel 私有诊断接口，也不把新增可选材质定制列入网页截图替换退出门槛。

窗口失焦、最小化还原、系统关闭透明或节能时，DWM 可能减弱材质。允许系统使用清楚的失焦实色，不强行维持桌面透出。当前标签、焦点和选中行仍应可辨认；不得仅用背景变化表达重要状态。

首次显示、从托盘恢复和重新创建独立窗口应避免白色／黑色整窗闪帧。材质切换不通过 reload、销毁窗口或重新创建网页实现。

## 5 NativePanel 材质搁置与能力留档

本次系统底材保留用于停靠侧栏的半透明表面；悬浮侧栏盖在实时网页上时，**继续使用不透明面板**。它不会因为父 BrowserWindow 使用 Acrylic 就自动模糊该网页，本轮也不显式为它申请自己的系统材质。

### 5.1 `.7` 已发布的面板材质契约（留档，暂不接入）

`.7` 补齐了 `.6` 缺少的 NativePanel 自身材质选项。以下为已发布能力核对，**不表示当前批注、悬浮侧栏或其它原生面板将启用 Acrylic**；只有用户后续重新启用这一规划时，才进入设计、接入和专项验收。

- `new NativePanel({ backgroundMaterial: 'acrylic', ... })` 和 `panel.update({ backgroundMaterial: 'acrylic' })` 请求面板自己的 Desktop Acrylic；只接受 `none`、`acrylic`，默认 `none`。更新时省略该字段保留现有请求，显式 `none` 恢复普通表面。与其它字段同批更新时先整体校验，非法字段不产生部分修改。
- 该字段仅作用于 NativePanel，不继承父 BrowserWindow 的设置，也不反向改变宿主窗口。`Menu` 本轮没有新增材质配置，继续使用原生菜单既有外观接口；网站信息调用保持原样。
- 面板继续使用原生 Views 控件，不为材质增加 WebContents、网页或额外渲染器。Windows 管理实际材质强度；没有模糊半径、噪点或任意 DWM 透明度参数，不能将 `theme.background` 的 alpha 当成材质强度。
- `theme.background` 提供系统无法应用材质时的后备色。将来接入时，根容器和子控件的不透明背景仍会遮住底材；需要另行设计可读性与透明范围。当前不进行这套透明化，面板主题维持可读的不透明背景。

### 5.2 当前采用固定不透明的面板策略

当前面板构造、复用和主题更新均保持 `backgroundMaterial: 'none'` 与不透明 `theme.background`，不订阅或继承宿主的 Acrylic 开关。宿主窗口在材质与实色之间切换时，不改变面板材质，也不使悬浮侧栏或批注输入框变透明；面板仍按普通浅深主题更新文字、背景、边界和无障碍配色。主题更新不重发编辑器旧 `value`，保留草稿、输入法、选区和焦点。

以后若恢复面板材质需求，`.7` 内核已有按 Windows 版本、高对比／强制颜色、减少透明度、节电模式、DWM 合成可用性及调用结果回退的保护；请求无法应用时会把后备背景强制画为不透明。但它没有把全部回退原因发布为应用可订阅的公开事件，不能据此承诺宿主配色也会同步识别全部临时降级。该事项仅留档，不进入当前实施路径。

### 5.3 透明命中与无障碍

`.7` 保留原生圆角可见区域命中：圆角外部与独立阴影不拦截下方页面；面板可见主体有透明材质仍接收自身交互。**原生圆角外的穿透不等于面板主体整体点击穿透**；`focusMode: 'none'` 也不构成被动提示完整穿透能力，不能据此宣布该缺口已经补齐。

主窗口框架、停靠侧栏继续按本规划验收。普通不透明 NativePanel 的文字／焦点对比度、键盘、输入法、关闭后的焦点恢复和圆角命中仍由各自功能规划覆盖；不增加“面板 Acrylic 应显示”的验收要求。`.7` 滚动条的系统配色和无障碍边界不因材质搁置而取消。网页 WebContentsView 的圆角需求继续取消，不受原生面板圆角影响。

悬浮侧栏原生化、子菜单协调和截图替换清理继续按原规划推进；本规划不恢复静态网页背景、不增加顶层 WebContentsView。面板材质搁置与尚缺的侧栏交互均不阻塞主窗口与独立窗口的系统底材路线。

## 7 接入顺序与验收

1. 核对 Windows 系统条件、原生接口及当前窗口类型，先在受控测试窗口验证系统底材与不透明回退。
2. 集中管理窗口材质、背景清屏和 titleBarOverlay 颜色策略，覆盖三类可见应用窗口的创建和运行时更新。
3. 处理根文档到指定表面的透明链；聊天／文件／网页内容维持原不透明边界，消除主题 `!important` 的遮挡和反复覆盖。
4. 接入外观开关和系统辅助功能回退，同步上述三类已有 BrowserWindow；NativePanel 保持普通不透明表面。最后验证首帧、失焦和特殊窗口状态。

验收使用真实桌面系统材质和受控动态背景，不能只检查 CSS 属性、隐藏窗口或 API 未抛错。留存测试截图只作为验收证据，不用于产品运行时背景。

- 独立浏览器和文件窗口标题栏表现一致；移回／移出、置顶、标签拖动和关闭不受影响。
- 所有内置主题、浅深色、系统跟随和窗口失焦下，文字、图标、系统按钮、选中行和键盘焦点清楚；设置页往返保持效果。明确覆盖系统浅色／应用深色及反向组合，逐窗口记录材质是否可读；未通过的窗口恢复当前主题实色，真实网页的主题媒体查询不因宿主设置改变。

- 首次启动、托盘恢复、最小化还原、最大化／还原、跨显示器和 100%／125%／150%／200% DPI 核对背景、窗口边界与系统按钮位置。
- 实时视频和 Agent 连续运行时开关材质、开关侧栏、移动窗口，网页不重建、不冻结、不触发弹层背景截图；输入保护及既有白屏恢复回归通过。
- 比较材质开／关时移动、缩放和视频播放的合成延迟、CPU／GPU、内存及窗口数；无设备或系统条件实测的项目标记未验证。
