## 1. 重新确定产品结构

主窗口围绕一个工作流组织：选择对话 → 发起任务 → 在工作区查看文件和网页 → 将选中的资料加入对话 → 查看结果。资源管理、插件技能和设置服务于这个工作流，各自有明确的场景和返回路径。

现代化主要体现在稳定的位置、清楚的作用范围、可恢复的状态和轻量的视觉层级。优先解决重复入口、整行空白、错位圆角和操作混杂，再调整图标与装饰。

### 已确定、必须继承的要求

- 窗口标题栏与左侧图标栏是同一块底层外框，底色连续。
- 侧栏、主内容与工作区属于同一内容层；弹窗、弹出面板、菜单属于最上层。
- 内容层没有额外外边距。圆角作用于合成内容面的外轮廓；侧栏与正文、正文与工作区的内部接缝是直角。此前把圆角单独加到 `.main` 上，误将内部接缝裁圆，不能沿用。
- 所有弹出菜单，包括右键菜单，使用统一的圆角规范。
- 标题栏只比原生窗口按钮略高；按钮区底色与标题栏融为一体。
- 常规界面控件使用默认箭头光标；文本输入、分隔条调整等使用对应的系统光标。
- 工作区入口在无标签时显示加号；有标签时显示数量，超过 9 个显示“9+”。
- 工作区标签先保持合理宽度，增多后逐渐收窄，确实放不下才横向滚动；不显示滚动条，支持滚轮。
- 对话摘要按钮位于对话标题右侧，跟随对话栏宽度定位；按第 18 节修订，工作区隐藏时其右侧紧接工作区入口。
- 独立浏览器窗口顶部空白必须能拖动窗口。
- 本轮只交付规划与结构示意，不修改应用界面。

### 本文新增的推荐决策

固定各区域职责、将插件与技能归入扩展中心、将文献检索改为明确的导航入口、取消工作区常驻省略号、统一工作区状态名称与菜单归属。它们是新方案，不是对当前实现的描述。

## 2. 现状诊断

1. 窗口标题栏的全局按钮包含当前对话摘要、工作区和页面更多，混入了页面级操作。
2. 对话、文件、插件和浏览器页面分别维护标题、工具行与顶部预留，旧的标题栏偏移与新外框并存；工作区留下的 44px 空白就是这种冲突。
3. 打开工作区后，窗口、标签栏和网页工具栏同时出现三个省略号，外观相同而作用不同。
4. 对话文件、浏览器资源、摘要卡片与工作区存在重复浏览入口，资源归属与当前显示内容容易混淆。
5. “显示工作区”“展开工作区”“打开浏览器”“还原”“隐藏”“关闭”没有稳定区分，图标也未充分表达状态。
6. 技能管理位于设置，插件管理又有独立场景；运行设置与日常内容管理混在一起。
7. 多处 CSS 通过追加覆盖修补界面，布局、拖动区域、浮层与原生网页的遮挡缺少统一归口。

## 3. 主窗口的固定空间结构

### A. 窗口标题栏：应用菜单与窗口操作

- 左侧：应用标识与 Navora，字号克制，不重复显示当前对话长标题。
- 中间：按第 17 节增加文件／编辑／视图／帮助，剩余位置为弹性拖动区，不另占一行高度。
- 右侧：系统最小化、最大化／还原、关闭按钮。工作区入口按第 18 节移至对话标题行。
- 移出的内容：对话摘要、对话更多、网页操作、插件按钮和设置页操作。
- Windows 推荐基线为标题栏 44px、原生按钮区 40px；其他平台按原生控件适配。

### B. 左侧图标栏：只切换主要场景

推荐固定顺序：对话、对话文件、浏览器资源、扩展、文献检索。底部为设置与帮助，不再增加一个语义不明的全局省略号。

- 图标栏推荐宽度 52px；按钮 36px，导航图标 20px。均为 CSS 像素，不跟随截图物理像素硬编码。
- 当前场景使用浅色选中面和单一位置标记，图标不因选中而换成另一套风格。
- 对话可标记有待确认任务；文件仅显示进行中下载数量或完成提示；浏览器显示当前范围的页面数量。提示与工作区标签计数的意义不同，悬停文字必须说明。
- 设置和帮助不携带业务计数。插件可注册的额外入口归入扩展中心，避免任意扩展把主导航不断拉长。
- 再点当前场景图标可切换该场景导航侧栏的显示，不关闭任务或内容。

### C. 导航侧栏：只负责定位对象

宽度建议默认 260px，允许在 240–360px 内调整。结构为：场景标题及收起按钮 → 必要的新建／搜索／范围筛选 → 对象列表。列表独立滚动，标题固定。

- 对话：新对话、搜索、置顶与时间分组、对话及子任务列表。批量管理并入列表工具菜单，进入批量模式后才显示批量操作条。
- 对话文件：当前对话／全部对话范围切换、文件搜索、目录树与下载状态。跨对话对象始终显示所属对话。
- 浏览器资源：范围切换、搜索、页面／页面组列表。只有一个页面组时可省去多余父节点；独立窗口中的页面有“独立窗口”标记。
- 扩展：插件、技能、商店入口和搜索筛选；具体对象的说明与操作放到主内容，不在侧栏堆叠管理按钮。
- 文献检索：检索条件和来源筛选；主区展示结果。不得藏在无说明的窗口更多菜单中。
- 设置：显示设置分类，替换当前侧栏内容；关闭设置恢复之前的场景与侧栏状态。

侧栏标题栏最多保留“一个主要操作＋收起”。已有搜索、新建、批量操作尽量进入下一行有名称的工具区，避免每个标题旁都出现一串图标。

### D. 主内容：同一时刻只有一个主场景

- 对话场景：对话标题栏、消息阅读区、输入区；需要时与工作区左右分栏。
- 文件场景：文件标题栏、路径／搜索／排序工具行、文件列表；打开文件可在工作区预览。窄空间中切到单区预览，提供返回文件列表。
- 浏览器场景：左侧页面导航，主区直接显示工作区标签和网页；不再另铺一套重复网页列表和一套浏览器标签。
- 扩展场景：对象标题、身份与运行状态、主要操作、内容分区。插件／技能日常管理移出设置；设置仅保留运行、路径、权限和开发配置。
- 文献场景：检索标题与查询区、来源进度、统一结果列表、结果详情与导出。打开来源沿用现有能力；在接入工作区前，不自动创建未知归属的浏览器会话。
- 创建器场景：从扩展中心进入，显示返回入口、草稿名称、保存状态、编辑区、生成与验证操作。离开存在未保存内容的草稿时按实际保存能力处理。
- 设置场景：设置标题、分类侧栏、表单正文和必要的应用／保存操作；不让已有工作区悬浮盖住设置。

对话消息、文件列表、网页与设置正文各自滚动；窗口标题栏、导航标题和场景标题不随正文滚走。

## 4. 对话场景的显示标准

### 标题行

左侧为单行对话标题；子任务在标题前显示返回父对话入口与“子任务”标识。必要时显示简短运行状态，不放完整执行日志。

右侧固定顺序为“对话更多操作 → 当前对话摘要 → 工作区入口”。工作区入口只在工作区隐藏时显示；工作区显示后，摘要回到对话栏最右侧。所有操作都位于对话栏内部右缘，有工作区时停在中间分隔条左侧；省略号仅承载低频对话操作。具体状态见第 18 节。

标题溢出使用省略号；给右侧操作预留固定空间，不能让长标题挤掉按钮。运行中的停止操作归入输入区，避免标题行再增加一组计时与停止按钮。

### 消息阅读区

- 正文采用连续阅读面，推荐正文 16px、行高 1.6–1.7，阅读宽度上限约 760px。
- 用户问题与助手结果有清楚的作者和段落层次；思考、工具过程、来源和诊断信息按需折叠。
- 工具执行只在正在运行时展开重点状态，完成后保留摘要与展开入口，不把整屏日志作为默认结果。
- 来源、复制、耗时等属于消息级辅助操作，位于所属回复末尾，不搬到窗口标题栏。
- 子任务嵌入所属对话关系，进入和返回都有明确路径，不把导航动作伪装成关闭。

### 输入区

- 中间为可编辑正文；附件引用、资料摘录和待发送资源按第 17、19 节进入同一编辑区域，来源块可编辑说明、摘录和显示名称。
- 底部一行按“添加资料 → 执行模式 → 权限 → 模型 → 发送／停止”组织。
- 添加资料统一为一个入口，菜单中区分本地文件、对话文件、网页与页面组；删除图标只属于具体附件条目，不显示无对象的孤立叉号。
- 发送和停止复用同一主操作位置；运行时保留输入能力，后续消息进入明确的待发送队列。
- 权限确认／用户选择在输入区上方显示当前待处理项及剩余数量，按队列处理；切换对话后按所属对话隔离。
- 模型和权限保留现有真实能力与运行限制，显示不可切换的原因，不暗改授权语义。

### 对话摘要

摘要是当前对话的信息面板，不再承担完整文件和网页资源管理。内容建议为任务概述、主要输出、引用来源、执行状态及必要统计，并提供跳转到对应消息／资源的入口。

从标题按钮打开有锚点的浮层，优先覆盖对话栏，避免挤出第三个常驻内容列；工作区不跟着消失。宽度建议 360px，并受当前视口约束。点关闭或 Esc 返回原按钮；切换对话立即更新归属。

## 5. 工作区的对象、状态与操作

### 归属与恢复

- 保留项目现有的“按当前对话保存工作集”原则。切换对话恢复该对话的标签、选中项与显隐偏好，不把上一对话网页偷偷带入新对话。
- 文件标签可引用其他对话的文件，但必须保存原始所属关系、显示来源标识；显示文件不会悄悄切换当前对话或获得新授权。
- 网页保留原有页面标识和浏览器会话。主窗口与独立窗口之间移动页面时迁移原页面，不重开地址，不丢失表单与登录状态。
- 重启恢复标签信息不等同于恢复未保存网页内存；恢复失败必须可见且可重新加载。

### 明确区分四种动作

1. **显示／隐藏工作区：**只改变可见性，保留标签和页面。
2. **展开工作区／恢复分栏：**工作区在主内容中切换全宽与分栏，图标栏及导航侧栏仍属于主框架，不是操作系统窗口最大化。
3. **移至独立窗口／移回工作区：**改变标签宿主，保持内容与归属。
4. **关闭标签：**真正关闭该标签；文件不因此被删除，网页按真实页面生命周期关闭。

### 对话标题行工作区入口（第 18 节修订）

- 0 个标签：圆角小框中的加号，提示“新建浏览器标签页”，支持快捷键；没有当前对话时先建立明确的对话归属。
- 1–9 个标签：框内显示准确数字；大于 9 个显示“9+”，悬停仍显示真实数量。
- 对话标题内的入口仅在工作区隐藏时显示；0 个标签时点击新建并显示工作区，有标签时点击恢复工作区。显示后由工作区右上角已有隐藏按钮接替，复用同一数量图形和相同屏幕坐标，显示开启状态；不增加第二颗按钮。
- 计数仅统计当前对话主工作区的标签，包括文件与网页；不统计资源库全部页面、其他对话工作集和已移出的独立标签。

### 标签栏

紧接主内容顶部，和相邻对话标题栏同高，前面不再插入标题栏占位或空白工具行。

从左到右固定为“标签列表 → 新建网页＋ → 展开／恢复分栏 → 隐藏工作区”。取消常驻“更多”。新建按钮紧随实际标签，展开与隐藏按钮靠右；不足空间时为右侧固定操作保留宽度。

- 标签常态目标宽度 220px，最多约 260px；随数量增加收窄到约 112px，之后才滚动。
- 标签高度 36px，图标 16px；标签栏高度 48px。选中、悬停与焦点有统一状态。
- 标签文字省略、悬停显示完整标题和来源。favicon 不可用时使用网页通用图标。
- 当前、悬停及键盘聚焦标签显示关闭按钮；关闭热区至少 24px。中键关闭，方向键切换；横向滚动没有可见滚动条。
- 标签右键及键盘菜单保留打开文件、移至独立窗口、关闭当前标签等操作；独立窗口显示移回主工作区。
- 不把“关闭其他／关闭所有”等新功能作为本次修复的隐含前提；如后续添加，需单独考虑未保存文件、下载和批注状态。

### 展开／还原图标的重新定义

此前图标替换提案未完成，不能再以修改其他图标尺寸代替。建议采用同一矩形框构成的两态图形：展开表示单面板加横向扩展方向，恢复表示左右分栏；不用与系统最大化相同的方框，也不使用与网页全屏混淆的四角图形。

提示文字固定为“展开工作区”“恢复分栏”，独立宿主按钮则固定为“移回工作区”。最终 SVG 需与现有整套图标并排核对光学大小；规划示意不表示已替换产品资产。

### 文件与网页内容工具行

- 文件：按类型显示文件名／路径、必要的查找、复制、打开系统位置等已有操作；文件级低频操作归入文件工具菜单。标签标题不重复叠成第二个大型标题。
- 网页：后退、前进、刷新／停止加载，地址栏，批注，手动操作／恢复 AI，下载，网页更多。地址栏占主要宽度。
- 新标签页没有批注和接管需求时隐藏这些操作；没有新下载时下载入口不以持续动画抢占注意力。
- 窄工作区收起低频文字或将次要命令归入网页更多；“恢复 AI”与当前手动控制状态仍须清楚可见。
- 网页工具行建议 44px，地址输入 32px。页内查找与显示设置是临时工具行，关闭后收回高度。
- 批注面板属于当前网页局部功能，显示归属与保存状态；进入选取时明确显示取消和 Esc，不隐藏正在进行的选择状态。

## 6. “更多”菜单只按对象归属出现

分栏浏览时最多出现两个主要省略号入口：

- **对话更多，位于对话标题：**修改标题、置顶／取消置顶、导出、打开对话文件夹、删除。批量管理属于对话列表工具，不混入当前对话菜单。
- **网页更多，位于地址栏右侧：**当前网页的页内查找、显示设置及其他已有网页命令。刷新有直接按钮，低频菜单不得再承载对话删除或工作区隐藏。

工作区标签栏不再有省略号；标签右键处理标签级命令。文件预览时网页更多自然替换为文件级操作；扩展和设置页用自己的有名称操作，不继承对话省略号。

右键不能成为命令的唯一可达路径：支持标签上的 Shift+F10／菜单键，打开文件仍可通过左侧文件导航完成。菜单开闭不自动切换页面或丢失表单焦点。

## 7. 各场景的内容与主要操作

### 文件

标题固定为“对话文件”，所属对话或范围作为次级信息。路径行提供上一级、面包屑、刷新与系统打开；列表工具提供搜索、排序、列表／网格。文件行显示名称、类型、大小、修改时间及实际下载状态。

建议采用单击选中、双击／Enter 打开，行尾提供一次点击的打开动作；这是相对当前部分单击打开行为的交互调整，后续实施需同步鼠标和键盘。拖动文件可放入工作区或输入区，两种目标分别表示打开与引用。

下载继续合并到所属目录中的实际文件行，不新增第三套下载中心；网页下载按钮展示临时传输面板，并能定位文件。移除下载记录不删除本地文件；删除文件是独立的明确操作。

### 浏览器资源

侧栏负责找页面，工作区负责看页面。当前对话与全部对话范围必须始终可见；跨对话页面不能静默合并会话。点击独立页面条目应聚焦其宿主，移动回主工作区要使用明确的移回命令。

关闭页面与隐藏工作区有不同文字和结果。关闭页面不删除对话；删除对话涉及的资源处理要按实际产品规则单独说明，不能借重规划自动扩大删除范围。

### 扩展中心

统一容纳插件、技能、商店及创建入口。插件详情显示名称、来源、版本、启用状态和加载错误，内容分区为说明、工具、版本；技能显示名称、用途、内容与适用范围。

主操作随真实状态变化为安装、启用／停用或更新；导出、打开位置和卸载属于该对象的次级菜单。失败在对象区域就地解释并提供重试，不以整页空白替代。插件运行与开发设置通过明确链接进入设置相应分类。

### 文献检索、设置与帮助

文献检索沿用当前已有的检索、来源筛选、增量结果、取消、导出与打开来源能力；不在本轮顺便承诺自动全文下载等新功能。

设置只容纳全局偏好、模型连接、浏览器配置、目录、权限、远程访问及运行开发选项；技能日常管理迁往扩展中心。远程窗口管理从远程访问分类进入。帮助统一提供文档、快捷键、引导与关于，避免多个“更多”重复导航。

## 8. 圆角、颜色与密度标准

- 底层外框：标题栏与图标栏使用同一中性底色；主窗口和独立窗口沿用同一语义变量。
- 合成内容面：导航侧栏、当前场景和工作区共同铺满可用区域，外边距为 0；仅外轮廓可用 12px 圆角，内部接缝为 0。
- 导航侧栏：使用轻微区分的浅中性色；主正文使用阅读面；场景标题和工具行使用相近但更浅的标题面。
- 菜单、弹窗和弹出面板：外轮廓 12px；普通按钮 6–8px；标签 8px；输入区约 16px。避免所有元素都套成独立卡片。
- 边界使用一条低对比细线，主要内容平面不叠阴影。选中、悬停、禁用、错误、焦点使用固定语义色。
- 场景标题 14px／600，常规界面 13–14px，辅助信息 12px；重要状态不降到难以辨认的小字。
- 普通按钮 32px、操作图标 16px；菜单项至少 32px，触摸环境使用至少 40–44px 操作区。布局间距统一使用 4／8／12／16／24px。
- 所有业务图标复用同一线性家族和笔画规范。数量是文字计数，不用随机缩放图形表示状态。
- 品牌图标可以保留自身颜色；窗口控制按钮底色融入标题栏，悬停警示继续尊重平台行为。

以上尺寸是推荐基线，需要结合真实 CSS 像素与系统缩放复核，不按用户截图的物理尺寸直接还原。

## 9. 窄窗口与状态切换规则

以实际主内容宽度决定是否分栏，而不是仅检查整个窗口宽度。

- 主内容可用宽度达到约 960px 时允许分栏，对话至少 480px，工作区至少 400px；剩余空间按用户拖动比例分配。
- 不满足分栏宽度时，打开工作区切换为主内容单区，提供“返回对话／返回文件列表”；不再用固定宽度的面板压在输入区上。
- 首次使用时，宽窗口可默认展开导航侧栏，较窄窗口默认收起。用户手动显隐的选择优先于自动布局，避免来回缩放时侧栏反复弹出。
- 640px 以下的紧凑布局将导航侧栏改为抽屉；桌面窗口仍保留原生控制区，远程网页端使用自己的应用栏。
- 自动窄化不覆盖用户此前的分栏比例和展开偏好；恢复足够空间后恢复合适布局，不重复新建标签。
- 摘要、菜单和对话框限制在当前视口内，矮窗口中正文滚动、主要操作可见；关闭后返回正确触发按钮。
- 切换到扩展、设置或创建器时暂时隐藏工作区，不关闭内容；回到原场景恢复此前上下文。

## 10. 独立窗口与拖动规则

独立窗口只显示一行紧凑标签标题栏与下方内容工具行，不再叠一行独立的 Navora 标题。标签栏空白可拖动，真实标签与按钮可点击和拖出排序。

- 整个弹性标签列表不能一概设置为不可拖动；空白与实际标签分别处理。
- 原生窗口按钮、移回工作区、新建及关闭按钮不得被拖动区域覆盖。
- 最大化／还原继续使用原生系统按钮；“移回工作区”与系统还原图标、语义明确区分。
- 文件与网页逐步共享独立宿主外框；混合宿主仍待实现的部分不能仅靠统一视觉宣称完成。
- 验收使用原生命中检测和真实拖动，确认标签点击区域、空白拖动区与窗口按钮命中分别正确。

## 11. 交互反馈与快捷键

- Ctrl/⌘ N 新建对话，Ctrl/⌘ K 搜索对话，保留既有含义。
- Ctrl/⌘ T 在当前对话工作区新建网页；独立窗口内使用其活动页面的归属，不挪用另一对话上下文。
- Ctrl/⌘ W 仅在工作区或独立内容窗口上下文关闭当前标签，不等同于删除对话。
- Ctrl/⌘ L 聚焦当前网页地址，Ctrl/⌘ F 在当前网页／可查找内容中执行对应查找。
- Esc 优先关闭最上层菜单、弹窗、批注选取或查找；无临时交互时才按明确的当前任务规则处理停止，不能关菜单时顺带停止 AI。
- Enter／Space、方向键与 Shift+F10 支持对象选择和菜单操作；输入法组合期间不触发发送或快捷操作。
- 菜单打开、地址建议与批注操作不得抢走正在输入的焦点；用户主动打开面板后，关闭时恢复原触发点。
- 正在加载、为空、失败、权限不足、不可用各自显示就地说明和适当操作。没有加载状态时不保留整行占位空白。
- 普通成功操作使用轻量就地反馈；需要关注的通知在全局通知层，避免遮住输入和主要操作。

## 12. 实现结构建议

建议组件层次为 AppShell → WindowTitlebar／ActivityRail／ContentSurface／OverlayHost；ContentSurface 内为 NavigationPane 与 SceneHost，SceneHost 根据场景组合 ConversationView、WorkspaceView、文件管理、扩展、设置与创建器。

- `ContentSurface` 唯一管理内容外轮廓与裁切；子区不再各自设置框架圆角。
- `WindowTitlebar` 唯一管理原生按钮预留与拖动区域；普通场景标题不再复制 40／44／56px 顶部预留。
- 场景模式、活动对话、导航显隐、工作区显隐／分栏／展开、临时浮层使用明确状态，避免多个互相矛盾的布尔值同时成立。
- 命令按应用、对话、标签、网页、文件、扩展对象归属注册；菜单从同一动作定义生成，不在三个地方重复维护不同文案与禁用条件。
- OverlayHost 统一记录面板层级、锚点、焦点恢复与遮挡。原生网页视图无法仅靠 DOM 的 z-index 覆盖，必须复用现有隐藏／冻结页面视图能力，统一响应浮层显示。
- 布局使用共享设计变量与网格关系，工作区相对其内容容器从顶部 0 开始；移除被替代的顶部占位和重复覆盖规则。
- 标签、文件、网页、下载、权限和批注的数据与安全边界沿用现有能力；界面重构不改变文件删除、会话权限或网页 Cookie 的含义。

## 17. 消息编辑器、附加上下文与菜单栏规划（2026-11-03）

### 17.1 实施前的问题记录

- 消息编辑器目前使用 `v-textarea`；添加／编辑链接和移除链接是输入框底部的两个按钮，正文中实际插入 Markdown 链接。
- 共享右键菜单 `TextContextMenuHost.vue` 已有剪切、复制、粘贴、删除、全选，但没有编辑器专属链接命令。右键在捕获阶段接管输入框，新增专属菜单需要协调事件和选区，不能简单再叠一个菜单。
- “附加上下文”目前只有引用对话文件、浏览器页面、浏览器会话；按钮先插入斜线命令，再打开资源候选列表。文件以文字标记进入正文，网页／会话以独立的 `contextRefs` 放在编辑器外，表示方式和编辑能力不一致。
- 草稿以字符串保存；浏览器引用、队列和发送参数各有独立状态。若只把外部标签挪进输入框，仍可能出现文字已删除而隐藏引用继续发送的问题。
- 本次继续核对：正文草稿已有约 350ms 的延迟保存，但 `contextRefs` 不随正文持久化，切换对话会清空；队列可保存引用，编辑时却只允许改文字；发送后切换对话再失败的恢复路径只回填文字。这些是结构化改造必须一并修复的数据完整性问题。
- 现有链接命令只保存字符串偏移，没有所属对话及文档版本；共享右键对结构化编辑区没有真实选区书签。全局 Ctrl+K／Ctrl+N 判断还需排除 Shift，防止新链接快捷键被旧搜索路由截获。
- 主窗口和独立窗口目前均关闭了原生菜单；顶部新菜单必须纳入现有 44px 标题栏与拖动区域设计。

### 17.2 总体布局

Windows 主窗口在现有标题栏中排列：应用图标与名称 → 文件／编辑／视图／帮助 → 弹性拖动空白 → 系统窗口按钮。工作区数量／新建入口按第 18 节放在对话摘要右侧。

- 标题栏保持一行 44px，底色继续与左侧图标栏连成一块；内容层、内部直角和零外边距沿用 V2。
- 四个菜单标签使用普通文字，选中或悬停时显示浅色圆角底。菜单面板圆角 12px，分组分隔，命令左对齐、快捷键右对齐；破坏性操作单独分组。
- 菜单标签、弹出面板和系统按钮不参与窗口拖动。常用桌面宽度下保留四个名称，通过压缩品牌文字和间距保证拖动空白，不挤占系统按钮。
- 独立浏览器、文件窗口使用同一命令定义，按窗口拥有的功能显示相关项；不把主窗口所有动作不加区分地复制过去。
- macOS 后续适配系统应用菜单，避免同时出现两套菜单栏；移动／远程窄屏可用具名“应用菜单”入口，不与左侧导航按钮混用。首批先落实 Windows 主窗口。

消息输入区调整为：可编辑正文与上下文块在同一个编辑区域；底部保留附加上下文、模式、权限、模型及发送／停止。移除常驻的两个链接按钮，编辑器外不再另放一排可与正文脱离的引用标签。

### 17.3 编辑器的边界

推荐使用支持文档节点、链接、选区与统一撤销的轻量结构化编辑器，首批只提供段落、换行、链接、引用／代码片段和上下文块，不一次引入完整办公文档排版。具体编辑器库在实施时评估，本规划不绑定未经项目验证的库。

- 普通正文直接编辑；文本类资料可以插入可编辑摘录，修改的是本条消息的副本，不自动改写原文件或网页。
- 文件、网页、图片、浏览器会话等来源表示为编辑器内的上下文块。块内显示名称、说明和摘录可编辑；资源身份、真实路径、所属对话和版本由来源选择器管理。
- 资料支持“引用原资源”和“插入可编辑片段”两种方式。文本类资料优先提供片段编辑；图片、二进制文件及浏览器会话保留来源引用，并允许编辑说明，不伪装成可直接改写原对象。
- 保留现有文字／Markdown 草稿的导入和导出路径。发送前将当前编辑内容转换为可读正文及结构化引用，用户看到的内容与实际发送内容一致。

### 17.4 文本链接：右键、编辑菜单与快捷键

右键规则按编辑目标区分：

- 选中可编辑普通文本：显示“添加链接…”；打开小面板，显示文字可修改，地址可输入，保存后保留选中文字的显示效果。
- 光标位于一个现有链接内，或选区属于同一个链接：显示“编辑链接…”“移除链接”；可另提供“复制链接地址”。移除只取消链接，保留原文字。
- 选区跨多个链接／普通文字：不根据正则猜测修改第一个链接。“编辑链接”禁用；可执行“移除选区链接”，只清除选区内的链接格式，并保留未选中的链接。
- 没有选区且光标不在链接内：不显示有效的添加／移除操作。通过明确选择文字再添加，不凭空创建占位链接。
- 只读消息或来源预览：提供复制文字／复制链接地址，不能修改原回复。地址栏、密码框、普通代码输入框等不出现消息格式化命令。

交互要求：

- 右键或打开“编辑”菜单前保存实际选区；菜单获得焦点后仍作用于原选区。保存、取消、Escape 后回到正确编辑位置。
- 链接新增、修改、移除各构成一次撤销操作，支持撤销／重做；剪切粘贴和上下文块删除共用同一撤销历史。
- 原文包含括号、转义、多行文字时使用编辑器节点和序列化能力，不继续依赖当前简单 Markdown 正则作为唯一识别方式。
- 保留 Ctrl/⌘ K 搜索对话的既有习惯。新增 Ctrl/⌘ Shift K 添加／编辑链接；右键和“编辑”菜单调用同一个命令。链接快捷键先于全局搜索匹配，避免 Shift 被忽略后误开搜索。
- 编辑菜单与右键菜单都保留剪切、复制、粘贴、纯文本粘贴、删除、全选；根据目标能力和只读状态禁用。普通输入框继续使用通用文字菜单。

### 17.5 附加内容进入编辑器后的操作

插入流程：在正文光标处打开“附加上下文”或斜线候选 → 选择来源 → 选择引用方式／范围 → 在原位置插入 → 将光标放到可编辑说明或摘录中。取消选择不插入半截命令；菜单打开后切换对话，不把旧结果插入新对话。

每个上下文块提供：

- 显示名称、来源摘要、可编辑说明；文本片段可直接编辑，文件片段可标记行范围，引用消息保留原消息位置。
- 打开来源、编辑摘录、更换来源、转换为普通文本、移除引用。更换来源是明确操作，不能只改标题就悄悄改变实际路径或页面身份。
- 图片／截图显示缩略图和可编辑说明；浏览器会话显示可读名称与可编辑使用说明，不展示会话凭据。
- 选中后可整体移动、删除、复制；删除后撤销能恢复完整内容与来源。删除引用不删除原文件、不关闭原网页。
- 来源已移走、页面已关闭或摘录版本已变化时，显示具体状态与重新选择／刷新入口；不静默换成另一个来源。刷新摘录前保留用户已编辑的副本，由用户决定是否替换。
- 内容较长时可以折叠显示，但可展开修改，发送前仍能检查实际内容。超过长度或上下文预算时提供缩小范围／仅引用的选择，不静默截断。

同一来源仅引用一次时，重新选择应定位已有块；需要不同摘录时允许新增多个片段，按块身份区分。发送时避免同一份完整资料被重复附加。编辑器外可保留“已附加 N 项”的状态提示，它只负责定位，不维护第二份引用清单。

### 17.6 附加上下文的扩展顺序

常用入口保持短列表，提供搜索和分组，进阶能力放入“更多来源”；不把十余种类型一次铺满主菜单。所有入口最后都进入同一编辑区域。

- **第一批先统一现有能力：**对话文件、已打开网页、浏览器会话；增加文件文本摘录、手工粘贴文本／代码片段。现有页面批注可以作为引用来源接入，复用其版本和来源关联。
- **第二批扩展常用来源：**本地文件／图片导入、剪贴板图片、当前网页选中文字、手动输入网址、单条或选中的历史消息、文件行范围。文件导入需要新增对应的选择／复制流程，不能只插入一个不可访问的本机路径。
- **第三批扩展精细范围：**区域截图／截图说明、PDF 页码与表格范围、子任务结果、插件／技能执行产物。保留来源范围、类型和版本；格式解析、消息引用及截图的调用链需要分别开发，当前不视为已有。
- 浏览器会话归入“浏览器（高级）”，与对话／聊天使用不同名称。引用会话不等于授予额外权限；添加网页或网址不自动启动浏览器任务或发送消息。

上下文选择、文件导入与内容提取需要加载、失败重试、取消及删除状态；切换对话或关闭编辑器后，迟到的结果不得追加到其他草稿。

### 17.8 统一命令、焦点与浮层

- 统一记录每个命令的作用范围、当前编辑目标、可执行状态、选区和快捷键。菜单打开时保存原目标；不能在点击“复制”时把菜单按钮本身当成编辑目标。
- 顶部菜单、右键、斜线候选和按钮由同一命令调用层驱动。上下文能力分别由消息编辑器、普通输入框、文件预览、创建器及浏览器窗口提供。
- 主编辑器保留 Enter 发送、Shift+Enter 换行及输入法组合保护。菜单、链接面板、片段编辑中的 Enter 先完成各自操作，不意外发送消息。Escape 优先关闭当前浮层或退出块编辑，不误清空草稿或停止任务。
- 菜单栏支持 Alt／F10 聚焦、方向键切换、Enter 执行、Escape 退出并恢复焦点。原生网页获得焦点时，相关菜单快捷键需要由宿主转发到正确窗口。

- 菜单在高 DPI、窄窗口与屏幕边缘内定位；所有弹出菜单保持统一圆角和默认箭头光标。

### 17.9 数据与实施顺序

编辑器文档是正文、链接和上下文块的统一来源。资源身份和用户编辑内容分别存储；发送正文与引用从同一文档生成，避免外部 `contextRefs` 与正文双向维护。草稿、排队消息、运行中插入消息、重试恢复和远程同步都需要支持带版本的文档结构，并保留旧文字草稿的兼容回退。

建议按以下顺序实施，每批结束展示对应效果：

1. **命令与数据基础：**建立精确快捷键、编辑目标／选区保存、带版本草稿、来源身份与发送快照；首先堵住切换对话和失败恢复丢引用的问题。旧文本编辑器继续工作，底部入口保留到等价替代可用。
2. **结构化编辑器与链接右键：**接入文档节点、统一撤销、输入法及粘贴；完成链接新增／修改／移除与节点序列化。新命令在右键和编辑菜单中完整可用后，删除底部两个常驻链接按钮，避免纯正则过渡方案成为长期实现。
3. **可编辑上下文闭环：**将现有来源块移入文档，落实摘录、说明、更换来源、撤销与异步取消；同步打通队列、运行中插入、失败恢复和远程同步，删除独立引用清单的写入口。
4. **四个菜单与窗口适配：**在 44px 标题栏呈现已存在的统一命令，完善原生网页焦点、遮挡和拖动区；按能力清理重复更多入口，不放无效命令。
5. **按来源扩展：**先完成本地导入、剪贴板、网页选区、网址与消息引用，再接入页码、表格范围和产物。每类来源交付完整插入、编辑、删除、失败和取消流程。

### 17.10 实施后的核对重点

- 选区新增、编辑和移除链接正确；移除保留文字；跨多个链接的选区不误改其他文字；撤销／重做恢复完整。
- 菜单打开前后选区、插入位置与所属对话保持一致；输入法、粘贴、拖放和键盘不会误触发送。
- 附加的文本能在编辑器内修改；二进制资料的说明可编辑；修改消息副本不改源文件或网页。
- 删除／撤销／更换引用与实际发送内容同步；关闭网页、文件移动、提取失败和长内容均有明确处理。
- 切换对话、重启、排队、任务运行中插入与发送失败后，文档和引用不会串到其他草稿，也不会遗漏或重复附加。
- 标题栏不增高，原生窗口控件与拖动区可用；菜单可用鼠标和键盘操作，且不会被网页遮挡。

以上为原规划与实施关口。2026-11-03 已开始修改实际应用；旧文本草稿、队列及引用的迁移在读取与编辑时执行。后续实施与核对情况见 17.21，不再将本节标为“仅规划”。

### 17.11 编辑区域的显示标准

编辑区保持一个连续的输入表面：正文段落、行内链接、文本／代码摘录与来源块按实际发送顺序排列。正文不增加卡片背景；来源块以轻量边框、来源图标及标题区区分，避免每段文本都被装进同样的容器。

- 正文继承系统 UI 字体与现有阅读字号，行高约 1.5；代码片段使用现有等宽字体。输入区随内容增高至视口约三分之一，之后内部滚动，不能挤走整个对话阅读区。
- 来源块标题行显示类型、可编辑显示名、范围及状态；真实路径／域名／所属对话作为只读来源摘要。说明和摘录位于块内正文，点击即可编辑。折叠仅改变显示，不删除或替换实际发送内容。
- 常用块动作在悬停或键盘聚焦时显示“打开来源”和具名菜单；菜单包含编辑说明、修改范围、更换来源、转换为普通文字、移除。块整体移动使用明确操作柄，不把编辑文字的拖选误判为拖块。
- 输入区底行从左到右保持附加上下文、模式与权限，右侧为模型、用量状态及发送／停止。链接入口从右键和编辑菜单进入；不存在第二排可独立维护的引用标签。
- 空草稿只显示输入提示；附加来源后原位置显示块。可保留“已附加 N 项”定位按钮，但数量从文档节点派生，点击跳到来源块，不另开一个可与正文脱节的引用仓。
- 运行中仍可继续写下一条草稿；队列状态与正在执行的消息分开显示，避免把已提交的不可变消息当作当前可编辑草稿。

### 17.12 文档、来源与发送的最小数据契约

以带版本的编辑文档作为唯一可写内容，不再分别维护 `draft` 和可变 `contextRefs`。以下字段是设计契约，名称在实现中可按现有类型调整：

- **草稿文档：**文档身份、所属对话、结构版本、递增修订号、节点列表、更新时间。节点包括段落、链接标记、换行、引用段、代码片段及来源块；首批不加入表格编辑或复杂嵌套排版。
- **来源块：**稳定块身份、来源类型、来源身份、所属对话、模式（原资源引用／可编辑摘录）、范围、来源版本、显示名、说明、用户编辑的摘录。显示名不能决定真实来源。
- **范围：**文件行／字符、网页网址与页面身份／选区描述、消息身份、PDF 页码、表格工作表与区域、图片裁剪等按来源类型区分。当前未实现的范围类型保持版本扩展点，不伪造可用数据。
- **提取状态：**待选择、提取中、可用、失败、来源失效；状态关联请求身份与发起时文档修订。提取结果与用户已经修改的摘录分别保存，不能由后台刷新覆盖用户文字。
- **提交快照：**提交身份、原草稿身份／修订、结构化文档、由文档编译的正文、引用清单、提交时来源版本及解析结果。该快照供直接发送、排队、插入运行任务和重试使用。

真实来源只保存可解析的资源引用；浏览器会话仅存其受信任身份，不将 Cookie、令牌或连接凭据复制进编辑器文档、剪贴板或导出正文。导出可读说明与可访问来源，不序列化临时提取句柄。

`contextRefs` 若仍被旧 API 使用，应是发送边界的只读派生值。正文、引用清单、附件数和预算估计必须来自同一文档修订；编辑器已经删除的块不能通过旧缓存继续发送。

### 17.13 链接编辑的完整流程与选区规则

统一由编辑器注册目标能力。菜单打开前保存编辑目标身份、所属对话、文档修订及可映射的选区书签；内容在浮层打开期间变化时映射位置，无法映射则取消操作并保留输入，不能按过期偏移改写另一段文字。

链接面板包含“显示文字”“链接地址”、保存和取消；已有链接增加“移除链接”。普通单击链接定位光标，Ctrl+单击按既有外链入口打开；说明文字明确操作，不能为了编辑而破坏正常选区。

- 单一段落内的非空选区可以新增链接；空选区只有光标位于已有链接时可以编辑。跨段落或包含来源块、代码块的选区禁用添加，并提示选择一段普通文字。
- 光标在链接内时编辑整条链接；选区完整属于一条链接时，面板明确显示整条链接文字，保存作用于该链接。只想移除部分范围时使用“移除选区链接”，未选中部分保留链接。
- 跨多条链接和普通文字不显示可执行的“编辑链接”；移除按选区拆分标记，文字顺序、空格和未选中部分不变。纯文本输入框不使用推测性富文本命令。
- 地址在保存前去除首尾空白并验证。首批支持有效 HTTP／HTTPS 与邮件地址；仅输入明确域名时显示补全后的 HTTPS 地址供确认。脚本、内嵌数据地址不作为可点击消息链接；本地资源通过来源选择器引用。
- 取消、Esc 或点击外部不提交修改，返回原编辑器选区；Enter 只保存面板，不发送消息。保存和移除各产生一个可撤销事务。
- 复制为纯文本保留显示文字；复制富文本／Markdown 可保留链接。粘贴链接不自动发起网页抓取；粘贴带格式内容只接受编辑器支持的节点，其他部分转为普通文本。

删除底部链接按钮的完成条件是上述能力在右键、编辑菜单、快捷键及统一撤销中都可用；不能先删除唯一入口，再把未完成的右键写成已替代。

### 17.14 附加上下文的选择、插入与编辑契约

来源选择器打开时保存草稿身份和插入书签，提供按类型分组、当前对话内搜索与来源预览。选择项目后显示可用模式及范围，再以一次事务插入来源块；菜单关闭或取消不留下斜线命令。可以批量选文件，但在提交前展示项目数与可用状态。

两种模式的含义保持明确：

- **引用原资源：**发送时按受信任资源身份解析所选范围。显示名和说明可编辑；发送前显示来源当前状态及预估用量。点击“查看将发送内容”可检查解析快照。网页／文件变化不能悄悄覆盖当前已确认快照，检测到变化后可刷新或沿用已提取副本。
- **插入可编辑摘录：**首次提取内容形成消息副本，用户可改写、删减、补充。发送以当前编辑文字为准，来源只作为出处；不再自动附加一份完整原资源。转换成普通文字后移除引用身份、保留可见内容。

图片与会话不提供伪装的全文文本编辑。图片允许说明和已提取文字作为不同内容；会话允许名称、用途与范围说明，实际会话仍由权限及执行层解析。仅引用一个会话不自动创建／控制网页。

块行为规定：复制块保留来源与可编辑副本，粘贴到同对话可继续引用；跨对话粘贴需重新导入或转普通文字，不能把不可访问的来源身份混入另一对话。块删除、重排、更换来源、改范围和转换模式可撤销；“转换为普通文字”失去来源关联前有明确菜单文案，不删除原始资源。

去重以来源身份、范围和引用模式联合判断：完全相同的引用定位已有块；同一来源的不同片段允许共存。来源级提取可复用缓存，但发送顺序与引用编号按文档顺序生成，不能因缓存命中删除用户有意编辑的段落。

提取任务绑定请求身份、块身份、对话身份和发起修订；块被删除、更换来源、撤销或切换对话后，旧请求不得回填。失败保留已输入说明并支持重试或移除；取消不清空整份草稿。

### 17.15 来源接入清单与能力边界

每类来源必须声明：选择入口、可预览内容、可编辑字段、范围、解析方式、来源失效条件和恢复动作。只接入口而没有编辑／失败流程，不计为完成。

- **对话文件：**选择已有索引文件，显示类型／路径／版本；文本支持全文件引用及行范围摘录，非文本按实际预览／解析能力处理。刷新索引不删除草稿中的已编辑片段。
- **已打开网页：**选择当前对话拥有的页面，显示标题／域名及所属窗口；可引用页面或粘贴已有选区。页面关闭后已提取摘录仍可编辑，实时页面引用标记失效并允许重新定位，不能静默替换为同名页。
- **浏览器会话：**位于高级来源分组，显示名称和所属对话；编辑用途说明。引用和新建会话、授予接管权限、启动任务保持独立动作。
- **手工文本／代码：**直接插入可编辑文本，代码可设语言；没有真实来源时不生成虚构路径或网页引用。
- **本地文件／图片与剪贴板：**通过文件选择、拖入或粘贴导入当前对话可访问的资源存储，显示进度；仅成功导入后生成可提交引用。导入取消、重名和解析失败均保留草稿。图片说明可编辑，移除草稿块不立即删除可能被其他消息引用的资产。
- **网址与网页选区：**用户输入网址或从当前页面选择内容；先选择“仅添加链接”还是“提取为上下文”，后者明确加载并允许取消。网页选区保留出处，编辑后的文字以草稿副本为准。
- **历史消息：**引用单条消息或连续选中的段落，保留对话／消息／范围与提取时版本；原消息后来编辑时标记版本变化，已提交消息不跟随改写。跨对话来源要经过现有可访问范围选择。
- **批注、截图、PDF 与表格：**按实际能力保留批注版本、图片区域、页码或工作表／单元格范围；范围不合法时在提交前修正。不能将整份文档当作用户选择的局部范围发送。
- **子任务及插件产物：**引用已完成产物的稳定身份、类型和版本；运行中结果标记等待，不把临时占位文本当作正式上下文。执行插件本身继续从扩展操作发起，不因打开选择器而执行。

首批选择器顶层只显示文件、网页、文本／代码与导入；会话及精细范围放在具名的高级／更多来源内，随实际能力接入。来源搜索不混合不可访问资源，也不把“打开资源”误称为“加入消息”。

### 17.16 草稿、排队、发送与失败恢复

**草稿保存。** 当前文档按对话持久化，正文与来源块在一次保存中提交；沿用约 350ms 延迟保存，切换对话、关闭窗口及退出前补齐待写修订。内容写入采用完整文档版本，不能出现文字新、引用旧的半次更新。选区和滚动是界面状态，可分开保存，不影响正文可恢复性。

旧字符串草稿首次打开时转换为普通段落和可识别链接，保留原始文本回退；读取不到的来源不伪造恢复。历史 `[文件：…]` 等文字标记不自动获得资源权限，仅按可信旧引用元数据迁移。旧队列的正文和引用迁移到带版本文档，无法可靠确定原位置的引用放在文末并显式展示，不推测插进正文中间。迁移幂等，重新启动不能重复附加。清空草稿也保留修订与清空记录，避免旧端同步时将已删除内容重新写回。

**提交顺序。** 点击发送后先冻结当前修订快照，解析来源并检查预算；确认提交入口已接收该提交身份后，才从编辑器清除这一份已提交修订。等待期间继续输入的新修订保留；重复点击或网络重试复用提交身份，避免重复消息。

**队列。** 队列项保存完整文档快照与来源，编辑队列使用同一编辑器，可增删来源及链接，保存生成新队列修订。直接取消／删除队列项不删除底层资源。队列发送解析结果固定在对应提交上，用户后来编辑普通草稿不能回写已排队内容。保留现有容量上限与重启后暂停规则；编辑保存时校验条目是否已经被取走执行，冲突时保留编辑副本，不能覆盖正在执行的快照。

**运行中插入。** “加入队列”“插入当前任务”明确是不同命令，均提交结构化快照；后者沿用现有任务接收规则，不能因消息文本相同而串到另一任务。任务已经结束时给出可用的普通发送／排队结果，不丢失快照。

**发送失败。** 失败记录保留原始完整文档、来源与原因。当前草稿仍为空且未发生后续编辑时可完整回填；已有新内容时提供恢复失败草稿／重新编辑／重试入口，不覆盖新输入。切到其他对话后失败，只更新原对话的失败项，不向当前对话插入文字或引用。

**同步。** 远程端与桌面端读取同一版本文档；不支持新节点的旧端显示可读回退并保留完整源结构，不能静默保存为丢失引用的纯文本。并发修改使用修订检查，冲突保留两份可恢复草稿，不以最后一次写入直接抹掉用户新内容。

**预算。** 按编译后的正文、已解析来源及实际模型计算预计用量。来源仍在提取时禁用提交并说明具体项目；超限时支持缩小范围、转摘录或移除，不能静默截断。来源失效时允许使用已存在的副本或重新选择，是否阻塞取决于该块是否已有完整可发送内容。

### 17.17 菜单的窗口范围与可执行状态

主窗口常驻四个菜单，保持第 17.2 节排列；文件菜单中的新建／恢复浏览器标签与第 23 节一致，不另放进视图作为另一条命令。浏览器导航、页面缩放、下载与页面设置仍归网页工具行或页面菜单，应用菜单不复制这些控件。

- **文件：**新对话；新建／重新打开浏览器标签；打开对话文件；打开当前对话文件夹；导出当前对话；关闭当前内容；设置；退出。无当前对话时禁用文件夹及导出，当前内容不明确时禁用关闭；设置／退出始终是应用级命令。导出只显示实际支持格式。
- **编辑：**撤销／重做，剪切／复制／粘贴／纯文本粘贴／删除／全选；上下文相关的链接命令和附加上下文；搜索对话。输入框只暴露可执行的原生编辑命令，不能对只读回复执行删除或把代码编辑目标格式化成消息链接。
- **视图：**侧栏、摘要、工作区显隐与展开状态采用勾选／明确状态文字；定位编辑器。没有工作区标签时，“显示工作区”调用既有入口创建一页并聚焦地址栏；展开只在工作区可用时启用。它与“隐藏”保持不同语义。
- **帮助：**使用文档、快捷键、使用引导、关于。帮助内容本地可用；外部文档使用现有外链打开逻辑。无实际反馈端点时不放无响应的反馈命令。

独立浏览器继续保留第 23 节已确认的紧凑标题栏，不额外挤入四个常驻文字菜单。Alt／F10 可调用同一命令系统的窗口菜单：新建／恢复浏览器标签、当前页操作、编辑、移回及关闭等按能力提供；主对话相关动作明确回到所属对话后执行。独立文件窗口只暴露它实际拥有的文件／编辑命令。macOS 使用系统菜单，避免自绘菜单栏重复；其他平台适配单独验收。

命令记录稳定标识、名称、作用域、目标解析、快捷键、可执行条件、禁用说明及执行结果。进入菜单前解析当前对话／宿主／编辑目标，执行前再次校验；关闭或切换后的过期菜单不操作新目标。

### 17.18 快捷键、选区与浮层的统一仲裁

菜单、键盘、按钮和右键都调用同一命令。快捷键按完整修饰键匹配；`Ctrl+K` 搜索与 `Ctrl+Shift+K` 链接不能共用忽略 Shift 的判断，`Ctrl+N` 同理。文本输入优先于应用导航，浏览器命令只在第 23 节定义的浏览器作用域中接管。

主窗口编辑命令沿用系统习惯：撤销 `Ctrl+Z`、重做 `Ctrl+Shift+Z` 并兼容 Windows `Ctrl+Y`、剪切／复制／粘贴 `Ctrl+X/C/V`、纯文本粘贴 `Ctrl+Shift+V`、全选 `Ctrl+A`。链接 `Ctrl+Shift+K`、新对话 `Ctrl+N`、搜索对话 `Ctrl+K`、打开对话文件 `Ctrl+O`；macOS 单独提供平台对应显示。只有有目标且具备能力时执行。

保留 Enter 发送与 Shift+Enter 换行。代码块和来源摘录内部编辑时 Enter 插入内容，来源面板／链接面板 Enter 执行面板动作；输入法组合期间不发送。Esc 从最上层浮层逐级退出，不停止任务、不清空草稿。

只允许一个顶层菜单或选择器拥有活动焦点。顶部菜单支持 Alt／F10、左右换菜单、上下选项、Enter 执行和 Esc 返回；子菜单支持方向键进入／退出。浮层打开时保存逻辑选区，不把网页或编辑器的选区替换成菜单文字；关闭后恢复原目标，目标已关闭时回到有效父容器。

原生网页获得焦点时由宿主路由对应命令，防止页面与应用执行两次。全局通用文字右键先询问已注册编辑器能力；富文本编辑器自行管理选区书签，不再被通用输入框处理吞掉。菜单和来源选择器纳入现有原生视图遮挡协调，恢复后保留网页状态，不做页面刷新。

### 17.21 核心功能实施记录（2026-11-03）

**编辑器与链接。** 消息输入已替换为 Tiptap 3.32.2 的结构化编辑器，正文、链接和来源块共用一份文档。选中文字右键可以添加／编辑／移除链接、复制链接地址；编辑菜单及 Ctrl/⌘ Shift K 调用同一能力。链接面板保留选区书签，输入法与 Enter 不会误发消息；底部旧链接按钮已删除。支持统一撤销／重做、纯文本粘贴、受限 HTML、同对话结构化复制，以及跨对话转普通文字。

**可编辑来源块。** 来源名称、说明和摘录可在编辑器内修改；真实来源身份与显示名称分别保存。块提供打开来源、改范围／换来源、刷新、折叠、复制、上下移动、转换为普通文字和移除；文本摘录可转换成代码片段。来源块放在正文顺序中，不再另外维护可独立发送的外部引用标签。删除块后，发送编译也随之移除对应来源。

**来源选择器。** 常用入口为对话文件、已打开网页、文字／代码及本地导入；更多来源包含历史消息、网页标注、链接和浏览器会话。已接入文本行范围摘录、网页正文／真实选区、当前页面截图、本地文件／图片与剪贴板／拖入文件。导入成功后复制到当前对话的附件目录，单文件 12 MB、每次合计 32 MB；不会只插入其他端无法访问的本机绝对路径。历史消息固定为可编辑摘录；手动网址作为链接引用，不自动访问网站。

引用与摘录采用不同发送路径：引用按实际身份与版本校验；摘录只发送用户当前编辑的副本，来源仅供定位，不重复附加整份文件或实时网页。页面关闭后摘录仍可编辑与发送；失效的实时引用需要重新选择。图片引用按模型能力接入实际图片输入，并有预算检查。文件指定行范围时必须提取为摘录；未成功提取的范围不能退化为整文件发送。

**草稿、队列与提交。** 增加带版本的文档、旧 Markdown／可信引用迁移、草稿比较保存、清空记录和冲突副本。正文、链接和来源一次保存，约 350ms 自动保存；无法确认保存或存在同步冲突时阻止发送。提交冻结文档并先持久化可恢复快照，之后显示独立的下一条草稿；新草稿使用新文档身份和撤销历史。回执只清理对应快照，不覆盖后续输入。提交身份包含文档与内容指纹，重试同一快照不会重复创建消息。失败或未确认的快照可检查、重试、合并回编辑器或明确移除。

队列使用同一编辑器，可以修改链接和来源块；保存比较队列条目自身的修订号。条目已执行、删除或被其他位置更新时保留编辑副本，并可放回主编辑器。草稿、队列、运行中插入、远程接口与失败恢复均传递结构化文档。等待服务端确认前的短暂保存阶段会锁定本次输入；快照保存确认后可继续输入下一条，不在等待时读取后来输入并加入上一条消息。

**应用菜单。** Windows 主窗口现有 44px 标题栏加入文件／编辑／视图／帮助，未增加第二排标题栏。命令包含新对话、新建／恢复浏览器标签、打开对话文件／文件夹、导出、设置、退出，以及编辑、视图和本地帮助。左下角应用级“更多”已清理为具名入口。窄屏／远程使用“应用菜单”入口；独立浏览器和文件窗口使用 Alt／F10 临时菜单，按实际窗口能力显示命令。

### 18.4 “移回工作区”四版候选图标

当前独立浏览器使用“箭头指向竖线”，图形没有表达工作区这一目标。此次提供四种 SVG 轮廓候选，只在规划示意中展示，不替换项目图标资产。

- **A｜分栏归位：**小型工作区轮廓、侧栏分隔线与向内箭头。作为此前比较稿保留。
- **B｜窗口归入（用户指定的方向）：**窗口轮廓与斜向指入窗口的箭头；箭尾位于窗口右上方，箭头向左下指向窗口内部。接下来按此方向细化光学尺寸与轮廓，表达页面移回主工作区。
- **C｜标签落位：**标签轮廓、向下箭头和下方容纳区。强调标签回到容纳区域；需留意与下载／导入图形的相似性。
- **D｜面板合并：**主面板、外侧小面板与水平归入箭头。突出宿主合并关系；小尺寸细节比 A 多。

旧比较图展示放大轮廓、实际 20px 尺寸与独立窗口标题栏中的位置。此前 B 版造型被用户评价为不好看，不能当作已确认资产；保留“斜箭头指向窗口”的语义方向，后续需重新细化比例、留白与线条交叉。旧 A–D 仅保留为过程记录。

此按钮与浏览器后退、恢复分栏、系统窗口还原分别命名。功能范围沿用当前独立窗口行为：将此窗口的全部标签页移回所属对话的工作区；单页时提示“移回工作区”，多页时提示“将此窗口全部标签页移回工作区（N 个）”。单个标签的移回可继续由标签右键承载。

移回要保留原页面、登录与表单状态及标签顺序；回到原属对话，保持原活跃页。移动中防止重复点击，按成功结果更新标签；失败页留在原窗口并给出可重试提示，不能先清空全部标签再重建。上述状态处理属于后续实现要求，本轮未验证或改变应用行为。

### 19.1 设计任务与已确定边界

Navora 是围绕对话协作的桌面工作环境。此轮的视觉目标是清楚、紧凑、位置稳定；优先保障查看文件和网页、编写消息、附加资料之间的连续操作。

以下作为已确定要求：

- 应用菜单放进现有标题栏。对话摘要属于对话标题行；关闭状态的工作区开关位于摘要右侧。

- 标签栏的新建加号紧跟整个标签列表最后一项。标签先压缩，再无滚动条横向滚动，支持滚轮。
- 独立浏览器的“移回工作区”保留斜箭头指入窗口的含义。此前 B 版造型被否定，不能把语义方向当作造型批准。
- 文字链接可通过右键新增、编辑和移除；附加内容进入消息编辑器后可以编辑。现有默认光标习惯与快捷键继续保留。

用户已选定移回图标 R2。数量图标的下一版细化、具体编辑器库与后续来源扩展顺序属于建议；不把它们写成应用已实现。

### 19.2 视觉基线与布局复核

沿用当前项目色值建立六个基础角色：外框 `#F7F7F8`、导航侧栏 `#F1F3F6`、内容 `#FFFFFF`、正文 `#1A2332`、辅助图标／文字 `#727B8A`、交互强调 `#3269AC`。现有标题背景和分隔线继续复用相应语义变量，新增状态由这些角色派生；不另建一套并行主题。

字体沿用系统界面字体链：Segoe UI、苹方、微软雅黑等。应用品牌约 12–13px、菜单和操作文字 13–14px、场景标题 14–16px；正文沿用现有阅读字号。保持一套字体与明确的字号层级，避免为桌面工具加入展示型标题。

尺寸建议：

- 窗口标题栏 44px；系统按钮基线约 40px，平台差异按原生区域处理。
- 对话标题、侧栏标题与工作区标签栏使用共享 48px 高度；独立窗口的标签和拖动区纳入 44px 窗口标题栏。
- 普通图标点击区 32×32px；图标约 18–20px。数量开关按第 19.9 节进一步细化为 20px 视口，框体与数字保持轻量，统一基于同一组件；本尺寸是设计建议。
- 标签默认目标宽约 220px、上限约 260px、压缩下限约 112px。标签内图标约 16px，标题单行省略，标签栏加号保持 32px 点击区。
- 菜单圆角 12px；输入区圆角可保留当前适合编辑的形状。内容面的圆角只作用于合成外轮廓，不给内部对话／工作区接缝加圆角。
- 图标默认透明底和中性灰；只有悬停、键盘焦点及开启状态出现轻量底色或强调。开启状态不依赖数量变化表达。

布局按真实任务重新检查：保留连续正文和独立编辑区；只在菜单或资料块确实存在层级时使用容器。此次重点是开关位置的连续性、资料内容可编辑和清楚的命令归属。

### 19.3 主窗口各区域的固定职责

窗口标题栏从左到右：品牌 → 文件／编辑／视图／帮助 → 弹性拖动空白 → 系统窗口按钮。菜单与按钮为可点击区域，其余明确的空白参与窗口拖动。

左侧图标栏沿用对话、对话文件、浏览器资源、扩展等场景入口及底部设置／帮助。侧栏显示当前场景的导航和搜索，不再复制窗口级命令。

工作区隐藏时：对话标题 → 对话更多 → 摘要 → 方框数量开关。打开时：左侧对话标题保留更多和摘要；右侧工作区显示标签 → 新建加号 → 弹性空白 → 展开／恢复分栏 → 方框数量开关（开启）。

网页地址工具行承载网页导航、地址、批注、接管、下载和页面更多。文件工具行按文件能力提供查找、路径和必要动作。插件内容标题只保留该插件需要的操作；此前要求删除的返回对话、刷新等冗余按钮不再放回。

独立浏览器从左到右：标签 → 加号 → 拖动空白 → 移回工作区 → 系统按钮。系统最大化／还原、工作区恢复分栏和移回主窗口分别命名、分别处理。

### 19.4 数量开关的坐标、状态与焦点契约

现状中，`postpile-theme.css` 的主窗口对话标题常用右边距为 24px，工作区标题为 12px；仅移动或换图标无法保证同位。实施时需要将两处统一到同一个定位基准。

建议把开关锚定到整个主内容面的右缘：右边距 12px、点击区 32px，因此中心距右缘 28px；纵向中心为共享 48px 标题行中线。在相同窗口尺寸和侧栏状态下，关闭、分栏及工作区全宽三种状态使用相同基准。参考线仅用于规划比较，不作为产品界面元素。

状态转换：

- 隐藏且 0 个标签 → 显示加号；点击创建一页、打开工作区、聚焦地址栏；原位切换为数字 1 和开启状态。
- 隐藏且 N 个标签 → 显示 N 或 9+；点击恢复原工作集与选中项，不新建标签；原位切为开启状态。
- 分栏或全宽且 N 个标签 → 相同方框数量开关显示开启底色；点击隐藏工作区，标签保留；焦点回到原位关闭状态开关。
- 切换对话 → 读取该对话自己的数量、选中项及显隐状态；不闪现上一对话的计数或页面。
- 数量只统计主工作区文件与网页标签。独立宿主标签继续通过资源列表管理，移回成功后再更新主工作区计数。

工程上优先复用一个开关命令及同一数量组件；若必须由两个容器分别承载，需明确共享状态、条件互斥、相同尺寸和焦点接替。任何瞬间都不同时显示两颗开关。不能通过把两个按钮都固定到窗口角落来掩盖不同定位基准。

### 19.6 菜单与命令的共同来源

四个应用菜单沿用第 17.7 节：文件负责对话与文件打开／导出／退出；编辑负责撤销、剪贴板、链接和附加上下文；视图负责侧栏、摘要与工作区布局；帮助负责文档、快捷键、引导和关于。

菜单、按钮、右键与快捷键共享命令名称、目标、可执行条件及结果。建议首先归并以下命令族：

- 工作区：新建浏览器标签、显示、隐藏、展开、恢复分栏、移至独立窗口、移回工作区。
- 对话：新对话、更多操作、显示／隐藏摘要、搜索对话、导出对话。
- 编辑器：撤销、重做、剪切、复制、粘贴、纯文本粘贴、删除、全选、添加／编辑／移除链接、选择上下文来源。

键盘沿用 Ctrl/⌘ N 新对话、T 新网页、K 搜索对话；链接使用 Ctrl/⌘ Shift K。Ctrl/⌘ W 只作用于明确的当前内容标签。菜单打开前保存原编辑目标和选区，输入法组合不触发发送；Esc 先关闭最上层交互。

菜单放入现有拖动区域后，需要重新界定 `drag`／`no-drag` 命中范围，并与原生网页视图协调遮挡和焦点。安装 Figma 插件不等于已创建设计文件；当前产出为本地设计示意，未宣称已写入 Figma。

### 19.7 编辑器与上下文的统一内容模型

消息编辑区域由正文、链接、文本／代码片段和来源块组成。来源块可编辑显示名称、说明及摘录，同时保留真实来源身份、路径、所属对话与版本。修改消息副本不会自动改写原资源。

插入入口统一为回形针菜单和斜线候选；选择前保存草稿和光标，插入后定位到可编辑内容。取消、提取失败或切换对话时，不遗留半截指令或把迟到结果插入另一份草稿。

右键根据普通选区、单个链接、跨多个链接和只读内容提供能力；新增、修改、移除链接都可撤销。移除只取消格式并保留文字；跨链接不猜测第一个匹配项。

文档结构是草稿和发送内容的单一来源，实际发送正文及引用从当前文档生成。资料块删除、恢复、转普通文字、替换来源都要同步引用，不维护另一份用户看不到的发送清单。草稿保存、排队、运行中插入、失败重试与远程同步要同时兼容带版本文档与旧字符串草稿。

来源按完整流程扩展：先统一对话文件、打开网页、浏览器会话及文本／代码摘录；再增加本地文件、图片、剪贴板与历史消息；最后接入截图、PDF 页码、表格范围和插件产物。每类来源都覆盖选择、预览、编辑、取消、失败恢复和移除。

### 19.9 方框数量图标的进一步细化

状态：设计建议，待查看效果；与已选定的 R2 是两件不同的事。保留用户确定的方框数量含义、同位显隐和开启状态，仅优化图形本身。

现有问题：当前图形使用 24 单位视口缩到 19px，内部边框实际约为 12.7×11.1px；11 单位数字实际约 8.7px，9+ 约 7.1px。框与数字在标题栏中偏小，9+ 尤其不易读。固定的文字基线还需按实际字体校正视觉居中。

建议采用一版统一细化方案：

- 点击区仍为 32×32px，中心距内容面右缘仍为 28px；两个显隐状态不改变位置、尺寸或右边距。
- 图标调整为 20×20px 的原生视口，方框宽 15.5px、高 14.5px，圆角约 2.6px、轮廓线约 1.2px。通过减少无效内缩获得可读空间。
- 单位数字实际字号约 10.5px、500 字重，使用系统 UI 字体与等宽数字特性；1、8 等不同宽度的字形共用视觉中心。
- 9+ 使用约 9.5px 字号，保持与单个数字相同的外框，不通过加宽按钮或突然缩小整颗图标容纳内容。悬停／辅助说明始终提供真实数量。
- 加号与数字共用中心和方框，保持相同轻量线宽；0 个标签时显示加号，不显示数字 0。
- 关闭状态为透明底和中性灰；开启状态沿用轻量选中底与开启色。框内保持通透，数字不反白，不额外加红点或第二层徽标。

### 23.2 范围与整体结构

将**工作区、浏览器资源全页和独立窗口**作为同一浏览器标签系统的三个承载位置。共享标签外观、菜单、快捷键、排序、关闭策略及页面状态；仅外围窗口布局和可用的移动目标有所区别。

保留之前确认的结构：

- 工作区：标签 → 新建加号 → 弹性空白 → 分隔线 → 展开／恢复分栏 → 开启状态的方框数量按钮。新建加号紧随标签，不固定到最右侧。
- 独立窗口：标签 → 新建加号 → 可拖动空白 → 分隔线 → R2 移回工作区 → 原生窗口按钮。系统按钮区与标题栏底色连续。
- 工作区隐藏时，数量入口仍在摘要右侧；显隐复用同位开关。此次标签规划不重新移动该入口。
- 页面地址行保留导航、地址、下载与页面菜单；标签动作进入标签右键，不再新增一颗常驻“更多”。
- 右键菜单、悬停卡片、标签列表属于最上层。内部内容接缝保持直角，内容层不增加外边距。

Firefox 的官方说明包含刷新、静音、固定、复制、移动、多种关闭与重新打开关闭标签等操作，可作为本项目标签功能的参考。以下布局、作用域和分批顺序是 Navora 的设计决策。[Firefox 标签右键菜单](https://support.mozilla.org/en-US/kb/tab-context-menu)

### 23.3 标签尺寸、颜色与状态

**共用几何。** 标签高度 36px、圆角 9px、间距 4px；目标宽度 220px、最大 260px、普通标签最小 112px。图标 16px、标题 13px、关闭点击区 24px；新建及布局按钮点击区 32px。工作区标题行 48px，独立窗口标题行 44px，标签都垂直居中。上述尺寸为本轮设计基准，实施时按实际缩放复核。

**共用颜色角色。** 使用现有主题变量定义标签栏背景、普通标签背景、悬停背景、当前标签表面、主文字、辅助文字、边框、强调和焦点。主题提供变量，不再用不同页面的高优先级选择器重写状态。

- 普通标签：中性文字、轻量底色，轮廓低于当前标签。
- 悬停标签：立即出现可识别的底色变化，显示关闭按钮；不靠移动、放大或文字变粗表达悬停。
- 当前标签：使用内容表面色、清楚的边界和稍高文字权重；独立窗口与工作区保持一致。当前标签悬停时，仍可看出反馈。
- 键盘焦点：独立焦点轮廓，不能与当前标签混为一个状态；失焦窗口保持当前页可辨认，窗口激活后正常显示悬停。
- 多选标签：以后采用轻量选区底，当前显示的标签仍保留更强边界；菜单显示受影响数量。
- 加载／失败：图标位置显示进度或错误状态，标签宽度不抖动；失败后提供重新加载，不将技术异常字符串铺在整个工具行。
- 音频：有声音时显示扬声器；静音时显示静音标识与说明，直接点击切换。状态区与关闭按钮各有点击范围，不能重叠。

关闭按钮显示规则统一：当前、悬停、键盘聚焦时显示，固定标签不常驻关闭按钮；其他状态隐藏图形但保留布局空间，避免标题跳动。所有标签操作保持系统默认光标，拖动只在真正启动拖放后使用系统拖放反馈。

### 23.4 悬停说明与大量标签

悬停立即改变底色；停留约 500ms 后显示轻量说明卡，包含完整标题、域名与加载／音频状态。空白新标签显示“新标签页”，不展示内部地址。卡片不抢焦点，不触发页面加载；菜单打开、滚动、拖动和窗口失焦时关闭。避免同时出现原生 title 与自定义说明两套提示。

Firefox 支持标签悬停图片预览；本项目先交付文字卡片，缩略图归入后续增强并提供开关。缩略图只按需取得，不持续唤醒全部后台页。[Firefox 标签设置](https://support.mozilla.org/en-US/kb/tab-preferences-and-settings)

标签数量增加时，先从目标宽度连续收窄；全部达到最小宽度后才横向滚动。始终隐藏滚动条。触控板横移和普通滚轮均可滚动标签轨道，支持拖动靠近轨道边缘时自动滚动；纵向滚轮只在轨道确有溢出时消费。

新建加号是轨道外紧邻标签的固定点击区：标签少时跟随最后一页，溢出时位于可见轨道右端，布局与窗口控件不随滚动消失。独立窗口另外保留至少 36px 的明确拖窗空白。极窄窗口优先保证新建、移回与原生窗口按钮，轨道继续缩短；窗口最小宽度应覆盖这些固定控件，不能压到互相遮挡。

激活、创建、恢复或键盘切换后将目标标签滚入可见范围；后台刷新或标题变化不自动滚动轨道。大量标签时提供“列出／搜索标签”入口，放在轨道溢出区，以明确列表图形呈现，不增加省略号。只搜索本对话的浏览器标签，并标明所在窗口。

### 23.5 右键菜单的统一内容

所有浏览器标签使用同一菜单定义。菜单圆角 12px、菜单图标 16px、条目高度约 32px；分组之间使用分隔线，靠近屏幕边缘自动调整位置。菜单目标为**被右击的标签**，右击后台标签不切换当前网页。

按以下顺序组织：

1. **创建与恢复：**在右侧新建标签页；重新打开关闭的标签页（显示 `Ctrl+Shift+T`）。恢复记录为空时禁用并说明。
2. **页面操作：**重新加载；复制标签页；固定／取消固定；静音／取消静音；复制网址。空白页无网址时禁用“复制网址”。
3. **移动：**“移动标签页”子菜单包含移至最前／最后、移至新窗口、移至指定兼容窗口；独立窗口额外提供移回工作区。最前／最后遵循固定分区，不能跨分区改变固定状态。
4. **选择与关闭：**选择本窗口全部浏览器标签；关闭标签页；“关闭多个标签页”子菜单包含关闭左侧、关闭右侧、关闭其他；存在多选时显示“关闭所选 N 个标签页”。

移动目标只列出同一对话中可接收页面的窗口，标题带窗口识别信息和标签数。顶部 R2 继续表示“将此窗口全部标签移回工作区”，其辅助说明明确“全部”；单标签右键里的“移回工作区”只移动目标标签，避免两者同名却范围不明。

空白标签栏右键提供新建、重新打开关闭标签、列出标签，不误作用于当前页。新建按钮、关闭按钮、原生窗口按钮不弹出标签菜单。键盘使用 `Shift+F10` 或菜单键打开目标菜单；Esc 关闭并将焦点交还目标标签，点击外部关闭。

菜单中只展示已经具备完整行为的命令：尚未接入的固定、静音、恢复等不会先放入正式应用作为无效占位。交互示意可展示全部目标能力，并注明规划状态。

工作区混合文件与网页时，网页菜单里的刷新、复制标签、固定、静音及批量选择只作用于浏览器标签；文件继续显示自己的打开、路径和关闭操作。关闭左／右／其他默认也只包含同一宿主内的浏览器标签，不连带关闭文件，并在菜单辅助文字中写明范围。

### 23.6 创建、选择、关闭与恢复规则

**创建位置与焦点。** 点击加号或 `Ctrl+T` 在当前标签右侧创建并激活，聚焦地址栏；当前项固定时插入普通标签区开头。网页通过中键或 `Ctrl+单击` 打开的链接放在来源右侧并在后台打开，`Ctrl+Shift+单击` 切到新页。网页 `target=_blank` 和 `window.open` 也必须通过同一创建入口、权限与对话归属处理。用户创建的页不能被后台 Agent 的新页面自动抢走焦点。

**切换与关闭。** 普通点击激活；中键关闭目标；点击关闭图形不触发标签激活。关闭后台标签保持当前页与焦点；关闭当前标签选右邻，无右邻选左邻。此规则由宿主统一返回，渲染器不再自行选另一个页面。文件混排时，工作区当前项关闭遵循同一可见顺序，浏览器专属批量命令仍只处理网页。

最后一页关闭：独立窗口关闭空宿主；主工作区按既有规则隐藏空工作区，对话保持不变。关闭固定标签需明确操作：标签右键“关闭”或当前项 `Ctrl+W` 可以关闭，中键及批量“关闭其他／左侧／右侧”跳过固定项。后续多选中明确选中的固定项可以由“关闭所选”关闭。

**连续关闭与移动稳定性。** 关闭或拖出后，不让剩余标签重新执行进入／展开动画。连续鼠标关闭期间保留相邻关闭命中位置，鼠标离开标签栏后再重新分配可用宽度；减少动态效果模式不做尺寸过渡。增加或移入允许短暂出现反馈，不能导致整条标签横向跳动。

**复制。** 在目标右侧创建新的页面身份，复用该对话对应浏览器会话，复制导航历史和当前历史位置；复制后激活，保持原页。复制固定页默认生成普通标签。它与移动不同，不能让两个标签共用同一个可操作页面身份。

**重新打开关闭标签。** 建议每个对话保留本次应用运行期间最近 30 个已关闭浏览器标签，跨同对话窗口共享；按实际关闭成功顺序记录。保存标题、原宿主／相邻位置、会话引用、导航历史位置、固定与静音状态；恢复到仍存在的原宿主，否则恢复到该对话主工作区，并定位到原相邻项附近。快捷键作用于当前对话，独立窗口使用自己的对话，不读取其他对话的记录。

移动、隐藏工作区、窗口显隐、失败的关闭和正常退出应用不计入“关闭标签”记录。批量关闭逐页记录成功项，用户取消网页离开确认后停止剩余关闭；成功关闭的项目仍可逐个恢复。所有入口遵循网页已有关闭确认，不通过强制销毁跳过。

导航历史的复制与恢复可采用 Electron 的 `navigationHistory.getAllEntries()` / `restore()`；本地运行时声明包含这些接口。官方说明为尽力恢复页面状态，因此不承诺所有表单、脚本运行和媒体进度均可还原。移窗则继续转移原页面实例，保留实时状态。历史恢复失败保留记录并给出重试或仅打开原网址选项，不重复生成多个失败标签。[Electron 导航历史 API](https://www.electronjs.org/docs/latest/api/navigation-history)

### 23.7 固定、音频、多选与分组

**固定标签。** 每个宿主左端设固定区，单项约 36px，仅展示网站图标与必要状态；普通标签在后。固定区不被普通关闭批量命令带走，取消固定恢复到普通区。固定不改变对话／会话，不自动成为全局收藏。固定标签过多时也必须纳入溢出与标签列表规则，不无限占满工具栏。

**音频。** 本项目现有页面默认静音，第一步读取并呈现真实状态，静音图形与菜单必须一致。以后区分“用户手动新建”与“Agent 后台新建”是否采用不同默认值，作为单独设置决策；在确认前保留当前默认。拖动、移窗和恢复保留页面静音状态，复制继承目标页状态；新建空白页不显示错误的“正在播放”。

音频播放事件与静音能力可由 `audio-state-changed`、`isAudioMuted()` 与 `setAudioMuted()` 同步，不能仅改变图标；本地运行时声明已包含这些能力。[Electron 音频状态与控制](https://www.electronjs.org/docs/latest/api/web-contents#contentssetaudiomutedmuted)

**多选。** `Ctrl+单击` 增减选区，`Shift+单击` 按宿主内浏览器顺序选连续范围，普通单击清空多选并激活一页；文件不被范围选择包含。右击已选项作用于选区，右击选区外项将菜单目标限定为该单项且保持网页激活状态。混合固定／静音状态时显示明确命令“固定所选／取消所选固定”“静音所选／取消所选静音”，不猜测反转结果。批量拖动保留相对顺序。

**分组。** 基础能力稳定后再接入命名、颜色、折叠、移入／移出和整组移动。组只属于同一对话与同一宿主；组颜色使用主题语义色，不能覆盖当前页及键盘焦点。休眠、释放内存与跨重启窗口布局恢复同属后续增强，休眠不能中断当前 AI／接管任务。

收藏、跨设备同步、容器身份等需要独立的数据与会话设计；不在标签右键里展示尚无对应资源模型的入口。本规划首先完整交付标签交互。

### 23.8 快捷键、网页焦点与可访问性

Windows 主基线：`Ctrl+T` 新建、`Ctrl+W` 关闭当前、`Ctrl+Shift+T` 重新打开关闭标签、`Ctrl+Tab`／`Ctrl+Shift+Tab` 按可见顺序前后切换、`Ctrl+1…8` 跳转前八项、`Ctrl+9` 到最后一项。浏览器快捷键在混合工作区只计算浏览器标签；`Ctrl+W` 跟随明确聚焦的当前内容，文件页沿用文件关闭命令。

`Ctrl+L` 聚焦地址栏、`Ctrl+R`／`F5` 刷新、`Ctrl+Shift+R`／`Ctrl+F5` 忽略缓存刷新、`Ctrl+M` 切换当前页静音；这些命令在浏览器页活跃时生效，不截获对话编辑器及其输入法组合。进入标签栏后使用左右、Home／End 导航焦点，Enter／Space 激活，菜单键打开菜单。

Firefox 提供关闭恢复及相应标签快捷键，可用于核对习惯。本项目默认采用可见顺序切换；最近使用顺序是后续设置，不在未提示时更改现有行为。macOS 使用平台惯例映射并逐项核对冲突，不机械地把全部 Ctrl 替成 Command。[Firefox 快捷键](https://support.mozilla.org/en-US/kb/keyboard-shortcuts-perform-firefox-tasks-quickly)

宿主捕获浏览器快捷键需要覆盖焦点位于原生网页的情况，同时避免宿主和页面重复执行；菜单、按钮、快捷键指向同一命令。明确暴露当前标签、固定、加载、静音与多选数量，屏幕阅读器能够区分当前显示页与批量选区。焦点跳转后保持标签可见，不因网页刷新将焦点强制带回标签栏。

### 23.9 拖动、移窗与状态一致性

一次拖动始终处理同一个页面身份：同栏排序、跨同对话窗口移动、拖出新建窗口、移回工作区都调用同一移动命令。成功后源宿主移除一次、目标添加一次；原网页历史、表单与实时会话继续存在，不重新加载。

拖动约超过 6px 才启动；拖动前的普通点击、右键、中键不能生成多余移动。轨道显示明确插入位置，靠近边缘自动横滚。松开在有效目标外的新窗位置才创建窗口；Esc 取消、目标关闭、过期 token 或对话切换均恢复稳定状态。

保留现有宿主身份、拖动令牌和对话隔离校验。跨对话目标给出不可放置反馈，不自动合并会话。源窗口只有一页时，整窗移动与单页拖出的行为需要统一：拖到现有兼容宿主可移动；拖到空白桌面优先移动当前窗口，不额外创建同内容的新窗口。

主进程对宿主维护带版本的顺序、当前项和标签元数据；混合工作区的顺序包含网页与文件引用，浏览器页面集合仅负责实例归属，不再成为另一套排序依据。渲染器提交操作意图，按结果快照刷新。移动过程中对涉及页面暂时阻止重复移动；失败时撤回临时占位并重新同步。菜单打开后目标已经移动或关闭时，重新校验目标身份并关闭过期菜单，避免再次出现残留标签与 `browser_page_wrong_host`。

AI 占用、批注或接管等现有移动限制继续按真实能力判断；菜单禁用状态和说明来自同一命令判断。批量命令在执行前列清范围；部分项目无法操作时说明结果，不静默丢失页面，不直接展示内部异常串。

### 23.10 共享结构与迁移边界

建议拆为三项公共能力，名称为实现定位建议：

- `BrowserTabStrip`：尺寸、可视状态、排列、横滚、焦点、悬停说明、拖动反馈与加号；文件混排经类型适配继续共用基础标签外观。
- `BrowserTabContextMenu` 与共享命令定义：目标集合、名称、快捷键、可执行条件、禁用说明和结果；复用现有圆角菜单及键盘能力。
- 宿主标签状态：主进程统一管理宿主的有序标签引用、当前项、固定／静音／加载信息、移动事务与关闭记录。主工作区使用带类型的网页／文件引用，独立浏览器仅使用网页引用；页面实例管理与文件读取仍由各自模块承担。

工作区当前文件顺序迁移时保留，由协调入口将旧本地顺序合并进首次宿主快照；迁移后本地存储只作为缓存／恢复输入，不继续与主进程分别写入两套活动顺序。对外发布同一份工作区投影，标签数、活动页面与屏幕顺序均从该快照派生；当前项为文件时，原生网页按既有机制隐藏。

主题层只赋变量，状态样式归共享组件，清理旧的重复覆盖。独立窗口与工作区适配只提供外框高度、可用空间和右侧布局动作，不复制整套 CSS 或菜单代码。

浮层必须复用现有原生网页遮挡／冻结机制；普通 DOM 的层级不能覆盖 `WebContentsView`。菜单或预览显示期间不允许点击穿透，关闭后恢复原网页与焦点，不借助提高 z-index 假装解决。缩略图阶段避免将实时网页截屏发送到外部服务。

后续实施需覆盖的场景：

1. 同一主题下工作区、全页资源及独立窗口的普通／悬停／当前／失焦／键盘焦点一致。

3. 后台标签右键操作不切页；菜单靠边、键盘打开和原生网页遮挡正确；文件菜单与网页命令范围清楚。
4. 连续关闭、关闭活动／后台／最后一页、批关取消与恢复，选中、焦点和宽度稳定。
5. 从工作区拖出，再在独立窗口新建后继续拖出；快速重复、Esc、目标关闭及整窗移回；每次只有一个宿主拥有该页面。
6. 复制和恢复的历史位置、登录会话、固定及静音符合规则；网页离开确认能取消，不强制销毁。
7. 原生网页内部获得焦点时快捷键执行一次；对话编辑器不被浏览器命令截获；辅助技术可识别状态。

这些是后续验收要求，本轮未运行应用测试，也未把交互示意当作已实现或已验收功能。

### 23.13 空白新标签页与重启恢复

用户新增“新建标签页不支持持久化，也就是下次启动时不会恢复”。规划时已提出解释选项并说明暂定规则；本批按后续开始实施指令采用：**没有实际目标网址的空白新标签页只在本次运行中保留；已访问、已提交导航的网页继续遵循会话持久化与恢复规则。**主缓存与工作区缓存的接入范围见第 24 节。

当前代码并非明确禁止空白页恢复：主进程 `browser-workspace.json` 保存／恢复与工作区本地标签缓存都可能保留 `about:blank`；只过滤其中一处，另一处的页面挂载仍可能重新创建它。后续需要统一保存与恢复条件。

拟定规则：

- 用户通过加号／快捷键创建、仍停留在应用新标签起始页、没有实际导航目标的页面不写入重启恢复集合。不要仅凭标题等于“新标签页”判定，网站标题可能相同。
- 输入地址但未确认导航仍属空白起始页；已确认合法网址并正在加载或加载失败的页面保留目标网址与恢复信息，避免失败页被误当空白页丢弃。加载完成的页面按正常网页保存。
- 网页临时跳转 `about:blank`、已有历史的页面与应用尚未初始化的页面不能仅按当前 URL 一刀切过滤；使用页面用途和导航状态区分。原本不持久化的会话继续不恢复，不因标签规则被升级为持久化。
- 工作区隐藏、最小化、展开或同次运行内移窗不删除空白页；“重新打开关闭标签”在同次运行中仍可恢复空白页。此次规则只决定应用重启恢复。
- 同时过滤主进程恢复快照与工作区标签缓存，恢复读取时也过滤历史快照里的空白起始项。先建立保留项映射，再计算顺序、当前页、数量与显隐，不能让旧标签标识在挂载时重新 `ensure` 出空页。
- 原当前项被过滤后选择保留下来的右邻，无右邻选左邻；顺序按恢复前的同一快照计算。混合工作区保留文件标签及其位置；若没有剩余项目则关闭工作区，入口显示加号，不自动补一页抵消规则。
- 独立窗口全部是空白起始页时，重启不创建空宿主；混合窗口只恢复真实网页，保留其相对顺序。主窗口、当前对话和消息草稿不受此过滤影响。
- 过滤发生在持久化投影／恢复层，不在用户新建瞬间销毁页面，也不清除访问历史、对话文件或其他已保存数据。

后续验收：仅空白、真实网页＋空白、文件＋空白、加载中／失败页、全空白独立窗口、混合独立窗口、工作区隐藏、异常退出与正常退出都需覆盖；恢复后不能短暂闪出被过滤的空白标签。若用户实际希望恢复全部空白标签，应先调整本节策略，并同步两处缓存。

### 24.1 外观与共用交互

工作区、浏览器资源全页和独立浏览器共用 `BrowserTabStrip.vue`、`WorkspaceTabItem.vue`、`BrowserTabContextMenu.vue` 及标签操作控制器。标签统一 36px 高、9px 圆角、4px 间距，普通标签目标 220px／最小 112px／上限 260px，固定项使用 36px 紧凑形态。已移除工作区旧标签状态覆盖，主题只为标签状态赋变量。

普通、悬停、当前、焦点、多选和右键目标具有不同反馈；采用默认光标。关闭按钮不推动标题，鼠标连续关闭时暂时保留剩余项宽度；移出或关闭不执行整条标签的进入动画。500ms 文字说明卡显示标题、域名及加载／固定／音频状态，并接入原生网页遮挡协调。

新建加号紧随轨道，达到最小宽度后才无滚动条横滚，支持滚轮及拖动边缘滚动。发生真实溢出时显示标签列表／搜索。工作区继续使用已有展开折角、数量开关和分隔线，独立窗口保留拖窗空白与整窗 R2。

### 24.2 真实命令与窗口状态

两处浏览器标签使用同一右键菜单，支持右侧新建、重新打开关闭、重新加载、复制、固定／取消固定、静音／取消静音、复制网址、最前／最后、移动至新窗口／兼容窗口、单页移回，以及本窗口浏览器多选、关闭、关闭其他／左／右／所选。后台右键不切换网页；浏览器批量命令不包含文件标签，固定项默认跳过普通批关。

固定和音频均来自实际页面状态，静音按钮控制真实网页；当前页面创建默认静音策略保持。复制创建新身份并恢复导航历史，保留原会话；固定页副本为普通页，多选复制保留各自来源关系。

主进程管理浏览器宿主的顺序、活动项和带版本快照；工作区保留文件混排槽位，网页相对顺序按主进程同步。现有文件混排顺序仍保存在工作区模型，尚未整体迁移为包含文件的主进程宿主模型。

单页关闭、菜单批关和原生窗口关闭共用用户关闭流程，保留网页离开确认，真正关闭后才加入当前对话最多 30 条运行内恢复记录。恢复优先仍存在且兼容的原宿主，否则回主工作区；网络加载失败显示为可重试页面，不承诺恢复所有表单和脚本运行状态。

同栏、跨窗和拖出支持服务器令牌承载的完整多选集合，保留顺序与页面实例。多页转移在锁定完成后统一提交，失败回退；整窗 R2 也使用批量转移。旧宿主、过期令牌和目标关闭会触发列表同步与可读提示。新建未完成时的关闭先等待创建并回写页面身份，防止临时标签残留。

新增快捷键覆盖重新打开关闭页、前八项／最后一项、地址栏、刷新／忽略缓存刷新及静音，原生网页获得焦点时同样转给宿主；既有新建、关闭和前后切换继续可用。混排时浏览器索引及批量选择只计算网页；Delete 使用真正获得焦点的标签，不能误关另一个活动页。

### 24.3 重启缓存

主进程快照与工作区本地缓存同时过滤没有 HTTP(S) 目标的空白起始页；保存／恢复均使用同一规则。已提交但仍加载中或失败的网页保存 `desiredUrl`，不能因为底层 URL 暂为 `about:blank` 而被丢弃。

原会话不持久化的网页同时从两处恢复投影中排除，不能由工作区挂载重新创建为持久会话。过滤后按右邻／左邻选择保留项，文件标签及相对位置不受影响；空工作区关闭，全空白独立窗口不恢复。过滤仅影响重启快照，不关闭当前运行中的空白页，也不清理访问历史。
