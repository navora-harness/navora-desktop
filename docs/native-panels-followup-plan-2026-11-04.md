## 1 已确定的范围

- 2026-11-04 用户取消网页 WebContentsView 圆角要求，不再作为接入或验收项；随后 `.7` 实施已移除网页圆角调用。菜单／NativePanel 自身的圆角不属于这次取消范围。
- `showPageInfoDialog` 的应用调用、参数和网站设置业务保持，不用 HTML 仿造。新增应用样式显式启用，不全局覆盖其默认控件；内核升级自带的网站信息／证书变化单独回归，不承诺与 `.5` 逐像素不变。
- 附加菜单沿用用户先前单独确认的 HTML 实现，保留输入框上方左对齐与键盘操作；这个例外不扩大到地址建议、标签提示或其他覆盖网页的浮层。
- 普通动作菜单统一使用已有 Menu.popup，与当前浏览器更多菜单采用同一条原生实现；覆盖聊天／标签／侧栏／文件／插件的动作菜单，保留原有图标、分组、子菜单、勾选、禁用和快捷键。需要搜索、列表、状态或编辑控件的界面使用 NativePanel。真正的系统确认可使用原生 dialog，不强行把所有界面套成同一种控件。
- 浏览器菜单内增加参考图中的横排缩放控件：左侧“缩放”，右侧“−、当前百分比、＋”，旁边独立重置按钮。它属于同一个原生 Menu，不改成 HTML，不通过拼接文字模拟按钮，也不拼接两个独立弹窗。
- 页面主动截图、批注取证与图像资料预览保留原用途；本轮清理的是“为了显示应用弹层而截图替换实时网页”的路径。
- 独立浏览器与工作区共用标签的主题、状态和尺寸规范；保留各自标题栏布局，不能因此出现两套标签配色。
- 独立窗口首次打开、再次查看和恢复后应直接显示当前网页，不依赖切换标签、刷新或重新创建网页来恢复。保留原 WebContents、表单、滚动位置、会话和 Agent 控制权。

## 2 源码核对与问题定位（0.3.39 基线）

### 2.1 截图中的标签提示尚未原生化

> **过时段落提示（2026-11-06）：**该缺口已由共享 NativePanel 标签提示接续完成，标题与下文源码分析保留原基线，不再列为未原生化入口。

`src/components/WorkspaceTabItem.vue` 仍通过 Teleport 创建 `.sidebar-ctx-panel.browser-tab-hover-card`。它显示完整标题、labelSuffix、description、域名与状态。`shared/workspace-tab-presentation.ts` 中的 description 又包含完整标题，所以当前提示确实可能重复标题、对话信息、网址和域名。

`src/components/BrowserTabPanel.vue` 的 `overlayCoversPage()` 会检测与网页相交的 `.sidebar-ctx-panel`。提示出现后进入 `prepareBrowserOverlayFrame()`，调用网页 preview、显示 frozenFrame，再提交空布局隐藏原生网页。因此这个提示卡虽没有自己的截图代码，仍能触发截图替换链。

提示还同时保留 DOM `title`，形成自定义卡片和系统 tooltip 两套提示入口。鼠标悬停使用 500ms 延迟，任何 focusin 使用 160ms；多个组件共享一个取消函数，但没有统一的目标身份和显示代次。页面或文件身份变化的 watcher 只清理图标／音频状态，没有同时取消提示。父层使用 tab.key，并非直接使用数组下标复用组件。

“移到另一个标签就立即跟过去”的精确事件顺序仍需复现，不能直接归因于某个单一 timer。目前明确的修复方向是合并提示入口、区分鼠标与键盘焦点、固定每次显示的目标身份，并取消迟到回调；不是仅增加一次延迟。

### 2.2 地址建议已经是 NativePanel，问题在控件形态

`shared/browser-native-panels.ts` 的 `browserAddressNativePanel()` 目前把每个候选转换成一个普通 button，把“历史”、标题等拼成同一个字符串，网址仅放在 tooltip；选中项通过文字前缀 `›` 表示。根列表宽度固定为 500，不能自然跟随实际地址输入区域。

已只读核对当前内核：`shell/browser/ui/views/native_panel.cc` 的 PanelButton 继承 `views::MdTextButton`；公开 NativePanelContent 没有列表行、行选中状态、单行尾部省略或按钮外观变体。截图中逐条胶囊按钮、边框和文字布局不是应用 CSS 可以消除的问题。

搜索、建议生成、方向键和导航行为已有应用代码；实现图二的交互无需重写这些业务。但要稳定接近图二的原生视觉，需要补原生列表行绘制，不能把 HTML/CSS 字符串交给 NativePanel。

### 2.3 截图路径比显式菜单更广

统一检测器还匹配 `.v-overlay--active` 下的内容与遮罩，以及 `[data-browser-chrome-overlay]`。因此不能只搜索 preview 调用，也不能把所有 v-dialog 一律计作当前已经截图；只有它与仍显示的网页相交时才触发。

还需反向检查遗漏：例如 `ConversationResourcesCard.vue` 有 `data-layout="overlay"` 状态，却没有上述统一标记。要核对其实际布局是否可能盖住网页，避免“没有截图”只是因为网页把面板挡住了。

### 2.4 独立窗口已经共用标签组件，仍需核对最终样式

BrowserHostPage 与工作区已经复用 WorkspaceTabItem／BrowserTabStrip；App 的 useAppearance 也会为独立 renderer 读取并订阅同一份主题配置，appearance-themes.css 已定义共享的 `--tab-*` 色值。因此不能直接把差异归因为“独立窗口未接主题”。

当前独立标签条使用 chrome 背景，工作区标题行使用 header 背景；BrowserHostPage 的新增、移回按钮仍有固定颜色与 hover 色。需要对比同一主题、同一标签状态的实际计算样式，检查主题到达时序、选择器覆盖、宿主背景和窗口失焦状态，定位标签底色、描边、文字与控件色的具体差异。上述静态事实还不能确定截图中的唯一根因。

### 2.5 独立窗口白屏属于新的呈现恢复专项

用户反馈是已有独立网页查看时整片空白，切换标签后恢复；截图中的地址栏已有目标网址。这与以前的“网页出现在窗口左上角”现象分开跟踪，不沿用旧问题的已修复结论，也不默认是网站加载失败。

现有 BrowserHostManager 会在 resize、激活或布局 owner 变化时使几何失效并隐藏 View；显示仍需当前页、owner、host generation、已提交几何等共同有效。窗口 show／hide 主要广播状态，focus 主要更新所选页；BrowserTabPanel 则通过挂载、active 变化、onPresent、尺寸观察和刷新提交布局。静态检查说明这些衔接值得重点排查，尚不能断言其中某个事件就是现场根因。

实施前需复现首次移出、资源列表再次查看、最小化还原、遮挡后返回、改尺寸和弹层开关的完整路径；同时记录激活页、owner／代次、requested／committed bounds、suspended／ready、View 可见性与截图替换原因，区分没有重新提交布局、错误去重、迟到隐藏、忙后未提交和残留冻结状态。日志不记录正文、输入内容或完整访问地址。

## 3 修复与迁移清单

以下区分直接命中现有检测链、条件命中和已经原生化；这是静态核对结果，不把尚未运行的界面检查写成通过。

### 3.1 独立窗口专项

- **高优先级：白屏恢复**。先补失败复现和呈现状态记录，再修当前活动页的布局提交与显示恢复；关闭弹层、显示窗口和安全空闲后都应最终收敛，无需用户手动切页。
- **外观一致性**。以工作区标签为同主题基准，统一普通、悬停、选中、选中悬停、多选、右键目标、静音和失焦状态的配色；独立窗口按钮去除另设的固定色。不得覆盖站点自身内容配色。
- **共同约束**。独立窗口和工作区使用同一套浮层登记、原生菜单／面板与截图退出规则，不能只修主窗口。

## 4 标签提示的目标样式和时序

### 4.1 内容与外观

- 卡片只显示一次页面标题，最多两行；下一行域名，必要时补简短状态，如加载失败、静音原因或固定。文件显示文件名和必要的父路径，子对话显示名称和简短状态。
- 不再次整段输出 description，不显示无关对话任务说明，不把完整网址与相同域名重复堆叠。无障碍名称仍可保留完整信息。
- 宽度建议 280–340 CSS px，内边距 10–12，字体沿用应用，标题 13、次要信息 12；圆角 10–12，边界和阴影克制。尺寸由应用 zoom 转为原生 DIP，设备缩放不重复计算。
- 原生提示启用后关闭该标签的重复 DOM title 提示，保留 aria-label。普通按钮自身的短 title 不在本项批量删除。

### 4.2 每个标签重新等待，旧内容不能跟过去

采用 idle → waiting → visible → idle 的明确状态。每次离开 A 都立即隐藏 A 并失效 A 的等待与显示回调；进入 B 后重新等待完整约 450–500ms，不继承已显示卡片的“热启动”。A 只在 A 的有效锚点下显示，不将同一个可见卡片移动过去再替换内容。

键盘提示只响应真实键盘导航／focus-visible，不因鼠标点击后留下的 focusin 进入更短计时。离开、按键、点击、拖动、横向滚动、切页、标签关闭、导航、移窗、最小化或父窗口失焦均取消提示。背景标题更新可刷新同一目标的文字，不能改变目标或重新抢焦点。

待显示请求携带窗口、稳定 tab ID、资源身份、文档代次和 hover generation；图标准备、IPC 和显示返回后都再次核对。用一个每窗口提示控制器复用一个原生实例，不为每个标签永久保留一个原生窗口。

后台标签也能展示自身提示，但悬停不激活它、不 present、不导航、不移动网页。现有页绑定接口要求当前活动页，不能为此放宽全局校验：提示按所属窗口中的标签身份单独校验，原生面板可只绑定父窗口；目标被关闭或转移后立即失效。

## 5 地址建议达到图二的原生效果

### 5.1 行布局

面板左边缘与实际地址输入区域对齐，宽度跟随输入区域并按屏幕工作区裁切；不再固定 500。外壳圆角约 12–14，内边距 5–7；行高建议 36–40 CSS px，首屏约 5–7 行，内容超出后在内部滚动。

每一行使用整行命中区域：左侧 16px 图标，中间标题，旁边是弱化的域名／路径；最右可显示“搜索网页”或“已打开”等简短类型。标题与网址共享可用宽度并分别尾部省略，不把它们拼成一个居中的按钮文字。选中或悬停显示柔和整行底色，普通行没有胶囊边框。

输入普通文字时保留首项搜索意图；识别为网址时显示明确的前往意图。历史结果使用可靠的本地站点图标或通用图标。重复网址和重复标题按现有身份规则去重，保留原排序语义，不为模仿参考图额外增加云端联想请求。

### 5.2 输入与选择

地址栏继续持有输入焦点，NativePanel 不抢焦点。键盘选中状态与原生焦点分离：Arrow Up/Down、Home/End 更新 selected ID，原生列表将该项滚入可见区；Enter 只执行当前仍有效的候选，Esc 收起建议并遵守现有地址输入恢复规则。

中文组合输入期间不因 Enter 导航，不因更新控件树丢失组合串。鼠标点击整行执行同一动作，鼠标悬停不能提交导航。输入变化后保留有效选中身份，否则回到明确的默认项；图标或历史读取迟到不能覆盖较新的查询。

### 5.3 原生菜单内的横排缩放

普通菜单外观沿用当前浏览器更多菜单。缩放行按参考图组织：标签左对齐，右侧紧凑分段控件内部依次是减号、百分比和加号，再留出独立重置图标。组内使用细分隔线、浅底和适度圆角；不为每个按钮画一个大胶囊。控件高度建议 28–32 CSS px，中间百分比固定足够宽度，避免从 90% 到 100% 时其它按钮移动。

减号／加号按有限的缩放档位调整当前网页，重置恢复 100%；到达边界时禁用对应按钮，已为 100% 时可禁用重置。点击后菜单保持打开，百分比和按钮禁用状态就地更新，直至用户选择其它命令、按 Esc 或点击外部。键盘应能逐个访问控件并激活，不能破坏原有菜单上下导航与子菜单行为。

只改变目标网页，不改变应用界面缩放、其它标签或其它窗口。沿用现有后端 25%–300% 范围，档位可从常用 25、33、50、67、75、80、90、100、110、125、150、175、200、250、300% 中确定；当前非标准值按相邻档位调整，显示值来自实际 getZoomFactor，不能以本地加减结果冒充成功。

0.3.39 基线的“网页尺寸与缩放”只展开另一行预设下拉框，不能算本项完成。本轮已在原生菜单接入横排缩放；网页尺寸仍保留独立的视口设置入口，避免与页面比例混淆。参考图的其它条目不自动成为打印、密码或 Cookie 等新增功能要求。

现有后端 `browser-workspace-ipc.ts` 的 zoom 命令已经针对 pageId 设置缩放并通知几何变化，应继续复用。不要直接套用 MenuItem 的 zoomIn／zoomOut／resetZoom role：菜单焦点可能属于应用主 renderer，并非需要缩放的网页。菜单动作须绑定所属窗口、目标 pageId 和当前显示代次，切页、导航或移窗后旧控件失效。

打开菜单不改变 Agent 控制权或网页几何。真正调整比例属于明确的几何变更：若当前可信输入正在执行，应禁用或等安全空闲后提交，不能静默中断并重放旧点击，也不能承诺实际缩放对坐标操作毫无影响。

## 6 需要怎样的内核定制

本节按 `.7` 发布制品更新，区分已发布能力与仍需补充的能力。内核扩展由定制 Electron 智能体完成；本项目依据发布类型和隔离探针登记应用能力，随后接入回归。`.7` 仍只有 NativePanel.isSupported()，没有公开的分项 feature 查询，不得虚构调用。详细字段与发布证据见[.7 总规划](./electron-7-readiness-and-implementation-plan-2026-11-04.md)。

### 6.1 .6 已发布：原生列表行

实际类型为 `item`，不是旧提案中的 `listItem`。用 children 组合 icon、text、iconButton；使用 selected、singleLine、maxWidth、UTF-16 highlights、style 与 contentInset 控制整行命中、选中底色、文字和留白。内部按钮有独立动作，不连带执行整行；选中展示不自动导航。

地址输入保持焦点，原生建议使用非激活模式；非组合态的键盘事件由宿主驱动 selected。相同 ID／type 保留输入与滚动，不相关刷新省略 value，防止旧值在 IME 组合结束后覆盖新字。最多 2000 节点，完整资源需分页／按需展开。

普通 button 默认外观仍保留，显式 variant 可选 default／plain／outlined。样式只作用于应用自己的节点，不全局修改网站信息控件。公开能力具备不等于本应用桥接已经支持；需同步类型、白名单、图标、缩放与动作验证。

### 6.2 仍需补充：被动提示与文字约束

现有 `focusMode: none` 已能不激活，不能据此推断鼠标也穿透。提示需要可选的原生命中穿透模式，让它不吞下原应到达标签或网页的真实事件；默认普通面板仍正常命中。不得通过应用合成重放点击，不能关闭 Agent 的输入保护。

文字已有 singleLine 尾部省略、align 和 fontWeight；仍需明确的最大行数和多行省略。需要时提供面板有效边界或最小可观测状态，供锚点离开、缩放和边缘定位检查使用。不能把 CSS 样式或 HTML 当作原生控件接口。

### 6.3 .6 已发布：Menu 内嵌控件行

实际接口是 `MenuItem.controls`，不是草案 `controlRow`。normal 项带非空 ID，包含 1–8 个 button／label；控件有 id、label、icon、accessibleName、enabled、closeOnClick 和 group，默认按钮点击不关闭菜单。

根 Menu 的 `control-action(detail)` 返回 `{itemId,controlId}`，没有 Electron event 参数，也不触发所在项的普通 click。成功更新实际网页缩放后替换 controls 并调用 menu.refresh()；打开期间 ID、类型、分组及所属行稳定，原位更新不执行业务。

控件位于同一个原生菜单窗口，不另开 NativePanel 填菜单空洞。按钮固定 24×24 DIP、标签 44×24、图标 18×18，不是任意 CSS 几何。Windows menu.popup 的 appearance 配置本菜单树外观，其它平台不传；不改进程全局配置。

现有应用桥接以一次 popup 返回最终 selectedId 为主，不足以承载连续缩放。需新增限定当前菜单请求的控件动作通知和局部更新：缩放事件不结束 popup Promise，业务处理成功后更新百分比；普通菜单项和关闭仍按原语义结束。请求关闭后取消在途更新，拒绝旧窗口／旧页面／旧菜单的回调，防止新菜单收到旧缩放结果。

按锁定制品、公开类型、方法存在性及后续真实交互探针确认支持，不把 menu.refresh 存在等同于所有字段可用。其它运行时继续保留明确的原生缩放子菜单，不误称横排控件已接入。

### 6.4 .7 已发布：多行、材质和滚动槽

- `textarea` 为独立节点，`submitOnEnter` 默认 true，非组合态无修饰 Enter 以 submit 携带当前全文，Shift+Enter 换行；false 时 Enter 也换行。固定高度自动折行并内部滚动，**不自动增高**；同 ID／type 保持原生输入，不相关更新省略旧 value。按钮 click 不携带文本，保存按钮与 IME 最后文字的同步需另外验证。
- NativePanel 构造和 update 已发布 Windows `backgroundMaterial:none|acrylic`，但**面板 Acrylic 当前搁置**。保留契约记录，当前使用 none 与不透明 theme.background，不继承父窗口、不随宿主材质开关启用，也不影响 Menu；只做实色主题回归，不把材质效果列入当前清理／发行验收。
- 面板构造／update 以及 list／textarea 各自有 `scrollbarPlacement:gutter|overlay`，默认 gutter，互不继承。12 DIP 独立槽位于各自分配边界内，不等于浮窗外滚动条或始终保留槽位；列表行、编辑正文与固定操作区分开布局并验收，避免双重竖向滚动。

### 6.5 仍需按入口补齐

- 多行完整交互：原生排版驱动的自适应高度、边缘约束下的固定下方按钮布局，以及按钮保存取得最新组合文本的明确顺序／原子契约。现有 textarea 基础不再列为未发布；其他资料编辑的 Enter 行为保持可配置，不全局套用批注规则。
- 多行限长已知风险：`.7` 按 UTF-16 直接截断，代理对边界可能损坏；IME 暂态超限 change 又可能被现有 4000 限制草稿库拒绝。接入须按[多行面板第 6 节](./已完成/native-annotation-multiline-panel-plan-2026-11-04.md#6-正文草稿与旧记录)落实 Unicode 安全限制或有界、无损的溢出草稿方案，不把 maxLength 同值当成数据保真证明。
- 持久侧栏：面板内行上下文菜单、必要的树／展开状态、宽度调整、拖放，以及跨 HTML／NativePanel 的阅读锚点和焦点恢复。共享业务状态不等于共享控件实例，当前没有任意滚动位置／定向焦点公开接口；选中行滚入视口是已有行为，不替代精确恢复。先映射业务状态，再补最小可验证契约，不一次引入任意 HTML 容器。
- 富内容：独立的受限图片预览节点和按键捕获控件，按资料／帮助入口需要增加；icon 不冒充大图预览，多行输入也不替代完整富文本编辑器。

上述补充能力在 `.7` 仍未公开或尚待证明；待定制方发布或真实交互验证后登记。`.7` 不存在分项 feature API，不能调用不存在的方法。未具备必要能力的入口状态写清，不能声明截图已经全部消除。

## 7 应用侧统一协调与截图退出

### 7.1 面板按用途协调

现有 `dismissOthers()` 会收起同窗口其它原生面板，适合普通临时菜单，但不适合所有新入口。需区分被动提示、临时操作面板、持久侧栏及其所属子菜单。

被动提示优先级最低：有前台菜单、编辑面板、拖动或组合输入时不弹出；它不能收起 Agent／下载面板。侧栏自己的行菜单与所属侧栏可共存，关闭子菜单先返回侧栏，关闭侧栏再恢复原触发器。不同顶层临时操作仍互斥。

互斥只影响本窗口。关闭旧面板不恢复焦点到新面板之后；后台提示不强制 focus、select 或切换页面。网站信息继续走原有接口，只在既有入口通知／原生焦点返回等可观测边界协调提示，不重写其内容和关闭逻辑，也不假设它已有额外的应用关闭事件。

### 7.2 逐入口移除截图，不直接删除总开关

建立显式的弹层登记：入口类型、所属窗口／资源、原生或 DOM、锚点、是否确实覆盖网页、允许的关闭方式。新原生入口不进入 DOM 覆盖计算；保留 HTML 的附加只在真实交叠时评估，不能按“面板存在”冻结全部网页。

每完成一个原生入口，删除该入口对截图兼容链的依赖并验证真实网页保持；未知覆盖界面先定位归属。确认没有依赖后，再收敛 MutationObserver 的宽泛选择器，避免残留 DOM 隐藏副本误判，也避免资源摘要等遗漏。

兼容截图限定到已命名且尚未迁移的入口，并保留原因记录。用户截图和批注证据在独立通道继续工作，不与弹层替换计数混算。

同一登记和统计必须覆盖工作区、独立浏览器窗口及页面移窗过程。登记项明确标注已原生、待迁移兼容、明确保留 HTML 或业务取证；正常原生菜单／面板不得触发 preview、冻结图或空布局。异常降级应有明确原因，不能继续作为常规展示方式。

## 8 独立窗口的修复目标

### 8.1 标签与标题栏外观

统一共享 `--tab-*` 变量与状态选择器，独立窗口沿用同主题工作区标签的底色、文字、边框、圆角、图标和控件反馈。标题栏可保留平台拖动区、系统窗口按钮及布局区别；底色搭配应连贯，不另做一套标签皮肤。失焦状态可以适度减弱，但主窗口与独立窗口采用相同规则，当前标签仍清楚可辨。

主题读取完成前采用一致的初始样式，主题切换和跟随系统模式要同步到所有已有窗口。核对菜单、标签、加号、音频与移回按钮的命中区域和留白，不通过覆盖网页样式解决应用外观问题。

### 8.2 页面无需切换标签即可恢复

把恢复拆成“确定当前页 → 验证宿主／owner → 获取有效容器 → 安全提交几何 → 确认显示”的单一路径。窗口显示、还原或从资源入口查看当前页时，即使 active ID 没变化，也要验证呈现状态；有有效提交可直接复用，没有则请求当前容器重新布局。普通焦点变化不能无条件重新 claim owner、隐藏 View 或重新激活标签，避免菜单和输入法焦点造成闪白与循环通知。

主进程失效几何后，应让 renderer 明确获知需要重提布局，或在边界仍有效时安全重用，不得只隐藏后等待下一次切页。前端去重必须包含宿主与有效代次，不能因矩形数值相同就吞掉必要的恢复。忙碌期间保留最新有效请求，在安全空闲后提交；若待提交请求已经失效，重新请求当前布局，不强行显示默认区域。

迟到的旧标签、旧 owner、旧窗口、空布局和截图结果均不得覆盖当前显示。关闭弹层后清除该入口的冻结状态，并只恢复当前页；移窗后释放旧宿主请求。对异常提供有限重试和可读提示，不用永久轮询、自动刷新、切到别页再切回或重建 WebContents 来掩盖问题。

### 8.3 专项验收

- 同一页面从工作区移到独立窗口后直接可见；从资源列表重复查看已有独立页、单标签独立窗口、隐藏后显示、最小化还原和切回应用均不需要额外切标签。
- 连续调整窗口、最大化／还原、跨显示器和 100%／125%／150%／200% 缩放下，网页边界正确，不白屏、不回到左上角；后台页不抢前台。
- 同一主题与同一状态下比较两种宿主的最终计算色值和可见截图；覆盖所有内置主题的浅色、深色、跟随系统及实时切换，检查选中／悬停／失焦、长标题、图标和音频控件。
- 网页保留相同 WebContents ID、表单和滚动位置；视频／动画持续，Agent 忙到闲后正确恢复。正常恢复不发出重载、不切换控制权、不重放过期可信输入。
- 主窗口和独立窗口都验证原生菜单、提示及列表打开／关闭后没有弹层替换截图；尚未迁移的入口必须能按名称追踪，不能把白屏、冻结图或残留遮罩当作恢复成功。

## 9 实施顺序与验收

1. **优先修独立窗口白屏**：复现“查看后空白、切标签恢复”，补呈现状态观测，修显示恢复、布局失效通知和代次去重；与既有左上角错位回归分开验收。
2. **统一标签外观并修提示身份**：核对两种宿主的实际样式，整理共享主题状态；建立每窗口提示控制器，排除双重 tooltip，复现 A→B→C、关闭、导航、拖动和焦点交错。这些应用侧工作不等待列表行内核。
3. **核对并接入定制内核能力**：由用户安排的定制 Electron 智能体提供原生列表行、文字省略／行数、被动命中模式及 Menu 内嵌缩放控件行；本项目按实际发布的类型与功能探测接入，保持现有控件默认值与网站信息面板不变。
4. **迁移标签提示、标签搜索，更新地址建议**：三者分别验收，不把地址建议的样式更新误记为新迁移；主窗口与独立窗口同时退出对应截图链。
5. **统一普通菜单并接入横排缩放**：按第 3 节入口清理独立 v-menu，接入原生控件行及实际网页缩放回执；随后迁移简单搜索／编辑界面，不重做已完成的通用 Menu 路由。
6. **补多行输入和持久面板**：批注、悬浮侧栏、浮动摘要和复杂编辑逐项保真迁移；保留原页面与业务实例。
7. **归档完整清单后再发行**：记录已原生化、仍有兼容截图、明确保留 HTML 与不属于浮层的界面，以及独立窗口专项结果；经用户后续明确，本轮三项全部完成并验证后再编译新版本，不提前发行部分清理版。

验收至少覆盖：

- 提示 A 显示后进入 B：A 立即消失，B 在完整延迟后显示；快速划过 B、C 不出现迟到提示。点击标签仍正常切页，提示不能自行激活任何页面。
- 标题仅显示一次；长标题、RTL、中文、相同文件名与异常状态布局稳定；窗口边缘、最小窗口和 100%–200% 缩放不溢出。
- 地址建议有图标、独立标题／网址、整行高亮及真实省略；鼠标和键盘选择一致；中文组合输入、删除、Esc 和历史更新不丢输入、不误导航。
- 普通动作菜单统一走 Menu，原有勾选／分组／子菜单／快捷键和禁用目标保持；缩放行连续点击不关闭菜单，百分比反映真实网页状态，25%／300% 边界与 100% 重置正确，键盘可操作。
- 缩放只作用于明确的目标网页；菜单存在时切页、导航、移窗及迟到回执不缩放错误对象，不改变应用界面比例。与 Agent 几何保护共享安全提交，不回放过期输入。
- 常用原生提示、列表与菜单打开／切换／关闭期间，弹层替换截图调用为零，底层视频或动画持续、同一 WebContents 和表单保持、Agent 定向输入连续完成。
- 前台面板存在时提示不出现；侧栏与所属菜单共存；跨窗口、导航、移窗、关闭及迟到动作不能串目标。
- 原生圆角命中、被动穿透、中文输入法和多显示器焦点用可见真实窗口验收，不能只凭回调注入和隐藏窗口报告完成。
- 原生实例与监听有边界：每窗口一个提示实例，关闭窗口销毁；反复悬停大量标签后不随标签数量永久增长。
- `showPageInfoDialog` 应用调用与网站设置语义保持，内核自带变化独立回归；附加菜单仍为 HTML，原有搜索、斜杠和资料插入回归通过。

## 10 变更位置

应用主要涉及 WorkspaceTabItem、BrowserTabList、BrowserAddressBar、browser-native-panels、useNativeUi、native-ui 服务及 BrowserTabPanel 的覆盖登记；独立窗口专项涉及 BrowserHostPage、DetachedWindowBar、BrowserHostManager、browser-workspace-ipc、useAppearance 和共享主题样式，其余入口依第 3 节推进。测试扩展现有 ui-workspace-tab-chrome、ui-browser-workspace、ui-native-browser-panels、浏览器恢复与多窗口套件，新增独立窗口不切标签恢复、跨窗口主题比对、真实指针跨标签时序、原生列表截图比对与面板角色互斥检查。
