## 2. .6 已能支撑的项目

### 2.1 地址建议和原生列表外观

真实节点类型为 `item`，不是历史提案的 `listItem`。可组合 `item + icon + text + iconButton`，用 `selected`、`singleLine`、`maxWidth`、UTF-16 `highlights`、`style` 和面板 `contentInset` 完成整行命中、标题／网址、选中底色及辅助动作。内部按钮独立回传，不连带执行整行。

`button.variant` 支持 default／plain／outlined，`style` 可设置状态底色、边框、圆角、四边内距、文字色／字重／对齐及输入框 borderless；`linkRange` 是说明文字中的原生链接，不是多行编辑。

地址建议恢复规划接近参考图：首行搜索／导航意图，下方历史与候选整行；标题优先、网址弱化、长内容省略，不再逐项胶囊按钮。原地址输入保持焦点，NativePanel 可使用 `focusMode:'none'`，宿主只在非 IME 组合态消费方向键／Enter 并更新 `selected`。宽度跟随实际输入区域，查询代次、候选 ID 和当前页面共同校验，旧结果不可执行。

同样的行规范可复用到标签搜索、聊天／文件候选及批注数量列表。固定真实身份，分页或限制首批结果；每树最多 2000 节点、深度 32，不能将全部资源无界展开送入面板。原生输入保留与滚动需要在实际 Navora 链路再验证。

### 2.2 菜单中的横排缩放

使用真实 `MenuItem.controls`：所在项是有非空 ID 的 normal 项，1–8 个 `button|label` 控件，字段包括 id、label、icon、accessibleName、enabled、closeOnClick、group。不要实现历史草案中的虚构 `controlRow`。

目标为左侧“缩放”，右侧减号／百分比／加号同组，旁边重置。按钮默认不关闭菜单；根 Menu 发出 `control-action(detail)`，detail 仅包含 `{itemId,controlId}`，没有 Electron event 参数，也不调用所在菜单项的普通 click。应用成功修改实际缩放后更新 controls 并调用 `menu.refresh()`；打开期间 ID、类型、分组及所属行保持稳定。

当前桥接只以 popup 结束返回 selectedId，需增加当前请求内的连续控件动作通知与原位更新，不把每次缩放都结束为一次菜单选择。按页面／菜单代次串行处理连点，读取实际缩放确认百分比；达到上下限禁用，失败回显真实值，关闭后取消迟到更新，不能作用于另一个标签。

控件原生几何固定：按钮 24×24 DIP，标签 44×24，图标 18×18，组圆角 8，组后间距 4。菜单外壳可配置，内嵌控件不是任意 CSS 布局；以此评估参考图接近度，不承诺任意尺寸与逐像素一致。

### 2.3 普通菜单统一

使用 Windows 专用 `menu.popup({appearance})` 按当前主题配置字体、行高、宽度、留白、分隔和颜色，子菜单继承同一菜单树设置。其它平台不传该字段；不修改全进程 MenuConfig 或站点 UI。数值按公开范围校验，要求整数的 DIP 字段在应用缩放换算后取整。

继续迁移插件／商店等剩余普通动作菜单，沿现有业务函数与权限，保留勾选、单选、禁用、快捷键、来源身份和焦点。NativePanel 样式及菜单样式均须显式作用于应用自己的控件，不能通过更改默认按钮间接改网站信息入口。

## 3. .6 仍未发布的必需能力

以下按发布类型、文档和源码核对，不能因为有 `floating-comment.png` 等样例就标记完成：

- **多行编辑**：`.6` input 仍是单行，action 只有 click／change／submit 与 value。用户现指定 `.7` 多行批注需要 Enter 确认、Shift+Enter 换行、自适应高度与下方按钮，见[面板规划](./已完成/native-annotation-multiline-panel-plan-2026-11-04.md)；未来 textarea 类型及固定 height 不自动满足整套需求，不得压成单行或拆成多个输入框。
- **被动提示**：`focusMode:none` 只是非激活，不代表卡片本体鼠标穿透；现有透明圆角／阴影命中也不能推出全区域被动穿透。最多两行及多行省略同样没有明确契约。
- **持久侧栏**：item 可表达展开后行的视觉，不等于已支持原生树交互、行右键、拖放引用、调整宽度与父子 popup 关系。不能以缩水列表替代资源管理。
- **图片与快捷键录制**：icon 是图标，不是大图预览／缩放／适配节点；单行 input 不是按键捕获控件。多行资料、图片证据、快捷键对话框仍有缺口。
- **外部点击与父子菜单**：当前 hook 观察外部点击，不消费／合成。不能承诺“关闭面板的同一次点击不会送入网页”。缺少公开父子 panel／Menu 关系，需补关闭传播、焦点、IME 候选与子菜单协调的契约和实测。
- **细粒度能力查询**：NativePanel 只有 `isSupported()`，没有公开 getCapabilities／feature query；不能向内核调用规划中尚不存在的方法。

最新批注保留地址栏和模式开关，输入已由单行 V2 演进为 `.7` 圆角长方形多行面板；开关／计数／选择可沿已有基础，输入按新契约接入。关闭命中、历史全文、草稿保真及复杂侧栏仍需分别完成，不能据此认为全部截图退出已完成。

## 4. 原生桥接与生命周期需先完善

当前 `shared/native-ui.ts` 和 `native-ui-validation.ts` 只覆盖 `.5`，主进程转换仅缩放部分几何，capabilities 还硬编码 `.5`。实施时一起扩展公开枚举、类型、白名单、图标转换、动作验证和新字段的缩放规则，不能只放宽 renderer 类型或仅修改版本字符串。

应用定义自己的能力状态：未知／已核对支持／不支持，依据锁定制品与公开类型、`isSupported()`、方法存在性，以及隔离原生 schema／交互探针。它是应用能力登记，不冒充内核 feature API；探针不得操作用户页面或把失败实例遗留为可见浮窗。

同 ID／type 更新虽保留输入，但刷新时携带旧 value 仍可能在组合结束后覆盖新字。与输入无关的刷新省略 value，草稿按目标、修订与请求代次确认；只有明确恢复／切目标才替换值。图片和 UTF-16 高亮按各自语义验证，不把文字 offset 当几何缩放。

`dismissOthers()` 当前关闭同 renderer 全部面板。改为区分被动提示、瞬时面板、持久侧栏、编辑器和子菜单；应用协调与原生父子契约共同完成，不能认为改 JS 就已保证菜单共存。来源绑定的 NativePanel 在导航、同 URL 刷新、销毁或移窗后可能失效，原父窗口不能更换；按当前页身份销毁重建，而非沿用旧 source。

## 5. 各专题补齐后的范围

### 5.1 公共默认会话和浏览器资源

以[公共会话规划](./已完成/browser-public-default-session-plan-2026-11-04.md)为准：公共默认共享存储，页面与任务保留对话来源，资源侧栏改为会话／页面两层，减少重复说明；独立窗口左侧为移回工作区、置顶窗口、标签页。

先落实可使用／可观察／可管理的区别，再接界面。网络日志与拦截规则当前按 sessionId 聚合，必须按页面或请求上下文隔离，包含 Session.fetch／worker／下载；来源未知不得归当前前台对话。数据清理、代理、UA、Cookie 全量管理属于共享影响操作。

迁移需要稳定默认身份、零页会话、逐页 chatId、实际分区、存储版本、备份与回退。旧持久分区不合并、不清数据，删除单个对话不清公共会话。首次取得、共享管理与无页请求一起纳入并发锁；授权等待后再次校验来源和策略。

明确 `session.persist=deny` 的兼容决策：首次自动创建／启用公共持久资料不能绕过既有拒绝，受阻如实返回；合法建立的公共会话不因禁止新建被反复确认或清空，复用继续按使用权限处理。用户显式临时请求仍可按授权使用。旧显式 persist 保留隔离含义；失败／降级返回真实策略，不静默切换账号。此专题核心不依赖 `.6`。

### 5.2 附加中的自动化／计划声明

以[任务声明规划](./已完成/composer-task-declarations-plan-2026-11-04.md)为准：仅当前消息生效、支持组合、标签可移除，附加继续 HTML。自动化按需导航／读取／API／点击输入；计划阶段只读核对和形成方案，不自动实施。

除前端提交键，还需统一 AgentInbox 指纹、主进程收据、队列编辑与运行约束。仅有声明的草稿虽不可发送，也必须保存和撤销；兼容纯文本编辑不能丢掉原计划限制。启动、重试、确认后恢复、崩溃恢复、插入和子任务都读取冻结约束，不能因空正文 resume 进入执行阶段。

先做派发层的计划边界再上线 UI 标签；不靠提示词冒充约束。声明核心不依赖新内核，不能因 `.6` 到位略过数据与运行迁移。

### 5.3 简洁批注模式

开关／选择以[轻量批注 V2](./已完成/browser-annotation-lightweight-plan-2026-11-04.md)为准，输入按[.7 多行面板](./已完成/native-annotation-multiline-panel-plan-2026-11-04.md)：取消底部栏，保留导航／地址输入和独立计数，目标旁圆角长方形自动增高，Enter 保存／Shift+Enter 换行，固定下方按钮。数量仍开 NativePanel 列表，不恢复整行替换或语音需求。

### 5.6 窗口 Acrylic 与半透明框架

先统一窗口创建和主题更新策略，再处理根层／主题 !important 及内容父层的实色遮挡，不只改构造字段。外观开关同步全部可见应用窗口，遇到高对比、减少透明度、不支持或失败回退实色。NativePanel／悬浮侧栏有自己的窗口，不能由父窗口 Acrylic 推定其材质，也不使用截图或 CSS 模糊来代替原生网页背景。

此项不依赖 `.7` textarea，可以按窗口外观路线独立实施；不改网页圆角或 Agent 控制。系统支持、失焦和多 DPI 以真实可见窗口核验，当前仅规划。

### 5.7 网页内容右键菜单

## 6. showPageInfoDialog 的升级差异

应用侧保持现有调用、来源校验、权限／网站设置跳转与默认控件使用，不新增自绘页面、不为新样式改变该入口。但 `.6` 内核自己调整了网站信息／安全子页，并将证书详情改为原版 `chrome://view-cert` WebUI。发布文档 `docs/zh/原生界面定制实现与测试.md` 第 1／5 节和对应报告已有记录。

因此“保持不变”不能扩成升级后仍逐像素等同 `.5`。规划将内核自带变化列为独立兼容核对项；实施前以当前行为对照，无依据不宣称完全相同。如需冻结 `.5` 的内核 UI，需要定制方提供明确兼容策略，而不是应用另写 HTML 假冒。

证书查看会创建专用证书 WebContents，属于内核明确用途；NativePanel／普通菜单本身仍不新建网页渲染器。验证应分别计数：常规菜单面板无新增 renderer；显式打开证书时仅出现预期实例，关闭回收，不获得 Navora 应用 IPC 或 Agent 操作权。不能把既有固定 WebContents=2 的样板断言当成全部新路径通用结论。

## 7. 实施批次及进入条件

1. **契约与迁移准备**：定稿应用能力登记、原生动作桥、会话权限／恢复格式、声明语义身份与运行阶段。当前仅完成规划；代码基线与现有未发行修复保持。
2. **.6 基础接入与明确可做项**：以后开始实施时更新 npm／lock／安装器版本、实际制品哈希与下载尺寸，验证 types／runtime 匹配，再接列表行、普通菜单外观和横排缩放。升级不能只改标记；旧 runtime 校验脚本和 hardcoded capabilities 一起对齐。
3. **业务后端与 UI**：阶段约束、统一提交身份／恢复先行；公共会话逐页归属、网络／下载／权限路由及并发迁移完成后，再接资源侧栏、左侧窗口按钮与附加声明。窗口 Acrylic／主题透明层可独立并行，业务数据前置不可省。
4. **迁移批注与复杂入口**：批注开关／目标沿 V2，输入按 `.7` 多行及自适应面板验证；历史全文、被动提示、悬浮侧栏、图片／多行资料和快捷键等逐项保真迁移。现有白屏／配色／五个菜单修复做新 runtime 回归，不把基础控件通过当作整个截图清理完成。
5. **删除背景截图总路径**：全部覆盖入口保真迁移或有用户明确同意的布局替代后，再删除 overlayCoversPage、背景 MutationObserver、frozenFrame、prepareBrowserOverlayFrame 等展示链。继续保留截图工具、网页预览用途、批注证据和旧记录读取，不把删除总函数当作迁移成功。
6. **发行**：所有必需能力和应用回归完成后才提交／推送、更新版本并打包；本轮只完善规划，不提前进入这一批，也不改变等待条件。

每批独立记录实际完成、运行证据、遗留入口和回退边界。公共资料及文档迁移使用备份、版本格式与失败回滚；不让新源码读取失败后写回空数据。运行时安装在后续实施中采用校验过的临时目录／受控替换，不在未验证制品上覆盖当前可用运行时。

## 8. 验收与剩余定制清单

原生入口必须验证：实时视频／动画推进、相同 WebContents 与表单／滚动保留、正常弹层背景截图为零、Agent 连续输入不受打断、旧页／旧代次动作拒绝、中文物理输入法、关闭后的焦点、父子菜单共存、独立窗口、多显示器与混合 DPI。原生面板的透明角与阴影命中仍需测试，与已取消的网页圆角无关。

业务验收增加：共享 Cookie 但网络日志和控制不跨对话，worker／API 来源可归属或安全拒绝，撤权／共享管理并发和重启恢复；同文不同声明不误去重，纯声明草稿不丢，计划经重试／授权恢复／子任务后仍不实施改动。所有来源处理和导出不记录密钥或用户输入正文。

下一份定制需求聚焦尚缺的可验证能力：多行原生编辑及修饰键／IME／选区语义、被动卡片全区域鼠标穿透与文本约束、持久侧栏交互、父子 popup 和外部点击传播、受限图片与按键捕获，以及稳定的公开分项能力查询。具体字段由定制版发布确定，应用规划只规定效果和验收，不造 API。

本轮检查限于文档、公开类型、源码和制品哈希；没有运行 `.6`、执行新应用验收或改动当前用户数据。
