# Navora Desktop 重构进展

日期：2026-10-30。完整范围与阶段验收见 [renovation-plan-2026-10.md](renovation-plan-2026-10.md)。本记录区分已验证的首批实现和后续工作，不表示整体重构已完成。

## 源码基线

开始重构前的源码已推送 `origin/main`。后续实现位于 `feature/harness-renovation`，保留主分支基线作为回退点。探针、运行数据和真实凭据没有进入提交。

## 浏览器和 Agent

- `browserCapabilities` 检查运行时方法，不把包版本或类型声明当成实际可用证据。
- `browser_get(snapshot)` 在隔离世界采集可见元素、语义名称、链接、正文与覆盖范围。ref 不写入页面属性；导航、节点移除和语义变化后失效。
- 缓存复用在渲染进程内完成；查询排序和结果预算也在渲染进程执行，避免每次将完整索引传回主进程。词法检索支持中英文分词、精确名称优先和通用词结果过滤。
- 默认快照为标题、控件、frame 与链接保留配额，避免大量导航链接挤掉正文里的操作控件。
- 普通模型压缩保留链接、控件和 ref；超大结果始终输出有效 JSON，不返回被截断的半个对象。
- 提示词移至 `shared/agent-prompt.ts`，旧 `shared/agent-tools.ts` 导出继续兼容。保留插件、技能、权限、下载和用户决策约定，移除站点特例和仅按 URL 是否变化就重复提交的规则。
- 原生跨 frame 定位和点击已覆盖不同端口的跨域页面。不存在指定控件时明确失败，不再点击猜测的 iframe 坐标。
- 修复 frame 枚举时 `framesInSubtree` 含当前节点导致的重复递归，并增加回归。

当前索引覆盖主文档和开放 Shadow DOM。闭合 Shadow DOM 可以原生深查询，frame 可以原生跨文档查询；这两者仍不是完整内容索引。

## 插件兼容

实际 Electron 回归创建旧契约的 CJS 插件，经过 `PluginStore` 发现并加载工具，经 `planPermissions` 和 `execute` 调用 `api.runTool` 获取新快照，并验证旧 `api.ctx` 入口仍存在。未声明的 click 能力继续被 Host API 拒绝。

尚未用真实账号和外部模型跑完所有官方插件的联网任务，不能用契约测试代替这些业务验收。

## 定制 Electron 文件输入修复

原 `45.0.0-cloudbypass.2` 包可以设置 input 的文件列表，但没有为渲染进程登记对应文件读权限。之后导航会触发 `RFH_CAN_ACCESS_FILES_OF_PAGE_STATE`，Chromium 终止渲染进程。本轮使用临时文件和本机页面复现。

修复在 `WebContents::SetFileInputFiles` 中校验绝对路径，并向实际目标渲染进程授予这些文件的读权限。补丁位于 `patches/electron/file-input-read-grants.patch`，已应用到旁边的 Electron 源码并完成 Windows 增量编译。

本机已通过 `npm run electron:use-build -- <out/Release>` 将修复后的可执行文件安装到本项目，并保存 `node_modules/electron/dist/navora-build.json` 校验记录。此次没有修改 Postpile 的分发目录，也没有发布新的内核版本。

源码包仍固定为 `45.0.0-cloudbypass.2`，因此新检出或重新安装原始内核后需要应用补丁和本机构建。发布准备阶段应把修复纳入正式内核分发包。当前 `dist` 命令先执行原生浏览器回归，并使用本项目的 `electronDist`，避免重新下载未经此回归验证的内核。

## 界面和动效

通过仓库内的 `vendor/postpile-ui-0.1.2.tgz` 安装 `@postpile/ui`，保留其色彩、圆角和层次。后续真实使用发现尺寸形变、模糊与全局按钮测量带来卡顿，现已取消全局按钮增强，菜单和弹窗只合成 opacity/transform，菜单进入 210ms、弹窗进入 240ms，离开 130ms。Vue 适配层通过 mergeProps 保留 Vuetify 自带的离场回调，避免关闭后内容和焦点陷阱残留。

真实应用的 preload、IPC、配置和渲染页面使用临时数据目录进行 UI 回归。测试以离屏合成器保持动画帧更新，不打开可见窗口；覆盖桌面、窄屏、菜单文字对比度、快速开关后的来源按钮恢复和设置工作区。减少动态效果使用 Chromium 原生启动开关单独运行。

截图输出在 `release/ui-smoke/`，减少动态效果版本位于其 `reduced-motion/` 子目录。聊天调整为简洁的左右消息排版；侧栏和设置收紧间距、隐藏重复说明。错误、运行、询问、授权、停止、成功使用统一的 SVG。菜单、移动侧栏和按钮对比度统一检查。

右侧深边的根因是 Postpile 的 `html { scrollbar-gutter: stable }`，与桌面内部面板滚动冲突；根页面改为不保留滚动条槽。搜索改用统一弹窗，真实指针点击和 Ctrl/⌘ K 回归覆盖标题、消息命中及焦点。Ctrl/⌘ N 新建对话，Ctrl/⌘ Shift B 复用/打开浏览器，Esc 或顶部按钮停止任务。浏览器资源提供直接关闭窗口操作。

Windows 使用 titleBarOverlay，macOS 使用原生交通灯，Linux 保留窗口管理器边框。分别提供 macOS 和 Linux 构建目标；实机运行验证目前仅在 Windows，其他平台仍需在对应系统使用匹配的 Electron 分发进行打包和验证。

## 模型、延迟与引导回归

模型目录支持显示名、上下文、输出上限、文本/图片输入、推理档位及其 API 值映射。SC117 配置按提供的截图：`qwen38-turbo-q6`、524288 上下文、81920 输出，`high → xhigh`、`off → none`，默认 low。提供实际模型目录获取，Chat Completions 可选择 max_tokens 或 max_completion_tokens；图片通过多模态消息发送，生成截图的 base64 不进入持久化聊天日志。密钥只存本地被忽略的 secrets 目录。

自动模式对普通问答采用单次模型请求；也可明确选择快速问答或执行任务。工具、插件和浏览器工作流继续保留。移除回答完成后阻塞运行状态的追问生成请求，快捷后续操作改用本地已有结果。问答不再额外生成 AI 标题。

引导跳过和无关设置保存不再被旧的远程默认密码拦截。远程配置发生变化时仍校验，远程服务启动也仍拒绝默认密码。

使用临时配置、真实 preload/IPC/Agent/界面和提供服务实测五档问答：off 3892ms、low 1528ms、medium 1636ms、high 2617ms、xhigh 1529ms，全部正确且无工具轮次。合成红色图片也正确识别。样本是一次本机网络测试，不能保证其他时刻或复杂任务相同耗时。结果保存在本机 `release/ui-live/live-model-results.json`，不含密钥。

## 验证

- `npm run typecheck`：包含业务代码和 Electron 集成测试入口。
- `npm test`：本轮 34 项测试通过；部分既有测试文件内部包含多条断言。
- `npm run test:browser`：实际内核检查快照与缓存、可信点击、输入、开放 Shadow DOM、闭合 Shadow DOM 查询、跨域 frame、失效 ref、文件输入后导航、原生 prompt、自定义文档响应、插件契约，并确认 debugger 未附加。
- `npm run test:ui`：完整构建后执行桌面/平板/窄屏、设置各页、图标对比度、搜索、引导跳过、档位持久化、浏览器快捷复用和停止任务，并独立执行减少动态效果模式。停止任务使用本地延迟服务验证取消，不消耗远程模型长输出。
- 可选真实服务测试：设置 `NAVORA_LIVE_MODEL=1` 和 `NAVORA_LIVE_KEY_FILE=<本地密钥文件>` 后运行 `node scripts/ui-smoke.mjs`；临时密钥副本随测试数据目录清理。

实现参考：[Electron 原生标题栏](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar)、[OpenAI Chat Completions 请求结构](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。第三方模型的具体配置来自提供的截图与实际接口验证。

本机 HTML 夹具包含 250 个商品块。一次记录中，10 次强制采集的宿主工具往返 p50 为 9.31ms，p95 为 17.29ms；20 次缓存查询 p50 为 0.80ms，p95 为 1.14ms，缓存命中 20/20，结果 5703 字符。这是本机页面采集与检索基线，不含外部网站、模型网络或推理耗时，不能推导真实站点的端到端提速比例。

## 2026-10-31：可调整工作区与简单查询延迟

- 增加最左侧活动栏，对话、工作区、浏览器资源可分别显示/隐藏；更多、下载和设置统一放在活动栏。下载组件的按钮现在也由同一全局规则管理尺寸、圆角、边框、悬停和键盘焦点。
- 侧栏支持指针捕获拖动调整宽度；两个水平分隔条调整对话/工作区与工作区/浏览器资源的高度。支持方向键和 Home，保存本机布局；拖动期间合并持久化写入。移动布局不把桌面宽度挤进主区域。
- 设置改为主区域页面；桌面设置分类通过 Teleport 进入原侧栏，侧栏独立翻转，退出恢复原列表与滚动。移动端保留横向分类。顶部收为单行工具栏，预留原生窗口按钮区域，精简重复操作。
- 聊天正文、工具分组、思考状态和输入框统一内容宽度；移除单独的思考品牌气泡和重复状态文案。停止按钮固定单行，运行状态使用同一套 SVG。恢复可见的菜单缩放/淡入、会话切换与侧栏翻转；不动画宽高、模糊或按钮克隆。减少动态效果独立回归。
- 会话切换并行读取相关状态，并通过选择序号防止快速切换时旧结果覆盖新会话。设置退出后重新绑定消息布局观察，保持自动滚动与布局测量。
- 修正主框架加载等待把 ERR_ABORTED 当成失败的问题，保留真实错误码，销毁或超时后清理监听；load、network idle 和额外延迟共用等待预算。默认读取等待从 8 秒降为 1.5 秒，仍返回 partial 与 loading 状态。
- 定位增加总时限、每个 IP 来源时限、可取消的 Windows 进程和五分钟内存缓存；每次调用依旧检查权限，缓存不绕过定位门闸。地点名称无法获取时明确使用“定位附近”，不推断城市。
- 新增 weather_get，按 [Open-Meteo 预报接口](https://open-meteo.com/en/docs) 和 [城市检索接口](https://open-meteo.com/en/docs/geocoding-api) 读取结构化数据，保留来源、当地日期、单位和数据时间。默认只取当天；多日查询最多七天。同名大城市与小村落按人口显著差异区分，其余歧义不猜测。该公开接口遵循其非商业使用条款；商用发行前需要自托管或配置商业接入。
- 自动模式下，明确的本地当天或城市当天查询直接格式化经校验的数据，省去模型规划与复述。插件、引用、执行任务模式和复合任务保留 Agent 路径；已启用插件仍可发现和执行。工具执行记录增加真实 durationMs。
- 后台标题生成延后到空闲阶段，新任务会取消它；标题请求不再占用下一条交互的模型名额，取消后不启动重试。简单天气不额外生成模型标题。

真实 UI/IPC/Agent 测试中，“看看今天的天气”2789ms，“查一下北京今天的天气”1380ms，各仅一次 weather_get，并获得有效温度、天气、降雨概率和来源。这些是本机单次测试，权限交互时间及网络变化不保证同样耗时。原问题任务记录为105251ms，含六次工具且未读到天气。当前快速路径不需要语言模型，因此这些天气测量不能当作 Cloudbypass 推理性能。

本次 Cloudbypass `/models` 200 返回约671ms，但独立的非流式简单问答在45秒内未返回，流式请求20秒未取得响应头。之前五档成功结果仅代表前一轮测试，不能视为当前服务仍健康。保留原配置和密钥，未声称当前模型问答复测通过；临时结果在忽略的 release 目录，密钥未进入源码。

额外验证：原生浏览器回归新增定位/网络双权限、取消的导航、等待总时限和监听清理；真实界面回归新增指针拖动、各面板开关、下载按钮一致性、设置侧栏翻转、明确存在的合成动画和后台标题让位于下一条请求。普通/减少动态效果、1440/960/720/390 宽度及设置全部分类均通过。测试进程需要写入完成标记，提前退出不会误报成功。

可选天气实测：设置 NAVORA_LIVE_WEATHER=1 与 NAVORA_LIVE_KEY_FILE 后运行 node scripts/ui-smoke.mjs。临时配置与权限仅用于隔离测试，不修改真实用户数据。
