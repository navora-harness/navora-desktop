## 1. U01：用户输入后才显示地址建议

用户明确要求：**不是聚焦就显示，输入内容时才提示**。

- 点击地址栏、选择现有 URL、Ctrl／⌘+L 只进入编辑，不展示历史／候选列表；在没有本次输入时，方向键也不能重新拉出全部历史。
- 本次编辑中，实际键入、粘贴等产生有效非空查询后才显示。删空或仅空白时收起；后台地址同步、页面导航、恢复与重新聚焦不当作用户新输入。
- 组合输入期间不抢输入法候选、焦点或 Enter；提交组合文本后再按有效查询更新。Esc 收起，失焦、切页、关闭／移窗使旧请求失效。
- 保留原草稿、选区、方向键选择和 Enter 导航；关闭建议不清掉用户正在编辑的内容。明确历史入口如以后提供，属于用户主动动作，不恢复聚焦自动弹出。

当前[open 条件](../src/components/BrowserAddressBar.vue:58)没有要求实际输入；[focusInput](../src/components/BrowserAddressBar.vue:81)会取消 dismissed，配合空查询历史造成聚焦弹出。实施需管理本次编辑意图，不只改一个显示样式。

## 2. U02：地址建议图标对齐

截图显示通用地球图形有偏斜／位置不稳的观感，根因不能仅凭截图确定。核对[原生候选行](../shared/browser-native-panels.ts:83)、共享图标资产和[原生图标栅格化](../src/composables/useNativeUi.ts:29)。

- 图标采用一致尺寸和留白，与标题／网址在整行内垂直居中；核对视觉中心与几何中心，避免“框居中、图形偏移”。
- 检查 SVG viewBox、path、自身倾斜设计、缩放比例、透明边距及原生 icon 控件布局，不用盲目反向旋转修补。
- 搜索／历史／页面的图标语义保持清楚；没有可靠站点图标时使用端正的通用图形，不为显示建议额外发网络请求。
- 检查 100%／125%／150%／175%／200% DPI、界面缩放、浅深主题及长标题。使用真正原生面板截图核对，而不是只看 DOM 资产。

## 3. U03：逐条删除历史建议

- 只对真正的历史结果提供独立紧凑删除按钮，预留右侧空间；普通时弱化，悬停／焦点时增强，不能挤到网址或滚动槽上。
- 删除点击与整行打开分别路由。搜索意图、直接访问、快捷链接或已打开标签不伪装成可删历史；删除不关闭网页、不清 Cookie 或全部历史。
- 复用现有[clearHistory(chatId, url)](../electron/modules/browser-start-store.ts:56)和[来源校验 IPC](../electron/modules/browser-workspace-ipc.ts:227)，行内操作必须提供目标 URL。保留当前实际对话归属，公共会话改造不顺带扩大历史删除权限。
- 动作绑定对话、页面、查询代次和记录身份；删除后刷新候选，保留有效选中项或选择邻近项，无结果则收起。保留地址草稿、选区及输入法。
- 删除期间防重复；持久化失败保留／恢复原记录并提示重试。旧行迟到动作不得删除新查询中的其他结果。
- 普通 Backspace／Delete 继续编辑文字。可评估“已选历史行且非组合态下 Shift+Delete”的明确快捷动作，键盘操作与点击共用删除语义。

验收包括删首／中／末行、重复 URL 不同来源、查询快速变化、双击、失败恢复、切聊天和组合输入；删除过程不得提交导航或生成背景截图。

## 4. U04：Agent 主图标与状态效果

已证实的样式冲突：[Agent 角标规则](../src/components/BrowserAgentControl.vue:70)设为 11px，而[地址栏父级规则](../src/components/BrowserAddressBar.vue:148)匹配按钮内全部 `.app-icon`，将角标一起放大为 18px，挤在 28px 按钮中遮住机器人。

- 机器人本体与角标使用明确的独立类和尺寸，父级尺寸规则只影响本体；不靠整体缩小把所有状态变得难认。
- 忙碌环、暂停、警告和工作提示设清楚的互斥／优先级，保留一个主要状态反馈，避免多个转圈／圆点堆叠。
- 动效不裁切、不遮住机器人、不改变点击区域；警告与暂停可静态辨认，不只靠颜色。减少动态效果时使用静态状态指示。
- 主窗口、展开工作区、独立窗口及不同 DPI／主题一起检查；真实 DOM 计算尺寸和截图都需核对。

此项是外观问题，不代替下一节的真实状态修复。

## 5. F01：持续“正在交还控制权”

用户反馈持续显示交还，并见输入保护／光标未启用。**是否真的卡在原生释放，尚需复现定位，不能只凭这几行状态确定。**

当前可证实机制：

- [状态映射](../shared/browser-agent-control.ts:9)把 renderer pending、handoff 等统一称为“正在交还控制权”；允许 AI、重试、重新加载也可能进入同一文案。
- [命令 pending](../src/components/BrowserTabPanel.vue:527)要等待完整命令 Promise 结束。后端[drain](../electron/modules/browser-automation-controller.ts:238)、[已提交输入与清理](../electron/modules/browser-automation-controller.ts:393)、[handoff](../electron/modules/browser-automation-controller.ts:440)各有等待，UI 缺少阶段／持续时间。
- 空闲或仅允许后续 AI 操作时，保护和光标未启用可以是正常状态；面板显示的也是传入状态，没有另一套独立原生确认源。

实施要求：

1. 区分“允许 AI”“请求交还”“等待任务结束”“等待已提交输入”“等待清理”“等待原生确认”，使用实际动作与阶段文案。
2. 按页面和请求代次记录开始时间、等待阶段、在途数量、原生确认／错误码；不记录用户正文、键入内容或凭据。
3. 复现新空白页、暂停／恢复、导航、脚本、已提交点击、失败清理与原生释放不返回，定位哪一层未收敛。前端迟到回包、切页或组件停用后也不能保留错误 pending。
4. 给超时以明确错误／待确认状态和安全恢复入口，保留诊断原因；**不能定时假报交还成功、隐藏状态或在不可取消输入尚在执行时放开保护**。
5. 重试仅处理当前有效请求与原生确认，不重放旧输入，不让旧交还覆盖新租约。已有等待顺序和来源校验继续保留。

验收需同时观察面板、主进程控制者、已提交输入及原生确认，覆盖永不返回、延迟成功、失败、重复点击、切页／移窗与晚到回包。若最终证实内核确认链缺能力，再列最小原生修复；不能把全部异常归因于 NativePanel 绘制。

后续已只读检查安装版首项聊天，确证另有 F02 整段文本被送入单个字符事件，并发现 F03 六次工具后的查询型提示与提前收尾吻合；详见[首项自动化失败诊断](./installed-automation-first-chat-diagnosis-2026-11-04.md)。该记录没有完整交还阶段，尚不能据此把 F01 归结为同一故障。

## 6. U05：菜单默认向窗口内部展开

浏览器更多当前请求 `bottom-end`，但[主进程菜单桥](../electron/modules/native-ui.ts:88)只使用 top／bottom 选择纵向位置，x 仍取按钮左缘，`-end` 实际被忽略；没有父窗口边界策略。`.7` 底层菜单使用左上锚点，因而显示器有空间时会向窗口外展开。

- 先补齐应用的 start／end 语义。右侧更多按钮优先从右边缘向左展开；空间不足时在所属窗口内容区自适应调整位置与尺寸，保持默认对齐意图，再处理显示器工作区。用户已明确纠正：不以方向翻转作为方案。
- 主／独立窗口使用同一定位策略；窗口过窄时采用真实可用宽度／高度和必要滚动，不仅依赖显示器边缘约束。
- 使用真实菜单宽度／原生定位契约，核对外壳、边距和控件宽度；当前应用按菜单字体、图标、控制行、padding 与最小尺寸估计占位，再在窗口内平移约束；极端长标签／超小窗口仍由原生屏幕边界兜底，不新增 HTML 或截图承载。
- **坐标系分开处理**：`.7` Menu.popup x／y 是窗口内容区相对 DIP，底层再加内容区屏幕原点；NativePanel anchor 是屏幕 DIP。不能给 Menu 再加一次窗口原点，也不能重复乘设备像素比。应用 zoom 只转换一次。
- 位置绑定真实所属窗口和当前请求；窗口移动／尺寸／缩放变化、关闭或菜单失效后按既定关闭／重开策略处理，不把旧坐标用于新窗口。

验收覆盖窗口四角、窄窗、最大化、负坐标副屏、混合 DPI、界面缩放及子菜单；同时核对菜单是否留在父窗口内、点击命中、键盘／关闭焦点、控制权和网页实时显示。只证明“没超出显示器”不算完成。

## 7. U06：菜单首项名称

将“新标签页首页”统一改为 **“返回主页”**。含义为在当前标签页打开浏览器主页，动作仍沿原 `home` 路由；新建按钮继续执行真实的新建标签动作。原生和兼容菜单共用文案及说明，不再让用户从“新标签页首页”猜测含义。
