# Navora Desktop 整体重构规划

更新日期：2026-10-30。执行范围为本仓库 `navora-desktop`。关联 SDK、官方插件和定制 Electron 的变更只有在兼容性或内核能力确实需要时单独推进。

## 1. 产品目标和约束

把 Navora 完成为以浏览器为执行环境的桌面 Agent Harness：能可靠访问页面、准确理解内容、定位和操作控件，维护任务状态，并通过插件扩展专业能力。外部模型负责推理，宿主负责状态、执行、权限和证据。

用户已授权全面重构，包括提示词、执行循环、浏览器工具、索引、工程结构和界面。必须保留现有插件能力；现有配置、会话、工作区和安装的插件应有兼容读取或明确迁移。界面沿用 `postpile-private` 新 UI 的风格与动效，功能布局围绕 Navora 自身任务组织。

执行顺序：完成规划；提交并推送当前可验证源码；再按阶段实施。每个阶段独立验证和提交，不把尚未验证的整仓重写作为交付。临时探针、浏览器运行数据、密钥和生成产物留在本地。

## 2. 已确认的现状

- 主进程集中持有 Agent、浏览器、文件、权限和插件状态；Vue 渲染进程经 preload 或远程 RPC 调用。
- `electron/main.ts` 同时承担服务装配、IPC、配置更新和生命周期；`browser-tools.ts` 集中了工具参数、等待、读取与操作；`agent-runtime.ts` 集中了模型、历史、重试和子任务。
- 本轮初查发现 35 处类型检查错误。已修复，当前 `npm run build` 会依次执行类型检查、测试、前端和主进程构建。
- 工作区目录链接越界、同名输入输出合并丢失数据和默认远程密码问题均已本地复现并修复；补入回归。当前测试运行器报告 13 项通过，其中既有测试文件内部还包含多条断言。
- 目前 `dom_summary` 采集链接和输入控件，但模型结果压缩会将结构摘要转成仅含标题的文本。这会丢失下一步行动所需的链接和定位信息，列为优先修复项。
- 当前安装的定制 Electron 类型中已声明 `querySelectorDeep`、`getNodeBoxModel`、`clickSelector`、`dispatchMouseEvent`、`setFileInputFiles`、`loadURLWithResponse`、会话请求头顺序和 UA metadata 等能力；运行可用性需要逐项探测。
- 当前已检查的声明未提供完整 DOM/AX 快照导出接口。不能将单节点深查询视为整页闭合 Shadow DOM 索引能力。第一阶段提供明确降级；后续内核快照接口需实际实现与验证。
- Postpile 已有独立 `@postpile/ui` 0.1.2，包含玻璃材质、按钮状态、菜单与弹窗变形、Vue 适配及减少动态效果支持。已在本仓库准备离线包，尚未接入界面。

## 3. 目标架构

调用链收敛为：界面与远程端 → 应用服务 → Agent Run → 工具路由 → 浏览器或工作区适配器。权限检查、取消信号、执行记录贯穿调用链；插件使用相同的工具路由与权限边界。

### 浏览器运行层

- 能力探测统一在一个适配层内进行，记录内核版本、可用方法、失败原因及降级路径。
- 会话负责分区、登录态、代理、UA 与 Client Hints 一致性、语言、请求头、下载和网络观察。
- 页面负责导航生命周期、文档身份、frame 身份、观察、定位、可信输入和操作后验证。
- 支持的方法优先调用定制 Electron 原生接口。页面脚本读取留在隔离世界；常规操作不默认附加 debugger。
- 对不可用的内核能力返回结构化错误，不静默声称成功。导航超时、页面渲染失败、登录要求、站点挑战和网络失败分别记录。
- 访问兼容性以固定环境中的实际结果验收，不承诺所有站点均可访问。需要交互的验证与登录保留可继续的用户接管入口。

### 页面观察和索引

- 统一页面快照：文档身份、URL、标题、主体片段、标题层级、可交互元素、链接、frames、截断与能力限制。
- 元素提供 role、可访问名称、ref、定位方式、状态和必要几何信息；不读取密码或隐藏字段值作为上下文。
- ref 绑定文档和元素身份，导航、移除或目标语义变化后显式失效；不依赖向页面 DOM 注入识别属性。
- 缓存按页面身份和变化版本失效；同一快照搜索复用索引，不反复整页扫描。限制节点数、文本长度、输出预算和缓存数量。
- 先提供确定性的中英文词法检索与字段权重，再根据真实任务评估是否需要向量检索。优先解决可见性、重复文本、语义名称和定位正确性。
- 模型端使用摘要、搜索命中和按需展开；保留可执行链接、ref 和表单信息。普通压缩不退化成只有标题的摘要。
- 记录采集耗时、缓存命中、节点数、返回字符数、截断原因及目标命中率，区分采集与模型耗时。

### Agent 执行和上下文

- 将执行循环分成运行状态、模型适配、工具调度、上下文装配、恢复与事件输出。
- 明确 idle、running、waiting_user、waiting_permission、stopping、completed、failed 状态及合法转移。
- 将工具结果区分为成功、部分成功、可重试失败、需用户输入和终止。超时不自动等于业务失败，工具返回也不自动等于目标完成。
- 收敛上下文为任务、近期步骤、当前浏览器状态、检索证据、权限和插件能力。长结果保存后按需检索，避免历史中重复塞入整页正文。
- 重试依据错误类别和已发生的副作用，避免重复点击、重复下载或重复提交；取消向模型请求、工具、子任务和浏览器等待传播。
- 提示词拆为稳定原则、工具使用策略、运行状态、用户偏好和插件说明。用任务回归验证行为，不继续堆叠具体站点和关键词规则。

### 插件兼容边界

- 保留 `plugin.json`、CJS 加载、安装/外链/会话作用域、启停、套件和商店入口。
- 保留工具 schema、`planPermissions`、`execute`、Host API、`api.registry`、`api.runTool` 和现有 `api.ctx` 兼容入口。
- 新浏览器适配器放在 Host API 之后，旧工具名和参数保留兼容路由。新增字段采用可选字段，不能让插件必须重新编译才能运行。
- 插件工具继续加入模型工具列表；任务级筛选不能把已启用插件静默隐藏。
- 建立固定样例插件，验证发现、加载、权限计划、核心工具调用、取消、异常、禁用和重新加载。官方插件的联网效果与宿主契约测试分别验收。

## 4. Postpile UI 风格与动效接入

以 `D:/electron/postpile-private/ui/` 为风格参考和组件来源，不修改该仓库。将版本化组件包保存在本仓库，通过本地依赖安装，避免运行和打包依赖另一台机器上的绝对路径。

- 接入统一色彩、字体、间距、圆角、表面材质和焦点样式，逐步替换页面中互相冲突的硬编码值。
- 复用按钮加载与状态交接、菜单从触发器展开、弹窗展开与收回；保留 Vuetify 的表单模型、焦点、滚动锁和业务事件。
- 为动画封装 Vue 生命周期适配：快速开关可中断，卸载清理动画及占位，尊重 reduced-motion 和 reduced-transparency。
- 应用壳包含会话导航、聊天主区、浏览器与工作区资源、运行状态和设置。窄屏使用抽屉，不把所有桌面列压进手机视口。
- 聊天呈现任务进度、工具结果、权限和用户决策；插件保留独立管理入口和运行可见性。
- 提供隔离演示数据进行 UI 验收，不在真实会话和密钥上做截图测试。覆盖空态、长对话、运行、失败、用户决策、插件、设置和远程登录。

## 5. 分阶段交付

### P0 当前源码备份与工程基线

交付：本规划、现有未提交业务源码、类型修复、工作区/合并/远程回归、统一测试命令，以及 Postpile UI 离线资源包。检查暂存区文件与敏感内容后提交并推送现有 `origin/main`；不强推，不覆盖远端提交。

验收：完整构建通过；远端提交与本地备份提交一致；本地运行数据和探针未进入提交。

### P1 浏览器能力适配与页面索引首版

交付：原生能力探测、结构化快照、词法检索、文档级 ref、结果压缩修复；现有读取/搜索/交互工具逐步接入。

验收：普通 HTML、SPA 更新、重复按钮、隐藏字段、开放 Shadow DOM、frame、导航后旧 ref 均有回归；实际定制 Electron 验证原生点击、深查询、文件输入和对话框能力。闭合 Shadow DOM 与跨域 frame 的索引范围明确报告。

### P2 浏览器导航与操作闭环

交付：导航状态统一、等待策略收敛、目标校验、操作后观察、会话配置一致性、下载和网络错误分类。

验收：重定向、SPA 路由、延迟正文、弹窗、新窗口、失效元素、登录态保留、代理切换、文件上传和下载分别验证；取消能结束等待且不会误报完成。

### P3 Agent 运行时与提示词重构

交付：状态机、工具路由、模型适配、上下文预算、证据和重试拆分；重写基础提示词并保留设置开关。

验收：固定任务集验证直达查询、搜索、表单、下载、失败恢复、用户接管和插件调用；比较任务成功率、步骤数、输入上下文量和耗时。真实模型验证需要使用已配置模型并控制调用数量，不把单元测试通过等同于模型任务成功。

### P4 插件契约固定与扩展

交付：兼容样例、Host API 回归、旧工具适配、插件错误隔离和运行记录。与 P1 至 P3 同步补回归，进入下一阶段前完成整体契约检查。

验收：旧样例无需修改即可执行；未声明能力被拒绝；已启用插件可被模型发现；禁用、重载、取消和子会话作用域正确。

### P5 Postpile UI 组件和动效基础

交付：本地 UI 依赖、Vue 菜单与弹窗适配、材质和主题、按钮状态；先接入共享外壳与设置，不一次性替换业务控制器。

验收：桌面和窄屏截图；菜单/弹窗打开、关闭、快速中断、滚动、键盘和 reduced-motion 测试；无来源按钮残留隐藏或悬挂动画。

### P6 Navora 工作界面翻新

交付：聊天主界面、会话与资源导航、浏览器状态、插件管理、运行证据和用户决策，应用 P5 设计基础；缩减 `ChatPage.vue` 的职责。

验收：空态到完整任务可用；消息流、滚动跟随、输入草稿、重试、子会话、插件、文件及远程界面均回归。交互改善不能删除原有能力。

### P7 数据、远程和发布整理

交付：配置和会话迁移、可靠写盘、服务重启与远程鉴权回归、包资源和启动检查、用户与开发文档。

验收：旧数据副本可升级，失败保留原数据；全新数据可启动；便携与安装路径正确；安装包使用隔离数据目录启动通过。发布或覆盖用户安装目录前另行确认目标。

## 6. 验收和性能测量

每次修改跑对应单元或集成检查；阶段交付运行完整类型检查、测试和构建。浏览器功能使用实际定制 Electron，不用普通浏览器的结果代替。截图检查覆盖 1440×900 和 390×844，并记录系统主题和减少动态效果状态。

性能先建立固定页面夹具基线，再比较同环境的新旧实现。至少记录首次采集和重复查询的 p50/p95、索引规模、返回字符数、缓存命中、选中元素正确性和端到端步骤数。优化目标是降低重复读取、上下文和错误定位；不能通过漏掉目标内容获得更短结果。数值目标在基线测量后确定。

站点兼容矩阵覆盖静态内容、SPA、电商、登录、挑战页和下载。记录页面是否可达、正文是否可读、是否能定位和操作、是否需要用户接管、内核版本及复测条件。站点变化单独归因，不把一时可访问写成永久保证。

## 7. 提交与迁移策略

先推送 P0 保存当前源码，再按能力适配、索引、运行时、插件、UI、发布拆成可回退提交。保持 `main` 可构建；任何远端分叉先获取并检查，不强制推送。

现有配置和工具调用采用兼容适配逐步迁移；新结构与旧入口并存期间明确唯一状态源。插件加载、权限门闸和数据目录切换前先有回归。生成产物、临时目录与真实登录数据不用于恢复源码。

## 8. 参考实现及取舍

[Playwright MCP](https://github.com/microsoft/playwright-mcp) 提供结构化页面观察与可引用元素，适合参考工具结果和定位契约；Navora 保留自身 Electron 宿主、会话与插件，不引入一套并行的浏览器所有权。

[browser-use DOM snapshot processing](https://github.com/browser-use/browser-use/blob/main/browser_use/dom/enhanced_snapshot.py) 提供 DOM 快照的可见性与交互信息处理，可参考数据建模和裁剪。其 CDP 实现不是 Navora 定制 Electron 原生能力已经存在的证据。

Postpile 的 `ui/README.md`、`ui/docs/motion.md`、`ui/docs/menus.md`、`ui/docs/dialogs.md` 为本地风格和交互参考。优先复用版本化公共组件，产品样式通过 Navora 适配层维护。
