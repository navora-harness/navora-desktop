# 首次光标位置与交还补全（2026-11-06）

状态：源码、构建与当前 Windows 隔离窗口验收完成；整项仍为部分完成，长期交还原场景未核销。本轮未发布安装包或更新个人安装。此记录接续[输入控制权规划](./browser-input-ownership-and-cursor-plan-2026-11.md)第 12 节，覆盖其中“首次隐藏尚未实现”的旧状态。

## 实现

- 控制器独立保存显示偏好、原生启用、位置有效代次与实际画面可见性。取得任务租约、纯导航／读取及键盘输入不显示默认零点光标，输入隔离和渲染保护仍完整启用。
- 只有成功派发的原生鼠标回执才能打开绘制。接入轨迹批次、主文档／iframe 目标点击、选择器点击、低层鼠标和滚轮；未派发终点、DOM 边界、触摸和键盘回执不充当鼠标位置证据。frame 使用原生自身已派发后的坐标转换，不把 frame 内偏移当主视口坐标。
- 导航（包括子 frame／页内）、几何失效、人工接管及原生 reset 清除位置资格。异步图像、原生启用屏障与迟到回执均再次核对失效状态；reset 同时清除轨迹缓存，新任务不借用旧任务起点。失效隐藏不解除任务保护。
- `cursorVisible` 不再复制 enabled：关闭时为 `false`，启用时实际画面可见性保持未知。面板显示“等待首次有效指针输入”或“已启用，显示待核验”。显示失败保留真实输入回执，不把已执行点击改成派发未知或触发重放。
- 修复交还并发路径：原生输入在途时，外部导航未结算不再阻止提前取消原生队列。仍等待回执、清理、导航及最终状态回读后才交还，不靠超时强行授予人工控制。

## 剩余边界

1. **首个闭合批次完整回执后显示。** 当前公开 API 未提供首个指针事件已派发的独立通知；不拆批、不增加伪动作、不调用内部诊断接口。首批较长拖动回执前保持隐藏，同代次后续轨迹正常可见。首批执行途中即时显示仍需内核提供有效位置绘制门槛及独立通知／状态。
2. **长期交还原现场未核销。** 已修复并验证“原生输入＋外部导航同时在途”路径，尚无证据证明它就是先前故障的唯一根因。需在原安装／原业务场景复现后，记录卡住阶段、取消、回执、导航与交还结果再关闭此项。
3. 单机强制缩放不等于不同物理显示器验收；空白测试页和同进程 iframe 不覆盖全部真实网站、OOPIF、跨显示器、宿主转移及平台矩阵。物理 OS 输入拦截也不由截图证明。
