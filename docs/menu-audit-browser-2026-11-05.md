以下第 1—6 节保留实施前的静态审计基线及验收要求；其中“缺失”“规划”等表述用于追溯原问题，当前完成状态以本段和实施记录为准。后续产品增强仍独立排期。

本文属于[全界面菜单审查](./已完成/menu-audit-and-followup-plan-2026-11-05.md)的浏览器专项。覆盖主工作区、展开工作区、独立浏览器窗口，以及浏览器资源、网页内容、地址、下载、Agent 控制和批注相关菜单。与[实时 View 清理](./已完成/browser-live-view-overlay-cleanup-plan-2026-11-05.md)、[原网页右键规划](./browser-page-context-menu-plan-2026-11-04.md)衔接。

## 1. 已确认的结论

用户指定的“在外部浏览器中打开”确实缺失。当前主工作区和独立窗口标签右键、网页工具栏更多、浏览器资源页面菜单、实际网页右键，以及应用命令目录中，均没有此浏览器动作。已有“移至独立窗口”是在 Navora 内部移窗，不能代替外部打开。

已有基础能力可复用：`window.navora.app.openExternal` → preload 的 `navora:app.openExternal` → main 的 `openInSystemBrowser` → 系统 `shell.openExternal`。现有通用入口允许 HTTP、HTTPS 和 mailto；本次浏览器菜单只允许 **HTTP、HTTPS**，不能把其他协议跟随交给系统。

首批必需的是用户点名的单标签右键和网页更多，并将同一页面实体的资源菜单、应用命令一起对齐；网页内容右键的外部打开和忽略缓存重载可以随后接入，属于入口补齐，优先级低于前述指定要求。

另外发现三类需要分别处理的问题：

- **已确认缺少入口**：外部浏览器打开；部分已有浏览器能力没有在相关菜单中出现，例如忽略缓存重新加载。后者属于可用性补充，不等于现有刷新功能失效。
- **已确认的呈现／策略不一致**：不同位置复制网址的协议条件不同；独立窗口应用菜单和主工作区应用菜单暴露的刷新／静音命令不一致；原生与兼容菜单的缩放内容不同。
- **待动态核实的静态风险**：部分菜单绑定了页签 ID，但没有像网页原生更多菜单一样完整绑定实际 URL、文档代次和宿主；导航后执行旧菜单可能使用更新后的 URL 或旧快照。不能把这一风险写成已复现故障。

保存图片、链接另开新窗口、直接为右键位置加批注等属于产品增强或既有未完成规划，不能全部作为缺陷要求一次塞入菜单。

## 2. 菜单逐项清单

### B01 主工作区与独立窗口：单标签右键

入口：主工作区 `FileWorkspace.vue`、独立窗口 `BrowserHostPage.vue`，共用 `useBrowserTabController.ts`、`useBrowserTabActions.ts` 和 `BrowserTabContextMenu.vue`。原生 Menu 为默认路径，`SidebarContextMenu.vue` 提供 DOM 兼容路径。

现有条目：在右侧新建、重新打开关闭的标签、重新加载、复制标签、固定／取消固定、静音／取消静音、复制网址、移动子菜单、选择本窗口全部浏览器标签、关闭，以及关闭左侧／右侧／其他浏览器标签。移动包括最前／最后、新窗口、兼容现有窗口；独立窗口额外有移回工作区。固定页不参与左右／其他的批量关闭候选；手动关闭固定页仍是明确动作。

实施规划：

- 单个有效 HTTP／HTTPS 页面增加“在外部浏览器中打开”，与“复制网址”相邻。主工作区、展开工作区、独立窗口保持一致。
- 通过统一动作读取目标真实 URL，不能复用当前输入框文字，也不能只依据 `desiredUrl || url` 启用后直接打开该字符串。
- “忽略缓存重新加载”放刷新次级组，复用已有命令，不再建立另一套刷新服务。不是首批阻断项。
- 继续保留移动、固定、多选、beforeunload 和忙碌规则，不为菜单增加的 URL 动作隐式接管网页。
- 不为外部打开新增全局快捷键；使用 Tab 聚焦后菜单键／Shift+F10、方向键和 Enter 即可完整操作。

### B02 标签栏空白区右键

现有条目：新建标签、重新打开关闭的标签、选择本窗口全部浏览器标签；没有页面上下文，因此不应出现复制当前网址或外部打开。

规划：保持精简。空白区右键不能偷用当前活动标签充当目标；列表为空时全选禁用，恢复项按所属对话的关闭历史启用。保留鼠标空白区与键盘标签菜单之间明确的目标区别。

### B03 多选浏览器标签右键

现有条目按所选数更名，支持刷新、复制、固定、静音、复制多个网址、同对话移动与批量关闭。混合对话选择禁止合并／移窗，其他适用动作按真实所有者分组；文件和问卷不进入浏览器批处理。

规划：首批外部打开限定单标签；多选时不直接给一个含糊的“在外部浏览器中打开”，避免一次打开未知数量的系统页签。未来确需批量时再提供明确的“在外部浏览器中打开所选 N 个网页”，显示符合条件的数量、保持原顺序，并报告部分失败。该批量项属于增强建议，不是用户此次示例的必需条件。

菜单打开后改变多选、移窗、关闭其中一页，应关闭旧菜单或拒绝旧动作，不能转向当前活动页。当前 IDs 保留与 URL／文档快照保留分开验收。

### B04 网页工具栏“更多”

入口：`BrowserTabPanel.vue`。现有条目：返回主页、网页尺寸与缩放、前进、在网页中查找、Agent 控制、下载列表、浏览器设置、移至独立窗口／移回主工作区，以及内嵌时展开／收起工作区。默认原生菜单另有缩放减／加／重置控制；兼容路径在显示设置行中选择缩放。

实施规划：

- 增加“复制网址”和“在外部浏览器中打开”，组成精简页面地址组，使用与标签右键相同的显示、禁用原因及执行器。
- 不重复堆入标签栏已有的全部批量管理项；工具栏已有返回、刷新、停止按钮也不要求全部重复。
- 沿原生更多已具有的页 ID、host ID、实际 URL、文档代次、导航请求代次校验，扩展新动作即可。
- DOM 兼容菜单也需获得相同页面上下文检查，不能只检查菜单文字是否变化。原生运行环境临时打开失败时保持实时 View，明确提示重试，不退回截图覆盖。
- 原生的 25%—300% 连续阶梯与兼容显示设置当前的 75%／100%／125%／150%／200%预设是已确认能力差异；改为共用缩放步长、范围和禁用条件，保留各自适合的控件形式。

### B05 浏览器资源：页面行右键与省略号

入口：`sidebar/BrowserResourcesPanel.vue` 与 `BrowserResourceActions.vue`。右键和省略号共用同一个页面菜单。现有条目：引用到输入框、打开页面／远程查看、复制网址、关闭页面。资源树支持 Shift+F10；鼠标与键盘菜单都保存被触发的页面。

实施规划：

- 有有效 HTTP／HTTPS 地址时增加“在外部浏览器中打开”。这是同一个页面实体的另一入口，应与标签和更多同步补齐。
- 复制网址按统一页面地址规则启用。现有资源菜单只判断字符串非空，能复制 `about:blank`；标签右键则只复制 HTTP／HTTPS，需统一为网站地址并提供空白页原因。
- 刷新、复制标签、静音等若确有资源管理需求，可放第二批；不把整套标签菜单照搬到树行。
- 当前 `menuWindow`／`menuSession` 保存对象，操作前补以 ID 重新查询并验证归属；树更新、切对话、页关闭和移窗后不得使用旧对象 URL。
- 远程查看与“外部打开”必须分清发生在哪一端：当前通用远程 shim 会调用宿主 RPC，不能把它误称为“在我的浏览器打开”。首批远程端隐藏此动作；以后另定义客户端打开可信 HTTP／HTTPS 链接，不能意外在远程宿主打开系统浏览器。

### B06 浏览器资源：会话行右键与省略号

现有条目：有页面时打开页面、引用到输入框、在此会话新建页面、独立会话重命名、关闭页面、清除网站数据、独立会话删除会话及数据。公共默认会话不允许重命名和删除；其关闭页面只处理当前对话，清除共享网站数据则明确影响所有对话。

规划：该层级代表网站数据会话，并不是一个 URL；**不增加“在外部浏览器打开整个会话”**。会话清除／删除确认继续显示真实影响范围，保留无网站数据时禁用清除、操作中的繁忙状态及部分页面取消关闭反馈。公共会话批量关闭应锁定菜单开始时的对话；当前确认流程已有切换保护，后续共用上下文机制时保留它。

### B07 真实网页空白区右键

入口：主进程 `browser-page-context-menu.ts` 的真实 guest `context-menu`，工作区与独立窗口共用；不是宿主 HTML 右键菜单。

现有条目：返回、前进、重新加载／停止加载，复制当前网址，在此网页中查找，进入批注模式、查看页面批注，检查元素、打开开发者工具。导航、关闭、隐藏、移窗、渲染崩溃、控制代次变化会使旧菜单失效；坐标动作另验证命中节点、滚动、viewport 和缩放。Agent 输入保护期间页面可能不产生右键事件；菜单不能为显示而自动解除保护。

实施规划：

- 地址组增加“在外部浏览器中打开”，复用宿主侧动作，不向网页暴露通用应用 IPC。
- “复制当前网址”使用共享 HTTP／HTTPS 可复制规则；不要无条件复制 Chromium 内部地址。
- 增加“忽略缓存重新加载”次级项，沿统一导航协调和控制权规则。
- 保留目前安全的“进入批注模式…”标签。等可信目标服务接通后再升级为直接位置批注，不能现在将现有动作改名为“在此处添加批注”冒充已定位。
- 不要求为该菜单另建 DOM 降级或 guest renderer；原生菜单不能开时清楚反馈，保持实时页面。

### B08 链接、图片、选区、网页输入框右键

这些是 B07 的上下文扩展，不是互斥的独立菜单；图片同时在链接内时应组合、分组并去重。

- 链接现有：新标签打开、复制链接地址。规划在 HTTP／HTTPS 链接上增加“在外部浏览器中打开链接”，使用该链接本身的快照，不打开当前页面地址；新窗口打开作为后续建议。javascript、data、file、内部地址不进入通用系统打开。
- 图片现有：复制图片、复制图片地址、新标签打开图片。HTTP／HTTPS 图片地址可后续增加外部打开；“保存图片”必须先接已有下载及文件权限服务，再呈现菜单项。blob、data、canvas 与跨域图分别做能力评估，不能把不支持的地址直接发给系统。
- 文本现有：复制与搜索所选文字；当前搜索固定拼为 Bing 地址。后续如设置中提供搜索引擎选项，需要改为统一搜索构造器，而不是只更改菜单名称。密码输入不提供选区派生复制／搜索。
- 输入框现有：撤销、重做、剪切、复制、粘贴、粘贴为纯文本、删除、全选，按 editFlags／密码／可编辑状态启用。跨 frame 无法安全保留编辑目标时禁用，显示原因；不能为了补菜单读取表单 value 或改用顶层焦点执行。
- 批注增强：在可信顶层选区／点位置直接建立草稿；跨域 frame、页面变化和不可确认的坐标退回明确的重新选择。需与既有批注 V2 目标规划联合实施，不是本轮已经可用。

### B09 地址栏、建议、站点信息与新标签页历史

入口：`BrowserAddressBar.vue`、`BrowserStartPage.vue`、`browser-native-panels.ts`；地址输入的剪切复制粘贴属于通用文本右键审查。

现有行为：输入／粘贴后访问或搜索、建议行打开、逐条历史删除、Shift+Delete 删除所选历史、Enter 执行、Escape 收起；站点信息有原生页面信息，兼容面板只报告能够确认的连接信息。新标签最近访问可打开、逐条删除、清空和显示更多。

规划：地址输入“粘贴并转到／粘贴并搜索”可以作为第二批体验增强，需真正保留焦点与输入来源后再实现；不能把剪贴板动作当成当前页外部打开。历史行的“复制网址／外部打开／在新标签打开”是后续建议，可复用 URL 实体动作；对历史不使用 live pageId，执行其固定历史记录 URL。删除历史仍不清空输入草稿，仍以 chatId、URL 和 visitedAt 验证所删记录。全量清空的确认策略与其余资源破坏性动作统一。

### B10 下载列表与每项更多

入口：`BrowserDownloadsMenu.vue`、`browserDownloadsNativePanel`。默认原生列表将常用操作做成行内按钮；兼容 DOM 列表将“在文件夹中显示／从列表移除”收进每项更多，菜单形式不同但动作大体对应。

现有条目：下载中可按能力暂停、恢复、取消；已完成可打开文件、在文件夹中显示；浏览器下载可取消并移除／结束后只移除记录；工具下载中提供“停止此下载所在的任务”；全局清除已结束记录。原生列表可翻页，动作携带下载 ID 和 chatId，执行前再次确认条目仍在当前范围。

规划：

- 现有下载动作无本轮必补缺项；保持记录移除与删除实体文件的区别，工具任务停止也不得伪装为只取消单个文件。
- 复制下载来源网址、复制本地路径、失败后重试属于后续增强。当前没有独立通用 retry 下载接口，不能先放无效“重试”菜单；重试应明确新下载、权限和目标文件冲突。
- 原生与 DOM 共用状态动作模型，统一禁用原因、移除文案和失败反馈；已删除／已变更状态的下载不得执行旧菜单动作。
- 鼠标、键盘完整操作不依赖只在 hover 时出现的省略号。切对话、面板不活跃、页移窗时继续收起旧下载菜单。

### B11 Agent 控制面板、批注列表与选项

Agent 控制入口支持点击切换、右键、向下键、菜单键／Shift+F10 和触摸长按。现有按状态提供“我来操作／允许 AI 操作”、暂停、本页恢复操作／重新加载、自动化设置，以及输入保护和光标状态。原生／DOM 使用同一 `browserAgentControl` 模型，页面切换后收起旧面板。

规划：没有证据表明该面板缺少“停止整个 Agent 任务”是 Bug；整任务停止与本页暂停分别存在业务边界，不在本页控制菜单里混同。“需要人工完成验证”等阻断状态应来自待实施的真实阻断识别，再提供接管、完成后重新观察等入口，不通过文本装饰假装阻断已被模型收到。外部打开网页不自动转移 Agent 控制或重放任务。

批注原生列表现有搜索、页面／对话范围、状态／时间排序；详情可编辑、定位、加入对话、检查位置、查看证据、已解决／重新打开、冲突副本恢复和二次确认移除。保留草稿、冲突、跨页不可定位等状态规则；没有证据要求再为每一条增加一套右键菜单。新增菜单入口须复用这些动作，不创建不同的保存／删除逻辑。

### B12 应用主菜单中的浏览器命令

命令定义在 `shared/app-commands.ts`。文件菜单已有新建／重开浏览器标签、关闭当前内容；独立浏览器有移回工作区；视图菜单仅独立浏览器模式暴露重新加载、忽略缓存重载、静音、置顶窗口。主工作区虽支持浏览器刷新等快捷键，应用菜单定义的 modes 尚未暴露这些网页动作。

规划：加入上下文命令 `browser.openExternal`，活动内容是有效网页时可用，主工作区和独立窗口共用；文件预览仍保留自身“使用默认应用打开”，二者按实体区分。刷新、忽略缓存刷新和静音按活动内容统一可见／可用，避免独立窗口和主工作区有同一快捷键却找不到对应菜单项。没有必要增加“浏览器”顶级菜单或重复已有菜单层级。

## 3. 统一动作与 URL 规则

### 3.1 菜单声明和执行分开共用

新增共享页面动作模型，包含动作 ID、简短名称、图标、可见性、启用条件、原因及破坏性级别。所有入口使用同一模型，不靠从 DOM 标签文字猜业务。菜单可按场景选择动作子集；“统一”指目标与规则一致，不要求菜单内容完全相同。

增加浏览器领域的外部打开调用，以页 ID／所属对话／宿主与菜单请求上下文解析地址；沿当前 workspace IPC 的应用宿主身份校验。主进程最终执行 HTTP／HTTPS 协议白名单和目标复核，并等待系统打开 Promise，向前端返回真实成功或失败。当前通用 `openInSystemBrowser` 只是调用后立即返回 true，不能据此宣称系统浏览器已经成功启动。

外部打开只传最终网址，不复制 Navora 的 Cookie、登录会话、缓存、Authorization 或页面内容；外部浏览器是否登录由其自身决定。带用户名密码的 URL 不应在系统启动参数中默默传播，须按统一地址策略拒绝或明确处理。站内 URL allowlist 的作用应在共用策略中明确，不能经菜单无意绕过已配置的访问限制。

### 3.2 当前地址与待访问地址必须区别

`desiredUrl` 表示用户打算访问的地址；记录中的 `url` 在加载失败处理时也会被赋为失败地址。因此不能把其中任一个字段一概视为“已经提交的真实文档地址”。正常页面以主进程真实页面状态和 `webContents.getURL()` 为基础，并保存文档代次；地址草稿与建议候选不能用于“打开当前网页”。

建议首版规则：

- 正常已提交 HTTP／HTTPS 页：显示并可执行外部打开，重定向后用实际页面地址。
- 正在导航且尚未确认新文档：条目暂时禁用，原因“等待网址确认”，防止打开旧页或把未确认的输入草稿当页面。
- 主框架加载失败／错误页：这是转到外部浏览器重试的实际业务场景。首批以主进程记录且经过 HTTP／HTTPS 校验的 `loadError.url` 提供“在外部浏览器中尝试打开此网址”，明确针对刚才失败的目标，并绑定该次失败／导航记录。没有可靠失败地址时禁用并说明原因。不拿 `desiredUrl`、地址草稿或旧文档的 `getURL()` 冒充失败目标，也不把它描述成当前已正常显示的网页。
- 页面崩溃：首批禁用当前网页外部打开，保留刷新恢复。以后若需“打开最后访问的网址”，也须作为明确的历史 URL 动作，而非声称当前页面仍有效。
- 空白首页、内部页、file、data、blob、javascript、mailto 等：不展示本浏览器外部打开动作；没有真实网址时复制网站地址也禁用。
- 网页上的链接／图片和历史记录是另一类固定 URL 实体，使用明确命中地址，不伪装为当前文档。若选中文字搜索，只有用户点选搜索后才构造目标。

上述规则要做成共享可测试的解析策略，再映射到各菜单，防止“只加按钮、每处自行猜 URL”。

### 3.3 保留菜单打开时的目标

页面菜单快照至少包含动作来源、chatId、pageId、hostId、文档代次、URL 状态、菜单请求代次及所选 IDs。URL 相关动作在选择后、异步等待后及系统打开前复核；任何一步无法确认都取消并提示重新打开菜单。链接、图片的快照另包含原 frame／上下文来源；坐标动作继续使用已有命中验证。

打开、移动、关闭和启用规则分开：打开菜单、复制网址或外部打开不需要改变 owner，不自动暂停、接管或释放输入保护。需要修改页面状态的刷新、编辑、批注仍遵守已有控制协调服务。

## 4. 分阶段实施

1. **统一基础与用户指定缺项**：定义当前页／失败目标 URL 和菜单上下文策略；实现可信页面外部打开服务与失败反馈；接主／独立窗口单标签右键、工具栏更多、资源页面菜单和应用命令。失败页使用明确命名的尝试打开动作。远程端保持明确限制；普通显式打开不另加确认阻拦。
2. **修正入口不一致**：统一复制网址、主／独立应用菜单、原生／DOM 缩放条件及旧菜单失效处理；网页右键复用外部打开服务，补有现成业务的忽略缓存重载入口。后两项为次一级菜单补充，按业务保留精简和分组。
3. **与实时 View 清理联合验收**：确保所有新增菜单走现有原生能力；受支持运行环境临时失败不触发截图替代；检查 DOM 兼容路径可操作性与旧回调隔离。不能只用截图证明页面仍然实时。
4. **后续产品增强单独排期**：保存图片、链接新窗口、历史行更多、下载重试、可信右键位置直接批注，以及将来确有需求的批量外部打开。只有服务和权限接通才展示条目。

## 5. 验收清单

- 同一 HTTP／HTTPS 页面在主工作区、展开工作区、独立窗口、资源行和网页右键都指向同一个真实地址；标签右键和更多菜单都具有用户要求的外部打开项。
- 重定向、正在输入地址但未提交、导航中、主框架失败、崩溃、about:blank、内部协议、大小写和非标准 URL 均符合统一规则。失败页不能误开先前文档或未提交目标。
- 菜单打开后切页、关闭、移动、切对话、改变多选、重定向或同页文档更新，迟到回调被取消；不会在当前活动页上执行旧目标动作。
- 外部浏览器打开 Promise 失败有清楚反馈；不会报假成功，不传 Cookie 或登录状态，不给 guest 增加宿主 IPC 权限。
- 普通／固定／多选／混合所属对话标签的现有关闭、复制、移动与恢复功能不退化；网页 beforeunload 取消后保留剩余页面并正确报告。
- 原生 Menu、原生 Panel 与兼容 DOM 路径有一致业务动作和条件；无失效按钮、无仅改文案未接通的能力。
- 鼠标右键、省略号、菜单键／Shift+F10、方向键、Enter、Escape、长按及焦点恢复行为正确；IME 输入中不截断组合文字。
- 网页空白、文本、普通／密码输入、contenteditable、链接、图片和复合命中、同／跨源 iframe 分别验收；不使用错误 frame 的焦点或坐标。
- 下载范围与条目状态变化、会话共享数据影响确认、Agent 控制权和批注草稿恢复保持既有业务边界。
- 真实 View 持续播放动画／视频，打开上述菜单不会调用截图替换、隐藏再重建页面或重放 Agent 操作；多 DPI、窗口缩放、独立窗口和快速开关菜单均验证。

上述为完整界面验收要求，不能将源码实现和定向单元测试等同于全部界面验收已通过；实际通过范围以实施记录为准。
