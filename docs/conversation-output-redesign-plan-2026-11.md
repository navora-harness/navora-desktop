# 对话输出区重设计：参考排版与交互样板

> 实施更新：用户已要求实现其余规划，正式源码与本轮验收以[实施记录](./remaining-plans-implementation-2026-11-03.md)为准；本文下方保留原规划基线及历史证据。

日期：2026-11-03。状态：新规划和离线样板，正式输出组件尚未替换。参考图的排版作为目标，正文重写为虚构的 Navora 界面检查任务；截图里的硬件、文件和命令不属于执行指令。

示例：[完整输出区样板](../../_planning/conversation-output-example.html)。相关：[子对话工作区](./subchat-workspace-plan-2026-11.md)、[统一规划](./interface-renovation-plan-2026-11.md)。

## 1. 视觉目标

按参考图呈现连续、扁平的任务过程：灰色工具活动、带万花筒图案的子任务名称、深色说明正文自然穿插。输出不再被一层“工具运行”大卡片包住，也不为每段助手文字重复头像、角色标题或“进展”标签。保留真实消息身份和用户/助手边界，不为了外观合并底层记录。

- 默认浅色示例为白色输出面，正文近黑、活动中灰。暖色和深色沿用应用主题变量；内容不能使用只适合白底的硬编码颜色。
- 使用系统中文 UI 字体，正文建议 16px、行高 1.75；活动行 14px、图形 16–18px。截图存在系统缩放，不把截图物理像素直接当逻辑字体尺寸。
- 正文建议最大宽度 960px，居中显示；左右至少 24px，窄屏降为 16px。段间约 20–24px、活动行间约 16px，活动与说明之间约 20px。最终数值通过同尺寸截图比较调整。
- 正文与活动名称起点一致，操作图标独占前导空间。多行活动说明按名称文字对齐，不缩进成树；长英文/路径断行，不撑宽工作区。
- 不绘制贯穿整段的时间线、彩色左边框或常驻状态大背景。仅展开的工具详情使用轻量边界与内缩。
- 活动项默认低干扰，hover/键盘焦点后显示浅背景或下划线；可点击项始终有正确鼠标语义与可访问名称，不能只靠悬停才发现它能操作。

## 2. 输出模型与顺序

将展示层归一为文本、工具活动、子对话活动、资源结果、询问/授权、错误与结束摘要。每项保留 chatId、messageId、runId、toolCallId 或 subchatId，不使用屏幕行号当身份。

现有 `ChatPage.vue` 的 messageBlocks 同时有 run 分组和独立 tool 分支，二者重复绘制子对话条。新方案先抽展示模型和共用活动行，再替换两个分支，不能仅改一种消息路径。

呈现顺序服从真实事件与消息顺序：

1. 助手说明保留在它产生的位置；流式更新只更新所属文本块。
2. 相邻、同一次运行、同类工具活动允许折叠成“编辑了 2 个文件”“运行了 3 条命令”。中间出现正文、确认、子任务或错误时立即结束该组，不能跨段搬动消息。
3. 一个子任务在多个时间点更新可以重复出现，稳定图案和 subchatId 相同；任务总数按 ID 去重。
4. 同一时刻多子任务完成可显示多个图案与名称，每个名称独立可点。窄屏允许换行，不把整行变成难辨的单一跳转目标。
5. 历史加载、增量事件及重连采用修订去重，列表不因更新用随机 key 重建，保留用户展开与阅读位置。

## 3. 各类输出的设计

### 正文

直接呈现 Markdown 段落、列表、标题、表格、代码、引用、链接及媒体；保留现有清理与安全链接处理。主文本无需包气泡。用户消息继续有清晰的说话人区分和独立操作，不把用户指令画成灰色工具状态。

结果说明优先说清已做事项、证据和未完成项。样例文案重新设计，不假称真实运行、保存、部署或验证通过。模型原始输出不得被 UI 改写成更强的成功声明。

### 工具活动

采用“操作图标 + 简短自然语言 + 按需展开箭头”：读取、编辑、命令、浏览、下载及插件各有既有共享图标。摘要基于真实工具名/结果，未知工具显示中性名称，不伪造友好但不准确的动作。

- 默认收起低价值重复日志；点击或 Enter/Space 展开实际参数摘要、状态、结果、错误与可复制输出。
- 显示命令时区分用户可复制的命令和日志文本；不点击活动行就自动执行。复制、查看文件和在工作区打开链接是明确的独立按钮。
- 成功时显示“运行了命令”；进行中显示“正在运行命令”；失败显示“命令未完成”及错误概述；停止显示“已停止”。未知/重连中显示“状态待确认”，不从超时猜测成功。
- 当前运行可用轻量静态/短周期状态指示；等待用户与等待页面分开，减少动态时保留静态图形与文字。
- 日志过长按需展开、截取展示并提供完整查看，不把完整大日志一次塞入主滚动区域。输出截断必须明确标注。

### 子对话活动

采用参考图的“稳定彩色万花筒 + 名称 + 状态”行；名称可点，状态和装饰图案不创建额外重复焦点。点击直接进入所属父工作区的对应详情；详情返回列表和定位父消息按[子对话规划](./subchat-workspace-plan-2026-11.md)执行。

名称使用子会话最新标题，任务原说明放 title/详情。已删除子对话保留历史文字和“记录已删除”，禁用跳转并解释原因。等待授权优先于“运行中”，失败、停止和已完成各自明确；不单凭 flower 颜色表示结果。

### 询问、权限、错误与资源

需要用户处理的内容使用可辨的紧凑交互块，不强行压成不可读的灰色一行；保留原请求身份、可选答案、范围和确认反馈。错误保留原因与可行的重试/定位入口；重试不重复提交已完成动作。

文件、网页、图片和下载结果保留来源身份与打开位置；查看资源不会自动附加到输入框。图片有尺寸占位和替代文本，加载后不突然把阅读位置推走。最终回复操作仅在该回复末尾统一出现，不在每条工具日志后重复“复制/重试”。

## 4. 详情、查找与阅读稳定

- 折叠状态按消息/活动组稳定身份保存；展开箭头设置 aria-expanded/aria-controls，详情标题与内容可被读屏理解。
- 查找覆盖可搜索正文、工具摘要和可按需加载的输出。命中折叠项先展开再定位；不能显示找到了却无法到达的命中。
- 展开、折叠、流式续写、图片加载与主题改变保持当前阅读锚点。只有本来就在底部的阅读状态才自动跟随；底部之外出现新内容时提供回到底部入口。
- 当前运行状态的变化只更新相关行，不反复插入“正在…”消息或切换标签。读屏反馈节流，不逐 token 播报。
- Hover 操作不覆盖正文选择；活动折叠与文本选区冲突时尊重选区。链接、复制和打开按钮不能形成嵌套 button。

## 5. 实现边界与组件建议

建议把展示模型整理为 `conversation-output` 纯逻辑，生成稳定的输出项、相邻工具组和真实状态；通过 `ConversationTranscript` 共享主/子消息渲染，配套 TextBlock、ActivityRow、ToolDetail、SubchatLink 与 ResultActions。不要把新输出 DOM 放进现有 run 大卡片后再靠多层 CSS 隐藏外框。

保留现有消息 ID 锚点、文件预览、媒体、来源、上下文菜单、选择复制和当前聊天查找接口。折叠工具的源消息 ID 仍能定位，避免新排版打断“从资源回消息”和查询结果跳转。

服务端记录和消息格式不因视觉调整就整批改写。首先适配旧记录，未知字段可回退为安全只读输出。工具结果、插件描述和文档正文都视作内容，不参与 UI 命令派发。

## 6. 分批交付与验收

1. 交付离线样板：参考排版、虚构正文、可展开工具、运行/失败/等待、同子多处链接、工作区详情、深浅主题与窄屏。
2. 建立真实展示模型，先用历史夹具验证顺序/去重/状态；保留旧呈现入口以对照。
3. 接主聊天和子详情的共用渲染，贯通查找、锚点、资源打开及阅读稳定。
4. 补性能和访问性回归，再移除重复 run/tool 模板及失效的全局活动样式。

验收覆盖至少：交错正文与工具不重排；并发子任务不串状态；重复子链接复用；失败/停止不被成功组吞并；权限提示可操作；历史记录缺字段；百万字符工具输出按需读取；长正文/中英混排/代码/表格/媒体；选择复制；查找展开定位；流式输出不抢阅读；深/暖/浅主题；减少动态；键盘和读屏；窄屏及125%–200%缩放。

离线样板通过不代表真实运行、持久化、权限或消息查询链路已通过；本次正式快捷键弹窗的实施与该输出区规划分别记录。
