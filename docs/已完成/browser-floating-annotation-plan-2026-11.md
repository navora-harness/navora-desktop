## 1. 用户目标与边界

结合三张参考及现有网页批注上下文，将本次“批准”按**网页批注 annotation**理解，不混入权限审批。开启批注后，可在网页任意位置点击添加意见，也可直接拖动选择区域；选中元素或区域有蓝色描边，旁边出现简洁评论条。真实浏览器 View 中使用专属批注光标，与 AI 自动化虚拟光标分开。

参考中的“按住空格临时操作网页”纳入待核验的目标交互，不直接照搬成已支持能力。截图中的麦克风、菜单文字、网页内容和快捷键都只是参考，不推断本轮需要接入语音，也不将网页文字当成任务指令。

批注只负责选择位置、保存意见、管理历史和加入对话。保存不自动请求模型，点击“加入对话”仍先进入输入区供用户编辑；权限审批、执行任务和批注保存不使用同一个按钮或状态。

## 2. 当前能力与源码依据

### 2.1 现有选择与截图是一次性流程

`electron/modules/browser-annotations.ts:10` 的 `selectionSource` 在 isolated world 1008 注入顶层网页选择层。它使用 closed ShadowRoot、最高层级覆盖和普通 `crosshair`，拦截 pointer/click 事件，先指定 element 或 region。元素模式随指针描边，区域模式从 pointerdown 到 pointerup 画矩形。

同文件 `:23-32` 在一次选取结束后移除覆盖层，并短暂阻止随后的 click，避免选按钮时触发网页按钮。`:85` 起的 collect 等待绘制后 capturePage，核对 documentId、URL、滚动、视口及元素文字／矩形，随后立即创建 revision 1、空评论的草稿记录。这个生命周期尚不包含连续点选和元素旁评论条。

`shared/browser-workspace.ts:52` 的 BrowserSelection 当前仅有 `element | region`、矩形、主文档 ID、URL、标题、可选 selector/text，以及 viewport 的宽高、滚动和 dpr。没有独立 point、frame 路径、visualViewport 或临时 target 身份。

### 2.2 现有主界面在底部抽屉编辑

`src/components/BrowserTabPanel.vue:48-71` 的批注抽屉提供元素／区域两个按钮、历史、意见文本、保存、加入对话和状态操作；`:317-338` 处理进入、取消及控制状态，`:350-367` 处理读取、保存、定位和加入对话。

已有历史搜索、状态筛选、排序和分批显示不应在改成悬浮编辑后删除。新悬浮条承担当前选区编辑，原抽屉可收敛为批注历史管理入口，不再强迫用户每选一次都到页面底部找输入框。

### 2.3 现有草稿、修订和证据可以复用

- `electron/modules/browser-annotations.ts` 的 update 以 revision 校验写入，评论最长 4000 字符；删除已移出列表的批注时，已加入对话的修订证据和对应图片仍保留。
- `electron/modules/browser-annotation-drafts.ts` 由主进程串行、原子写入草稿，包含 version、editorId、sequence、baseRevision/baseComment 以及冲突副本。
- `src/composables/annotationDrafts.ts` 保留每个编辑器 buffer，立即提交草稿，处理跨窗口同步和焦点中的冲突，不能为了浮动编辑重写成一份无版本文本。
- `electron/modules/browser-workspace-ipc.ts:182-212` 已有 begin/collect/cancel、list/update/remove、draft/recovery/resolve、locate/compare 和 present。present 创建特定修订的证据文件，并返回包含 annotationId、annotationRevision 的引用。
- 现有图片限制为单图最大 8MB、每对话批注图片总计 100MB、记录最多 200 条。新界面继续表达真实限制，不用连续点击静默生成大量空记录。

### 2.4 控制权与跨 frame 的现有边界

进入批注的 IPC 已通过 `automation.withTransfer` 等待输入操作收敛，选择服务记录之前的 manualControl，并在完成、取消或主文档导航时恢复。`browser-automation-controller.ts` 还维护真实 owner、run lease、epoch 和原生输入保护；单独恢复一个 manualControl 布尔值不足以描述新的长时间编辑／临时操作生命周期。

当前选择脚本在顶层执行，elementFromPoint 会走入可访问的 open ShadowRoot，但没有批注专用的 iframe/OOPIF 内部目标、frame 生命周期与坐标转换契约。点击 iframe 时可能只选到 iframe 容器，不能称为已经支持跨域内部元素。

目前没有 Space 临时透传、专属批注系统光标、统一点／拖识别或可信原生悬浮评论层的既有 API。现有脚本包含选取不触发网页点击、导航锁、人工控制恢复、草稿跨窗和修订冲突等检查（如 `scripts/ui-browser-workspace-entry.ts:379` 起），不代表这些新增能力已验收；本轮未运行该脚本。

## 3. 单一生命周期状态机

每个真实页面同一时刻只有一个批注会话，主进程为权威；前端、isolated world 选择层和原生叠层共享 sessionId、pageId、document epoch 与事件序号，不各自维护能互相矛盾的 selecting/manual/open 布尔组合。

建议状态依次包括：关闭 `off`、等待接管 `entering`、待选 `armed`、拖选 `dragging`、选区就绪 `target-ready`、编辑 `editing`、提交 `saving`、临时网页操作 `passthrough`、失效待处理 `stale`、结束／清理 `leaving`。失败附带可恢复原因，不把保存失败变成已经关闭。

主要约束：待选和拖选由实际 guest 选择层负责；编辑时同一会话只显示一个评论条；提交期间防重复；导航、关闭页面、崩溃、失焦、窗口移动或模态层都通过明确状态转换清理。页面隐藏和窗口销毁的幂等结束可以重复调用，但不能恢复过期控制权。

保存一条后回到 armed，继续添加；用户关闭批注模式才整体退出。保存不直接将任务 owner 交回 AI，否则下一次点击前会出现控制权空隙。查看已有记录和编辑已有评论使用同一套会话与修订规则。

## 4. 任意点击、元素与区域的识别

开启按钮进入统一模式，不再要求预先选“元素”或“区域”。悬停用轻蓝轮廓预览有效目标，不激活链接、按钮或输入控件。pointerdown 记录候选，pointerup 前超过约 6 CSS px 的明确距离则转区域拖选；不足阈值视为点击，不以高 DPI 物理像素直接比较。

点击优先选中合理可见元素。过滤批注自身 UI、隐藏节点、空矩形和无意义的巨大根节点；图像、链接、文本块和控件可作为元素证据，但不读取输入框的 value。点击空白且无合适元素时保存真正的 point 目标，不伪造成一个 CSS selector 或极小 region。

区域矩形支持各方向拖动，限制在当前可见页面边界内；过小区域保持点选或提示重新选择，不能产生零尺寸截图。拖选不自动滚动整页，后续若加入边缘自动滚动，必须与临时网页操作及截图坐标另行验收。

选中后保留蓝色细描边与轻填充，评论条靠近选区但不盖住主要目标。拖选取消、pointercancel、lostpointercapture、右键菜单和多指手势不能触发一次网页业务点击，也不能提交半成品目标。触摸没有悬停，使用按下预览与松开确认，滚动手势不同时创建批注。

新目标先进入临时 target，不在每次点击时立即写入一条空评论历史。当前评论未完成而用户选择另一位置时，先保留原临时草稿，再切换；界面提供返回该草稿的入口，不能静默覆盖输入或生成多个不可见空记录。

## 5. 目标、锚点与坐标契约

为新格式增加版本及明确的 `point | element | region` 区别，保留旧 element/region 的可读性。新目标建议携带：目标身份、批注会话身份、chat/page/session、顶层与目标 frame 的 document epoch、frame 路径、目标类型、选区矩形或点、选择时 URL／标题、可验证的元素描述，以及坐标空间声明。

页面 CSS 坐标、frame 局部视口、主页面 layout viewport、visualViewport、宿主 CSS 坐标和截图像素分开记录。转换需要使用实际页面 zoom、visualViewport 的 offset/scale、frame 矩形、宿主缩放及截图实测尺寸；不能简单把 clientX 乘 dpr 当成所有环境的截图位置。

point 记录页面文档位置与选择时上下文，不假装刷新后一定能定位同一语义对象；region 是选择时几何证据。element 使用 frame 身份、结构／稳定属性、文本摘要等组合验证，保留 selector 作为候选而非唯一真相；唯一性、文本、可见范围或 frame 不一致时标为 stale，不滚到错误元素。

滚动、resize、浏览器 zoom、侧栏 pin/unpin、自动展开工作区都会更新当前锚点的显示位置和评论条位置。可以验证的元素在当前文档中跟随实际 rect；点／区域按文档坐标重新映射；离开可见范围时显示贴边提示或暂时收起评论条，不把箭头连到屏幕外的错误位置。

## 6. 简洁悬浮评论条与可信叠层

评论条只保留短输入、保存／完成、取消和必要状态。需要多行时适度展开，普通 Enter 换行，Ctrl/⌘+Enter 可作为明确保存候选并与现有快捷键审查，Esc 按输入／弹层／选区层级返回。保存与加入对话是不同动作，不能因按 Enter 意外发起 AI 任务。

默认靠选区右侧并留 8—12px，空间不足时依次尝试下方、左侧、上方；对实际 guest 可视区进行 clamp。窄视口使用贴边评论条但保留可见锚点标记，长文本和错误信息限高内部滚动，保存、取消始终可达。蓝色标记、文字和焦点对比在明暗主题和高缩放下可辨。

评论内容由可信应用 UI 编辑，不把完整应用 preload/IPC 或评论编辑器随意暴露给网站。closed ShadowRoot 是显示隔离工具，不将其当成网站脚本永远无法观察用户输入的安全保证。

真实 WebContentsView 有独立的原生层级。最终悬浮编辑需要宿主拥有的可信叠层表面，并验证输入命中、焦点、原生光标与截图关系；现有 Vue 中放一个大 z-index 面板不足以证明它能盖在 View 上方。叠层能力属于新增契约，不能在接口盘点中写成已经存在。

异常或尚未迁移路径可复用既有截图→解码→绘制→隐藏 guest 的有界流程；最新正常路径使用原生实时浮层。使用降级时必须明确是冻结预览，临时操作网页前恢复真实页面，结束操作后重新验证选区及截图；不把一张截图冒充实时可交互 View。截图失败时保留意见并提供返回／重新选择，不能出现空白底图和无响应输入。

评论条、蓝框和批注标记不进入供 AI 使用的原始证据截图；可单独生成带标记的预览。保存前短暂隐藏自身覆盖层并等待绘制，截图后恢复，不能把错误页面或自己的输入条截成用户目标。

## 7. 专属批注光标：真实指针与 AI 虚拟指针分开

批注光标属于**用户操作的真实系统指针**。默认设计为准确点位配简短评论标记，可在拖选时使用匹配的框选图形；采用项目自有小尺寸 SVG、明确 hotspot，并在浅深背景上有可辨描边，不复用领航箭头、环形瞄点或精密十字三款 AI 图形。

优先在真实 guest 的 isolated 选择覆盖层应用专用 `cursor:url(...) hotspot, crosshair` 规则，并核验 Chromium／定制内核、SVG/data URL、CSP 与页面样式的实际接受行为。宿主 HTML 的 cursor 规则不自动作用到 guest，DOM 跟随鼠标的装饰图也不是系统指针。

资产和 hotspot 独立于 `browser.automation.cursor_style`，不得调用 setVirtualCursorImage 将 AI 虚拟光标伪装成批注指针，也不改全局操作系统指针。临时网页操作时撤回批注 cursor，让网页链接、文本框等恢复各自指针；回到 armed/dragging 时再应用。

自定义 cursor 不可用时明确回退原生 crosshair 并保留“批注中”的视觉提示，不能隐藏真实指针后只画一个假图。不同 DPR、浏览器缩放、宿主尺寸、窗口迁移、跨 frame 和恢复后要验证实际 hotspot。触摸环境不用不存在的鼠标指针表达状态。

若需要主进程或定制内核级 cursor 接口作为增强，先查实可用能力与生命周期，不在规划中发明某个参数。页面关闭、模式结束、崩溃和异常清理后不遗留批注 cursor，不改变正常 AI 光标配置。

## 8. 按住 Space 临时操作网页

Space 只在批注会话的页面选择态、焦点属于该 guest、无拖选／提交／模态层、非组合输入时作为临时模式键。评论条、网页 input/textarea/contenteditable、搜索框、快捷键录入和 IME 候选输入中，空格保持普通输入，不触发切换。

首次符合条件的 keydown 转入 passthrough，暂时撤回拦截层和批注 cursor，显示“临时操作网页，松开返回批注”。忽略 repeat，不把用于切换的空格重放给网页造成默认翻页；在该状态下允许真实点击、滚动等正常网页操作。

keyup 结束按住状态，重新测量与验证文档及目标；仍为原文档则恢复待选／可继续编辑，有变化则标 stale。临时操作后网页输入框获得焦点时不强抢焦点或吞下一次文本输入，提供明确“返回批注”入口，并保留未保存意见。

需要覆盖 guest 与可信评论叠层间的焦点转移，不只在 Vue window 上监听按键。Space 可以在 OOPIF 内按下或在窗口外松开；窗口 blur、页面隐藏、切标签、导航、renderer gone、模式关闭、模态层出现和失去 pointer capture 都清除 heldSpace 与临时样式，不能因漏 keyup 永久透传或永久拦截。

拖选过程中按 Space 不切换成业务点击；先完成或取消手势。Esc 优先退出临时操作或取消当前候选，再按明确流程关闭会话；权限确认等更高层弹窗优先处理自己的 Esc。临时操作与 AI 的人工接管是相关但不同的状态，Space 不直接执行 automation.resume。

## 9. 页面控制权的临时接管与恢复

开启前向页面控制器申请带 token 的批注会话：记录当前 owner、run lease、control generation 和文档 epoch，等待当前不可中断输入及清理结束。等待期间提示，未确认交接前不显示一个看似可点击的选择层，也不取消整个聊天任务来抢页面。

从 armed 到 editing、saving、passthrough 的整个会话都属于用户批注操作期，同页 AI 写操作不得并发穿插。Space 只是该期内的选择拦截开关，不是交还 AI 的开关；其他页面或任务是否可继续仍遵守既有控制范围，不扩大到全应用冻结。

退出时只有当原 owner/lease 仍有效、没有新的显式接管或暂停、控制代次未变化、输入清理被原生确认，才恢复到之前适当状态。进入前就是人工操作或暂停，退出后仍保持原状态；任务已结束、页面已导航／崩溃或恢复不确定时保持可解释的暂停／用户状态，不能无条件调用 resume。

新页面、临时操作改变的 DOM 或几何需要推进 observation epoch，AI 继续操作前重新观察，不能沿用批注前的元素引用。恢复失败保留意见和可达的手动恢复入口，不撤销输入保护来掩盖错误，不自动提交或重新执行用户任务。

## 10. 多条批注、保存取消与修订

每页可以有多条已保存批注，当前只展开一条评论条，其他记录使用安静编号／标记；重叠位置可通过列表选择，不堆叠多个输入框遮挡网页。历史按 page/chat 范围查看，保留现有搜索、状态、排序和分页。

保存目标与评论应为一次幂等提交：同一 targetId/requestId 重试只生成一个批注，不因超时连点重复截图或创建记录。保存成功后取得 annotationId、revision 和真实保存状态，清理相应临时草稿；失败继续保留评论与选区并可重试，不能提前显示成功。

取消新目标不创建空历史；含文字时保留可恢复临时草稿，明确丢弃才移除。编辑已有批注取消时不覆盖已保存评论，未提交缓冲依照既有草稿规则保留或显式放弃；加入对话的旧修订证据不因后来改字或删除记录而改变。

已有 revision CAS、草稿 version/editorId/sequence 和冲突副本继续使用。前端不能用“最后到达覆盖”取代它们；跨主窗口／独立窗口更新时显示冲突，保存自己的副本、采用最新或明确合并，避免在浮层关闭时丢文字。

现有草稿 API 要求 annotationId 已存在、baseRevision 至少 1，且 drafts 列表过滤掉不存在的批注。新增“尚未提交的 target 草稿”必须另有可恢复存储契约，不能直接用假 annotationId 调用旧 API并声称已保留。提交成功时将临时草稿与正式批注关联；清理使用版本／序号，避免迟到写入重新生成已取消目标。

## 11. 导航、iframe/OOPIF、缩放与证据

顶层完整导航、SPA 路由／hash、iframe 单独导航和同 URL 文档替换都要检查 epoch。仅比较 URL 不足以证明原锚点仍有效。保存中的页面变化应阻止把旧评论绑定到新内容，保留评论并允许重新选择；恢复旧历史时展示创建快照，不把 stale 改成 valid 只为了画蓝框。

同源 frame 可在确认 frame 身份后扩展选择；跨域 iframe/OOPIF 需要由主进程向有效目标 frame 的 isolated world 分别安装选择器、转发事件，并把其局部目标映射到顶层。不能由网页提供任意 frameId 或冒充宿主；frame 销毁和进程切换要撤销对应目标。

首阶段若无法可靠支持 OOPIF 内部元素，明确提供“选择整个嵌入页面”或区域批注，记录真实目标类型和边界；不把 iframe 容器当成其内部按钮。区域截图可包含可见嵌入内容，但不等于已经提取其 DOM 语义。

选择和截图需锁定相同的文档、frame、滚动、缩放与可见 viewport。异步变化时拒绝错误证据而非悄悄裁错位置。截图像素映射根据实际捕获图片尺寸验证，保留完整可见上下文及选区坐标，可按需另存局部预览，不仅留无法辨认来源的小裁片。

记录必要的 URL、标题、目标文字摘要、时间和页面身份，不读取 Cookie、密码或表单值来补充上下文；用户主动写的评论与页面内容分开。原始快照、标记预览和评论修订分别标明，后续 AI 修复依据固定的 evidence revision，不随当前网页变化重写历史。

## 12. 既有接口保留与新增契约

保留旧 begin(element/region)/collect/cancel 作为兼容路径，并保留 list/update/remove、草稿冲突、locate/compare、present 的真实含义。加入对话仍返回可追溯修订的引用，不能改成只拼接一段无来源文字。

新增独立版本的会话契约，至少覆盖以下职责，具体命名在实现时与现有桥接统一：

- 开启／结束批注会话，返回 session token、能力与实际控制状态。
- 目标候选更新与选择确认，包含 point/element/region、frame/epoch、坐标空间及事件序号。
- 临时操作开始／结束与清理确认；只接受当前会话和页面 owner，不暴露通用网页 IPC。
- 临时 target 草稿的保留、恢复、取消及正式提交；提交具备 revision、幂等 requestId 和截图有效性确认。
- 保存、导航失效、frame 变化、控制权和叠层位置的有序通知；迟到消息被代次和身份拒绝。

远程端当前只读查看批注，不因新增接口自动获得本地页面选择或系统 cursor 能力。独立窗口继续校验 chat/page 所属，不允许通过批注草稿、截图或 frame 请求读取其他对话资源。

## 13. 分批实施和验收

1. 提取会话状态机、目标版本与坐标转换纯逻辑，确定临时草稿和幂等提交；保持旧记录与引用可读。
2. 在普通顶层本地测试页接通点击／拖选、蓝框、专用真实 cursor 与基本保存取消；验证不触发网页按钮和不产生空记录。
3. 接可信评论叠层或明确冻结回退，验证 viewport clamp、焦点、输入、截图排除自身 UI及失败恢复，达到原生叠层 P0 后再提供正式入口。
4. 接 Space 临时操作、整期控制权和导航清理，测试漏 keyup、组合输入、模态层、拖动和显式人工接管。
5. 接多条历史、跨窗草稿／修订、OOPIF 分阶段能力与帮助说明；清理旧双入口歧义，不删现有证据与恢复机制。

上线验收包括：

- 点击普通文本、按钮、链接、图片、空白、open ShadowRoot，蓝框与评论锚点正确，选择不触发网页 click；从任意方向拖 region 不产生零尺寸或页面外坐标。
- 评论条在四角、滚动、低高度、缩窄工作区、自动展开、侧栏浮动、125%—200% 缩放及多 DPR 下保持输入、保存和取消可达。
- 真正 guest 中实际系统 cursor 使用独立图形且 hotspot 准确；主页面之外不受影响，Space 与退出恢复页面正常 cursor，禁用自定义图形时原生 crosshair 回退可见。
- 连续保存多条、切换目标、取消新目标、编辑已有记录、保存失败／重试、重复提交、截图空白和空间限制均不丢评论或生成重复空记录。
- Space 在页面选择态可临时操作；在评论框、网页输入、contenteditable、IME、快捷键录入中保持普通输入。repeat、失焦／漏 keyup、切标签、导航和崩溃后无永久透传或拦截。
- AI 原本操作、等待、暂停、人工接管及任务结束等状态分别进入／退出，控制交接和恢复与 token/epoch 一致，不让 AI 与用户同时写同页。
- 同源和跨域 frame、OOPIF、frame 导航／销毁、SPA、同 URL 更新均有明确支持或降级，无法验证锚点时展示 stale，不错绑目标。
- 原始截图无评论条／蓝框污染，矩形与截图像素一致；加入对话使用正确 annotationRevision，后续改字／删除不改旧证据。
- 隐藏、重开、独立窗口移动、跨窗并发和 renderer reload 后草稿可恢复；旧 version/revision 拒绝覆盖，冲突副本可见且不会因临时目标迁移丢失。
- 多个弹层与真实 View 叠层时无白屏、错误点击透传或遮盖；只读远程和其他 chat 的权限边界保持。
- 纯逻辑、离线样板、组件与真实原生窗口分开记录证据；没有实际运行的原生 cursor、frame 和控制权检查保持待验收，不用示例截图代替。

本规划与[浏览器资源界面规划](./browser-resource-redesign-plan-2026-11.md)、[浏览器控制权与光标规划](../browser-input-ownership-and-cursor-plan-2026-11.md)、[工作区响应式与悬浮侧栏规划](../workspace-responsive-and-floating-sidebar-plan-2026-11.md)衔接。浏览器更多菜单中的“浏览器设置 → 设置 > 浏览器”由独立实施任务负责，不属于本文已经完成的能力。

## 15. 离线样板验证

[浮动批注样板](../../../_planning/browser-floating-annotation-example.html)已通过 39 项隐藏隔离 Electron 的 DOM/真实合成鼠标键盘检查，[报告](../../../_planning/browser-floating-annotation-example.report.json)列出具体项目。已目检[邻近评论条](../../../_planning/browser-floating-annotation-example.comment.png)与[窄屏](../../../_planning/browser-floating-annotation-example.narrow.png)。
