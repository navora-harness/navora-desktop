## 1. 最新交互约定

- 附加入口在所有尺寸下都只有回形针图标，不常驻“附加”文字。原生 `title` 使用“附加：点击或输入 / 添加内容与工具”，`aria-label` 使用“附加”。短说明不列出全部菜单项。
- 输入区不放固定格式工具栏。选中可编辑正文时，出现参考截图中的轻量格式悬浮面板；这是对上一轮“只保留快捷键、不出现选区浮条”的进一步调整。原有快捷键继续保留，并列入帮助界面。
- 回答方式、会话权限都使用“图标＋当前名称”；下箭头仅提示可展开，不能充当这两个控件的功能图标。
- 发送入口保持醒目的图标按钮；上下文用量使用独立的细环入口，不与发送、等待或进度动画混淆。
- 模型选择以当前会话的选择为中心，常用选择直接可见；服务商、接口地址和复杂参数在设置中维护，避免在输入区重复一套配置表单。

上述约定以本次用户的补充为准。没有选区时不显示格式悬浮面板；附加菜单、模型面板与格式面板也不同时堆叠。

## 3. 输入区底栏排版

桌面默认顺序为：左侧“附加图标／回答方式／会话权限”，右侧“模型／上下文环／发送”；运行时增加独立停止入口。编辑正文与底栏之间只保留自然留白，不增加第二条格式工具栏。

- 附加按钮视觉约 32–36px，回形针 18–20px。回答方式、权限和模型使用同一基线与间距，避免一个像表单、另一个像工具栏。
- 发送视觉约 38–40px 圆形，采用对比鲜明的前景与实心背景；普通状态是清晰的单一发送符号，不能出现过细的空心图标与低对比色叠加。
- 上下文环约 20–24px，点击区域独立扩大到约 32–36px，和发送之间留出间距。环是静态容量，不持续旋转。
- 窄宽度先截断模型长名称、隐藏非必要思考等级文字，再允许左右组自然换行。附加始终只图标；回答方式与权限优先保留短中文名称，不靠三个无标签图标让用户猜含义。
- 模型菜单、用量面板和悬浮格式面板均受当前视口约束；打开时自动翻转或避让边缘。长列表自己滚动，不把正文顶出窗口。
- 鼠标悬停可读原生 title；键盘聚焦另有可辨识焦点与可访问名称。title 不能成为键盘及辅助技术唯一说明渠道。

## 4. 模型选择面板

### 4.1 默认结构

面板建议宽 360–400px，含标题、搜索、模型列表、当前模型能力摘要与必要的思考等级。默认不展示高级参数输入。

1. 顶部“本会话模型”，显示当前选择；关闭按钮有独立名称。搜索可匹配模型名称、真实 ID、服务商名称，不把接口地址或密钥放入结果。
2. 当前模型固定可见，下面是“最近使用”和“全部模型”；全量按服务商分组。相同身份在同一列表只出现一次，排序稳定，异步刷新不能跳走键盘高亮。
3. 每条两行：名称＋选中标记；服务商＋必要状态。仅在有已知差异时提供“支持图片”等紧凑能力说明，不堆砌芯片、火焰、徽章与营销标签。
4. 底部呈现当前模型的输入能力、配置的上下文／输出上限；来源不足时标“本地配置”或“默认值”。“管理模型…”进入设置中的对应模型，并保留当前草稿和返回位置。

最近使用必须按稳定身份保存，不保存 Key、请求内容或私有网址；已删除的服务商不留可点击的失效快捷项。收藏可作为后续增强，不阻塞首批落地。

### 4.2 思考等级与高级项

- 模型支持思考等级时显示“思考程度”，初始沿用该模型默认值；不支持时整组隐藏。
- 常见档位用简短文字和当前状态即可。自定义档位过多时进入下拉，不能把横排按钮挤成两三行小格。
- 同一面板中切换模型会重新读取支持档位；沿用档位必须确实兼容，否则采用新模型默认并说明变化，不能在请求里发送旧模型残留值。
- 温度、输出上限、上下文窗口、协议参数等留在设置的“高级配置”折叠项。输入区提供摘要和入口，不能偷偷覆盖服务商默认值。
- 模型选择点击后直接提交本会话设置。提交期间锁定本次选择操作、保留原选中态并标记“切换中”；成功后更新，失败后保留旧选择并就地重试。不能假成功后让用户按错误模型发送。
- 模型、思考等级或回答方式正在保存时，发送显示“正在确认会话配置”，阻止按 Enter 或连点绕过；成功后由用户提交，不后台自动补发。每次提交同时确认文档与会话配置修订，主进程保存已确认的服务商／模型身份、思考档位和配置修订，不把密钥值写入消息快照。
- 队列在入队时固定上述非秘密配置；执行前复核配置身份与兼容性，模型被删除、端点修订或容量变化时暂停该项并提示处理，不静默换到另一端点。权限始终按执行时有效授权复核，快照不能恢复已经撤销的权限。另一个窗口更改配置、保存失败与发送并发需在同一提交链路验收。

### 4.3 能力、失效与错误

- “未填写 Key”“需要鉴权”“未测试”“已验证”是不同状态。允许无 Key 的本地／兼容端点不因空密钥被整体禁用；明确需要密钥而缺失时提供“配置密钥”。不得统一宣称“无 Key 仍可使用”。
- 没有供应商能力元数据的模型显示“能力未验证”；文本／图片等只按明确配置或已验证结果表达。工具调用能力目前没有单独字段，应先补元数据契约再展示，不按名称猜测。
- 草稿含图片而目标模型明确只支持文本时，先说明不兼容并给出换模型／移除图片入口，保留草稿；不能静默丢图或把图片当空文字提交。
- 当前模型被删除或服务商失效时保留“当前选择不可用”的可读条目，要求选新模型或修复配置；不静默跳到另一个付费或不同权限端点。
- 首次载入显示局部骨架／加载说明；刷新时保留已加载列表。刷新失败展示“刷新失败，当前显示上次列表”与重试，不能闪成“暂无模型”。
- “没有匹配结果”“尚未添加模型”“服务商刷新失败”“切换失败”使用不同文案和操作；不共用一个空白面板。
- 运行中允许打开面板查看，但选择项锁定并说明“任务完成后可切换”；不通过禁用整个触发器隐藏原因，也不更改正在运行请求的模型。
- 对话切换、关闭面板后，迟到响应按 chatId／请求代次校验；旧会话结果不能覆盖新会话模型。

### 4.4 键盘与焦点

模型列表采用一个完整的单选列表交互（例如 radiogroup＋radio），支持方向键、Home／End、Enter／Space 确认，Escape 返回触发器。不要只添加 radio 属性却让每条都成为无组织的 Tab 停靠点。

搜索在面板内聚焦；按键仅在输入搜索或列表导航时消费，不触发正文发送或全局搜索。关闭不修改草稿、不丢失正文选区。模型长名称截断后可通过 title 查看完整名称。

## 5. 回答方式与会话权限

### 5.1 回答方式

产品名称统一为“回答方式”，沿用自动／快速问答／执行任务三种真实执行模式，避免把“自动”误认为权限预设。

- 自动：`wand-magic-sparkles`，说明“按问题选择直接回答或调用工具”。
- 快速问答：`comments`，说明“直接回答，不操作浏览器与文件”。
- 执行任务：`robot`，说明“可使用浏览器、文件与插件，仍受会话权限限制”。

这些名称均来自现有图标目录。触发器和对应菜单项使用同一图标。条目以 menuitemradio 表达单选，当前项同时有文字和勾选，不能只用颜色。

运行中可查看当前方式，切换项禁用并说明原因。改变回答方式只影响后续任务；打开菜单、悬停或查看说明都不改变当前任务。保存失败恢复原值并给出重试。

### 5.2 会话权限

保留当前保守／均衡／放手／自定义及现有图标，图标线型、尺寸与回答方式一致。触发器 title 写明当前会话和范围，菜单解释每个预设实际影响，不把“放手”误写成所有技能与操作均无条件允许。

- 预设选择是会话配置，不替代正在等待的单次权限确认，也不等于“切换人工操作”。
- 若允许运行中调整，应明确仅影响之后尚未授权的操作；不能追认之前拒绝的动作、自动点击已有确认卡或释放浏览器输入所有权。
- 自定义显示实际摘要并提供查看详情；未单独改动时不显示没有内容的复杂矩阵。
- 权限变更期间防连点，结果绑定原 chatId；失败保留原状态，不先改图标再静默失败。

## 6. 发送、补充与停止

### 6.1 操作与状态

- 空草稿：发送禁用，title 为“输入内容后发送”。只有可提交来源的草稿仍可发送；纯空白或仅无效来源不能伪装为有效内容。
- 可发送：高对比圆形发送图标，title 为“发送（Enter）”，另在帮助说明 Shift＋Enter 换行。图标方向与项目既有发送语义一致。
- 确认提交中：保留按钮尺寸，显示局部等待状态、`aria-busy` 和“正在提交”；禁用重复发送。不能用这个等待环替换上下文容量环。
- 正在生成：停止作为独立的方形图标按钮。输入新内容时显示补充入口，title 明确“加入队列”或“插入当前任务”；有队列时显示独立数量，不将数量塞在发送符号中。
- 停止处理中：立即显示“正在停止”，阻止重复停止；得到结束确认后恢复。停止不能顺便删除草稿、队列或已保留的失败快照。
- 发送失败：草稿／冻结快照完整保留，给出重试或放回编辑器；重试同一 clientMessageId，不能重复插入两条用户消息。

发送、排队与插入属于不同意图，不能只改变图标而不改变 title／可访问名称。运行中保留停止入口，不能因为用户开始打字就把停止按钮完全替换掉。

### 6.2 输入法与快照

- 中文组合选词期间 Enter 只确认候选，不发送；组合结束同一事件周期仍需防误触。快捷键、斜线菜单和格式面板都遵守同样保护。
- 来源详情、模型搜索、格式下拉和链接编辑面板内 Enter 执行各自操作；不能冒泡触发发送。
- 正文 Enter 发送、Shift＋Enter 换行；代码块和摘录内部 Enter 换行。发送条件统一由提交校验决定，不让点击与按键产生不同结果。
- 继续沿用当前冻结文档、保存确认、来源校验、幂等提交、失败恢复路径。提交完成前后输入的新草稿属于另一份文档，迟到回执不能清空新内容。
- 将“不可发送原因”在靠近正文的状态区明确展示，例如超长、来源失效、同步冲突、模型不兼容；不能只给灰色按钮且没有原因。

## 7. 上下文用量面板

### 7.1 信息层级

入口 title 例为“上下文：预计 38%，点击查看”。未知时写“上下文：部分内容尚未计入”，不要显示一个精确的 0%。微小非零占用可显示“<1%”，避免四舍五入后看似完全空白。

面板第一层展示“下次请求预估”与模型的“配置容量”，同时显示已计入／未计入范围。下一层展示分类：历史消息、当前草稿、系统说明、工具定义、引用资料、图片／其他输入、输出预留。没有数据的项用“未计入”或“待解析”，不能填零。

“上次请求实际用量”放在单独分区，注明模型、请求时间以及输入／输出；它只描述对应请求，不随草稿编辑移动。没有服务商 usage 时显示“服务商未返回”，不得用本地估算填充实际栏。

### 7.2 预算算法与数据来源

1. 将实际请求准备阶段的预算估算抽成主进程共享结果，让界面与发送前检查使用同一范围、同一模型能力和同一算法版本。不要复制两份越来越不同的经验公式。
2. 草稿预估基于文档编译结果；摘录计算用户编辑后的副本，引用按真实读取策略去重。同一资料出现三次不等于全文读三次；有意重复正文仍正常计数。
3. 尚未解析的文件／页面显示待解析状态；只为看用量不能触发网页导航、下载、工具执行或修改原始来源。已缓存结果须绑定来源版本。
4. 图片、多模态与服务商 tokenizer 不明时保留估算标识及安全余量；不把“每图 4096”等兜底值称为模型真实规则。
5. 上下文容量和最大输出区分：显示输入估算、输出预留和剩余可用空间；缓存 token 是输入的子项，不再加一遍。累积输出、工具循环总量和当前请求窗口不能混为一个比例。
6. 后续给 SSE／非流式响应补 usage 采集、可选字段、请求身份与持久化，再开放实际分区；服务商不支持返回 usage 时保持缺失，不因缺字段判定请求失败。
7. 用量事件绑定 chatId、requestId、模型与文档修订号；切换模型／草稿后旧估算作废，异步迟到的统计不能覆盖当前面板。

现有 60%／85% 视觉阈值可以先保留，但高占用提示必须与实际提交的安全余量／输出预留一致。估算不完整时优先显示“不完整”；已确认超限时给明确原因，不能仅靠红色提醒。

### 7.3 可执行的整理动作

- “查看占用来源”定位到草稿中的较大摘录，供用户缩小范围或移除；不会后台删除内容。
- “新建对话”保留原对话和草稿；“压缩历史”属于后续独立功能，必须展示保留范围及结果，不静默改写历史。
- “调整输出预留”进入对应模型高级设置，明确它影响的范围；面板本身不偷改全局上限。
- 用量面板保持可交互，点击面板内部的说明／整理动作不自动关闭；Escape／外部点击关闭并恢复触发器焦点。

## 8. 格式悬浮面板与其他浮层的协作

格式面板的详细实现归入附加与富文本规划，本文件固定以下控件协作约束：

- 仅非空、可编辑且可格式化的文字选区触发，贴近选区并避让屏幕边缘。输入光标、来源引用 atom、只读来源标题、输入法候选、模型搜索内容都不触发。
- 首层放链接、加粗、斜体和“正文”样式选择；样式子面板按参考显示正文、标题 1／2／3、编号列表、项目符号列表，并标记当前状态。未完成文档白名单和发送编译支持的格式不得只做显示效果。
- 按钮操作前保存真实选区；点击浮层不使选区失效。嵌套样式菜单能返回，Escape 逐层关闭并恢复选区；所有格式操作进入统一撤销记录。
- 打开附加、模型、权限或回答方式菜单时暂收起格式面板，不移除选区；关闭其他浮层后按实际选区决定恢复。链接编辑与样式子菜单属于格式面板自己的子层级。
- `title` 和帮助列出快捷键，支持不依赖鼠标使用。键盘进入悬浮面板不能改变正文 selection，Tab 不被永久困住。
- 格式悬浮面板、样式菜单与附加候选都采用“受限高度＋内部滚动”，可用高度随窗口、缩放、输入框与选区位置计算；弹层外壳不得越出视口。格式主行保持可达，较长样式／新增能力在独立列表中滚动，不能无限拉高，也不以缩小字号容纳。
- 主操作行以后增加更多按钮时，优先把低频动作收入“更多”；受限窄宽度仍可横向滚动。列表上下滚动，方向键／Home／End 自动将当前项滚入可见区域，激活后仍作用于原选区。
- 内部滚动事件不能被误当作点击外部或页面滚动而关闭浮层；滚到边界不把聊天正文一起卷走。触屏拖动、窗口尺寸改变、系统及应用缩放后，末项、确认和关闭都须可达。
- 全部浮层接入原生浏览器遮挡协调，遵守[输入所有权规划](../browser-input-ownership-and-cursor-plan-2026-11.md)与已有截图／隐藏时序方案。加大 z-index 不能解决原生 view 盖住浮层或打开浮层后网页空白。

## 9. 拆分实施与验收

### 第一批：底栏与文案

- 附加仅图标、title／aria-label；回答方式与权限图标；发送／停止视觉及状态；统一焦点、点击区域、长名称和窄窗排版。
- 验收无固定格式栏；附加按钮无常驻文字；鼠标悬停可读简短用法；Tab 可识别每个入口；390px／桌面／高缩放不溢出，图标不退回问号。

### 第二批：模型面板与会话配置

- 搜索、最近／分组、能力摘要、默认思考等级、加载与错误、切换事务和上下文兼容检查。
- 验收重复模型名跨服务商可区分；空 Key 端点不被武断禁用；列表刷新失败保留缓存；当前模型失效不静默换端点；切换中失败原值可恢复；对话切换后迟到响应不串写。
- 验收模型、回答方式与权限菜单的键盘导航和可访问单选状态；运行中可查看并理解锁定原因，当前请求不被改写。

### 第三批：格式悬浮面板

- 选区定位、链接、基本 mark、段落／标题／列表转换、选区书签、子菜单、输入法与撤销；帮助同步快捷键及格式能力。
- 验收多行与跨段选区、边缘翻转、滚动重定位、来源节点边界、点击按钮不丢选区、一次撤销恢复；自动保存／重新载入／粘贴／编译后语义一致。

### 第四批：上下文预估与实际统计

- 抽取统一预算结果、补草稿和来源状态、保留输出余量，再接真实 usage 和持久化。
- 验收同一文档／模型下 UI 与提交检查口径一致；未知项不显示零；两次请求和草稿编辑不混入上次实际；usage-only chunk、缺 usage、取消请求、缓存输入和图片均有明确结果。

### 贯穿检查

- 发送连点、回执超时、失败重试、运行中排队／插入、停止处理中继续输入、输入法 Enter、浮层内 Enter 和选区快捷键均验证内容完整且不重复提交。
- 键盘、高对比、减少动态效果、浅深色、长中文和英文名称、系统缩放与窗口缩放都检查。按钮不可用的原因可读，风险状态不只用颜色。
- 模型切换、设置保存、来源读取、发送接受／失败和停止完成需有简短读屏状态。普通完成用低打扰状态区；用户操作失败关联对应控件。流式文字、逐字搜索和用量变化合并播报，不能每个 token 都读出；禁用发送原因通过关联说明可被读取，不只放在鼠标 title。
- 所有浮层打开／关闭后浏览器画面持续可见或可靠恢复；不改变自动化输入所有权，不因鼠标经过 view 触发人工接管。

本规划不重新运行全项目检查，也不覆盖已有检查结论。正式改动按批次执行相关类型检查、组件交互和原生 view 回归；原有已失败项由项目检查记录继续跟踪。

## 10. 模型快照与实际用量实施记录（2026-11-03）

- `shared/model-selection.ts` 定义已确认的服务商、模型、有效推理档位、回答方式及非秘密配置指纹。正文发送冻结时绑定身份，主进程只接受仍与确认态一致的新提交；密钥值不进入文档、消息或队列。

- 运行中插入同时核对当前运行的五项身份；不一致返回队列等待新运行，不把新模型任务交给旧模型请求。
