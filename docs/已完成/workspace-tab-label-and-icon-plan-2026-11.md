## 2. 已有实现：统一几何不需要重做

### 2.1 标签与宿主

- [shared/workspace-tab-geometry.ts](../../shared/workspace-tab-geometry.ts) 已定义普通标签最小 112px、理想 220px、最大 260px、高 36px、固定网页标签宽 36px、间距 4px。该文件还提供条带理想宽度计算与共享 CSS 变量。
- [WorkspaceTabItem.vue](../../src/components/WorkspaceTabItem.vue) 已被主窗口、独立网页窗口与独立文件窗口复用。身份图标／favicon 均为 16px；标题为单行弹性省略；音频、关闭按钮当前各为 24px 命中区。
- 仓库当前条带组件是 [BrowserTabStrip.vue](../../src/components/BrowserTabStrip.vue)，没有另一个 `WorkspaceTabStrip.vue`。它用于 [FileWorkspace.vue](../../src/components/FileWorkspace.vue) 的混排栏与 [BrowserHostPage.vue](../../src/pages/BrowserHostPage.vue) 的网页栏，负责溢出横向滚动、选中项可见、边缘拖动滚动和关闭时冻结宽度。
- [FileHostPage.vue](../../src/pages/FileHostPage.vue) 使用同一个标签项，但条带仍为自己的 `.file-host-tabs`，没有直接接入 `BrowserTabStrip` 的冻结宽度和边缘滚动逻辑。共享标签尺寸不等于三个宿主已经拥有相同条带行为。
- 主窗口展开后的父聊天是 `kind='conversation'`、`closable=false` 的首标签；其状态由 `conversation.status` 提供。`Ctrl W`／Delete 在父聊天项上恢复分栏，不删除聊天。子对话 hub 目前属于新规划与离线样例，尚未出现在正式标签种类中。

### 2.2 标题与图标的真实来源

[FileWorkspace.vue](../../src/components/FileWorkspace.vue) 的文件标题取路径末段；网页标题使用 `FileTab.path`，相同网页标题临时追加顺序数字。[BrowserHostPage.vue](../../src/pages/BrowserHostPage.vue) 也有自己的同名标题编号逻辑。独立文件窗口同样只取 basename，尚没有跨目录同名文件的短路径消歧。

[useFileTabs.ts](../../src/composables/useFileTabs.ts) 将原生网页标题截到 160 个 JavaScript 字符后存入 `path`；正式原生记录仍在 [browser-registry.ts](../../electron/modules/browser-registry.ts) 中持有标题。当前主工作区的长标题预览不能被默认视为保留了原始完整标题。

网页 favicon 来自 Registry 的 `page-favicon-updated`；现阶段选择 HTTP(S) 候选，主工作区还经 `webUrl` 筛选。新文档导航会清除旧 favicon。标签项在图片加载错误后回退为内置图标，并在 URL 变更时清除该失败记录。组件本身未形成统一的 URL 验证、尺寸限制和图像代理契约。

当前普通文件标签默认是 `file-lines`，不是按 MIME／后缀细分。项目已有 [AppIcon.vue](../../src/components/icons/AppIcon.vue) 与 [ui-icons.ts](../../shared/ui-icons.ts) 的尺寸自适应图标资产，16px 会选择小尺寸版本；文件列表的 `FileManager.fileIcon()` 已使用 `image`／`code`／`file-lines`，但这些映射尚未用于标签项。

### 2.3 状态、音频、关闭与预览

- 加载状态目前是标签底部的非确定进度线；它不是页面加载百分比。`status` 是另一段最多 88px 的文字槽。独立浏览器还有基于控制状态的边框样式。
- 关闭按钮在可关闭、未固定的标签上一直占据布局空间，只通过 opacity 在悬停／选中／聚焦等状态显示。不能把截图中的标题省略直接归因为“悬停新增关闭按钮”。音频按钮则使用条件挂载，出现／消失可能改变标题可用空间，属于需要验收的新增稳定性目标。
- 固定网页项当前宽 36px、不显示标题与关闭；音频按钮以 18px 角落覆盖呈现。其小目标与身份点击的关系需要重新安排，不能简单照搬普通标签的两颗操作按钮。
- 网页 hover card 已有 500ms 延迟、单实例互斥、屏幕边界限制、滚动／键盘／菜单打开时关闭。当前只在 pointer hover 下出现，标题最多两行；文件主要依靠原生 `title`。这不等于完整长标题、键盘和触摸查看已经统一。
- [FileTab](../../shared/file-tabs.ts) 没有文件 MIME、未保存编辑或下载状态字段。[FileDownloadIndicator.vue](../../src/components/FileDownloadIndicator.vue) 当前服务于文件列表等位置，不能据此宣称标签已支持下载进度。不要凭文件名显示“已保存”“下载完成”或未修改圆点。

## 3. 统一标签的排版契约

### 3.1 几何、槽位和命中

继续使用 36px 高、112／220／260px 普通标签宽度和 4px 间距。父聊天、文件、网页、未来子对话 hub 使用同一套普通标签尺寸；不因类型或选中状态单独加宽。36px 是标签本体高度，48px 是现有主窗口标签行高度，二者不可混成一个 token。

普通标签按“身份图标 → 标题 → 状态／音频 → 关闭”排列。身份图标 16px 居中；关闭／音频 glyph 16px、命中区至少 24px，和标题按钮分离。视觉上小的图标不等于小的点击目标。标题保留 `min-width:0` 与弹性收缩，操作槽不随文字长度收缩。

常规宽度保留当前约 10px 内容内距和 8px 内间距。接近 112px 时切换紧凑内距，不把所有状态都压进一行：先隐藏辅助文字和次要路径，保留身份、必要状态、关闭目标，再对标题省略。112px 同时容纳身份／音频／关闭时可用标题已经很少，必须通过实际槽位预算验收，不能只验收外框高度。

固定网页项继续保留 36px 身份位和不关闭的约定。音频角标只负责传达状态，避免在同一个 36px 区域叠放两个互相争抢的小命中目标；开关音频可从该项上下文菜单和键盘菜单执行。固定项的完整标题、音频原因和“已固定”应可读出。

标题、favicon、状态、音频和关闭沿同一垂直中心线；SVG 描边、favicon 透明边与 logo 视觉重量要目检。图片按比例 contain，不拉伸网站商标，不用放大图标补偿透明边。没有身份素材时仍保留同宽内置图标槽。

### 3.2 关闭、状态与稳定宽度

保留已存在的关闭占位和关闭时短暂冻结宽度，避免连续点击关闭时目标移动。未选中标签即使暂不显示 X，其关闭占位也不使标题在 hover 时跳动。触摸环境不依赖 hover 才能发现关闭入口。

为音频设置文档生命周期内的稳定槽：页面首次出现可操作音频状态后，该文档的标签保留音频槽；短暂静默时不反复挤压标题。文档导航、更换标签身份与明确复位时才重新决定槽位。静默、从未出现音频的普通页不需要凭空展示“已静音”图标。

错误、待授权、未保存、下载、音频等状态不可各自再挤一颗图标。优先展示需要用户处理的错误／确认，其次是可操作音频，再次是普通进展；细节进入完整预览或菜单。同一事实只表达一次。颜色之外必须有形状、文字说明或可访问名称。

## 4. 各类身份和标题

### 4.1 父聊天与子对话

固定父聊天使用聊天图标，标题是父聊天名称；“运行中”“需确认”等为状态，不拼进持久化聊天名。父聊天始终是展开混排栏的唯一首项，不显示关闭按钮，也不进入资源计数。

未来每个父聊天只维护一个“子对话”hub 标签。hub 使用一致的子对话入口图标；具体任务详情中的万花筒由 `childId` 确定，并与聊天流和 hub 列表一致。打开不同子对话复用 hub，不将每次点击创建为新 tab，也不把每个任务各自计入标签总数。万花筒颜色表示身份，完成／失败状态用独立文字或状态形状表达。

### 4.2 网页

标题来自原生网页标题，未提供时回退到可识别主机名／“新标签页”。搜索图标只有在明确的搜索入口或可靠搜索上下文中使用，不能根据标题里恰好包含“搜索”就推断页面种类。favicon 是首选身份，地球是无图或加载失败的回退。

加载沿用固定槽或底部状态线，避免 favicon／spinner／错误图标不停互换造成宽度变化。加载失败与控制权错误要区分：前者是网页可用性，后者是自动化交还／保护状态；可用页面的 favicon 不应因为一次工具失败就永久丢失。

新增统一的展示层解析器，供主工作区、独立浏览器、标签搜索列表与 hover 共用。区分原始完整标题、当前显示标题、消歧后缀、完整说明与稳定身份 key；展示后缀不回写网页标题。相同标题优先用主机名／来源上下文消歧；相同网址的多个真实页面仍是不同标签。必要编号绑定稳定页面身份，不因一次拖动或关闭邻项就重新编号。

标题省略由可用宽度负责，不先用 `slice(0,160)` 代替完整标题存储。迁移保留现有 tab key／pageId 和恢复逻辑，完整标题增加独立字段；长 emoji、组合字符、中英文混排不能被截成破碎字符。

### 4.3 文件

文件标签优先显示 basename 与后缀，使用已注册的 `file-lines`、`image`、`code` 等图标；新增 PDF／压缩包专用图标前先补入同一资产目录和 16px 小尺寸，不传入不存在的名字落到问号图标。

相同 basename 用最短可区分父目录作为次级后缀，例如 `README.md · docs` 与 `README.md · reports/2026`。跨父聊天同名时补来源聊天，不把整条绝对路径塞进标签。后缀优先省略，文件扩展名尽量保留；完整相对路径与所属聊天放进预览／可访问名称。

现有文件身份由 `chatId + normalizedPath` 决定，应继续复用。重命名或窗口转移只更新展示和已确认身份映射，不能为了消歧再开一份同文件标签。未保存和下载状态必须来自真实编辑器／下载记录；当前无字段时不添加推测标记。下载完成只消除或更新下载状态，不改变文件类型身份图标。

## 5. 音频语义：实际静音与原因必须分开

[browser-registry.ts](../../electron/modules/browser-registry.ts) 已从真实 `isAudioMuted()`／`isCurrentlyAudible()` 输出 `muted`／`audible`，并监听 `audio-state-changed`。当前 [BrowserTabAudioIcon.vue](../../src/components/BrowserTabAudioIcon.vue) 在静音时显示喇叭叉号，未静音且有音频时显示波纹；没有音频时不渲染音频按钮。这不是“任何没有声音的网页都被静音”。

本轮已存在的 [BrowserAgentAudio](../../electron/modules/browser-agent-audio.ts) 策略默认开启 `browser.automation.auto_mute`，只在实际 AI 任务租约／操作期间临时静音，等待模型期间保持，结束／暂停／接管后恢复；手动选择通过 `BrowserTabsService → setPageMuted → setManual`，复制和持久化只保存手动偏好。独立真实原生验证 [browser-agent-audio-native.report.json](../../../_planning/browser-agent-audio-native.report.json) 的 24 项已经通过。它证明源级音频策略和原生状态，不代表新标签文案或新设置界面已全部验收。

新增展示应明确四种情况：

- 没在播放，也未静音：不显示“正在播放”，不画静音叉号。
- 正在播放且未静音：波纹喇叭；操作名称为“静音此页面”。
- 用户手动静音：喇叭叉号；说明“手动静音”，取消后改变用户偏好。
- Agent 期间临时静音：说明“Agent 操作期间自动静音”；本次恢复声音沿用现有手动覆盖策略，不能误导成关闭全局设置。任务结束后恢复，不把临时状态存入副本或恢复文件。

同一任务中用户手动恢复声音后，不能仍标为“Agent 自动静音”。用户原本已手动静音，即使 Agent 正在操作，也不能把原因改写成临时自动静音。

当前 `BrowserTreeWindow` 只有最终 `muted`、`audible` 和 automation，没有可靠静音原因字段；`muted=true + owner=ai` 无法区分上述来源。实施新原因文案前，需要由音频策略生成只读的手动偏好／自动作用域／覆盖状态快照，再逐层传入标签；不能由前端猜测。网页播放状态、任务控制权和静音原因是三个不同维度，不增加三颗重复的喇叭图标。

## 6. 完整预览、可访问性与图标安全

保留 500ms 左右的 hover 延迟及单实例互斥；新完整预览覆盖网页、文件、父聊天和 hub，并在键盘聚焦时提供同等信息。内容包括完整标题、网页主机／文件路径／父聊天、必要状态和静音原因。当前两行截断预览不足以承载“查看完整长标题”的承诺。

纯 tooltip 保持无交互、边界可见；需要复制完整标题／网址／路径时使用菜单命令或独立可聚焦的详情面板，不往 pointer-events:none 的 tooltip 塞按钮或不可触达的滚动区。触摸长按可打开同一上下文菜单；不用原生 title 作为触摸与键盘的唯一说明。

`aria-label` 应一次读出“名称、类型、状态、来源”，避免调用方和共享组件都追加“正在加载”而重复朗读。选中使用 aria-selected 与清晰轮廓；音频按钮使用准确的行为名称和 aria-pressed；图标装饰部分对读屏隐藏。关闭、音频、菜单的命中不能触发选中、拖动或关闭其它项。

favicon 作为不可信网页输入处理：用 URL 解析统一验证允许协议、长度与来源策略；拒绝 `javascript:`、`file:`、带控制字符的地址和异常素材，失败后回退内置图标。不要引入第三方 favicon 查询服务，也不要因取图扩大页面原本的网络权限。若增加缓存／代理，要明确所属浏览器会话、请求策略、大小／类型限制、超时及失效；不把远程 SVG 以内联 HTML 注入。现有 HTTP(S) 筛选和 `<img @error>` 是基础，不等于这些新增防护已经完成。

## 7. 计数、溢出与状态优先级

现有 `WorkspaceLauncher` 的数字来自 `fileTabsState.tabs.length`，展开时额外显示的固定父聊天不计入；因此参考图中“固定父聊天 + 四个资源标签”对应数字 4，并不能据此认定少算。全页浏览器资源视图可能只显示浏览器子集，而入口仍拿全部资源数量，需要将“工作区已有资源总数”和“当前窗口所显示标签数”的文案区分清楚。

新增 hub 作为一个可关闭内容标签计一次，内部任务数独立显示。相同网页 URL 的两个 pageId 计两次；同文件身份、同 hub 或重复收到的同 pageId 快照不重复计数。多选数量不混入打开标签数量，9+ 只改变视觉缩写，辅助说明保留完整数字。

窄宽优先保留普通标签的关闭、真实音频／异常状态和身份；辅助路径、耗时、普通进度文字优先退出。固定项保留身份与固定语义，普通项不为了容纳所有徽标变成固定项。空间不足时横向滚动并提供可搜索的当前混排列表；现有 `BrowserTabList` 只包含网页，文件窗口也没有同一入口，混排列表属于新增范围。

## 8. 交换位置与拖拽动效

### 8.1 源码已有反馈及缺口

[tabDragFeedback.ts](../../src/composables/tabDragFeedback.ts) 已创建拖拽缩略影像、给源标签加 `tab-is-dragging`，并按指针在目标左右半区显示前／后插入标记。[control-system.css](../../src/styles/control-system.css) 当前令源项透明度降低并缩放到 .97；这不能证明邻项也在缩放。`BrowserTabStrip` 已在边缘 28px 区域用 RAF 横向滚动。

[useBrowserDrag.ts](../../src/composables/useBrowserDrag.ts) 和 [useFileDrag.ts](../../src/composables/useFileDrag.ts) 使用不同的主进程拖拽令牌，drop 后才提交移动；Esc 取消令牌与反馈。浏览器拖出条带与文件拖出窗口的判定目前不同，未来不能为统一动画随意合并其宿主／分离窗口语义。父聊天拖出则恢复分栏，不创建聊天窗口。

`FileWorkspace` 还保留 `.workspace-tab-move` 的 170ms transform CSS，但当前三个模板是普通 `v-for`，未见与之配对的 TransitionGroup 或 JS FLIP。不能把残留样式当作排序动画已完整接入。关闭项的 leave 样式已设为立即隐藏、无退场缩宽，应继续保留。

加载线和插入线目前都使用标签 `::after`。这是需要独立图层化并验收的叠加风险，不作为未经复现的截图故障结论。

### 8.2 新增交互契约

1. 拖起时仅给拖拽影像轻微浮起与阴影，源位置保留相同 slot 宽度。标题、图标和邻项不缩放。固定父聊天不进入普通排序组；固定网页只在固定分区内排序；hub 不因打开另一个子任务改变身份。
2. 目标使用独立插入线，和加载／选中／错误状态分层。指针跨过稳定阈值后才移动候选 slot，避免半区边界来回抖动。多选拖动保留原相对顺序，禁止把一组里的成员作为自己的插入锚点。
3. 同窗排序在 drop 时提交一次真实顺序；拖动中的预览不反复写入持久化状态。按稳定 ID 保留 active、focus、多选、菜单归属和内容实例，不按新数组下标重新挂载网页或编辑器。
4. 提交前记录旧 slot 位置，DOM 顺序确认后只对位移项做短 FLIP，建议 120–180ms。取消或失败回到已确认顺序，清除插入线、ghost、transform 和临时宽度锁。新操作到来时取消或重定向上一轮动画，不叠加多个旧 reorder。
5. 所有测量共用同一套逻辑 x、实际 slot width、gap 和滚动偏移。不要一处用未变换的布局宽度、另一处用正在动画的 `getBoundingClientRect()` 再计算新位置。关闭冻结与拖拽宽度锁有明确拥有者，dragstart 不能留下旧冻结值，结束后也不能误释放另一次操作的锁。
6. 边缘滚动持续更新插入位置和可见标签，不改变真实顺序；到达端点立即停止，离开、drop、Esc、窗口失焦或销毁时清理 RAF。RTL 的逻辑起点、滚动方向和插入位置统一换算。
7. 跨窗移动继续走原有令牌、宿主校验、主进程事务和失败回滚；它不是一次同窗 FLIP。源／目标分别确认自己的快照后做局部位置反馈，不把旧窗口的屏幕坐标当成新窗口的动画坐标。
8. 动画只作用于标签视觉层。重排不激活其它页面、不抢焦点，不在每一帧改原生 viewport、调整 BrowserPage bounds 或触发自动化几何失效。只有实际内容区布局／活动页变化才走既有 layout 流程。
9. 关闭标签继续立即移除命中并复用冻结宽度，不加退场宽度收缩。正常动画和关闭行为分别验收。减少动效时顺序与位置立即更新，保留静态插入线和清晰选择反馈，不运行 FLIP、浮起或连续过渡。

## 9. 浏览器整行工具栏与地址框

### 9.1 当前样式叠加情况

[BrowserAddressBar.vue](../../src/components/BrowserAddressBar.vue) 基础样式曾给地址框 34px、连接按钮 22×24px，后面的同组件规则又把连接按钮改为 28px。[BrowserTabPanel.vue](../../src/components/BrowserTabPanel.vue) 后续规则先把工具行改为 44px、上下各 5px、导航按钮 30px、地址框 32px，再在末尾把地址框覆写为 40px、上下 4px、Agent 入口 30px。导航组有自己的边框与内距，后续导航图标为 20px。这里确实存在多次覆盖的尺寸来源；不能只改基础 34px 那一处就认为整行调整完成。

[BrowserAgentControl.vue](../../src/components/BrowserAgentControl.vue) 自身默认 32px 入口，在地址框里受父组件覆写为 30px。Agent 控制权、busy 和异常已有准确的 aria/title 与状态图形，应保留其行为。页面批注、下载、更多操作是 `browser-page-tools`，展开工作区时可被 Teleport 到标签行右端；地址框内仍保留 Agent，不应为了对齐再造第二份控件。

[appearance-themes.css](../../src/styles/appearance-themes.css) 通过主题选择器和 `!important` 覆写地址框／导航组底色、边框，焦点又有边框与外阴影。设计必须同时核对 scoped CSS、全局主题和控件通用样式。当前 source 的 44px 工具行与 40px 地址框、上下内距存在预算冲突，需要实测计算盒与可见边界；本次只读审计没有把截图像素直接当成 CSS px。

标签几何在 `shared/workspace-tab-geometry.ts`；主窗口行高来自 [main-window-layout.css](../../src/styles/main-window-layout.css) 的 `--workspace-header-height:48px`。目前没有覆盖地址行所有部分的统一共享几何契约。

### 9.2 新的整行几何与状态建议

先做常规桌面的候选：标签行继续 48px／标签 36px；浏览器工具行单独为约 44px，地址框与导航组外框 36px。36px 地址框便于与现有 30–32px 按钮保持可见内缩，也能在 44px 行中留下合理上下余量。这个值是待样板与 DPI 验收的建议，不是本轮已经改成的定值。

为工具行、地址高度、组高度、按钮命中、图标、水平 gap、垂直内距、圆角建立独立 tokens。若最终选择 40px 地址框，工具行必须同步容纳它的内距和边框，不能继续保留互相冲突的 44px／上下 5px。使用 `box-sizing:border-box` 和明确的预算，不靠负 margin 抵消。

整行按“网页导航组 → 地址框（连接／网址／Agent）→ 当前页附加操作”排列并沿同一中心线。导航组的后退、前进、刷新／停止始终使用一致 hit area，禁用只改变状态不改变位置；刷新变停止只换 glyph 和行为，不挤动地址。图标绘制尺寸与命中尺寸独立，安全图标和 URL 文本基线要目检。

Agent 继续内缩在地址框内，建议周围至少 3px 可见空隙，圆角随地址容器协调。选中状态只落在入口自己的按钮表面；hover、focus-visible、允许 AI 与正在操作分别表达，避免一个大色块同时承担四种含义。输入聚焦以单层边框／细轮廓为主，网址文字选区用文本 selection 色；常态地址框保持中性底，Sand／Mist／Dark 各自验证对比和外轮廓。

URL 输入保持弹性、`min-width:0`，未编辑时可做安全的显示省略；编辑／Ctrl L 时恢复完整值并可横向选择，不切掉协议后还让用户误以为正在编辑原始完整地址。已有组合输入、地址建议、连接信息和 Ctrl L 焦点恢复逻辑应完整保留。

窄屏优先保留导航、可输入地址和 Agent 接管入口；批注、下载与其它次要操作折入可达菜单或沿用展开时的标签行工具区，不让整行换成两排挤占网页。新菜单保持相同实例和状态，不能同时在原位置留一个可聚焦副本。粗指针模式增加可用命中范围时要检查相邻目标不重叠，必要时采用经过验收的独立触摸密度 token。

### 9.3 原生视口边界

`BrowserTabPanel.layout()` 已按实际 viewport DOM 矩形计算原生布局，并由 ResizeObserver／激活与浮层变化协调；应继承这个机制。新行高不能通过“固定减去 44 或 48px”定位网页。页面尺寸设置、页内查找、批注说明等可能另占一行，原生顶边应跟实际 viewport 元素对应，而不是简单等于地址框下沿。

地址行调整后，等待 DOM 布局确认再合并提交新的有效边界；不为 focus 阴影、hover 和纯 transform 每帧更新原生视口。多屏缩放／DPI、窗口最大化、分栏／展开和独立窗口都需验证工具行真实下沿、frame 边框和网页起点无重叠／白缝。用户另提的浏览器位置／宿主故障仍属于单独规划，不在本文宣称已经修复。
