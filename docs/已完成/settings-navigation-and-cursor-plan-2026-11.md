## 2. 已确认源码事实与待复现问题

### 2.1 设置已有返回按钮，退出路径尚未统一

`src/pages/SettingsPage.vue:6-14` 已有顶部返回箭头，调用 `requestClose`。同文件 `:2820` 的 `canClose` 在局部提交 `saving` 为 true 时返回 false；包含未保存密钥或密码时要求明确确认丢弃，其余设置草稿保留；随后等待 `persistInstantPrefs`。`:2832` 根据 embedded 状态发出 close 或跳回主路由。

`src/pages/ChatPage.vue:49` 的设置齿轮只将 `settingsOpen` 设为 true，重复点击不能返回。`:542` 的 close 回调仅将它设为 false；`:1936` 的另一条 back 路径还会切换到聊天。多处代码直接改变 `settingsOpen`，没有统一保存进入来源或恢复焦点的入口。

`ChatPage.vue:1917` 的 `canLeaveSettings` 会等待设置组件提供的 canClose；组件引用尚未可用时回退为 false。`src/router.ts:14` 将 `/settings` 重定向到 `/?settings=1`，`ChatPage.vue:5612` 读取后清除此参数，因此当前设置主要由页面内布尔状态驱动，不能单纯依赖路由历史完成返回。

### 2.2 已确认一条离开检查失联，其余场景仍需分别复现

新增浏览器菜单的集成验证确认一个具体缺陷：设置页使用 `lazyPanel` 包装，外层只暴露 `runAction(action)`，而聊天页的 `canLeaveSettings` 直接查找外层 `.canClose()`；因此离开检查一直返回 false，实际设置页的凭据确认也未被调用。已补外层 `runAction('canClose')` 桥接，沿用设置页原有方法；组件尚未就绪时仍拒绝离开，不能将无返回值直接当作允许。

这解释了使用该检查的路由/命令离开路径；顶部返回按钮直接发出 close，不走同一调用，不能据此宣称用户全部“无法退出”现场均已解决。其它入口、返回与恢复策略仍需统一，保存中的返回仍可能没有足够明确反馈，不把问题一概归因于标题栏遮挡、拖动区域、保存挂起或弹窗。

专项真实 UI 已验证无凭据时可通过路由离开；有未提交模型密钥时实际询问，取消保留原分类与草稿，确认后再切浏览器分类。该项属于[34 项最终回归](../../../_planning/browser-settings-current-native/completed.json)，不以顶部返回按钮检查代替路由 guard 检查。

实施前需在用户对应布局与保存状态下记录：按钮是否可见、是否 disabled、实际命中元素、canClose 是否返回/等待、当前侧栏选择、设置入口和是否存在未保存凭据。先构造隔离数据复现，不读取或修改真实用户密钥来验证。

### 2.3 普通草稿与秘密已有不同生命周期

`src/composables/settingsDraftSession.ts` 当前明确采用窗口内存保留普通设置草稿，凭据不得写入 localStorage 或配置文件作为草稿。`SettingsPage.vue:2877` 的卸载逻辑保存非秘密设置草稿并清除密钥草稿；`canClose:2820` 为未提交凭据保留显式放弃确认。

## 3. 浏览器虚拟光标改为卡片选择

### 3.1 预览与真实效果保持同源

保留现有三款与配置值：领航箭头 `navora-arrow`、环形瞄点 `focus-ring`、精密十字 `precision-cross`。卡片分别提供图形、名称、简短用途和已选标记。默认仍使用现有领航箭头，不为视觉重构创建新的设置键、丢失旧选择或改变输入保护。

将图形几何和 SVG 生成整理到不依赖 Electron、Node Buffer 或 DOM 的纯共享模块，由设置预览与原生 raster 绘制共同消费；前端不能直接引入完整主进程模块。保留原生像素缩放、hotspot 和透明光标的现有行为，仅移动共享定义，不重写控制权逻辑。

卡片中使用局部浏览器背景预览，展示原尺寸样本并提供适度放大的图形。不同款式共享预览区域高度和卡片尺寸，不用不同 SVG 尺寸制造卡片高低差；预览可展示目标点，但不能让用户误以为点击卡片会运行网页自动化。

### 3.2 选择与生效

- 点击卡片选择并沿用自动保存机制，状态区显示保存中、失败或已保存；失败可重试，不显示已选但保存失败的假成功。
- 使用明确的单选语义，鼠标、Tab、方向键和 Space/Enter 可选择；已选状态包含文字或勾选，不只依赖边框颜色。
- 采用外观主题卡片的边框、圆角、间隔、已选与键盘焦点规则，响应式布局随可用宽度切换三列、两列或单列。
- 允许在隐藏虚拟光标时预选后续样式，提示“开启显示后使用所选样式”；选择样式不隐式打开光标，不改变页面输入保护或接管状态。该行为相较当前隐藏时禁用下拉有所调整，实施与验收须明确记录。
- 图形预览在明暗主题、125%—200% 缩放下可辨；不要通过改变真实光标的颜色或热点来适配卡片背景。
- 当前运行页面的图形更新沿用已有运行时设置协议；应用失败/原生能力不可用时据实际状态提示，不把设计预览当成原生接口可用性验证。

### 3.3 覆盖边界

卡片重构不修改“显示虚拟光标”“防止操作相互干扰”“平滑移动”的独立开关含义；不增加 DOM 假光标替代原生控制，也不因为用户预览样式而移动系统指针。运行中是否能立即更新、不同 DPI 下实际可见性仍需原生窗口验收，离线预览仅证明外观和选择交互。

## 4. 帮助关于统一跳转

主窗口使用统一入口 `openSettings('about')`，左侧设置图标选中、侧栏关于项选中，主内容显示完整关于。已经打开设置时只切到关于，不重复创建设置实例；关闭帮助菜单后将焦点移到关于标题或返回按钮，不恢复到已隐藏的编辑器。

`help.about` 保留为同一个语义命令，改由应用主页面显式处理，不再走本地简短关于弹窗。快捷键说明、使用引导继续各自展示，不因统一关于而合并或删除。

独立文件窗口和浏览器窗口通过可信宿主桥接向主窗口请求打开关于：

1. 主进程校验请求来自应用自有窗口，不允许普通网页直接导航主设置。
2. 请求仅携带受支持的设置分区 ID，不透传任意路由、脚本或文件路径。
3. 主窗口不存在时沿用创建主窗口入口；尚未 ready 时排队一次，ready 后打开关于。重复点击合并，避免多个主窗口或多个设置实例。
4. 主窗口最小化或隐藏时还原并聚焦；独立文件或网页本身不被关闭、重载或合并。
5. 失败时在发起窗口提供可理解的提示及重试，不能显示一个与完整关于不一致的备用弹窗来掩盖失败。
6. 返回设置来源时保持主窗口原有页面；跨窗口请求记录来源，允许返回并恢复原窗口焦点，但不在用户已主动切换内容后异步抢焦点。

关于中的版本、平台、数据位置等信息继续读取实际应用信息，不在桥接事件或组件里再维护一份版本字符串。本轮仅规划桥接，不能写成现有 API 已支持该能力。

## 5. 明确进入与返回策略

### 5.1 一个受控入口

所有设置入口统一经过 `openSettings(section?, source?)`：左侧齿轮、应用菜单、错误修复引导、帮助关于，以及独立窗口请求。进入时保存返回快照，包括原主页面类型、父对话 ID、工作区选中标签与展开状态、侧栏状态和可恢复焦点；不复制聊天数据或浏览器 View。

设置内部切换分类仅改变设置分区，不覆盖最初返回来源。关闭后恢复原内容；原标签已关闭或对象已删除时退回仍存在的主页面，并给出轻量提示，不尝试重建已删除对象。

### 5.2 始终可见的返回动作

设置顶部固定显示箭头与“返回上一页”，title 可具体说明“返回浏览器/返回对话”等目标；不要只依赖难以发现的图标。左侧齿轮在设置已打开时切换为返回行为，不再不断设为 true。可在设置侧栏头部提供同一动作，但所有入口调用同一个离开流程。

增加 Alt+Left 的设置返回操作，按上下文处理：仅在设置视图、无更高层弹窗/编辑子页面接管且非输入法组合时触发；先关闭内部菜单或返回需要独立处理的编辑子页，不直接越过未保存凭据确认。此键不能在浏览器 View 或普通聊天中抢占页面后退；平台冲突与原生宿主转发需单独验证。Escape 优先关闭最上层浮层，不默认丢弃设置。

### 5.3 离开期间的保存与草稿

普通设置选择继续自动保存，路径、连接等组仍通过各自具名按钮提交；返回不能替用户保存未确认的新路径、重启服务或提交连接。

离开时收敛未完成自动保存，并显示“正在保存设置，完成后返回”之类的明确状态。局部提交进行中，按钮可以暂时阻止重复动作，但必须显示原因、进入统一待返回状态并在提交结束后落实此前的返回意图，不能无限吞掉每次点击。

保存超出限定等待或失败时，提供留在设置重试与保留普通草稿后返回的可达选择。具体等待上限在实施时根据现有提交事务与运行时重配协议确定；返回不会取消已经提交的后端事务，也不会把未知结果当成功。后续异步结果仅更新仍属于该次设置任务的状态，防止迟到响应重新打开设置或抢焦点。

密钥和密码沿用显式放弃确认：取消离开则保留当前编辑；确认离开则清除凭据草稿，普通草稿仍保留。禁止将秘密写入返回快照、localStorage、诊断日志或工作区持久化。遇到自动保存失败，展示失败与恢复位置，不能只显示统一“已保存”。

### 5.4 关闭后的恢复

恢复主页面的同一真实实例，不重跑模型、不重新加载网页、不清空输入，不改变用户原先选中的父对话。恢复可见后再还原阅读位置与焦点；目标已失效时选择可达控件，不调用隐藏编辑器聚焦。再次进入设置恢复上次分区和普通草稿；各分区滚动位置按需要单独缓存，不用一次返回强制滚到顶部。
