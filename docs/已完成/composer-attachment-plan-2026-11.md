## 1. 本轮交付范围与优先级

本轮先交付本规划和离线可交互示例，用于判断菜单密度、编辑器排版、正文与附加内容的关系，以及工作区展开后的对话／文件／网页切换。示例使用演示来源，不读取真实对话文件，不执行模型、插件或技能，不代表正式消息发送和浏览器宿主已经接入。

正式实施以本文件中的新名称、附加菜单和第 9 节展开行为为下一轮目标；继续继承 V2 规划中已经确定的隔离、来源版本、快照、失败恢复与原生网页遮挡规则。遇到旧文档的描述差异，以实际代码和明确的实施记录判断现状，不能把所有规划项一起当成已实现。

本轮的三个重点：

1. 将“附加上下文”统一改为“附加”，入口先显示轻量菜单，减少打开整屏来源面板的打断。
2. 完善已存在的结构化编辑器，使来源引用可以插在一句话中，较长资料继续作为可编辑摘录插在段落之间。
3. 展开工作区后，对话作为首标签，与文件和网页使用同一栏切换，返回分栏时保留原对话和工作区状态。

## 2. 当前实现核对

### 2.1 编辑器与来源已有能力

- `src/components/ComposerEditor.vue` 已使用 Tiptap，包含 StarterKit、自定义 Link 与 `ComposerContextBlockNode`；不需要重新替换为另一种富文本编辑器。
- 已有段落、链接、粗体、斜体、删除线、行内代码、列表、代码块等节点／标记及统一撤销历史。现有 StarterKit 的格式化能力与共享文档白名单需要共同核对；共享白名单接受 `underline`，但发送编译当前没有专门序列化下划线，不能据此宣称所有格式已经完成端到端验收。
- `shared/composer-document.ts` 的 `schemaVersion: 1` 文档已有身份、所属对话、修订号和更新时间。正文、来源块由同一文档生成提交正文和浏览器引用。
- `src/editor/composer-extensions.ts` 的 `contextBlock` 是块级节点，内容限定为段落／代码块，不能直接嵌入一句话中。当前可以把块插入文本段落之间；新增句内引用需要新增 inline 节点。
- 来源选择器已能列出当前对话文件、已打开网页、浏览器会话、当前对话历史消息、网页标注，以及手动文字／代码和网址。它还调用现有导入、文件行范围提取、网页正文／选区、截图等能力。
- 当前入口是名为“附加上下文”的 `v-dialog`；编辑器输入 `/` 仅在空段落触发，同样直接打开对话框。这与本轮要求的弹出菜单不同。
- 当前块包含显示名、模式、范围、版本和真实来源身份。可编辑的是消息副本；更改名称不会更改真实来源。
- `useComposerDraft.ts` 和 `ChatPage.vue` 已有文档草稿、比较保存、冲突处理、排队消息及提交快照路径。新节点必须沿这些路径接入，不能另建一份只存在界面中的附件数组。

### 2.2 截图中的内部矩形边框

全局 `src/styles/control-system.css` 的 `:focus-visible` 规则匹配带 `tabindex` 的 Tiptap 编辑区域；旧样式只为 textarea 移除了内部 outline。因此，编辑器自身的 `outline: none` 可能被较高优先级的全局规则覆盖，出现截图中的硬矩形。

正式修复应仅给消息编辑器的 `.composer-richtext:focus-visible` 增加明确的局部规则，使用外层 `.composer-box:focus-within` 呈现完整圆角焦点。按钮、菜单项、输入框和来源节点仍保留可见的键盘焦点，不能全局取消轮廓。示例采用连续圆角输入表面验证效果。

### 2.3 扩展与工作区已有能力

- `CreatorWorkspace.vue` 和 `shared/creators.ts` 已区分插件创建器、技能创建器，提供工程列表、模板、保存、校验、生成、安装、试用与导出链路。新菜单可以复用创建器入口；打开创建器不等于已经创建、安装或执行产物。
- `PluginWorkspace.vue` 已有插件搜索、已安装／商店列表、详情、管理和导入；`plugin-store.ts` 有全局与会话范围的插件装载、能力声明与工具调用。它们不是编辑器附件来源 API。
- `skill-store.ts` 与 `shared/skills.ts` 已有技能目录、正文读取、启停、导入／导出和从对话整理技能的辅助函数。当前存在技能能力不等于已有“只在本条消息使用指定技能”的结构化提交字段。
- `useFileTabs.ts` 和 `shared/file-tabs.ts` 当前保存文件和浏览器的混排槽位。`FileTab.kind` 只区分浏览器与普通文件，尚无对话标签类型。
- 浏览器相对顺序、真实活动页面和跨窗转移由主进程的宿主状态管理；文件槽位仍在工作区模型。`useFileWorkspaceLayout.ts` 的展开状态主要控制宽度／预留空间，不能直接表达“对话成为首标签”。

## 3. 附加菜单的结构与名称

### 3.1 两个入口，共用命令

- 输入区左下角始终只显示回形针图标，不带常驻文字与 `/` 键帽；`title` 为“附加文件、网页或会话，也可输入 /”，可访问名称为“附加”。右键／编辑菜单及帮助文案同步使用该名称。
- 点击按钮与输入 `/` 调用相同命令，浮层固定在整个输入框上方，与输入框外缘左对齐，间距约 8px，不跟随字符光标移动。上下键选择、Enter 确认、左右进入／返回、Escape 关闭。受限视口优先减小面板高度并内部滚动；最小空间仍不足时使用受视口约束的临时面板，输入框不被挤离屏幕。
- 输入提示改为“描述任务，输入 / 附加内容或使用工具…”。
- 常用来源选择尽量在同一个浮层内进入二级候选列表；需要预览、选择范围或更换来源时，再进入现有来源选择器的精简详情步骤。
- 触发入口、命令 ID、图标、可用状态与执行逻辑共用定义；不要分别维护按钮菜单和斜线菜单的两套功能清单。

### 3.2 默认菜单

菜单上方可显示一行轻量搜索；下面两组按用户要求固定排列。

“添加”使用小号弱化 label，下面显示：

- 对话文件：当前对话的文件和图片；可进入文件候选、导入与范围预览。
- 浏览器页面：当前对话可访问的已打开页面；可选引用、正文摘录或已有网页选区。
- 浏览器会话：按会话名称和页面数选择；保持“浏览器会话”全称，避免与聊天对话混淆。

“工具”使用同样的 label，下面显示：

- 插件创建器：打开已有插件创建器工作区。
- 技能创建器：打开已有技能创建器工作区。

底部提供“更多来源…”进入扩展来源列表。高级来源不一次性挤入默认五项。搜索可以检索更多来源，但每项都要保留类型标识和已接入状态；正式应用不放置可点击却没有实现的占位动作。

### 3.3 菜单内的进一步探索

后续可在“更多来源”内分为资料、能力、对话三类：

- 资料：本地文件／图片、粘贴文字、网页选区、网页标注、截图、网址、PDF 页码、表格区域。
- 能力：已安装技能、插件说明与工具、创建器工程，以及已经生成的插件／技能产物。
- 对话：当前对话消息、选中的消息范围、其他对话的摘要与已完成子任务结果。

这里的分组是后续信息架构。每一项是否能执行，以第 8 节的接入状态为准。创建器属于导航动作，引用资料属于内容动作，指定技能／插件执行属于运行指令，三者共用入口但保持不同结果。

## 4. 富文本与附加内容的排版

### 4.1 行内引用

在“参考 [需求说明.md] 并对比 [产品页面]，帮我总结差异。”这样的句子中，资料以轻量行内胶囊显示。胶囊包含来源图标、短名称及状态；不撑高整段，不把附件排成编辑器外的独立列表。

- 行内引用保存稳定节点 ID、来源身份、所属对话、显示名、模式、版本和可选范围；显示名不是解析资源的依据。
- 它作为一个可选中的 inline atom，在左右方向键、退格、删除、复制、粘贴、撤销和跨行时具有明确边界。一次删除移除该引用，不删除原资料。
- 单击打开轻量操作面板：查看来源、重命名、更换来源、转为摘录、转为普通文字、移除。打开来源与编辑正文的手势不能冲突。
- 新引用插在已保存的真实光标位置；不得把所有资料统一追加到文末。选中文字后通过附加按钮插入，默认插到选区末端并保留原文字，只有明确的替换操作才覆盖文本。
- 对同一来源可以在不同语义位置插入多个行内引用；提交解析按来源身份／版本去重读取，但正文保留每个引用的位置。不能沿用“同源即跳到旧块”的规则阻止句内重复提及。
- 引用图片时可显示图片图标和名称；预览从操作面板打开，不在一行正文里强塞缩略图。浏览器会话保留会话标识和页面数，不显示凭据。

### 4.2 可编辑摘录

需要改写内容或检查具体范围时，使用块级摘录：标题行显示来源名、范围与“摘录副本”，正文可以直接输入、加粗、链接、改成代码块。上下文块可插在段落之间，与上下普通正文共用滚动与撤销历史。

- 使用现有 `contextBlock` 继续承载可编辑段落／代码块，不将长摘录压成只读胶囊。
- 修改摘录只改变本次消息副本，明确保留出处；发送只使用当前编辑副本，不再附加整个原文件或实时页面。
- 刷新来源须先预览并明确替换；不能后台刷新覆盖用户改过的内容。
- 可以折叠较长内容；折叠仅改变展示，发送检查仍能查看实际副本。
- 行内引用转摘录时产生一个独立的块和稳定来源；摘录转引用前提示其编辑副本会被替换，并支持撤销恢复完整文本。
- 手动文字／代码作为摘录，当前历史消息默认也使用摘录；二进制文件与浏览器会话继续使用来源引用和可编辑说明。

### 4.3 格式化与视觉

- Ctrl/⌘ B 加粗、Ctrl/⌘ I 斜体、Ctrl/⌘ Z 撤销；重做沿用平台习惯。链接继续使用 Ctrl/⌘ Shift K，保留 Ctrl/⌘ K 搜索对话。
- 编辑区不显示固定格式按钮。根据用户最新参考，选中文字后显示轻量悬浮面板：链接、加粗、斜体、“正文”下拉；下拉包含正文、标题 1／2／3、编号列表、项目符号列表，并标记当前状态。此前“只保留快捷键、不出现选区浮条”的目标由本条替代。
- 快捷键继续保留；帮助 → 快捷键说明集中列出功能、平台按键与作用范围。示例顶部“帮助”提供同样说明，并支持 Alt F10 进入选区面板。点击按钮、打开样式或链接子层不丢失选区，关闭后可继续编辑；格式操作进入统一撤销记录。
- 文档层已支持 heading／link／orderedList，正式接入无需另建格式数据。`contextBlock` 仅允许段落和代码块，摘录中的标题／列表选择先禁用并说明原因；跨摘录边界、引用 atom、代码、只读标题和输入法组合期间隐藏面板。标题内链接需扩展现有仅 paragraph 的选区判断。
- 同步调整外部 HTML 粘贴的安全标签白名单：目前会剥离标题、列表、删除线标签；开放格式应从粘贴、保存到发送保持一致，只保留必要属性及安全链接，不接受外部 HTML 伪造来源身份。
- 确认 Tiptap 扩展、共享 mark 白名单、剪贴板净化和发送编译对每个开放格式均一致。下划线等未完成的端到端格式先修正序列化或暂不暴露，不以浏览器显示效果代替提交支持。
- 正文保持冷蓝灰文字、清晰插入光标、约 1.6 行高和连续输入表面。初始高度留足两行；内容增多后在约三分之一视口高度内滚动。
- 容器使用轻量圆角边框，聚焦时只加强外层轮廓；内部不再显示截图中的矩形。
- 延续现有 Fluent Regular 图标映射和系统 UI 字体。附加用回形针、文件用文档、网页用地球／页面、会话用窗口组、插件创建器用插件、技能创建器用书本／技能图标。统一 16px 图标、相同视觉重量，不混用 emoji、填充图标或第二套线型。
- 菜单建议宽 280–320px，分组 label 为 11px 左右，条目高 34–38px，圆角延续 12px；宽度和高度随视口约束，边缘自动翻转并可滚动。
- 选区悬浮面板与正文样式子菜单同样限制高度并内部滚动：固定基本格式操作行，候选列表单独滚动，新增样式或附加能力不会藏到屏幕外。内部滚动保持浮层及原选区；方向键／Home／End 使当前项自动滚入可见区域。附加菜单顶部搜索与底部提示保留，资料条目在中部滚动。

示例视觉基线：白色内容面 `#FFFFFF`、冷灰背景 `#F3F6FA`、输入表面 `#F7F9FC`、正文 `#283E56`、结构线 `#DCE4ED`、交互蓝 `#376D9F`。字体使用 Segoe UI／微软雅黑 UI，正文 14px、菜单 12px、分组与辅助说明 10–11px。重点放在可读的正文与来源关系，不增加装饰性卡片；左右分栏共享直线接缝，外框与编辑器各自保持连续圆角。

## 5. 键盘、输入法、焦点与异步操作

- `/` 在段首或空白后触发，允许在正文中途调用；在 URL、文件路径、链接文字、代码块／行内代码中保持普通字符。连续输入成为路径或网址时应解除菜单，不吞掉字面文本。
- 斜线查询只针对触发位置到当前光标的范围；选中条目后只移除本次触发文本，不误删相邻正文。按 Escape 关闭菜单时保留用户已输入的字面文字，不保留隐藏命令节点；按钮菜单取消时草稿完全不变。
- 菜单打开期间，上下键选择、Enter 执行当前项、右键／Enter 进入二级、左键返回、Escape 逐层关闭。菜单处理优先于消息发送，Tab 不被无限困住；关闭后恢复原选区。
- 菜单和来源详情打开前保存 `chatId + documentId + revision + selection bookmark`；异步结果先验证所属文档和有效选区，再插入。
- 中文输入法组合期间不打开 `/` 菜单、不执行菜单项、不触发发送；`compositionend` 同一事件周期的 Enter 继续保护。代码块和可编辑摘录内 Enter 换行，主正文沿用 Enter 发送／Shift+Enter 换行。
- 切换对话、进入创建器、关闭浮层或离开当前文档后，使旧提取请求与菜单会话失效；迟到结果不能进入另一个草稿。
- 页面浮层沿用原生网页遮挡协调，不只增加 CSS 层级。打开菜单时停用被遮挡原生视图的命中，关闭后恢复页面状态与焦点。
- 来源请求要有加载、空状态、失败、重试和取消。文件行范围改变后必须重新读取确认，不能把旧预览作为新范围发送。

## 6. 数据模型和正式接入差异

推荐增加 schemaVersion 2，并提供显式的 v1 → v2 迁移。旧 `contextBlock` 原样保留，不自动把旧块缩成胶囊而丢失说明或摘录。

需要一起交付的变化：

1. 新增 `contextInline` 节点，限定在允许行内内容的段落等位置，不能有子块；来源字段复用已有校验器。若后续抽取独立引用表，节点与引用表也必须保持同一文档的一致性，不能再出现隐藏引用清单。
2. 扩展 `normalizeComposerDocument` 的节点白名单、结构与位置校验、节点 ID 唯一性、体积限制；迁移、合并与重复节点 ID 修复同时识别两种来源节点。
3. 扩展 `compileComposerDocument`，在原位置输出清晰的来源标记，并从 inline 与 block 共同派生引用／编译上下文。摘录仍只编译当前副本，来源读取去重与正文引用次数分开计算。
4. `ComposerEditorHandle` 增加统一插入方式，区分行内引用与块摘录；来源选择器返回选择结果，而不自行决定所有内容只能插入块。转换、替换和删除构成一次可撤销事务。
5. 同对话结构化复制保留受验证来源；跨对话粘贴先降为可读文本，或走显式“复制资料到当前对话”流程。外部 HTML 不得伪造真实来源节点。
6. 提交、队列编辑、运行中插入、恢复快照、重试、远程同步与导出全部接受新结构版本；旧客户端不能静默忽略新节点后覆盖新草稿。无法识别时保留可恢复的原文档并提示版本兼容。
7. 菜单命令使用可区分的结果类型：插入资料、打开创建器、管理扩展；“工具”导航命令不生成假的附件节点。后续指定技能／插件执行，须有独立运行意图契约。

建议归口为可共享的菜单命令定义、菜单呈现组件、行内节点视图与现有来源详情组件。避免将新菜单、全部来源读取和复杂迁移继续堆进 `ChatPage.vue`。

## 7. 草稿、快照、预算与隔离

- 结构化文档继续作为唯一可写草稿；附件数量、引用列表、用量提示均从文档派生。
- 自动保存覆盖行内引用、块摘录及格式；切换对话和退出时沿用比较保存／冲突恢复。菜单搜索与当前高亮属于临时 UI 状态，不进入消息正文。
- 点击发送时冻结这一份文档，统一校验来源和版本，产生不可变提交快照。保存确认后开始下一份新草稿，回执和失败不得覆盖新输入。
- 直接发送、加入队列、插入运行任务、失败重试使用同一快照和幂等身份。删除一个节点后，它对应的来源必须同时从这次提交中消失；多处引用同源只解析一次。
- 引用校验失败时给出来源名称及重新选择／转摘录／移除操作；已有摘录不因原网页关闭而丢失。不能把失败的局部摘录退化为整份文件。
- 引用浏览器会话只授予既有可访问身份，不复制 Cookie／令牌，不自动扩大权限或执行浏览器动作。插件说明、技能正文和历史消息属于资料，不能因为被附加就变成高优先级指令或安装请求。
- 每个来源校验真实所属对话；其他对话的资料必须显式选择并走复制／共享契约，不复用本对话的相对路径冒充同一文件。
- 保留现有单文件 12 MB、每批合计 32 MB 等导入限制；以后增加逐项估算的 token／图片预算，明确显示估算与超限原因，不静默裁掉用户摘录。

## 8. 更多来源的探索与接入状态

### 8.1 已有底层能力，可优先复用到新菜单

- 当前对话文件／图片：已有文件候选、受控导入和文本行范围摘录；新菜单增加更快的候选和行内引用模式。
- 浏览器页面／会话：已有树形身份和引用；页面正文、真实选区、当前活动页面截图已有提取调用。截图目前来自现有页面，不代表已有新的系统区域截图工具。
- 当前对话历史消息：选择器已经读取当前对话用户／助手消息，默认插入可编辑摘录；新增搜索和“引用这条消息”快捷入口可复用。
- 网页标注：已有版本、选中文字、批注与可选截图，适合放在更多来源中。
- 文字／代码／网址：已有手工输入；网址当前只作为引用，不自动访问。
- 插件创建器／技能创建器：已有真实工作区，可接入菜单导航，保留原对话草稿和返回位置。

这些是代码存在的能力；切换到新菜单后仍需验证读取、插入、删除与真实发送，不能仅换入口就标记全部验收。

### 8.2 已有资料或运行设施，尚未成为附加来源

- 技能资料：从现有技能目录选择名称、说明与版本，再预览正文；可以“附加说明／正文”作为资料。“本条使用此技能”需要下一小节的新契约，不能只把名字贴进正文就宣称已锁定执行。
- 插件资料：从插件目录读取 README、能力与工具说明，显示已安装／启用／异常状态；选择器不执行插件来生成候选，也不因选择资料自动启用或安装。
- 创建器工程：工程已有修订号和文件内容，可设计“附加当前工程／选中文件”；需要固定项目和修订，避免发送时悄悄变成更新后的文件。
- 已完成产物：很多结果已是对话文件，可以先按文件附加；按子任务、插件执行或技能执行筛选仍需稳定产物索引和完成状态。
- 从对话整理技能：已有辅助函数，但“使用此对话创建技能”仍需接入创建器草稿预填和审阅流程，不直接全局安装。

### 8.3 需要新增数据或运行契约

- 明确指定技能／插件：需定义单次提交的调用意图、版本、适用范围和失效处理；按现有权限进入运行流程。附加资料、指定使用、安装启用应是可理解的不同动作。
- 其他对话摘要／消息范围：需跨对话选择、可访问性验证、固定消息／版本和资料复制规则；首批不自动读取其他对话全部消息。
- 子任务结果：需只列完成／可读取的任务产物，记录来源任务身份与快照；运行中结果不可伪装成完成资料。
- PDF 页码与表格区域：共享 range 字段有扩展空间，但当前未提供完整 PDF／表格解析与范围预览。必须真实提取后展示，再进入可编辑摘录。
- 任意网址正文：需明确加载／提取操作、失败取消和权限；保留“只附加链接”的轻量方式。
- 新的系统截图／区域裁剪、录音转写：需要相应采集、预览与文件归属契约。可作为后续探索，不作为本轮示例的真实能力。

建议扩展顺序为：当前消息与网页标注等现成来源 → 技能／插件资料选择 → 已完成产物和其他对话摘要 → 单次运行意图、PDF／表格等需要新契约的来源。每次只交付一个闭环，避免菜单看似丰富而大量条目不可用。

## 9. 展开工作区：对话、文件与网页同栏

本节响应用户追加要求，是下一轮展开行为的目标；与 V2 旧的“仅将文件／网页工作区扩宽”不同。正式应用尚未接入，示例只使用离线页面演示。

### 9.1 三种布局状态

- 普通分栏：左侧保持当前对话与输入区，右侧工作区显示文件／网页标签；用户可以同时参考资料和编辑消息。
- 展开为单区域：主内容区顶部共用一条标签栏，顺序为当前对话首标签、已有文件／网页标签，之后为新建网页加号。选择对话时显示消息和完整富文本输入区；选择文件／网页时显示对应内容。
- 收起返回：明确的“恢复分栏”按钮回到对话加工作区，恢复展开前的宽度和最后活动资料标签。另一个“隐藏工作区”操作才关闭右侧呈现；两个动作名称与图标不能混为一谈。

首次展开时保留发起展开的资料页为活动项，顶部立即可见当前对话首标签。用户主动点对话再开始编辑；从对话入口展开时可默认激活对话。后续切换只改变当前呈现，不打开新对话或复制资料。

### 9.2 对话首标签的语义

- 对话首标签代表当前 `chatId` 的现有真实对话，不是网页、不占浏览器会话、不纳入网页页面数。显示对话标题、对话图标和轻量运行状态。
- 建议作为固定首项、保留正常标题宽度，首批不允许拖到网页之后或拖出新窗口。其固定语义与浏览器固定页不同，不使用缩成 favicon 的浏览器固定样式。
- 建议不显示关闭叉。若用户对首标签执行“关闭当前标签”，解释为恢复分栏并聚焦原对话，不删除对话、不停止任务。界面中更明确的主要入口仍是“恢复分栏”。
- 关闭最后一个文件／网页后，回到对话并恢复普通对话布局；不要遗留空白全宽工作区。关闭活动资料页时优先右邻、再左邻、最后回退对话。
- 删除当前对话必须走现有具名删除流程；对话首标签的关闭／隐藏不能复用删除命令。
- 工作区数量开关继续统计可打开的文件／网页，不把固定对话首项算成新增一个资料标签；可访问名称可以说明“当前对话及 N 个工作区标签”。

### 9.3 状态保留与挂载

- 保存对话草稿、结构化选区书签、消息滚动位置、是否停留底部、阅读锚点、展开前布局和最后活动资料标签；切回对话时恢复，不强制跳到最后一条消息。
- 正在运行的 Agent、排队消息和工具结果继续运行，切标签不会取消或重启任务。对话首标签必须显示待确认／失败等需处理状态；点击可定位到具体确认卡。资料页标题动作区保留任务状态与停止入口，不因聊天隐藏而失去干预能力。状态变化不自动切标签、不抢焦点，返回资料后保留其阅读位置。
- 真实对话组件保持唯一实例，通过共享容器或稳定呈现位置切换显示。禁止为了全宽标签再挂载第二个 `ChatPage`、第二份编辑器或第二套任务订阅。
- 文件预览保持自身滚动与选择；网页复用现有主进程页面和宿主身份，只切换可见性与命中。不能切一个标签就销毁重建网页而丢失表单、历史或登录态。
- 隐藏的编辑器与原生网页不得抢键盘焦点；切换时完成 IME 组合与草稿保存，不让 Enter 落到隐藏的发送按钮。

### 9.4 模型与命令作用范围

- 新增统一视图层标签模型，明确 `conversation | file | browser` 三种类型及 owner chatId；对话首项可作为派生视图插入，不把它写成一个 `FileTab` 文件路径或假的浏览器 pageId。
- 沿用主进程对浏览器顺序、活动页及跨窗转移的权威状态；不让新的同栏视图抢写另一个网页顺序源。文件混排槽位和展开活动项需确定统一保存／恢复规则。
- 浏览器右键只作用于 browser 项。刷新、静音、复制网址、固定、移窗、关闭其他网页、多选网页等命令不能覆盖对话和文件；“关闭其他网页”不删除首对话项或文件。
- 混排栏的可视索引与浏览器索引分别处理。主窗口展开时 Ctrl Tab／Ctrl Shift Tab 切换统一栏的对话／文件／网页；Ctrl/⌘ 1–8 与 Ctrl/⌘ 9 按统一栏选择第 1–8 项／最后项，固定对话是第 1 项。独立浏览器窗口保持仅网页索引。原生网页焦点下的快捷键转发必须按宿主分派，不能跳过首对话或把统一栏索引传给浏览器数组。
- 统一栏使用 tablist／tab／tabpanel，Tab 只停在当前选中标签；左右键及 Home／End 移动并激活标签，各内容已挂载的前提下保持快速切换。隐藏的 DOM 面板退出 Tab 顺序，原生网页同步停用命中。关闭或移出活动资料后，将焦点交给按稳定 ID 确定的回退标签；关闭当前对话首项仍按第 9.2 节恢复分栏，不删除对话。
- 对话项提供对话动作，文件项提供文件动作；弹出菜单仍按原目标和有效身份执行，后台右键不误切当前页。
- 按 chatId 保存展开状态与活动视图。切换到另一对话后不得显示上一对话的草稿、文件、网页或旧首标签；异步页面事件必须校验 owner。
- 独立浏览器窗口继续是浏览器宿主，不因本轮主工作区同栏而自动加上完整对话；跨窗拖动不支持的对话项要明确不可拖出，不能伪装成功。

### 9.5 与旧规划的衔接

保留 V2 第 24 节已实现的浏览器标签尺寸、菜单、真实关闭确认、页面身份、恢复和转移链路。本节新增的是主工作区展开后的共同容器与对话视图；不是重做浏览器管理。旧的 `browserExpanded`、布局宽度和 `FileTabs.active` 不能单独承载所有新状态，应先完成视图状态契约再修改正式挂载结构。

## 10. 实施批次与验收

### 第 0 批：本轮规划与示例

交付本文件与独立示例。示例包含附加按钮与 `/`、添加／工具两组、示例来源插入、文本与引用穿插、格式化效果，以及工作区展开／恢复、对话／网页／文件切换。所有演示数据标明示例；工具和发送操作只演示反馈，不声称执行真实创建、读取或提交。

验收看布局和交互是否便于理解，检查空白、长名称、多个引用、菜单翻转、窄宽度和焦点外观。示例成功不计为真实 IME、多端同步、主进程浏览器和发送链路已经通过。

### 第 1 批：附加菜单、命令与输入区视觉

统一名称与命令清单；按钮及 `/` 进入菜单；接入已有文件／页面／会话来源和创建器导航；定点修复内部矩形焦点。已有块和发送格式先保持完整可用。

完成条件：无两套菜单数据、来源取消不改正文、入口都保留正确选区、没有无效占位命令；鼠标和键盘能完成五个默认入口，IME 不误发，原生网页不会盖住浮层。

### 第 2 批：行内引用与端到端文档迁移

完成 schema v2、行内节点、转换、编译、去重、格式一致性、复制粘贴和所有草稿／队列／快照路径。

完成条件：句中插入准确；删除、重复引用、转换和撤销后的实际提交与可见文档一致；重启、切换对话、排队编辑、失败重试和旧文档迁移保留来源；不支持新结构的客户端不能丢节点覆盖草稿。

### 第 3 批：展开后的共同标签栏

先定义三类视图模型与唯一会话挂载，再接入展开／恢复、首对话项、活动项保存、文件／网页切换与命令作用范围。

完成条件：反复展开、切对话／网页／文件并恢复分栏后，草稿、选区、消息／文件滚动和页面状态保留；任务不重启；没有重复消息订阅或编辑器；关闭最后资料页正确回退，浏览器批量菜单不会影响对话或文件。

### 第 4 批：逐类扩展来源

按第 8 节优先级加入技能／插件资料、已完成产物、其他对话和精细范围。先完成身份、版本、预览与发送语义，再暴露入口。

每类来源的共同完成条件：真实可访问、可预览、可插入、可编辑／移除、可持久化、发送结果可核对、取消／失败可恢复、对话边界不串用。需要运行意图或新权限的功能必须有独立且可理解的语义。

## 13. 弹出层使浏览器视图变白的回归方案

状态：本轮根据用户截图完成代码与 Git 差异定位并加入规划，**尚未修复生产代码，也未操作真实用户页面或取得该实例运行日志**。应先恢复这个故障，再实施新的附加菜单与工作区样式。

### 13.1 已证实的代码链与尚待验证的部分

当前浏览器更多操作使用 `ActionMenu`，打开后令 `BrowserTabPanel.vue` 的 `moreOpen` 为真；`overlayCoversPage()` 随即判定页面被覆盖。组件会通过 `api.layout(pageId, null, layoutOwner)` 请求原生视图让出输入。`electron/modules/browser-host.ts` 的 `setLayout()` 收到空边界后设置 `host.suspended = true`，并对该宿主页面执行 `view.setVisible(false)`。

Git 差异确认：原来在隐藏前等待截图、解码并呈现替身图的流程，改为了发起截图后立即隐藏。关键差异如下，省略了不相关代码：

```diff
 if (covered && !frozenFrame.value) {
-  const frame = await api.preview(id.value)
-  if (frame) {
-    const image = new Image()
-    image.src = frame
-    await image.decode()
-    frozenFrame.value = frame
-    await nextTick()
-    await new Promise(resolve => requestAnimationFrame(resolve))
-  }
+  void api.preview(pageId).then(async frame => {
+    if (!frame || !current()) return
+    const image = new Image()
+    image.src = frame
+    await image.decode()
+    if (current()) frozenFrame.value = frame
+  })
 }
 await api.layout(id.value, bounds, layoutOwner)
```

主进程的 `browser-workspace-ipc.ts` 在 `capturePage()` 完成前、完成后都校验 `host.suspended`。可构成明确竞态：截图开始 → 空边界使宿主 suspended 并隐藏原生 view → 截图返回时因 suspended 被判无效 → `frozenFrame` 为空，显示槽位白底。这个时序与截图现象吻合；它是代码可证的高置信原因，仍需在隔离页面中记录实际调用次序，确认用户实例没有其他叠加原因。现有证据不支持直接归因 GPU、网页加载失败或 Electron 自身故障。

### 13.2 第 0.5 批：优先恢复故障的最小修复

保留“截图不能无限阻塞恢复控件”的要求，也恢复“隐藏前必须已有可显示内容”的顺序：

1. 打开浮层时创建可失效的 generation，绑定 `hostId + pageId + layoutOwner + documentEpoch`。截图与图片解码使用一个短 deadline（例如先以 150ms 为目标，再按实测调整）；超时或关闭浮层后立即让当前流程失效。`capturePage()` 的原生 Promise 不假定能取消，迟到结果通过 generation 丢弃。
2. 优先使用同页面、同文档 epoch、相同视口／缩放／滚动几何的最近有效帧；没有缓存时在 deadline 内取新帧。导航、移窗、页面切换、尺寸和文档变化使缓存失效，缓存只留内存。
3. 有有效帧时，至少完成 `image.decode()`、设置 `frozenFrame`、`nextTick()` 与下一渲染帧，再请求隐藏原生 view；每个异步边界都重新校验 generation。不能先隐藏，再寄希望于未来的截图补上白底。
4. 截图空值、失败或超时且无有效缓存时，菜单类操作回退原生菜单，或使用独立原生浮层承载菜单，让网页继续可见。Agent 等恢复控件也必须有不依赖截图的浮层通道；不以无限等待截图保证背景，不以直接隐藏留白保证按钮可点。
5. 最后一个覆盖层关闭后先恢复有效的原生布局，取得当前页面和 generation 的显示确认，再撤掉冻结图；关闭与重开交错时，旧恢复回执不得撤除新浮层的替身图。

不能仅删除主进程截图后的 `suspended` 校验；那会允许已切页、移窗或失效的旧帧被接受，且无法消除隐藏到截图完成之间的白屏。不能通过重载网页、重建 view 或禁用全部遮挡处理绕过故障，否则会损失页面状态或让网页盖住菜单。

### 13.3 统一遮挡协调的后续结构

将附加菜单、更多菜单、下载、地址建议、标签菜单及模态层归入一个按宿主管理的遮挡协调器，显式区分“页面不可见”“临时被浮层覆盖”“Agent 输入控制”，不再由每个组件把所有情况写入同一个 suspended 布尔值。

协调器使用覆盖原因令牌集合和 `live → preparing → frozen → restoring` 状态；多层浮层只释放各自令牌，最后一层关闭才恢复网页。输入焦点、可见性、页面身份、几何修订和缓存生命周期由同一代次管理，保留现有浏览器实例、表单、历史和登录状态。

长期优先让菜单／恢复控件在原生层级的独立浮层或菜单中呈现，避免普通 DOM 菜单依赖整页截图与隐藏来绕过原生视图层级。若使用新的 overlay view／窗口，需要明确宿主归属、屏幕坐标、DPI、焦点、关闭和跨窗隔离；仅提高 DOM 的 `z-index` 不能替代这个结构。
