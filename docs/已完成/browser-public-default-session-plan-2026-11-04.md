## 1. 实施前现状与调整依据（历史）

- `browser-registry.ts` 的会话绑定单个 `chatId`，分区由对话 ID 和序号组成，新页面继承会话归属。下载、权限确认、资源事件、关闭恢复也依赖这一关系，不能只增加一行“默认会话”。
- `browser_open` 和 `browser_session_create` 默认临时会话，专用持久化经过 `session.persist`。普通标签、资源侧栏与 Agent 又分别可能选第一个、最后一个或 `isDefault` 会话，需统一解析。
- 资源侧栏为“所属对话 → 会话 → 页面”，空会话另套折叠组，并重复显示数量、空提示和新建提示。既有 `isDefault` 是对话内偏好，不是公共会话。
- 独立窗口移回按钮在标签栏右侧，现有语义是移回当前窗口全部标签。尚未发现应用侧窗口置顶接口；原生 Electron 已具备所需窗口能力。

## 2. 会话模型

### 2.1 唯一公共默认会话

当前应用用户资料下固定一个“默认会话”，手动浏览和各对话 Agent 默认共用其中的登录、Cookie 与站点存储。不同应用用户资料继续隔离。推荐采用持久存储，重启后保留登录；界面名称统一为“默认会话”，公共属性放在图标提示或详情中。

默认入口始终存在，零页也可发现；真实 Electron Session 首次访问网络或打开页面时按需取得，不为展示入口创建网页或对话。关闭全部页面保留网站数据；默认会话不提供普通删除动作，可显式清除数据。

继续提供隔离的“临时会话”和“持久会话”，使用独立分区。不同账号、一次性环境、独立代理／User-Agent 或明确的隔离需求才创建专用会话。

### 2.2 存储共享，页面保留来源

将会话存储范围与页面所属对话分开记录：公共会话不绑定一个对话，页面保留实际创建来源 `chatId`，下载、权限、引用、日志和 Agent 控制仍据此归属。

- Agent 默认只列出和控制当前对话页面。共用登录不自动授予其他对话页面的控制权；跨对话引用与移交沿明确授权流程处理。
- 用户可通过“全部对话”查看和打开页面；界面查看范围与 Agent 控制权限分别校验。
- opener 打开的子页面继承来源页面的会话与归属，不从前台对话推断。
- 会话级下载及权限回调按请求 WebContents 定位实际页面。来源不明时不落到任意对话或他人下载目录。
- 删除／关闭对话只处理本对话页面与任务，公共登录和其他对话页面保留；专用会话按自身生命周期处理。
- 移窗、移回工作区保留原 WebContents、分区、历史、表单与 Agent 租约。现有跨对话窗口合并限制继续保持，不因共享存储顺带放开混合窗口。

## 3. 统一创建与复用

所有新建入口使用同一个会话解析服务，按以下优先级选择：

1. 明确指定且有权使用的会话，或从已有标签／opener 新建：继承来源会话。
2. 明确需要临时或持久隔离：创建或复用当前任务的专用会话。
3. 无隔离要求、无来源：取得唯一公共默认会话。

普通 Agent `browser_open`、无来源的手动新建和 API-only 的 Session.fetch 使用公共会话。复用页面的效率规则仍针对当前对话；其他对话已开公共页面不阻止当前对话建页，也不会被直接接管。

应用工具契约拟增加明确的范围选项，并返回实际范围、是否复用及页面来源，具体字段实施时定稿。`browser_session_create` 默认模式应幂等取得公共会话，显式专用模式才创建隔离分区；底层创建方法保持显式策略，不静默改变全部旧调用。同步删除工具说明中的“默认临时”和“已有资源时先清 Cookie”等旧指引。

兼容旧工具调用显式的 `persist:true/false`，分别按原有专用持久／临时请求解析；新范围与旧参数冲突返回参数错误。省略参数的新调用统一公共默认会话。

公共持久数据按应用默认浏览器资料策略管理，网站访问和敏感操作继续执行授权。新建专用持久会话沿用 `session.persist`；既有明确拒绝策略需在升级时映射和说明，不因默认值更改绕过。拒绝或策略冲突应如实返回，不暗中切换会话。

清公共 Cookie／站点数据及修改代理、UA 会影响所有使用者。Agent 遇到账号冲突应优先创建专用会话，不能为单个任务随手重置公共环境。共享范围的破坏性操作需要说明影响并确认，检查关联页面及任务；失败保留可重试状态。普通关闭／停止只作用于请求范围。

## 4. 资源侧栏

### 4.1 会话优先，两层展示

保留标题“浏览器”、搜索与紧凑的当前／全部对话筛选。主体调整为：

- **默认会话**固定在前，展开后直接列页面。
- **专用会话**按名称展示，展开后直接列页面，存储类型用简短标记或提示说明。

去掉外层“所属对话 → 对话名称”树，同一个公共会话只出现一次。页面图标和标题为主，所属对话在全部范围中作为次要信息；当前范围不重复标来源。默认会话使用公共／浏览器图标，专用会话沿会话图标，不与窗口置顶混淆。

### 4.2 筛选、计数、搜索

- 当前对话：默认入口常驻，子页面只显示当前对话页面，专用会话同样按归属过滤，数量只统计可见范围。
- 全部对话：默认节点只出现一次，展示全部可查看页面，页面行可附所属对话短标签；专用会话保留真实归属。
- 无当前对话：使用全部范围，默认入口仍可见。新建沿现有所属对话选择流程，不制造隐藏对话；有当前对话则直接采用。
- 有页面／全部会话移入列表更多菜单，默认隐藏无页专用临时会话；空持久会话通过“显示空会话”或搜索可发现。默认入口不受空会话过滤影响。
- 搜索会话名、页面标题／URL 和所属对话名。匹配会话显示其中符合范围的页面，匹配对话仅显示相应页面。默认入口保留，但不混入不匹配页面；无结果提示只出现一次。
- 数量随筛选更新，零页时不同时堆叠“0”、空组、“暂无页面”和“在此会话新建页面”。

### 4.3 精简提示与动作

删除“所属对话”汇总行、重复“当前”标记及层层说明；会话只有一条简短空状态，创建入口沿加号／会话菜单提供。新建、存储说明、清理等放到原生菜单。会话菜单删除含混的“设为默认会话”，使用明确的“在此会话新建页面”。

主列表只使用一个滚动容器，滚动槽留在行元素外；会话展开不再嵌套滚动。长名称省略、状态不改变行高，筛选刷新保持仍有效的展开项、滚动与键盘焦点。悬浮侧栏沿既定原生能力接入，不增加截图替换路径。

## 5. 独立浏览器标题栏

从左到右为：**移回工作区 → 置顶窗口 → 标签页 → 新建标签页 → 列表／拖动留白 → 系统窗口控件**。macOS 的最左侧应用按钮位于原生红黄绿预留区之后；Windows 保留右侧原生系统按钮。

- 移回和置顶与新建标签页共用尺寸、圆角、主题、悬停／按下／焦点反馈，不做额外的大按钮。
- 移回继续执行当前窗口全部标签移回，多页提示数量。成功后回收空窗口；失败保留页面和顺序，不能只移回选中页却关闭其他页。
- 置顶只作用于当前原生浏览器窗口，区别于标签固定。默认关闭，按窗口生命周期保存；新窗口不继承，移回后不置顶主窗口。
- 按钮提供选中态、`aria-pressed` 与“置顶窗口／取消置顶”提示；菜单与按钮共享原生状态。应用侧补来源验证接口，调用现有 Electron `setAlwaysOnTop` / `isAlwaysOnTop` 及状态事件，不乐观假定成功。
- 来源只允许控制请求所属的可信独立窗口，销毁时清监听。切标签、最小化／恢复状态一致，按钮操作不打断网页输入或 Agent。
- 左侧按钮属于非拖动区域，不参与标签排序；窄窗口先压缩标签区域。去掉旧右侧移回专用留白，重新测量标签和网页边界，保留系统控件与可拖动区。

窗口置顶可使用现有 Electron 能力，不需要额外内核定制；图标继续使用项目既有体系。

## 6. 迁移与实施顺序

1. 拆分存储身份与页面归属，定义公共会话唯一身份、恢复格式与统一解析器，同步下载／权限／网络请求和资源事件路由。
2. 接入工具契约、提示和所有手动创建入口，验证公共复用、专用隔离与旧参数兼容。
3. 调整资源列表、范围、搜索、空状态及菜单，清理旧的重复说明。
4. 移动独立窗口按钮、增加置顶接口，复查拖动、标签宽度与原生网页布局。
5. 运行迁移与真实浏览器回归，记录实际完成状态；按届时明确的交付范围验收，不将 0.3.40 或原截图清理等待条件混作本专题完成证明。

旧专用会话保留原 ID、partition、登录与数据，不自动复制 Cookie 到公共会话。旧 `isDefault` 保留为历史偏好，但不抢占公共默认入口；默认改变不声称旧账号已经迁移。

恢复时先建立公共会话身份，再按每页归属恢复宿主；旧记录缺页面来源时继承原会话 `chatId`，已删除对话的页面不转入其他对话。数据格式带版本，升级保留可回退记录，不在迁移时清除网站数据。

## 7. 验收重点

- 两个对话及并发首次打开只取得一个公共会话，页面、任务、权限、日志和下载仍正确归属；不跨对话误控制。
- 真实 Cookie/localStorage 在公共页面间共享、重启保留；专用临时／持久会话隔离，旧分区账号可继续使用。
- API-only、新标签、opener、关闭恢复、显式专用请求、旧参数与拒绝策略按一致规则执行。
- 对话关闭／删除和共享数据清理不会误停其他任务；取消、失败及并发操作不破坏资源树与数据。
- 当前／全部、零页、无当前对话、搜索、空会话发现、窄栏、滚动及键盘操作无重复默认节点和无效提示。
- 各主题／DPI 下独立窗口左侧布局、移回全部标签、置顶和菜单状态同步正确；网页实例、焦点和 Agent 连续性保持，未新增截图替换。

以上为原规划的验收要求；用户随后要求实施，已完成源码与公共 32 项／专用兼容 14 项、网络 26 项及真实资源界面 6 项隔离检查，详见[实施记录](../automation-and-browser-followup-implementation-2026-11-04.md)。公共无来源 Service Worker 的规则／日志覆盖明确不完整，不把共享 Cookie 解释为跨对话页面权限。

## 8. .6 核对后补齐的实施前契约

### 8.1 使用、观察和管理分开授权

`browser-network.ts` 当前按 sessionId 聚合请求规则、日志、观察和清理。公共会话迁移不能仅放宽 `assertSessionOwned()`：本对话可使用共享存储发起自己的请求，不因此获得其他对话网络正文、请求头、日志或拦截规则的读写权。

规则、观察和日志按实际页面／请求发起上下文投影；Session.fetch、worker 和下载需要显式请求归属，无法可靠判定时不回退到前台聊天。代理、UA、全量 Cookie 导出与清理归共享管理，不作为普通页面操作的旁路。资源树与变更事件也按各对话可见页面投影，公共节点只展示一次。

### 8.2 持久化策略兼容

- 显式临时请求保留隔离与临时语义；显式持久请求继续通过既有持久化授权。
- 省略范围使用公共默认会话；首次自动创建公共持久分区或启用保留策略时尊重现有拒绝与确认策略，不能由升级自动旁路。若阻止创建则返回真实原因，不暗中换成空账号／临时分区。
- 已经合法建立的公共会话按使用权限复用，不每次开页重复申请“创建持久会话”，也不把禁止新建解释成删除、清空或强制关闭已有资料。
- 运行中撤销授权对后续未授权操作生效；不追认以前的拒绝。未来确需改变既有降级行为时，结果结构和用户说明明确标注，不只改提示词。

这是应用权限兼容决策，与 `.6` 的原生面板能力无关；不新增日常浏览逐步确认。

### 8.3 恢复与共享管理

恢复格式保存稳定公共身份、真实 partition、逐页 chatId、宿主与顺序、格式版本；零页公共会话不能因无 session.chatId 被丢弃。旧记录逐页继承原会话来源，已删除对话不转归别人；缺失的持久分区明确异常，不静默建另一个空账号。

既有恢复限制包含最多 100 会话／每会话 32 页；公共唯一会话会改变这些限制的含义。实施时按现有总页面配置和各对话资源预算核对，不把全部公共页面误截为一个旧会话的 32 页，也不绕过原有总配额。主文件升级前保留版本备份，失败不写回空列表；回退版本读取旧备份而非破坏新公共资料。

公共首次取得有幂等锁；清理／代理／UA 变更串行化，并覆盖在途 Session.fetch、worker、下载和恢复，不只锁页面按钮。等待授权后复核来源、策略和操作代次；任务停止或普通关页不能 dispose 公共网络处理器或停止他人请求。删除对话改为逐页处理本对话，不调用会话级清数据路径。

### 8.4 新增验收

除第 7 节外，必须用两个真实对话验证网络规则／日志互不越权、未知请求归属处理、公共分区超过旧单会话恢复阈值、零页重启、拒绝创建与合法复用的区别，以及共享管理与无页面请求并发。通过这些后再切换默认创建入口和简化资源侧栏。
