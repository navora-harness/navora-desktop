## 1. 面板外观与结构

目标旁显示轻量圆角长方形，而非随高度增大仍保持半圆端部的胶囊。建议宽 360–440 CSS px，外圆角固定约 12–16 CSS px，外边距与主题一致，细边和轻阴影；窄窗口按可用空间收缩。

内部从上到下为：

- **多行输入区**：无重复内部边框，placeholder“添加评论…”，允许自动折行和手动换行。
- **固定动作区**：左侧仅在必要时显示保存状态／错误，右侧“收起”“确认”。常态不堆帮助段落、字数或更多工具。

输入上内距约 12px，正文约 14px／22px 行高，输入与动作区间距约 8–10px；按钮视觉高约 30–32px。数值是应用样板候选，接入后按 DIP、字体和系统缩放核验，不作为任意内核接口已经存在的声明。

面板继续紧邻当前选区和蓝色锚点。原蓝框、锚点与独立批注光标沿选择层处理，评论正文只在 NativePanel 中；不通过额外 WebContentsView 或截图背景呈现。

## 2. 高度随实际内容变化

空态建议预留 2 行输入，输入时按**真实排版高度**增高，默认到约 8 行；确认按钮和收起按钮始终在输入区下方可见。整体建议最小高约 110px，默认上限约 250–280px，最终还受当前屏幕／窗口实际可用高度约束。

高度计算必须包含软折行、字体／行距、中文、emoji、粘贴和实际输入宽度，不只数换行符，也不按字符数估算。删字后允许回落到最小高度，避免内容清空后仍占大块空间。

- 达到上限后只让输入区内部滚动，底部动作区不跟着卷走。
- 确定最大输入高度前，先为上下内距、按钮区、错误行和间距预留空间；空间不足时优先减小输入可见行数，不把按钮裁掉。
- 面板位于页面下缘时向上展开，空间不足再翻转／移动；尽量保持锚点关系稳定，不因每输入一个字上下跳动。
- 字体、窗口宽度、应用 zoom、系统 DPI 或显示器改变后重新测量。移动的是批注面板，不改变网页 viewport，也不重建页面。
- 输入法候选期间保持 caret 和候选窗可见，尺寸更新不得清组合、抢焦点或移动到另一显示器；可合并同帧尺寸更新，不牺牲输入响应。

## 3. 键盘与中文输入法

- **Enter**：编辑区聚焦、非组合态且无修饰时，确认保存当前全文。
- **Shift+Enter**：插入换行，保持编辑，不保存；达到最大行数时滚动输入区。
- **输入法确认键**：中文／日文等组合态下 Enter 先确认候选，不能同一次事件又保存；组合结束的按键周期也要防重复提交。
- **粘贴**：多行文字按文本插入，保留段落和换行，不因文本含 Enter／换行而触发提交。
- **Esc**：先交输入法取消组合，再收起面板并保留草稿；本次 Esc 不顺带退出批注模式。
- **Tab／Shift+Tab**：在输入区及底部按钮间按序移动。按钮聚焦时用原生键盘激活；其他 Ctrl／⌘／Alt 组合不自动解释成确认。

长按 Enter、连续点击确认和键盘／鼠标同时确认只产生一次提交。选中文字、撤销／重做、光标导航和普通编辑快捷键保持原生行为。编辑区中的空格永远正常输入，不触发页面的临时浏览快捷键。

Enter 保存与“确认”按钮必须执行同一条校验／保存流程；不能一条路径保存全文，另一条只保存最后收到的旧 change 值。

## 4. 底部按钮与状态

首批保留两个清晰动作：

- **收起**：先保留草稿，再关闭当前编辑面板；不写入新的历史批注，不清除正文。放弃／删除仍从草稿或列表的明确动作执行，避免“取消”到底是否丢文字的歧义。
- **确认**：保存当前批注。只有空白时禁用，保存中防重复；主进程确认成功后收起、返回待选，并更新已保存数量。保存失败时全文、选区和光标保留，就地重试。

允许后续在输入框下方同一 row 中增加有真实动作的按钮，不把按钮塞回文本框右端，也不增加第二套常驻工具栏。首批不加入截图麦克风或未实现动作。

状态提示只在草稿未同步、保存中、失败、冲突或接近长度上限时出现；常态不反复显示“草稿已保留／Enter 保存”等说明。错误导致面板增高时仍按屏幕上限保留按钮。

## 5. .7 已发布能力与剩余契约

已从 `.7` npm 分发包中的 `electron.d.ts` 核对独立 `textarea`、`submitOnEnter`、面板及编辑器的 `scrollbarPlacement`，并核对同一发布 manifest 对应的原生验证报告。它们已进入本次分发；包内部分文档仍沿用“source-preview／未包含于 .6”的历史说明，以 `.7` 发布清单、公共类型和同哈希安装验证区分已发布状态，不能沿用旧文案认定它们尚未发布。

真实排版自动增高、内容／期望尺寸通知、关联按钮提交快照、组合状态事件仍未出现在公开类型中；以下分别标明可直接接入和待补齐部分。基础多行已可接入不等于用户要求的整套批注编辑体验已经完成。

### 5.1 原生编辑与提交

已发布 `type: 'textarea'`，支持原生自动折行、多行编辑和内部滚动，沿用 `value`、`placeholder`、`maxLength` 与通用样式。`submitOnEnter` 默认 `true`：非输入法组合态且无修饰的 Enter 发送 `action: { id, type: 'submit', value }`，其中 value 为该控件的当前全文；Shift+Enter 换行。设为 `false` 时 Enter 也换行。旧 `input` 仍为单行，不使用不存在的 `input.multiline`，也不添加 Ctrl+Enter 保存规则。

分发方真实测试包含中文 IME、首个 Esc 优先交给组合、候选确认后再提交，以及独立保存／取消按钮使用宿主草稿。该证据不能替代应用接入验收，也不承诺所有输入法均无按键周期边界问题。

独立按钮的 `click` **仍不携带输入全文**，发布文档要求宿主追踪编辑器 `change.value`。底部确认先使用稳定编辑器 ID、单一面板事件序列和草稿版本衔接同一校验／保存流程，不能在按钮回调中猜测当前文字或读取测试私有状态。公开 API 没有组合状态通知、按钮关联编辑器提交或原子读取快照保证；尤其要单独验证“正在组合时立即点确认”“最后一个字符后立即点击”“收起前组合提交”不会保存旧草稿。无法证实时保留此门槛并要求最小原生契约补齐，不以延迟若干毫秒或旧 change 值当作已解决。

### 5.2 自适应尺寸与固定动作区

**仍未满足：**`.7` 的 textarea 使用指定 `height`，超出后内部滚动；发布文档明确“不自动增长”，公共类型也没有 autoGrow、行数边界或原生内容尺寸事件。固定高度用于隔离验证及接入样板，不能作为用户已同意的最终替代，自动增高仍是本规划完成条件。

目标仍为原生根据实际多行排版自动增长，允许设置最小／最大可见输入高度或等价行数，并在上限后只滚动编辑区。不能只新增 textarea 类型就宣称已满足自适应需求。

如果需应用协调面板位置，原生应提供可验证的实际内容／期望尺寸或尺寸变化通知；坐标空间明确为 DIP，并与当前编辑器及版本对应。应用根据测量值更新，不用隐藏 HTML textarea 重新测量原生字体。

已有 `column` 容纳编辑区及下方 `row` 可直接用于圆角长方形和固定动作区的正常空间样板；外圆角使用 NativePanel 的 `radius`，不改变网页 WebContentsView。编辑器与面板外层分别明确设置 `scrollbarPlacement: 'gutter'`；列表也独立设置，不能以为面板选项会向内继承。gutter 只在已分配边界内为内容预留 12 DIP 滚动条区域，不把滚动条画到面板或编辑器边框之外。正文内距不控制滚动条离边框的距离，文本框内不选可能遮挡文字的 overlay。

低高度／屏幕裁切时仍需先按实际可用高度约束编辑器，保证动作区可见。`.7` 面板可整体约束并滚动，但无固定页脚／最小编辑高度公开字段，不能直接承诺任意小屏都会只滚动正文。后续布局契约或应用可验证的尺寸协调必须满足本要求；不得由最外层滚动把整排按钮卷走。

### 5.3 更新、焦点和生命周期

同 ID／type 更新按公开契约保留输入、焦点与滚动；接入还须验证文本与尺寸变化不重置 caret／选区、撤销历史或 IME，不能把全部编辑状态的保留视为无需实测的保证。状态或列表刷新省略旧 value；只有明确恢复或切目标才替换全文。

从旧 input 变为 textarea 是控件类型变化，不能当作无损热切换。升级或切换前先保存目标草稿，新会话再创建正确控件；旧回调按目标、文档代次、编辑版本和请求代次拒绝。

NativePanel 仍由真实所属窗口管理，支持隐藏复用、窗口销毁释放、导航／移窗失效和焦点恢复。外部点击关闭、父子菜单及点击传播问题继续单独核验；新增 textarea 不自动解决这些旧缺口。

## 6. 正文、草稿与旧记录

新建及编辑已有批注统一使用同一套多行面板，不再把长评论转到额外详情编辑器。保留现有最大 4000 UTF-16 码元的正式提交校验，完整保留用户文字和 emoji 是接入目标，**不能仅设置原生 maxLength:4000 就认定已经无损**。

`.7` 已知限长风险：已核对发布报告对应的 `native_panel.cc`，ContentsChanged／ApplyDeferredInput 直接用 UTF-16 `substr(0, limit)` 截断；当 3999 个普通码元后输入一个代理对 emoji 时，4000 的边界会落在代理对中间，随后转 UTF-8 存在替换／损坏风险。组合态暂不截断却仍发送 change，可能超过 4000；当前 `browser-annotation-drafts.ts` 的已存批注草稿和新目标草稿均拒绝超限文字。这是静态核对的接入风险，本轮未运行复现；原有“含 emoji”的发行限长案例没有覆盖这个断点，不能当作已经解决。

实施前选择并验证完整无损策略：优先补齐 Unicode 安全的原生限长与组合提交边界；如应用选择关闭原生硬截断，必须同时提供有明确长度／资源上限的溢出／组合草稿保存、冲突和重启恢复路径，不能只改 maxLength 就把超限内容交给会拒绝的旧草稿库。正式意见仍按 4000 校验，超限不提交、不静默裁字；不能等原生已损坏后再用二次截断假称恢复。收起／关闭前无法确认全文已保留时，不得标成“草稿已保存”或丢弃最后输入。

读入兼容 LF／CRLF，提交明确换行规范，旧修订和证据不被界面打开或摘要刷新重写。列表仍可首行省略，编辑时加载原全文；多行粘贴不再降级到单行。

草稿包含目标身份、全文、基线 revision、编辑器版本和请求序列。提交时冻结该版本，等待必要的草稿同步；确认期间的新输入保留为新草稿或暂时受控，不能被旧成功回包清掉。修订冲突保留副本，不覆盖其他窗口更新。

保存仅改变批注记录，加入对话仍是列表中的显式动作，发送任务仍由用户在聊天输入区执行。计数只在记录成功后更新，未确认文字不计入已保存批注。
