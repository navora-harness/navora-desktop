## 1. 两个已找到的直接原因

### 当前查找会展开侧栏、改变工作区

[ChatPage.vue:1439](../../src/pages/ChatPage.vue#L1439) 的 `openConversationFind()` 不只打开查找：它还执行 `activateSidebar('chats', false)`、清除工作区模式，并在覆盖布局中调用 `hideFileWorkspace()`。前者实际展开聊天列表并保存侧栏状态，因此用户看到的侧栏弹出是入口本身造成的。

改为专用搜索入口：打开、输入、重新打开和切换搜索范围都只操作搜索状态，不改变侧栏开关、分栏宽度、活动标签或工作区展开状态。需要导航到隐藏聊天时，在用户执行命中跳转时才显示对应聊天内容；不展开左侧聊天列表。

### 全局搜索的输入模式不等于真实聚焦输入框

全局搜索已使用 NP，但 [native-dialog-panels.ts:12](../../shared/native-dialog-panels.ts#L12) 将包含关闭按钮的标题行放在输入框之前。当前定制内核的 `input` 模式只在没有焦点时向后选择可聚焦控件，并不专门定位 input，因此可能先聚焦关闭按钮。现有 `chatSearchInput?.focus()` 针对未挂载的 HTML 回退输入框，对 NP 不起作用。

另一个问题是原生实例复用：已显示时再次 `show()` 不保证重新聚焦；重复设置打开状态也不会自然触发新的显示请求。需要明确的“用户再次打开／聚焦搜索”请求，不能只增加一次 DOM `focus()`。

## 2. 搜索范围与入口

本次“工作区搜索”默认定义为**当前打开的活动标签页内容查找**，不是公网搜索、全盘文件扫描或后台全部标签搜索。

- 无工作区：只提供“当前聊天”。
- 主窗口已打开工作区：提供“当前聊天”和“当前活动标签页”。浏览器使用地球图标；文件使用文件图标；子对话使用对应聊天标识。
- 点击“在当前聊天中查找”：默认选择当前聊天，工作区现场保持。
- 在网页／文件内容区按 Ctrl/⌘F：默认选择该工作区活动标签；从聊天区按键则选择当前聊天。
- 独立浏览器窗口：只查该窗口自己的活动网页；独立文件窗口只查自己的活动文件，不暗中操作主窗口的聊天。
- 活动标签可能属于另一聊天，查找使用标签自身的归属及权限，不能借用主窗口当前聊天 ID。
- Ctrl/⌘K 保持“全局搜索聊天”的既有语义，沿用相同顶部输入样式；选择结果后才切换聊天。打开全局搜索本身也不提前关闭工作区。

同一搜索会话切换范围时保留关键词，清除旧范围高亮并重新计算序号。切换标签／导航时绑定新目标和查询代次；目标关闭后，主窗口可回到仍存在的聊天范围，独立窗口显示目标不可用或关闭面板。

“所有已打开标签”及全文磁盘检索不纳入第一版，避免引入后台页面操作和额外索引。

## 3. 顶部搜索卡设计

使用真实 NativePanel，继续使用现有 Fluent 图标和主题。搜索卡作为窗口级浮层，不占用聊天或网页布局高度，不创建网页截图占位。

```text
空关键词：
┌─────────────────────────────────────────────┐
│ 搜索图标  搜索当前聊天…   聊天  网页  │  关闭 │
└─────────────────────────────────────────────┘

有关键词：
┌─────────────────────────────────────────────┐
│ 搜索图标  自动化          聊天  网页  │  关闭 │
├─────────────────────────────────────────────┤
│ 上一个  下一个                    2 / 8 个匹配 │
└─────────────────────────────────────────────┘
```

- 空输入只显示一行；没有工作区就省去范围按钮。
- 查找为非模态浮层，不使用全窗遮罩；点击原页面可继续阅读或操作，搜索条保留且不抢回焦点。使用公开的 `dismissOnOutsideClick:false`、`dismissOnEscape:true`，并保留显式关闭按钮。
- 有有效关键词后向下展开计数行；上边缘固定，避免输入时搜索卡上下跳动。
- 查找中显示“查找中…”，零命中显示“0 个结果”并禁用上下项；不支持的内容显示明确说明，不能显示假零结果。
- 范围按钮有选中背景、提示及可访问名称，保持图标紧凑；文件范围提示具体文件名，网页范围提示当前页面标题。
- 现有“区分大小写”“包含工具与日志”保留在低频选项区域；后者仅对聊天范围有效。选项不得抢占主输入行。
- 全局搜索使用相同的输入行，下方显示对话标题、简短命中摘要和时间；结果随条数增长，不继续固定预留 380 高空白。全局计数说明“对话数”，不与页内匹配次数混淆。
- 建议桌面宽约 420–480 CSS px、空态高约 48–56；实际宽度取当前窗口顶部安全区的可用宽度。窄窗缩短输入区并保留必要按钮，不缩小到难读字号。
- 搜索采用专用顶部锚点，不全局修改所有 `NativePanelDialog` 的居中定位。避开系统窗口按钮、标签工具和拖动区域；原生内容树宽度及文字预算同步收缩，不只移动锚点。

## 4. 查找引擎适配

### 聊天与子对话

复用 [ConversationFind.vue](../../src/components/ConversationFind.vue) 和 [conversation-find.ts](../../shared/conversation-find.ts) 的现有查找语义，抽出可由 NP 驱动的控制器。保留防抖、实时答复去重、可选工具／日志、高亮、折叠内容定位和退出后恢复临时展开。关闭跟随到底部的行为只发生在实际命中导航时。

搜索数据与 DOM 是否正显示分开：聊天处于工作区后面时仍可计算结果，不通过打开侧栏来“获得可搜索内容”。用户导航命中后再展示对应聊天视图并定位。

### 浏览器标签

复用 [browser-workspace-ipc.ts:105](../../electron/modules/browser-workspace-ipc.ts#L105) 的 `find/stopFind`、结果总数／当前序号、token 和文档归属校验，替换 [BrowserTabPanel.vue:387](../../src/components/BrowserTabPanel.vue#L387) 的 HTML 查找条展示。

仅查当前窗口所属、活动且可见的目标页。保留批注和进行中操作的现有限制，遇到受限状态给明确提示，不为了搜索绕过 Agent 输入或布局保护。换标签、导航、移窗和关闭时清理旧请求与高亮，迟到计数不能写到新目标。

### 文本、代码和 Markdown 文件

[FilePreviewPanel.vue](../../src/components/FilePreviewPanel.vue) 目前没有查找接口，代码也是只读文本，不是代码编辑器。新增当前可见内容的查找适配器：Markdown 预览搜渲染文字，源码模式搜源码；切换模式重新计算并保留关键词。

HTML 文件保持按源码预览，不执行。大文件目前只显示前 256 KB，结果需说明“当前预览内容”；不能声称搜过整个文件。图片、当前不支持预览的 PDF／Office 等显示“不支持当前内容查找”，不自动新增 OCR、解析器或磁盘读取。浏览器内 PDF 查看器另做能力实测，不提前宣称支持。

## 5. 每次打开自动聚焦

统一要求适用于当前查找、全局聊天搜索、工作区文件搜索及标签搜索等搜索型浮层。地址建议继续保留焦点在原地址输入框；普通确认框不因此自动改焦点行为。

实施规则：

1. 搜索输入框是原生树中第一个可聚焦控件。搜索图标可在前，范围、关闭、刷新和结果按钮排在后面。
2. 首次、关闭后重开、已打开时再次点击或再次执行搜索命令，都产生显式聚焦请求。
3. 当前 `.9` 没有公开 `focusControl` 或选择范围 API。应用侧可在显式打开时通过公开 `destroy → show(focusMode:'input')` 建立新显示会话，由宿主状态恢复关键词；不依赖私有 `_getState`，也不承诺本版没有公开能力支持的“自动全选”。
4. 一次打开期间的计数、列表、主题和尺寸更新只 `update`，保持 input ID，并省略更新中的输入值，避免重置选区和 IME。不能每次输入或结果返回都销毁重建。
5. 关闭后回到当前有效的聊天／文件／网页焦点。外部点击或切到另一窗口时不强行抢回焦点；异步旧显示请求不能在新窗口抢焦点。

重复聚焦需要给搜索宿主增加明确的请求代次／入口，不能依赖 `v-model` 从 true 再赋值 true。

### 当前 NP 键盘能力的验收门槛

公开 input 仅有 change/submit，Enter 可以接下一项；事件没有修饰键、选择范围和组合输入状态。不能把现有 DOM 的 Shift+Enter/F3 处理直接搬过去就宣称成功。

NativePanel 有独立原生窗口，当前公开接口未提供通用键盘转发。本段涉及的 NP 持焦 Ctrl/⌘F、Ctrl/⌘K、F3、Shift+Enter 和 F11 转发已按用户要求取消；保留搜索方向按钮、全屏按钮及宿主既有快捷键，不再以这组按键作为完成门槛。

## 6. 真正窗口全屏，优先独立浏览器

当前项目仅接入最小化、最大化和还原，尚无 `setFullScreen/isFullScreen`、F11 或完整全屏生命周期；移动端对话框的 `fullscreen` 和“展开工作区”不等于系统窗口全屏。

### 窗口全屏

- 为受信的本地应用窗口增加全屏切换、查询和状态事件；操作当前宿主 BrowserWindow，而不是 WebContentsView 或主窗口的固定引用。
- F11、应用菜单和独立浏览器可见入口进入／退出真正全屏；最大化按钮继续保持原语义。浏览器 guest 持焦时通过所属宿主转发，NP 持焦转发已取消，不列入本轮键盘验收。
- 主窗口、独立浏览器和独立文件窗口各自维护状态，互不切换或抢焦点。
- 保存进入前的普通窗口边界和最大化状态；退出后恢复。窗口状态保存逻辑不能把全屏屏幕尺寸写为下次普通窗口大小。
- 第一版保留必要标签／地址工具与明确退出入口。全屏时调整 Windows 标题按钮的预留空间，避免系统按钮已隐藏但右上角仍留大块空白。
- 进退全屏、切屏、DPI 和缩放变化后，等待布局稳定再更新真实 View 边界和搜索树宽度／顶部锚点。保留 WebContents、页面内容、草稿和 Agent 状态，不通过重建网页恢复布局。

### 网页／视频元素全屏

[browser-registry.ts:986](../../electron/modules/browser-registry.ts#L986) 当前权限处理只接受地理位置，其余权限包括 `fullscreen`、`automatic-fullscreen` 都会拒绝。需要单独接入当前前台活动页正常用户触发的网页全屏，并处理进入／退出生命周期；保持无手势自动全屏关闭，不放开其他未知权限。

区分网页元素全屏与窗口 F11 状态：视频退出后恢复进入视频前的 F11／普通状态，不能总是退到普通窗口。网页导航、标签关闭或移窗时清理该页面的全屏状态。元素全屏应占满可视区域，退出后恢复原固定视口和缩放偏好，不永久改写这些设置。

Escape 的处理顺序按当前接收者和状态确定：输入法先处理组合输入；NP 持焦时先关闭当前搜索；没有搜索且处于网页元素全屏时退出元素全屏；纯窗口全屏保留 F11 和可见退出入口，不用全局 Esc 破坏网页自身交互。

## 7. 全屏下的 NP 搜索

- 每个独立窗口自己创建搜索面板，使用该窗口的父窗口、内容坐标及当前目标，不由主窗口代开。
- 窗口全屏期间仍可打开聊天／网页当前查找；搜索卡位于所属窗口内容顶部安全区，避免被标签条、地址栏和系统窗口按钮遮挡。
- 进退全屏后同步更新原生树宽度、文字预算和锚点；150ms 位置轮询不能代替全屏与布局状态接线，也不重复乘设备像素比。
- 已打开的搜索通过布局更新保留查询和输入状态；不能因为窗口重排反复重新聚焦。若系统销毁原生弹层，应只在原请求仍有效、所属窗口仍活动时恢复。
- 网页视频全屏下的搜索由当前可显示内容能力决定，不强制唤出隐藏的应用栏；退出视频后恢复常规搜索位置。

## 8. 实施顺序

1. 拆出当前搜索控制器和范围适配接口，移除搜索入口引起的侧栏／工作区状态变化。
2. 实现顶部 NP 卡，接现有聊天与网页引擎，补文本／Markdown 预览查找；统一主窗口及独立窗口的目标归属和旧回执清理。
3. 修当前／全局搜索的首焦点与重复打开，复核文件／标签搜索；真实测试 NP 内组合键路由，明确是否需要定制运行时补充公开能力。
4. 接窗口 F11 全屏、还原及 View 重排；优先验收独立浏览器，再覆盖主窗口、独立文件和搜索 NP。
5. 接受控网页／视频元素全屏与嵌套退出状态，完成截图和行为回归后再决定打包版本。

## 9. 验收清单

- 点击当前查找不打开聊天列表、不关闭工作区、不改变分栏／标签；全局搜索未选结果时也不改变现场。
- 无工作区／浏览器／文本／Markdown／子对话／不支持内容均有正确范围和状态；计数、上下项、大小写、工具日志和实时消息保持原语义。
- 当前／全局搜索首次、重开、已经打开再触发、点击结果按钮后再次触发，都可以直接输入；用真实原生按键产生 change/submit 验证，不以 DOM focus 或注入 action 充当聚焦证据。
- 中文组合输入、Enter／Escape、结果刷新、点击外部、跨窗切换、导航和迟到结果不破坏草稿、焦点或作用域。
- NP 持焦快捷键转发已取消；确认可见的上下项、关闭和全屏按钮继续可用。
- 独立浏览器从普通／最大化状态进入全屏再还原；网页持焦、切标签、移回主窗口、跨 DPI／屏幕和缩放均检查；NP 持焦快捷键转发已取消。视频元素全屏嵌套 F11 的退出顺序正确。
- 开搜索不请求替代网页截图、不隐藏活动 View，原页面身份和 RAF 连续；全屏只作必要布局变更，不重建网页。
- 截图至少包含：无工作区空条、浏览器范围切换、有命中／零命中、全局结果、暗色窄窗、独立浏览器全屏和退出恢复。实际 NP 窗口截图与本文设计稿分开保存。

完整跨 frame 连续性、NativePanel Acrylic 和独立桌面自动化仍按此前决定搁置。本规划不把未实现的搜索／全屏能力计入已发布 0.4.6。
