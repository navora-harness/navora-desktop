## 目标与边界

打开普通菜单、搜索、编辑和资料浮层时，浏览器继续显示同一个实时网页 View；动画、网页任务和 Agent 操作连续运行。保留原有功能、主题、键盘操作、焦点恢复、草稿和取消语义。已有不重叠布局直接保留；只对真实冲突选择位置约束、已有原生承载、停靠或可恢复失败反馈。

普通浮层不再进入“捕获网页预览 → 用图片覆盖 → 隐藏真实 View → 浮层关闭后恢复”的通用路径。不能只删图片、继续隐藏 View 留白，也不能让网页反过来盖住仍需交互的 HTML 内容。显式登记的带遮罩业务确认框可以继续使用这一兼容流程，确认期间背景静态是允许的；本轮不要求将其迁成原生模态窗口。

正常切换或关闭标签、转移窗口、无有效布局时的 View 隐藏属于正常生命周期；用户主动截图、批注证据截图、远程画面不属于本次要删除的功能。验收时将这些调用与浮层替代画面的调用区分记录。

## 明确保留的确认框例外

仅以下由应用业务直接打开、确实需要遮罩并等待确认／取消的动作，可在有活动网页时保留截图背景及暂藏 View：

- 删除对话／子对话确认。
- 删除对话文件或文件夹确认。
- 退出应用确认。
- 关闭浏览会话页面的确认，包括关闭当前对话的会话页面或关闭该会话全部页面。
- 清除网站数据／共享网站数据确认。
- 删除浏览会话及数据确认。

实施时按确认类型、业务动作、目标 ID 和所属窗口显式登记，绑定一次确认请求。上述为拟议的业务白名单，不是目前代码中已经存在的统一 API；不能只凭 DOM 出现 `.v-dialog`、`.v-overlay__scrim`、`aria-modal` 或任意布尔标记自动认定可截图。打开普通菜单后尚未选择删除等动作，也不进入此例外。新增确认类型要有明确业务定义并更新台账，不能扩成“任何浮层都能申请截图”。

帮助文档、快捷键、商店浏览、产品详情、新建会话表单、来源选择、复杂编辑、资料卡、普通搜索等即使当前使用 `v-dialog` 或带遮罩，也不自动属于确认框豁免；保留现有界面或按实际冲突调整承载，但不延续通用截图替换。系统原生确认本身没有进入旧 DOM 截图流程的必要，继续复用其现有实现即可。

确认框只在当前宿主确有可恢复的活动网页时捕获背景。进入前保留必要草稿与原页面／布局身份，遮罩必须真实阻断底层网页输入。取消须恢复同一有效页面；操作失败也恢复仍有效的原页面和焦点。确认完成后若业务保留了原页则恢复，若业务本来关闭、删除页面或退出，则按正常业务导航／生命周期处理，不能无条件恢复或复活已销毁页，也不能切回用户后来选择的另一页。重复打开、嵌套确认和迟到回执按请求身份隔离，最后一个有效确认关闭后才解除该宿主的兼容状态。

## 已确认的当前实现

[BrowserTabPanel.vue](../../src/components/BrowserTabPanel.vue) 的 `overlayCoversPage()` 检查当前 DOM 浮层与网页区域是否相交，包括 Vuetify 活动遮罩／内容、侧栏上下文面板和 `data-browser-chrome-overlay`。相交后 `layout()` 调用 `api.preview()`，解码并绘制 `frozenFrame`，再向 `api.layout()` 提交空布局隐藏 View；预览失败还有占位提示。关闭浮层后才恢复真实 View 并清除图片。该路径在当前 `.9` 能力完整时也仍存在，不只是旧内核降级。

以下是逐项核查的生产入口。当前通用判断既检查几何相交，也有浏览器本地 DOM-open 标记直接判覆盖，不能将“使用 HTML”直接等同于每次打开都会冻结网页，更不能据此要求全部原生化。后续仅明确确认类型可触发兼容流程，普通界面只在真实覆盖或输入冲突时局部调整。

- [ChatPage.vue](../../src/pages/ChatPage.vue)：删除对话、关闭会话、退出等直接 `v-dialog` 确认按上述白名单保留兼容；回答方式、权限、模型等 `v-menu` 和带覆盖标记的悬浮侧栏退出通用截图判断。工作区展开期间禁用悬浮侧栏，只解决了该布局状态，不能覆盖所有窗口状态。
- [ComposerAttachmentMenu.vue](../../src/components/ComposerAttachmentMenu.vue)：附加一级与来源选择使用 DOM；编辑器选区工具、链接编辑、上下文资料卡及其预览也需按实际生产入口核查。保留搜索、选择、选区、内容编辑和草稿行为。
- [ApplicationMenuBar.vue](../../src/components/ApplicationMenuBar.vue)：快捷键、使用引导及旧文档等 DOM 界面；“关于 Navora”实际导航到设置的关于页面，不能列为当前帮助弹框。设置正常导航与菜单浮层分开核查。
- 原生能力不可用时的兼容分支，以及 `SidebarContextMenu` 等原生调用异常后的 DOM 回退。不能只验正常原生入口，就认定已清除截图路径。

已经原生化的顶部查找、地址建议、下载等常规路径不重复改造，但必须作为回归对象。收窄触发前，对覆盖标记、Vuetify 浮层和预览／空布局调用重新盘点，区分明确确认、普通内容及正常生命周期，不能把上面清单当作穷尽名单。

## 能力核查与承载方案

实施前核对本地实际运行时、公开类型、宿主适配和真实窗口行为。`shared/native-ui.ts` 当前提供菜单、面板、多行、滚动槽等能力，面板角色只是应用协调状态，不意味着具备原生父子弹层或窗口模态能力。必须按实际能力探测结果选择方案，不新增未经运行时支持的接口名称，也不把发行方声明直接当成本应用验收。

- 简单动作及选择菜单：优先复用现有原生菜单／面板及主题、图标、快捷键。回答方式、权限、模型的选项、当前选择、禁用原因和异步更新保持完整。
- 删除、关闭会话、退出等白名单确认：按用户明确允许保留现有带遮罩兼容流程，保留明确目标、默认取消、取消返回、重复提交保护和正确父窗口；不要求新增原生模态迁移。若某入口本来已是真正系统确认，保持原实现。现有非模态 `NativePanelDialog` 不能直接冒充模态输入阻断。
- 附加、选区、链接和资料卡：保留现有聊天列内的 DOM 承载，只在实际越界时补约束；需要另换承载时才考虑已有原生能力或聊天列内的停靠／展开区。不能牺牲编辑器选区、中文输入、来源搜索和持久草稿来换取无截图。
- 悬浮侧栏：复查固定／悬浮偏好、收起恢复和主／独立窗口行为。选择真实可承载的原生方案或布局避让，不能继续依赖覆盖检测隐藏网页，也不能默默永久改写用户偏好。
- 设置、关于、快捷键及复杂帮助：优先复用应用内停靠页面或适合的独立窗口，保持原入口和返回位置，不为简单清理强行重建一套原生复杂表单。
- 普通菜单／面板能力缺失或调用失败：保留不重叠的兼容界面，或回退到可用的停靠内容／独立窗口，或给出具体可恢复的失败反馈；活动网页保持可见。不能借失败自动申请确认框例外，回到截图替换、空白占位或挡住控制的 DOM 覆盖。

NativePanel 自身 Acrylic、完整跨 frame 连续性和独立桌面自动化仍按既有决定搁置。本次不以这些独立目标作为无限扩展范围的理由，也不绕过已知的真实能力缺口。

## 实施顺序

1. 建立有限的布局与调用基线。覆盖真实分栏、空间不足后的单视图、展开和独立窗口；区分浮层本体、全窗遮罩、正常原生和兼容分支，不把同窗共存当成实际覆盖。
2. 收窄截图替代触发。在同一改动中移除普通浮层的 `covered` 判断及其空布局，保留仅由显式确认请求进入的截图／占位／暂藏 View／恢复状态；非活动标签、隐藏工作区、首页、失败页与卸载的正常生命周期不变。只删普通浮层图片却继续隐藏 View 不算完成，也不能直接删掉确认框仍需的恢复代码。
3. 保留已有列边界的编辑器／附加／资料卡，验证动态网页与其共存。回答方式、权限、模型、用量等四组 `v-menu` 按实际位置补聊天列边界；不因缺少边界保证就预设全部原生化。
4. 只收尾实际冲突：确认框检查遮罩阻断与恢复，保留用户允许的兼容方式；非确认的大面板、浏览器工具栏 DOM 兼容分支及真正相交的悬浮侧栏，按需要采用页面导航、位置约束、停靠或可恢复失败反馈。正常原生主路径继续复用，不将菜单业务重构或确认框原生化作为前置。
5. 按下方标准运行定向验收并更新实施记录。原生失败与能力不支持分开验证；发布版本另按用户当次要求打包，不能将规划或单个入口通过写成 0.4.9 已完成全量清理。

## 完成验收

- 普通菜单、搜索、编辑浮层及其失败回退打开／关闭期间，替代用途的 preview 请求为 **0**；活动 View 有可见有效边界，没有为展示这些内容提交隐藏 View 的空布局。删除图片但留下空白不算通过。此项不将明确确认框兼容调用误判为失败。
- 非确认浮层打开期间核对网页 WebContents／页面身份不变、RAF 或等效动态内容持续更新，网页输入与 Agent 已有任务没有被重建、取消或暂停；短时间弹层也观察打开、更新、关闭全过程。
- 明确确认框验收：截图请求带有效确认类型与请求身份；遮罩期间网页真实输入被阻断，不能点击、滚动或键入到被暂藏的网页；确认／取消只执行一次且作用于原目标。取消或失败后，同一有效 WebContents、页面、布局、焦点与草稿正确恢复；确认后按实际业务结果恢复或正常关闭／退出，不复活已删除页面。背景为静态图、暂时隐藏 View 是允许行为，不要求确认期间 RAF 连续可见。
- 焦点只按明确交互移动；关闭后恢复到正确控件。检查中文输入法、选区、键盘导航、Escape、取消和重复点击，不将模态阻断与任意抢焦点混为一谈。
- 聊天编辑器、问卷及其他已有草稿在切换、关闭、失败和恢复后保留，旧异步回执不会覆盖新窗口／新会话内容。
- 主窗口、分栏、工作区展开和独立浏览器窗口分别验证；覆盖浅色／暗色及当前主题、不同 DPI、窄窗、最大化和移动后的位置。以实际原生窗口截图观察位置和层级；验收取证截图与产品内明确确认框的背景截图分别标记。
- 普通原生菜单／面板能力缺失、显示失败和调用超时等受控失败仍可操作，保留实时网页并给出可恢复路径；不能因为异常重启或重建 View。确认背景捕获失败可保留明确占位与遮罩，但不能绕过输入阻断，关闭后必须恢复有效页面，不能卡在空白。
- 正常切换标签、关闭页面、移回主窗口以及主动截图／批注证据功能回归通过。检查与本次改动有关的类型、布局与生命周期测试，避免用无关测试数量替代实际动态验收。

## 详细实施拆分（2026-11-05 菜单审查补充）

本节仍是规划。菜单业务缺项与展示方式分开处理：先定义“这个对象能做什么”，再决定使用原生菜单、原生面板、停靠内容或系统确认框。不能让同一动作在原生菜单与兼容界面中拥有不同的权限、确认或目标解析逻辑。

下列 O1–O4 是发生实际冲突时的处理方案，不要求全部实施后才能收窄通用截图判断。已经分列且不重叠的 DOM 界面保留；O2 的明确确认框兼容方式由用户允许保留，独立菜单补项另行实施。

### O0：基线与通用约束

- 入口台账至少包含触发组件、所属窗口、目标对象、菜单动作来源、显示方式、失败回退、是否存在草稿与是否可能覆盖网页。菜单缺项明细见本轮菜单审查文档。
- 扩展已有隔离检查的观测：区分普通浮层、白名单确认、用户主动截图与正常生命周期，记录确认类型／请求身份、活动 pageId／WebContents 身份、View 可见性与边界、空布局请求、RAF 或动态计数、输入控制代次。日志不保存页面正文、输入内容、会话 Cookie。
- 单个入口从迁移到验收覆盖打开、内容更新、关闭、切页、原生能力不可用和原生显示失败。确认框取消／完成导致的恢复与普通菜单打开分开统计，不能给普通面板套确认类型掩盖隐藏网页。
- 延续现有 layout owner／generation 与忙碌提交契约。普通浮层的布局变化等待现有安全提交点或在旧区域内展示，不越过输入保护强制重排或先提交空布局。明确确认需要暂藏 View 时沿受控确认流程处理，保留当前页面身份及有效的恢复代次，不改成随意隐藏所有窗口。

### O1：普通动作菜单与选择菜单

涉及 `ActionMenu.vue`、`SidebarContextMenu.vue`、`ApplicationMenuBar.vue`，以及 ChatPage 的回答方式／权限／模型与思考等级等入口。

1. 将动作 ID、标签、可用条件、当前勾选和执行处理从展示组件中分离，供鼠标右键、更多、键盘菜单和原生展示共用。旧菜单打开后若对象或 URL 已变化，关闭旧菜单或拒绝旧选择，不能把动作施加到新对象。
2. 已经不与 View 重叠的选择界面保留。实际冲突需要换承载时，简单操作及有限选项优先使用现有 Menu；带搜索、分组和异步列表的模型选择可复用 NativePanel 的现有 input／list／item 能力。读不到列表、模型被移除和选择提交失败时保留原选择并显示可重试状态，不为消除截图强制重做全部下拉框。
3. 逐项替换原生不可用／返回 unsupported 时自动打开覆盖 DOM 的分支；`SidebarContextMenu` 的异常 catch 也纳入。优先展示不覆盖 View 的停靠操作区，无法保持功能时给出具体失败反馈，不静默吞掉操作，也不进入截图兼容。
4. 本地原生能力缺失与远程浏览器端分开处理。没有原生 View 的远程端可以保留合适的 DOM 菜单，但不能把它的回退直接套用到本地实时 View 上。

完成条件：业务条目、禁用原因和勾选一致；已迁移入口所有路径均不请求替代预览、不提交覆盖造成的空布局。菜单交互与 Agent 页面控制权互不冒用。

### O2：保留明确确认框的遮罩兼容与恢复

涉及 ChatPage 中现有 `deleteDialog`、`closeSessionDialog`、`quitDialog`、文件删除，以及浏览器会话关闭／清理数据／删除的确认。范围遵循前述显式业务白名单；不是所有 `v-dialog`。

- **用户已明确允许保留旧流程，不安排强制原生模态迁移。** 将现有截图、暂藏 View 和恢复收束到业务确认请求。先验证请求类型、目标与窗口，再按确认上下文捕获／绘制背景及暂藏页面，不再扫描任意 `.v-overlay` 或 scrim 来推断确认状态。
- 确认请求绑定动作、目标 ID、对象修订及窗口；主进程重新检查对象存在和操作条件。取消为默认与 Escape 行为，窗口销毁视为取消；重复打开合并为同一待确认请求，不重复执行。
- 退出／关闭／删除先完成现有草稿保存或冲突处理，再进入确认和实际动作；保存失败保留当前内容。仅在用户确认后执行既有停止、关闭或删除，不因打开确认框就提前取消 Agent 或丢弃现场。
- 兼容流程暂藏当前 View，使应用遮罩覆盖整个所属窗口并阻断网页输入；不能只显示一张不拦输入的背景图。焦点陷阱、Escape、外部点击、中文输入与确认按钮状态保留既有约定；其它独立窗口是否受影响按业务目标明确，不顺带隐藏。
- 取消、确认失败、异步异常及完成统一结算本次请求。仅当原页、宿主和布局身份仍有效时恢复原 View；页面已经按确认动作关闭／删除，或用户在允许的流程中切页／移窗时，按最新有效状态处理，拒绝旧关闭回调恢复错误页面。背景捕获失败仍保留遮罩和清楚占位，不得失去输入阻断或退出恢复能力。

完成条件：仅白名单确认能够进入兼容流程；遮罩期间底层输入被真实阻断，取消零副作用，确认恰好执行一次，迟到结果不作用于另一对象；关闭后恢复同一有效页面或完成预期关闭／退出，草稿和取消语义保持。允许确认期间使用静态背景，不以实时绘制作为本类完成条件。

### O3：编辑器附加、格式、链接与资料卡

涉及 `ComposerAttachmentMenu.vue`、`ComposerSourcePicker.vue`、`ComposerSelectionToolbar.vue`、`ComposerEditor.vue` 链接面板、`ComposerContextPopover.vue` 及内联／块级资料节点。

- 附加入口保留现有 DOM 面板、统一搜索、来源切换、文件／网页／会话／消息引用、“本条”声明及插入光标。先核对已有容器宽度约束；只有实际无法避让时，才评估停靠内容或适用的原生承载，不重做已正常分列的来源编辑。
- 格式工具保留现有受聊天列约束的浮层；应用操作前验证原编辑器和选区 bookmark 仍有效。链接编辑保留显示文字、URL 校验、编辑／移除、取消和独立草稿，不因面板获得焦点就丢失选区。
- 资料卡保留来源、位置、状态、预览、重命名／切换引用与摘录等现有能力。预览不为了浮层绘制而替换浏览器 View；长内容滚动与当前软件主题保持一致。
- 普通分栏优先在聊天列中承载，不允许溢出到网页矩形。工作区展开或窄窗没有足够空间时，使用明确的保留布局区域或专用编辑窗口；不通过偷偷激活聊天、收起工作区或重建编辑器解决。
- 原生面板输入能力不足时使用上述停靠方案，不能假设存在公开的任意富文本、IME 选区控制、原生父子弹层或图片编辑接口。继续保留撤销／重做与持久草稿，声明仍只作用于已提交的单条任务。

完成条件：中文组合输入、选区、多行内容、引用身份、撤销和失败重试均保留；打开任何来源编辑内容期间，浏览器仍有真实、有效且可见的区域。

### O5：收窄截图路径与收尾

实施主线直接取消 `BrowserTabPanel` 的普通浮层覆盖判定与其引发的预览／空布局，不要求先迁移所有菜单。`frozenFrame`／`frozenUnavailable`、`prepareBrowserOverlayFrame` 和 `browser.workspace.preview` 若继续服务明确确认，则保留所需能力并绑定确认请求；不能按历史“全删”目标一并删除。只有不再有真实用途的分支、监听和接口才清除；用户截图、批注证据与远程查看保留各自实现。

`overlayCoversPage()` 不再凭任意菜单、浮层、遮罩的存在或几何相交隐藏网页；确认进入／退出来自显式业务状态。删除通用 body 覆盖扫描、浏览器普通 DOM-open 到截图状态的关联及无用途的旧标记；需要保留的确认字段、preload／适配和检查应清楚标明范围，不能仅给原通用判断改名为“确认”或让测试忽略普通菜单的截图调用。

最终回归按入口台账分别执行。普通菜单与面板检查零替代预览、零覆盖引发的隐藏、无草稿损失；确认框检查白名单、遮罩输入阻断、目标隔离和同页恢复。正常原生、能力缺失、显示失败、窄窗、主／独立窗口与正在运行的 Agent 按适用路径覆盖；不通过关闭网页、把网页移到屏幕外或取消任务让普通路径断言变绿。

## 本次收窄的源码依据

- `shared/workspace-layout.ts` 为分栏预留聊天至少 480px、内容至少 400px；不足时自动展开工作区，聊天视图隐藏。窄窗不能通过强制分栏制造并不存在的生产场景。
- `src/utils/composer-overlay.ts` 横向使用所属 `.composer`／`.subchat-detail` 的实际边界；选区工具栏、链接编辑、资料卡均使用该边界。附加入口使用 `.composer-box`／`.subchat-composer` 作为 anchor，面板宽度不超过 anchor，生产来源选择嵌在该面板中。
- 回答方式、权限、模型、用量四组 `v-menu` 只有窗口定位，没有显式聊天列限制。这是需要核查和补边界的理由，不是已证明常规布局重叠。
- `overlayCoversPage()` 同时检查 `v-dialog` 的全窗 `.v-overlay__scrim`，因此卡片本体不与网页相交也可能触发。附加／链接／普通右键的自定义 `.ctx-scrim` 不在该选择器中，不能混称同一触发原因。最新方案保留明确确认的兼容行为，但取消“有任意 scrim 即可截图”的推断。
- 原生 `WebContentsView` 是宿主窗口的子 View，不能假定普通 DOM 的 `z-index` 能覆盖它。收窄后验证少量跨列 DOM 兼容菜单；确认框沿用户允许的遮罩与暂藏 View 路径验证输入阻断和恢复，不强制迁移原生模态。当前 Agent 输入保护不等于应用 DOM 模态机制。

以上为源码复核依据；动态检查按实际记录注明范围，不能据此宣称全部界面验收通过。此次仅按用户决定修订规划，产品中普通浮层触发尚未清理，确认框白名单也尚未落地。
