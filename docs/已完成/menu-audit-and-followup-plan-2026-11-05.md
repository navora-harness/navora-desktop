## 1. 审查范围与结果口径

覆盖应用提供的顶栏、托盘、更多、右键、子菜单、选择菜单与相关原生面板；同时检查主工作区、展开布局、独立浏览器／文件窗口，以及原生与 DOM 兼容入口。按业务对象归档，而不是只查文件名带 Menu 的组件。

- [浏览器详细台账](../menu-audit-browser-2026-11-05.md)：单标签、多选、标签栏空白、网页更多、资源页面／会话、网页及链接／图片／选区／输入框右键、地址／历史、下载、Agent／批注及应用命令，共 12 类入口。
- [应用详细台账](../menu-audit-app-2026-11-05.md)：顶栏／托盘、侧栏／聊天／消息／子对话／问卷、编辑器／附加／资料、文件树／管理器／标签／预览／回复文件集、插件／技能／商店／创建器／设置及筛选，共 31 类入口。

以上是菜单族，不是界面菜单数量。只拦截事件而不提供菜单的地方单列；系统选择控件检查其业务选项与状态，不要求人为再造一套菜单。操作系统和第三方网站自行提供的内部菜单不属于应用菜单缺项清单，但 Navora 接管的真实网页右键已纳入。

每项分为：已经具备、同类入口不一致、源码确证缺口、待动态验证风险、后续产品增强。没有运行真实界面的条目不能写成已复现或验收通过；已有直接按钮和快捷键也算有效入口。

## 2. 首批需要补齐的菜单

### M1 浏览器地址相关操作

用户指定的缺项已确认：浏览器标签右键和网页更多均没有“在外部浏览器中打开”。“移至独立窗口”只是在 Navora 内部移窗，含义不同。

首批将主／独立窗口单标签右键、网页更多、浏览器资源页面行及应用命令接到同一外部打开动作。网页真实右键随后复用该服务。与复制网址相邻分组，统一使用“在外部浏览器中打开”；链接右键注明“打开链接”，不误用当前网页地址。

- 正常已提交的 HTTP／HTTPS 网页可用，重定向后使用真实页面地址；由主进程重新核对 pageId、所属窗口／对话、文档身份及实际 URL。
- 地址输入草稿、待导航地址不能冒充当前页；导航中或崩溃且目标不明时显示禁用原因。加载失败但主进程已保存有效 HTTP／HTTPS 失败地址时，提供“在外部浏览器中尝试打开此网址”，方便换浏览器重试，并明确这次打开的是失败目标；不能误开旧页面。
- 空白页、内部地址及非 HTTP／HTTPS 目标不出现本项。首批不一次打开多个外部页面，不新增普通显式打开的二次确认。
- 普通外部打开不移动 Navora 网页、不转移 Agent 控制，也不复制 Navora 的登录状态。远程端不能误调用远端宿主系统浏览器，第一批按能力限制，客户端打开另定本地语义。
- 复用现有系统打开能力，但修正当前 `openInSystemBrowser` 提前报成功的行为：等待系统 Promise 并返回真实结果，失败有反馈。

同步对齐复制网址、主／独立窗口的刷新／静音应用命令，以及原生／兼容菜单的缩放范围。忽略缓存重载是已有业务的入口补充；图片保存、历史行更多、下载重试与批量外部打开单列后续增强。

### M2 文件与文件集

已确认：普通实体文件树、消息文件链接及交付卡已有较完整的统一文件动作，保留并复用；缺口主要是文件管理器普通文件右键、主工作区文件标签的常用文件动作、独立文件标签右键。

统一接入已有预览、打开方式、默认应用、另存为、复制完整／相对路径、复制可读内容、在文件管理器中显示等能力，按文件／目录／只读／内容类型启用。关闭标签不删除文件；菜单出现期间文件被改写、移动或删除时，按 owner/path/revision 复核并提示刷新，不把旧选择作用到新文件。

文件集第一轮保留逐文件正确性和键盘入口；“复制文件清单”、集合批量保存或 ZIP、命名与跨回复整理另立产品范围，不能把前端循环弹保存框当作批量导出，也不默认加入“删除文件集”。

### M3 聊天、编辑器和设置等

- 对齐聊天列表行与当前聊天更多中的查找、文件夹、停止等有业务意义的入口。右键某一条聊天应操作它本身，不默认取当前活动聊天。
- 补普通输入、文件／聊天行、链接及交付卡的键盘上下文菜单，支持菜单键／Shift+F10。保存真实焦点与选区，不因打开菜单改变正文或误操作其他控件。
- 链接菜单在不支持原生菜单时不能无响应；本地有 View 时采用不遮网页的降级，远程网页端按实际客户端能力处理，给出明确反馈。
- 顶栏退出、托盘退出、关闭会话等统一为相同的业务意图，保留运行中任务提示、草稿保存、默认取消、确认后恰好执行一次。当前仅确认链路差异，不能据此断言已有资料丢失。
- 插件／技能／商店按现有能力补一致性：随附不可卸载、外链只取消关联、变体操作清楚命名；设置下拉按真实值域处理。草稿复制／删除、服务商复制等是后续产品增强，不伪装为缺失的现成操作。

## 3. 所有菜单的共用规则

1. **对象明确。** 菜单保存右键目标或明确选中对象；链接、文件、网页、会话分别有身份。打开期间对象或版本变化，旧动作关闭或取消，不追着新的 active 对象执行。
2. **业务同源。** 复用 `appCommands`、文件动作与浏览器动作模型；标签、树行、更多、键盘入口可以选取不同子集，但同名动作的目标、能力、确认和结果一致。
3. **状态清楚。** 无意义的条目隐藏，暂时不可用的条目给原因；没有实际服务的不放空按钮。忙碌、只读、运行中、未知平台能力与对象失效分开处理。
4. **取消可靠。** Escape、菜单取消、另存为取消和确认取消不产生副作用，旧异步回调不重开菜单或改变新对象。焦点恢复到原控件，中文输入和选区保持。
5. **呈现可替换。** 默认原生与兼容界面共用动作；原生不支持与临时显示失败都有明确路径，本地实时网页不能因此进入截图替代。

## 4. 三项待实施修复的详细方案

### R1 让网页一直实时显示

详细拆分已补入[实时 View 清理规划](./browser-live-view-overlay-cleanup-plan-2026-11-05.md)的 O0—O5。

同日按用户提出的实际布局复核后收窄：普通菜单、搜索和编辑浮层退出截图替代，保留已经限制在聊天列中的附加、资料、链接和格式界面，不先迁移所有菜单。回答方式、权限、模型和用量菜单核查并补列边界；只对真正越界的兼容浮层及全局大面板作局部处理。

用户随后明确允许：确实需要遮罩的业务确认框保留“截图替代 + 暂藏 View + 关闭后恢复”的旧流程。应改为显式确认类型控制，而非任意 `v-overlay` 或遮罩都能触发；帮助、文档、商店浏览和复杂编辑不自动归为确认框。无需为删除/退出等确认统一重建原生模态。

普通路径退出截图与少量真实冲突修复合批验收；菜单业务补项不作为删除前置。不能只删除图片再把网页隐藏留白。保留用户主动截图、批注证据、远程查看和正常标签生命周期。

完成条件：非确认菜单打开／更新／关闭期间替代预览为零、View 不因浮层隐藏；明确保留的确认框检查遮罩输入阻断与草稿，取消时恢复同一网页。确认动作未关闭网页时恢复；业务已删除页面、关闭会话或退出时沿用正常导航，不复活已销毁页面。两类分别计数，不能再以全局 preview 为零作为完成标准。

### R2 让 Agent 准确记住已经执行的事

详见[运行时详细规划](./agent-evidence-and-page-blocker-repair-plan-2026-11-05.md)第 3 节。

每个任务轮保存宿主生成的版本化执行摘要，明确当前轮和历史轮。自动、聊天、Agent 和总结路径共用历史构造器；长对话压缩与重启后保留关键执行、失败、停止和未核实事实。解释历史不要求再操作浏览器，更不应因本轮零次调用就否定上轮。

派发动作、字段回读、按键效果与业务完成分别记录；旧的零／false／缺字段不当成失败证明。补操作失效的脱敏原因，旧数据保守恢复，不能根据助手自述重建成功。

完成条件：真实成功或部分失败后追问、切换回答方式、重启、长历史、取消、旧回执等都能正确回答；模型请求可定位证据，不重放输入，也不虚构完成。

### R3 让 Agent 发现验证和页面阻断

详见[运行时详细规划](./agent-evidence-and-page-blocker-repair-plan-2026-11-05.md)第 4 节。

增加独立于页面正文预算的阻断摘要，区分未知、本次未见、疑似、已确认。验证域名和 iframe 只作为线索，还要核查是否可见、在前景并确实影响交互；正文因节点上限被截断时保留覆盖不足说明。脚本读到商品数据不等于网页畅通。

疑似时至多补一次有针对性的只读观察；确认需要本人验证后暂停对应页面的后续步骤，告知用户、保留网页和原任务，使用现有接管流程。用户完成后重新观察，继续剩余步骤，不复活已结束运行、不重复输入或提交。此项是识别、提示与交接，不包含解题或绕过验证。

完成条件：跨域验证、隐藏验证组件、预算截断、普通遮罩、底层 DOM 仍可读、页面变化和验证后恢复均被正确区分；不误报隐藏组件，不用无限刷新或点击重试替代识别。

## 5. 实施顺序与验收安排

1. **菜单动作与目标底座。** 先统一上下文、URL／文件能力和失败反馈，补用户指定的外部打开、文件与键盘入口。每一类都可单独验收。
2. **历史执行事实。** 先使既有操作在追问中被正确解释，再补失效原因和回读统计；这是验证阻断历史留存的基础。
3. **网页阻断与交接。** 做独立检测、模型摘要保底、页面准入、用户提示及复查恢复，使用隔离本地页面和受控跨域夹具验证。
4. **收窄截图流程并修复实际冲突。** 可作为独立批次推进，不依赖前面所有菜单业务补项。保留不重叠的现有 DOM 界面，普通浮层不再截图或隐藏 View；少量跨列兼容菜单局部处理。按用户决定，仅明确需要遮罩的业务确认框保留旧流程。
5. **整体验收与交付。** 按台账覆盖主／独立窗口、鼠标／键盘、原生／失败回退、运行中／只读、主题／窄窗／DPI、草稿失败和取消；分别记录源码静态确认、自动检查、真实界面验证。全部达标后另按用户要求打包。

菜单完整性和三项修复可按上述边界分批实现，但任何一项都不能用另一项通过来代替。当前仅规划完成，四个工作包的功能实施状态仍为待实施。
