## 需求与首版范围

用户提供的回复截图包含一份文档和六张图片。原卡片只有左侧预览按钮在悬停时着色，右侧“打开方式”保留白底；多个文件还会让回答尾部堆叠大量独立卡片。

首版将同一次回复、同一文件所有者交付的两个及以上文件显示为一个“文件集”，默认折叠。文件集头部展示文件数量、文档/图片/代码/其他文件分类数量和真实总大小；展开后展示逐文件清单。只有一个文件时保留原独立卡片。

文件行的悬停及键盘焦点背景覆盖整行，包括右侧“打开方式”，两个操作按钮自身保持透明，避免出现一张卡上的两块重叠底色。预览和打开方式分别保留自己的点击区域与键盘焦点。

## 视觉方案

延续软件已有主题、Segoe UI / Microsoft YaHei 字型、12px 文件标题及 11px 次要信息，不增加独立配色或装饰。主要颜色均来自 `--navora-surface`、`--navora-ink`、`--navora-muted`、`--navora-stroke`、`--control-hover`、`--navora-accent`，实际值随当前软件主题变化。

雾蓝浅色主题的校准值为：内容底色 `#FEFFFF`、正文 `#263C50`、次要文字 `#5C7185`、描边 `#D7E3ED`、悬停 `#CCDFF0`、强调色 `#3D6F96`。这些值用于目检，组件继续引用主题变量，不写死颜色。

布局采用一个安静的集合头和紧凑单列清单，最大宽度 680px；文件名左对齐并允许省略，完整路径通过原生 `title` 展示。展开/收起不引入动画，减少回答末尾的视觉移动；在 390px 窄窗口下清单保持单列且不产生横向溢出。

```text
[ 文件夹 ] 文件集  7 个文件                         展开 ⌄
           1 份文档、6 张图片 · 209.9 KB

展开后：
[ 文档 ] 商品整理.md                            打开方式 ⌄
         文件 · 4.8 KB
[ 图片 ] 肩包.jpg                               打开方式 ⌄
         图片 · 9.8 KB
```

## 归属和刷新规则

- 继续使用 `replyArtifactGroups()` 对成功生成且仍存在的交付文件建立最终回复归属；不将过程文件、证据文件或其他回复的文件混入集合。
- 主聊天与子聊天均传入实际最终消息 `message.id`，集合标识使用 `[replyId, ownerChatId]`。相同路径在不同聊天中仍是不同文件。
- 文件去重以 `[ownerChatId, path]` 为准，数量与总大小来自去重后的真实元数据，不按文件名推断归属。
- 沿用资源原有顺序，不额外排序；集合标识不含 revision、大小、文件数量，元数据刷新和后续新增文件不会使已展开的集合折叠。
- 展开状态保存在当前组件生命周期内；重新打开应用时默认折叠。首版不增加独立展开状态持久化。
- 文件被移动或删除后，清单跟随现有资源扫描结果更新；不伪造旧文件快照。

## 文件操作与边界

每个文件仍使用原有预览事件和原生文件菜单，包括打开方式、系统应用、另存为、复制路径及在文件管理器中显示。菜单继续携带文件所有者、路径和 revision，保留文件变更校验。完整路径仍按文件自身的 `ownerChatId` 查询工作区根路径，不按当前聊天拼接。

这是一组回复交付文件的展示方式，不建立实际文件夹、不移动文件、不改写回复内容。首版不包含跨回复手动组集、集合重命名、批量导出 ZIP 或批量移动。后续如增加批量保存，应先补选取范围、目标目录、重名与失效文件的处理，再实现对应的原生文件操作。
