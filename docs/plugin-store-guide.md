# 插件商店使用与维护

更新日期：2026-11-01。对应桌面当前插件工作区和商店 schema v1；平台产物及原生运行时方案仍待实施。

## 桌面端

左侧图标栏 → 插件。侧栏包含搜索插件、已安装插件、插件商店；右侧是所选插件的概览、工具、版本及操作。搜索模式同时查看本机与商店，已安装模式不依赖商店连接。设置 → 插件仅保留开发模式开关，批量管理移入插件工作区。

安装流程为选择产品、选择版本/变体（需要时）、预检、确认、下载/读取包、校验大小和 SHA-256、导入并加载。升级显示当前与目标版本；同套件换包需确认替换。安装并非授权插件以后无限制调用工具，执行时仍通过既有权限计划和 Host API。插件入口在主进程执行，应安装可信代码。

非 HTTPS 来源提示保留在安装窗口。删除插件、取消外链有确认；随附包不能卸载或覆盖。商店断开不影响已安装分类，刷新失败保留已有条目并显示重试。

## 配置目录源

`store.base_url` 默认 `http://127.0.0.1:8791`，支持 HTTP(S)、`file://` 与 catalog 目录绝对路径。文件路径应指向包含 index.json 的目录；HTTP 服务的根目录同样直接提供 index.json。调整源使用本机配置，勿提交用户 config.yml 或密钥。

商店源代码在并列仓库 [navora-store](../../navora-store/README.md)。本地启动：

```bash
cd ../navora-store
npm install
npm run serve
```

仅更改文档或核对目录不需要运行 rebuild，避免无意改变现有发布物。桌面进程缓存目录约 15 秒；发布后刷新若仍见旧版本，待缓存到期再试。

## 发布与更新

```bash
cd ../navora-store
npm run publish -- /path/to/plugin.zip
npm run list
npm run serve -- --port 8791
```

官方插件使用其源码仓的 build/pack 流程。外链指向包含运行时 plugin.json 与 main.cjs 的已构建目录，通常是 `dist/<packageId>`，不能把含 TypeScript 源码的工程根当作可运行产物。

批量发布可将 ZIP 放入 incoming 后执行 `npm run rebuild`；已处理内容移入 incoming/.processed。`--force` 会覆盖同版本，请仅在确实需要替换时使用；通常应发布新版本。说明从包内 README.md/docs.md 或旁路说明提取，catalog 下的每版本说明与包保持同步，不手工篡改 ZIP、摘要或说明来修正界面。

## 排查

- 列表读取失败：确认源是否启动、地址是否直接提供 index.json，使用重试；本机列表仍可管理。
- 导入后加载失败：右侧查看入口错误；检查 main、CJS 产物及依赖是否已打包，再重新加载。当前安装器不运行 npm install 或编译原生依赖。
- 摘要或体积不匹配：重新发布完整的新版本，不跳过校验。
- 套件冲突：安装确认中核对被替换的包；随附冲突不能强制覆盖。
- 安装后无工具：检查启用状态、入口导出和权限计划；已停用插件可能保留已知工具列表，实际调用以启用状态为准。
- 版本未更新：核对产品 kind + productId、具体 packageId 与版本，再考虑目录缓存；不要把产品 ID 和套件变体 ID 混用。

协议字段与服务器布局见本仓保留的 [商店协议快照](./store/PROTOCOL.md) 和 [商店维护说明](./store/README.md)，源文件位于并列商店工程。需要扩展平台产物时，先实施 [跨平台安装设计](./plugin-platform-installation-plan.md) 的兼容隔离，再更新协议，不把规划字段写成现有功能。
