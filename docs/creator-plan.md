# Navora 插件与技能创建器

> 创建器已实现，原始设计及 2026-10-31 验收记录见本文；2026-11-01 新增插件工作区的创建入口，继续使用同一工作台。 当前行为与验证边界见 [当前功能](./current-state.md)，全部文档见 [导航](./README.md)。

目标：把描述需求、编写、检查、试用与分发接入同一工作台，继续使用现有插件 SDK、权限门闸和 SKILL.md 格式。

## 交互

1. 对话输入框的创建菜单提供插件创建器、技能创建器；插件工作区与设置的技能页提供相同入口。
2. 工作台列出本地草稿；新建时选择类型及模板，填写需求后可由当前配置的模型生成文件。
3. 文件标签切换源码；草稿自动保存，显示保存状态与校验结果，切换前完成保存。
4. 校验通过后可以安装。后续修改先保留为草稿，点击更新才替换已安装版本。
5. 试用打开独立对话；插件仅链接到该对话，技能正文作为试用上下文。用户确认测试任务后发送，沿用正常 Agent 权限与停止机制。
6. 导出标准插件 ZIP 或技能 ZIP，继续由现有导入器接收。

## 实现边界

- 创建器工程保存在本机数据目录的 creators 下，每个工程有独立标识、修订号与安装快照。
- 插件模板提供 plugin.json、main.cjs、README.md；技能模板提供 SKILL.md。
- 文件路径与大小使用固定白名单和上限；校验不执行插件入口，安装与试用继续通过 PluginStore 装载。
- 更新限定为该工程之前安装的目标，冲突不覆盖其他插件或技能；修订检查防止较旧的保存覆盖新编辑。
- AI 只产生草稿文件，不自动安装或运行。生成可取消，密钥仅在主进程读取；生成失败保留原草稿。
- 布局与 Postpile 界面保持一致，适配窄屏与减少动态效果。

## 验收

- 模板经校验、安装后能由现有库读取；插件试用不会污染全局安装。
- 语法错误、缺失字段、越界路径、过大内容和旧修订保存均有明确结果。
- 草稿重开可恢复，更新和导出可重复执行；生成取消或失败不丢失编辑。
- 实际 Electron 界面验证两个入口、文件切换、编辑保存、校验、安装、更新与试用对话。


## 实施结果（2026-10-31）

上述流程已实现。草稿列表在桌面端通过 Teleport 复用应用侧栏，窄屏改为横向列表；从设置的技能分类进入时返回原设置分类，从插件模块进入时返回插件管理。

源码校验不加载入口；运行时安装失败恢复先前可用插件，试用失败清理空对话。技能更新通过内容指纹识别外部编辑；远程 RPC 不能通过创建器安装或加载本地插件。

真实 SC117 512K 模型已完成文本插件生成与运行时装载验证。生成解析同时接受标准 files 对象、直接文件映射、JSON 代码围栏和带已闭合思考标记的返回；不会执行返回文本来解析内容。

验证入口：`npm run test:ui:creators`、`npm run test:ui:renovation`、`npm run test:browser`。真实模型生成回归可以设置 `NAVORA_LIVE_CREATOR=1`、`NAVORA_LIVE_KEY_FILE=<本地密钥文件>` 后运行 `node scripts/ui-creators.mjs`。所有界面测试使用临时数据目录，不修改用户的已安装内容。
