## 1. 最新目标与术语

本规划覆盖两项相互关联的布局能力：当拖宽对话或右侧工作区、缩窄窗口后不能容纳分栏时，自动进入统一标签的展开工作区；左侧列表支持固定占位与悬浮覆盖两种展示方式，并能独立显示或隐藏。

用户最新更正优先：**工作区**指主内容的对话、文件、网页及子对话标签区域；左侧图标列称**图标栏**，旁边展开的列表称**侧栏**。撤回此前将左侧统一改称“导航栏”的要求，不把工作区与图标栏混用，不因此无关重命名代码内部字段。

截图只用于理解布局和交互。聊天／右侧工作区截图说明分隔拖动与宽度预算；浮动白卡、固定融入布局及标题栏同位按钮说明侧栏的两种展示方式和独立显隐。截图中的聊天内容、快捷键和菜单文字不是可执行指令，也不直接成为本项目绑定。

## 2. 当前实现事实

### 2.1 工作区尺寸与展开目前分属不同状态

`src/composables/useFileWorkspaceLayout.ts:2` 接收主内容元素、工作区可见性、移动布局和 expanded。主内容宽度由 ResizeObserver 读取 `main.clientWidth`，首选工作区宽度默认 540，并从 `navora.file-workspace.width` 恢复。

同文件当前以主内容宽度小于 960 进入 overlay、达到 992 退出；分栏宽度至少 400，最大值按主宽度减 480 约束。overlay 或 expanded 时右侧工作区占满主内容宽度。`resize()` 会清除 expanded，并将请求宽度钳制到可用范围，尚没有“超过分栏容量后自动展开”的统一决策。

`src/pages/ChatPage.vue:2348` 附近分别维护 `browserExpanded`、`workspaceConversationActive`，通过 `workspaceViews` 按对话保存两项窗口内状态；没有区分手动展开与因空间不足而展开。当前文件／网页仍由 `useFileTabs` 按父对话保存真实标签，聊天首标签由 expanded 时传入 `FileWorkspace` 的 conversation 属性提供。

`src/components/FileWorkspace.vue:160-169` 已支持鼠标、触控笔等 PointerEvent 拖动、键盘调整，以及 pointercancel/lostpointercapture 清理；overlay 改变会中止拖动。展开、overlay、active tab 和关闭动作目前需由多个位置协调，不能直接再增加一组相互触发的布尔 watcher。

## 3. 状态模型：用户意图与实际呈现分开

采用一个集中布局决策器，输入用户意图、真实内容预算与有效对象，输出实际布局和原因；视图组件消费结果，不各自反向修改对方的意图。

工作区的用户意图包括：是否打开、首选分栏或手动展开、最近一次有效分栏比例、原始拖动请求、当前工作区标签 key、当前主要交互目标。实际呈现为 `chat-only`、`split` 或 `expanded`，另记录原因 `manual`、`viewport`、`divider` 等，以及可选的待恢复分栏快照。

自动展开不能覆盖“用户希望分栏”的意图；手动展开也不能被一次 ResizeObserver 通知改回分栏。用户明确选择恢复分栏后，如果空间仍不足，界面说明“空间允许后恢复分栏”，实际继续保持可用的展开模式，不执行一个没有反馈的空动作。

侧栏使用两个独立维度：

- **展示偏好**：固定 `fixed` 或悬浮 `floating`。
- **是否显示**：`visible`，以及上次有效 `panelId`。

关闭侧栏只改变 visible，不抹掉 panelId 或展示偏好。固定／取消固定只改变展示偏好，不借机切换对话、关闭当前列表或创建另一个实例。实际呈现可以附带“窗口过窄，暂时悬浮”等原因，但不能悄悄改写用户固定偏好。

拖动状态、IME 组合输入、菜单／模态层、设置离开确认和原生布局变更作为临时交互状态，不写入长期偏好。布局切换采用递增代次和对象身份，丢弃迟到的尺寸、截图、聚焦和恢复回调。

## 4. 宽度预算与最小可用宽度

预算统一使用**内容区 CSS 像素**，不使用显示器物理分辨率，不用 devicePixelRatio 再乘除，也不以操作系统窗口外框宽度直接代替布局宽度。系统缩放、网页缩放和侧栏宽度变化最终都以实际测量结果进入决策。

可分配宽度 B 取主内容区域的真实内宽。若从整个 content-surface 测量，则只减去实际占位的固定侧栏宽度与布局边界；图标栏若已在测量区域之外，不再重复扣减。悬浮侧栏不占内容预算。当前 main 的工作区 reserve 属于其内部空间，不能从已经拆分过的聊天宽度再扣第二次。

分栏基本条件为 `B >= Cmin + Wmin + D`：Cmin 为聊天最小宽度，Wmin 为当前工作区内容的最小宽度，D 只计实际占位的边界／间隔。可先沿用当前聊天 480、工作区 400 CSS px 作为基础，通过真实消息、编辑器、浏览器地址栏、文件预览和子对话详情验证后固化；内容类型确需更大宽度时由明确 capability 提供，不按标题长短临时改变阈值。

各 pane 的最小宽度包含自己的内边距、操作按钮和原生滚动槽，不能另按每条内部滚动条重复扣预算。资源摘要若继续占位，其宽度也进入统一预算；不要在聊天、工作区和摘要三个局部逻辑中分别认为自己拥有同一块空白。

分隔线推荐保留 1px 视觉边界、约 10—12px 可命中区域，悬浮或键盘聚焦时加强反馈，不常驻粗蓝色竖带。命中区域若覆盖两侧各一部分，就不把整段命中宽度作为 D 再占一遍空间。

分栏比例优先恢复用户最近一次有效选择；窗口大小变化只对呈现值做钳制，不反复将钳制结果写回首选宽度，避免窗口缩小一次后永久丢失原比例。

## 5. 自动展开与恢复顺序

### 5.1 窗口缩小与侧栏占位变化

工作区已打开且有有效内容时，只要分栏预算不足，就进入带聊天首标签的展开工作区；不继续把聊天或右侧内容压到最小宽度以下，也不沿用没有聊天首标签的覆盖面板作为默认窄桌面结果。

自动展开保留当前已选中的文件、网页或子对话标签，不新开空白网页、不重建内容。聊天始终是同一标签栏中的首标签，可立即切回。展开过程中不因某个子任务完成、浏览器标题变化、资源角标更新或后台消息而切换选中页。

如果进入前工作区尚未打开或已无有效标签，空间变化只调整聊天布局；不能生成空工作区、空网页或盖住聊天的白屏。纯浏览器内容为零页面时继续遵守隐藏标签栏并提供空状态入口的原有契约。

### 5.2 分隔拖动越界

保留未钳制的原始请求用于判断意图：只在钳制后的宽度上判断会永远无法知道用户试图越过边界。拖动过程中先保持两侧可用的预览几何；超过最小宽度边界约 24px 的明确余量时显示“松开后展开工作区／对话”提示，在 pointerup 提交转换，避免分隔组件在仍持有 pointer capture 时被卸载。

用户把右侧工作区拖到无法再保留聊天最小宽度时，展开当前工作区页。用户明确把对话放大到右侧内容无法保留最小宽度时，可切到展开模式的聊天首标签；这是有方向和提示的显式放大对话操作，不是后台自动选页。普通窗口缩小不套用这个方向判定。

pointercancel、失去捕获、Escape 取消拖动及模态层出现时清理捕获，回到上一次已提交的布局，不把未完成预览持久化。键盘 Arrow 调宽、Home 恢复比例、End 等端点操作需说明目标，并走同一个预算与提交逻辑，不能鼠标可展开而键盘只被静默卡住。

以上 24px 是待体验验证的初始建议，不是已实施或永久固定阈值。拖动切换与窗口自动收敛采用不同判定，不能通过手抖反复展开／恢复。

### 5.3 迟滞与不抢操作的恢复

自动进入条件和退出条件分离：预算不足可在尺寸连续稳定的帧后进入；恢复要求达到分栏最低预算再多约 64—96 CSS px，并稳定约 250ms。推荐值需以最低宽度附近往返拖窗、系统缩放和侧栏 pin/unpin 的检查结果确定。

仅当此次 expanded 的原因是空间限制、用户仍希望分栏且没有后续手动改变布局意图时，才自动恢复；普通标签选择不算改变布局意图。保持恢复前当前选中的内容和焦点；展开时选了另一文件，恢复分栏后仍选该文件，不强制跳回自动展开前的旧文件或聊天。

恢复时应用最近一次有效分栏比例；若回到原预算则可还原原宽度，否则按原比例映射并遵守最小宽度。保存的是用户比例与参考预算，不是缩窄时被迫得到的钳制宽度。

正在编辑、IME 组合输入、持有 pointer capture、菜单／模态层打开、权限确认或设置离开处理中时，不突然重排焦点区域。可以完成必要的防溢出收敛，但延后非必要恢复；交互完成后重新评估一次，避免在弹层关闭瞬间连续多次切换。

### 5.4 手动展开和拖出聊天标签

手动展开在放大窗口后保持展开；只有明确的恢复分栏动作改变该意图。聊天标签拖出原有标签栏继续表达“退出展开／恢复分栏”，不创建独立聊天窗口；空间足够时恢复原比例，不足时保留可用的统一标签并显示待恢复原因，不能叠出两份聊天或空白层。

切换父对话分别保存各自工作区选择和手动意图；未打开的工作区不因另一个父对话自动展开而被打开。文件、网页、子对话和聊天均保持同一真实实例，草稿、阅读位置、原生页面输入和自动化任务不受布局切换重启。

## 6. 侧栏固定与悬浮的清晰操作

### 6.1 两种展示方式，显隐独立

固定侧栏占据内容网格中的列，与页面融为一体；悬浮侧栏作为图标栏旁的白卡覆盖内容，不挤压工作区。两者共享列表、搜索、选中、滚动、批量操作和设置导航实例。

标题栏保留一个同位置的“显示／隐藏侧栏”按钮，通过 `aria-expanded`、title 和当前打开状态反馈。它只改变 visible：隐藏后再次打开恢复上次 panelId 和固定／悬浮偏好，不总是切回对话列表。

侧栏头部提供“固定侧栏／取消固定”按钮，或在同一明确菜单中提供这两项；取消固定后侧栏仍显示为悬浮，固定后侧栏仍显示并参与预算。禁止一个按钮含混地在“隐藏→悬浮→固定”三态循环，导致用户无法判断下一次动作。

图标栏继续切换具体列表：点击其他图标切换同一个侧栏内容；点击当前图标可按一致规则关闭或重开。该规则与标题栏的显隐按钮共享状态，不出现图标显示选中但侧栏已经关闭的假状态。

### 6.2 预算不足时尊重固定偏好

固定侧栏改变主内容预算，首先由统一决策器判断是否需要自动展开工作区，不同时启动旧自动折叠 watcher 抢回宽度。如果固定侧栏已令剩余单页内容也低于最低可用宽度，可临时以悬浮方式展示，并说明“窗口较窄，侧栏暂时悬浮”；记录用户偏好仍为 fixed。

空间恢复后，只有在固定候选预算足够并通过迟滞、且没有后续取消固定意图时才回到固定。决策基于同一份宿主预算评估完整候选布局，不能“先固定变窄→改悬浮变宽→又固定”的 ResizeObserver 循环。

悬浮宽度可以继承固定时最近一次合法面板宽度，但上限按当前可用内容边界钳制；窄窗口必要时采用已有移动抽屉模式，不保留一个只剩几像素可点击外部区域的悬浮白卡。

### 6.3 几何、边界和滚动

桌面悬浮卡位于图标栏旁、主标题栏之下，与可用窗口四周保留约 8px 边距；不越过原生窗口控制区和系统安全区域。高度按可用内容区限制，标题、搜索和固定／关闭按钮不随列表滚走。

悬浮和固定时使用同一原生 scrollport 与外侧滚动槽规则；行背景、菜单按钮不延伸进轨道。切换方式后保存实际滚动位置与焦点项，不因 Teleport 宿主变化又从首行开始。菜单和 tooltip 按真实可用 viewport 翻转、限高，菜单可超出白卡，但不能被祖先 overflow 裁去。

## 7. 外部点击、焦点、键盘与触摸

悬浮侧栏是非模态导航区域，不对整个主内容永久施加 inert；打开时保留原内容状态。通过点击标题栏或图标栏进入时将焦点移到合适的搜索／选中项，关闭后仅在需要时恢复触发按钮，不强制聚焦消息编辑器。

pointerdown 判断“外部”时同时考虑侧栏本体、图标栏触发器、属于侧栏的 Teleport 菜单、导入弹窗和输入法候选交互。点击侧栏打开的菜单不算外部点击；选中文本、拖动轨道或调整分隔线时不能突然关闭。

非模态点击外部可关闭悬浮侧栏，并在同一次操作中保留合理的主内容意图；不得在原生网页被临时隐藏／截图替代时将该点击误投到冻结图像后方的网页。跨原生表面无法可靠传递的点击应先关闭再恢复页面，不伪造一次业务点击。

Escape 按层级处理：先关闭最上层菜单、取消当前拖动或结束侧栏内搜索，再关闭悬浮侧栏；IME composing/keyCode 229 时不关闭，不越过模态确认。固定侧栏不因普通 Escape 自动消失。Tab 能从侧栏到主内容，避免给非模态白卡设置无出口的循环焦点陷阱。

键盘显示／隐藏使用统一命令，不照搬截图的 Ctrl+Shift+S：`shared/composer-shortcuts.ts` 已将 Mod+Shift+S 用于编辑器删除线。对 Mod+Shift+L 的本轮检索未发现现有绑定，但这不等于全平台和第三方网页保证无冲突；首期可保留菜单命令和按钮，快捷键待冲突清单、原生转发与帮助说明统一后确定。不得全局截获编辑器格式快捷键来实现侧栏显隐。

触摸和触控笔有足够命中区域，保留滚动惯性，不依赖悬浮才显示固定／关闭动作；拖动与点击分离，超出滑动阈值不同时选择列表行。减少动态效果时直接切换，不用长动画遮住当前输入目标。

## 8. 查找、设置和工作区工具的衔接

当前聊天查找必须以可见聊天为目标：从菜单打开时先选择统一工作区中的聊天首标签，或者退出临时覆盖布局，再显示输入，不把搜索栏打开在 display:none/inert 容器里。已建立的搜索栏独立布局行和消息区空间仍需保留；本规划不宣称重新完成了一轮查找测试。

原生网页内 Ctrl+F 仍查网页，侧栏列表搜索仍查列表；侧栏显隐和 pin/unpin 不改变快捷键目标。关闭悬浮侧栏后保留聊天查找查询、命中和阅读位置，不因为宽度变化清空搜索。

设置、创建器及其返回流程纳入同一侧栏呈现：显示设置时侧栏可以切成设置分类，但不覆盖进入前的布局意图。返回时恢复先前 panelId、visible、固定／悬浮偏好、工作区标签与分栏意图，再按当前预算求实际布局。未提交秘密仍走明确放弃确认，不能将点击侧栏外部当成同意丢弃凭据。

展开工作区的聊天搜索、更多和摘要工具保持在统一标签栏分隔线左边；文件、浏览器、子对话切换时只显示当前内容的工具。侧栏白卡不复制这些工具，也不因显示侧栏把工作区切回其他标签。

## 9. 原生 View 与空白冻结画面的 P0 依赖

新增悬浮面板如果覆盖原生页面，必须进入 `overlayCoversPage` 的真实几何判断，可使用已约定的浮层标记或明确的共享浮层注册。只设置较大的 z-index 不能完成原生叠层；不相交的浮层也不应让网页无故隐藏。

优先复用已存在的截图→解码→至少一轮已绘制画面→隐藏原生 View 的有界流程，并校验页面 ID、宿主、layout owner 和代次。冻结画面是真实页面的暂存预览，不是实时网页；实际存在相交时，当前能力可能需要暂停原生页面的可见呈现，必须明确其限制，不能承诺只覆盖白卡区域就能保留其余部分实时交互。

截图失败／页面被销毁／超时要有可见的预览不可用提示与可关闭入口；不能先隐藏网页再无限等待截图，也不能移除输入保护或自动把控制权交给用户来绕过。关闭后用最新几何和有效 owner 恢复同一个页面，不重载、切页或丢失表单输入。

固定／悬浮切换、自动展开和侧栏恢复的短时间连续动作都可能产生过期 capture/layout 回调，需要同一代次串行收敛；关闭弹层后迟到的旧截图不得重新盖住页面。多个菜单、侧栏和模态层重叠时按仍有效的遮挡集合决定恢复，不能其中一个关闭就提前恢复到其他弹层上方。

此链路作为本能力上线的 P0 门槛：在真实 WebContentsView 上证明无白屏、无错误点击透传、无布局 owner 丢失，之后再开放悬浮侧栏覆盖网页。若将来采用定制内核的原生叠层能力，应先确认实际 API 和回退边界，不在本规划中假定已有该参数。

## 10. 持久化与迁移

新增有版本的布局偏好，存用户意图、合法面板 ID、固定面板宽度、分栏比例及必要的父对话视图标识；不存临时自动展开原因、pointer capture、DOM 焦点对象、截图或浏览器实际控制权。

从现有数据迁移：`navora.sidebar.rail` version 2 的 active 转为 panelId+visible，active 为空保持隐藏并提供合法 lastPanel 回退；`navora.sidebar` 的总 width 减去 52 一次后恢复面板宽度；`navora.file-workspace.width` 转为首选宽度／参考预算。无版本、畸形、越界或已卸载面板回退默认，不影响已有聊天、文件和浏览器标签。

首选比例只在明确用户提交拖动或恢复默认时更新；自动缩窄、临时悬浮和自动展开不写成永久偏好。实际窗口内的布局恢复不改变另一独立浏览器窗口，跨窗口是否共享固定／悬浮偏好需明确范围，不能用一次同步通知抢走其他窗口的阅读与焦点。

## 11. 实施顺序

1. 提取纯布局决策和状态归一化，覆盖用户意图、预算、自动原因、迟滞及恢复，先替代分散 watcher 的互相修正，保持现有真实内容不变。
2. 接入分隔拖动原始请求、键盘调整、自动展开与恢复；统一聊天首标签和选中内容，验证无工作区、关闭末项、父对话切换等路径。
3. 引入侧栏 visible 与 fixed/floating 两维状态，统一标题栏同位按钮和 pin/unpin；先在不含原生页面的场景验证单实例、焦点、滚动与菜单边界。
4. 完成原生 View P0 遮挡与恢复检查后，再启用浮动侧栏覆盖网页；联测连续拖动、窗口变化、多浮层和自动化持有控制权。
5. 接设置返回、查找、快捷键说明和偏好迁移，清理旧自动收起／overlay 的冲突分支与过时样式，保留可诊断的布局原因。

## 12. 验收标准与证据

- 宿主宽度、实际主内容 CSS px、固定侧栏占位、首选比例、实际布局、展开原因和选中 key 可用隔离诊断记录，证据不包含真实密钥或聊天正文。
- 仅拖窗口、改变系统缩放、拖固定侧栏、拖聊天／工作区分隔都能按同一预算进入展开；自动展开包含聊天首标签，保留当前工作区页，不创建空浏览器。
- 最低宽度附近往返变化、侧栏 pin/unpin、窗口最大化／恢复和 ResizeObserver 连续触发不振荡；手动展开在扩大窗口后仍保持。
- 自动展开扩大后可恢复分栏与原比例；期间手动切换标签或改变展开意图后，不被旧恢复任务覆盖，不突然跳到旧页。
- 工作区从未打开、末项关闭、父对话切换、已删除文件／子对话、零网页和浏览器加载失败均有可用主内容，无白屏与不可达返回。
- 固定和悬浮复用同一个列表实例；标题栏按钮只显隐，pin/unpin 只改变展示方式，关闭重开恢复上次列表、搜索、滚动和合法焦点。
- 固定侧栏占位，悬浮侧栏覆盖且不挤压内容；最小/最大侧栏宽度、125%—200% 缩放、低高度及移动抽屉均不越过标题栏和窗口安全边界。
- 行末动作与原生滚动槽间隔一致；Teleport 菜单不被裁切、不被当作外部点击，末项和全部操作可用键盘及触摸到达。
- IME、Escape 分层、Tab、pointercancel、失去捕获、选择文字及模态确认不会误关侧栏、误切内容或重复提交。
- 查找栏可见可聚焦且不被消息区覆盖；聊天、网页、侧栏各自查找作用域保持；设置返回恢复正确布局和普通草稿，秘密确认不被旁路。
- 原生网页与悬浮侧栏相交时先有有效冻结画面或明确回退，再隐藏 View；不相交时无需隐藏。连续开关、截图失败、页面关闭和多个浮层的迟到回调不导致白屏或错误恢复。
- 布局切换不重跑模型、不重载网页、不改变页面输入保护、静音偏好或人工接管，不丢表单、草稿、阅读位置与资源身份。
- 离线示例与纯状态测试仅验证相应设计；真实鼠标／键盘、WebContentsView、窗口缩放与多浮层需分别留下生产源码或构建后的隔离证据，未执行部分保持待验收。
