保留当前主题、圆角、输入首焦点和结果展开方式。窄窗按标题栏左右安全区收缩宽度和调整横向位置，避开 Windows 标题按钮；macOS 使用左侧标题栏留白。此调整不改变其他居中面板的位置。

源码：`src/utils/search-panel-layout.ts`、`WindowFindHost.vue`、`NativePanelDialog.vue`。原生搜索继续显示同一个实时网页，不使用截图替代 View。

## 后续规划：局部查找右移与紧凑化

状态：已实施并完成源码构建，未重新生成安装包。以下保留最初验收要求；当前尺寸、单范围入口和还原行为以文末追加实施记录为准。只修改局部查找的承载与内容树；现有共享顶部布局仍供全局搜索使用，不能通过修改共享默认值把 Ctrl+K 一起移动或缩小。

1. **定位。** 以实际窗口按钮区域左边界为右侧基准，查找卡片可见外框的右边缘再向左留 25px；纵向仍沿用标题栏中部附近的当前位置。原生卡片自带边距，计算和实拍均按外框校验。优先读取真实标题栏可用区域，只有能力不可用时使用已有安全区回退；不把“距窗口右缘 25px”误作“距窗口按钮左侧 25px”。
2. **大小。** 内容宽度目标约 360px（当前默认 448px），图标按钮从 30px 收至约 26px，减小内边距、行距与圆角；输入文字保持可读，长结果与选项保持滚动/省略和明确提示，不删聊天/工作区切换、结果导航、选项或关闭入口。
3. **窗口适配。** 普通、最大化、不同 DPI 与独立窗口均按各自按钮边界重新定位；窄窗先收宽再向左夹紧，不能盖住系统按钮或超出窗口。全屏没有按钮区域时按右侧 25px 安全距处理。
4. **全局搜索隔离。** Ctrl+K 继续使用原有位置、尺寸、圆角、内边距及焦点行为；全局搜索使用的 `NativePanelDialog` 不随局部查找调整。局部查找在聊天/网页/文件间切换时保持同一面板的尺寸与位置。
5. **验收。** 原生外框与窗口按钮区域实际间距 25px（允许 DPI 舍入误差），视觉更紧凑；核对全局搜索前后几何一致。保留 Enter/上一个/下一个/Esc、中文输入与查找选项，动态网页无截图替代或菜单导致的隐藏。

以上是局部界面调整。剩余浮层截图替代总路径仍待按[清理规划](./已完成/browser-live-view-overlay-cleanup-plan-2026-11-05.md)实施；最新对话的问题见[历史证据与网页验证诊断](./已完成/agent-history-and-page-blocker-diagnosis-2026-11-05.md)。

## 追加：当前查找条外观、单范围入口与最小化还原

> **过时段落提示（2026-11-06）：**本节 4px 内距/37 DIP 是上一版样本，已由后文“2026-11-06 留白回调”替换。最小化还原已实现并有验收，不能继续套用早期撤回/待实施描述。

用户提供参考图后，继续优化的是 Ctrl+F 的当前内容查找条；Ctrl+K 的对话列表搜索保留前一轮独立方案。本节取代上文局部查找圆角 16、内距 8 和阴影外框 15 DIP 的旧尺寸描述，属于当前源码增量，未重新生成安装包。

- 空态主行和输入高度明确为 28 CSS px，面板内距 4、左右内容留白 8、圆角 20，关闭原生阴影。实测空态外框高度从旧样本约 59 DIP 收紧至 37 DIP，保留原字体和可点击按钮大小。
- 唯一可查找范围时不显示范围按钮：没有工作区时隐藏“当前聊天”，独立浏览器只有网页范围时隐藏地球。聊天与工作区均可查找时保留两个轻量按钮，去掉选中底色，并在关闭按钮前保留细分隔。
- 无阴影面板右侧延伸实测为 1 DIP，据此调整局部定位补偿；窗口按钮前的目标间距仍为 25 CSS px。全局 Ctrl+K 不使用这项补偿。
- 最小化时，原生面板的 `parent-hidden` 在搜索仍请求打开、且宿主确实已最小化的情况下视为临时挂起，不向查找宿主回报用户关闭。还原后等宿主尺寸稳定，再以原面板实例、IPC 会话和控件恢复显示及锚点，不重发输入内容。显式关闭的搜索框不会被下次还原重新打开；草稿、关键词、结果、光标选区和查找范围保持。
- Renderer 在隐藏或零尺寸阶段不保存无效锚点，可见性恢复后重算；主进程还会核对原宿主、调用者、来源有效性以及最新逻辑锚点，拒绝失效页面或转移后的旧动作。
- 图标模糊已通过真实原生像素比较定位：按钮按 20 DIP 绘制，原图片却声明为 16 DIP，发生二次放大。本查找条的按钮改用实际 20 DIP 图像及匹配的像素密度；左侧放大镜仍为 16 DIP。主题、DPI 和内容更新保留尺寸提示，其他面板及菜单默认行为不变。实测只把 SVG 尺寸改大、增加图片多倍率表示均不能改善，因此没有采用这些无效替换。

### 2026-11-06 留白回调

用户实用反馈表明上一轮 4px 内距过紧，现将原生面板内距调整为 8px、内容行距从 4px 调整为 6px，保留左右内容留白 8px（与面板内距合计 16px）、360px 宽度、28px 输入行及清晰图标。空态实际外框由 37 DIP 调整至 45 DIP。兼容界面使用对应的 8px 纵向、16px 横向留白。

展开选项改为每项一行、24px 行高，避免两个带文字的原生开关横排时把后一项挤出内容区；末行与面板底部保留至少 8px 留白。单范围入口隐藏、定位及最小化还原行为沿用上一轮。

本次类型检查、前端构建、897 项单元检查及针对留白的真实原生界面检查通过，核对浅暗色空态、可编辑查询、有结果及展开选项截图，证据为 `release/ui-window-find-padding-review/completed.json`。尝试运行完整界面套件时，曾在屏幕外原生输入和全屏后的 Escape 自动化焦点环节超时，因此不将本次限定验收记作完整快捷键或生命周期复验；先前完整验收记录保持原有范围。

### 2026-11-06 最小化时左上角闪现补修复

用户确认还原前后仍会在左上角短暂露出搜索框。本次检查覆盖原生中间消息，不再只断言还原结束后的坐标。原生面板会在 `parent-hidden` 通知前跟随宿主边界；Windows 把最小化窗口移到临时坐标时，仍可见的面板先被工作区夹紧到屏幕边缘，然后才隐藏。负向临时坐标对应左上角夹紧，解释了最终位置正确但过程中仍闪现的问题。

宿主现在通过 Windows 公开的 `hookWindowMessage`，在 `WM_WINDOWPOSCHANGING` 已确认最小化、但原生边界跟随尚未执行时，提前隐藏仍逻辑打开的搜索面板。保留实例、会话、控件及搜索内容，正常还原后继续复用；普通移动、最大化和未执行的最小化指令不触发。已有消息钩子不被覆盖，观察器释放时移除本服务安装的钩子。隐藏必须发生在最小化状态已成立后，避免提前隐藏引发的宿主激活打断最大化窗口的最小化操作。

还原继续等待宿主几何和焦点稳定，再显示一次面板。窗口焦点／可见性变化但本地查找几何未变时，Renderer 跳过重复内容刷新；避免把 Electron 记住的旧网页焦点覆盖到原生搜索输入上。显式关闭的面板不会复活。

最终验证：类型检查和源码构建通过，901 项单元检查、285 项桥接检查通过；独立原生宿主 5 项检查覆盖最小化消息阶段已隐藏、普通／最大化还原、观察到的可见位置与单次显示、查询及选区保持、关闭后不复活。实际 Vue／preload／主进程／网页查找完成 15 项定向检查，还原前后搜索内容更新计数均为 42，没有重发控件树，输入焦点、查询、结果、实例、会话及位置保持。

证据为 `release/ui-native-panel-restore/completed.json`（含原生消息和显示过程采样）与 `release/ui-window-find-restore-timing/completed.json`。这是 Windows 当前内核与缩放环境的定向验收，不把定时状态采样描述为完整屏幕逐帧录制，也未重新执行后续全屏／Escape 套件。未重新生成安装包，运行中的旧进程需重启后应用修复。
