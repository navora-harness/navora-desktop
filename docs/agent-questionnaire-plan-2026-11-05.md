问卷模式用于集中收集 Agent 完成任务所需的需求、偏好和约束。Agent 一次提出一组问题，用户在工作区标签页填写，点击“提交并继续”后，答案作为结构化用户输入交回对应任务。聊天保留入口、状态和实际提交的答案摘要。

建议采用应用统一渲染的表单模板。Agent 负责组织题目、选项和解释，应用负责控件、校验、草稿和提交。这样可以复用工作区体验，并让同一份问卷在切换聊天、关闭标签和重启后保留一致的状态。

## 使用场景和触发规则

适合需求收集、项目初始化、方案偏好、执行参数等需要集中确认多个事项的场景。用户可以直接说“用问卷问我”，Agent 也可以在发现多项信息缺口时主动发起。

建议默认规则：

- 一两个简单问题沿用聊天内的单题询问。三项以上、能够同时回答的问题优先组成问卷。
- 每批建议三至八题，按主题分组；问题较多时先收集会影响方案的关键项，再按答案补问。
- Agent 先利用当前对话已有信息，避免重复询问。推断出的建议必须标明来源或依据，并允许修改。
- 每题用一句话说明需要这项信息的原因；可选项明确标记，用户可以快速完成必要部分。
- 后一道题必须依赖前一道答案才能确定时，先问前置问题。首版不要求 Agent 预先编造所有分支。
- 问卷收集需求和偏好；已有的权限确认、下载确认等继续使用对应的宿主机制。

## 用户流程

1. Agent 生成问卷，聊天中出现一张卡片，显示标题、题目数、所属任务和“打开填写”。
2. 用户正在该聊天中、且没有正在填写的其他问卷时，首次问卷打开为工作区标签页；已经存在问卷标签时复用该标签。后台聊天、子任务或正在填写另一份问卷时只显示待处理提示，点击后再切换，避免切走用户当前页面。
3. 表单顶部显示填写目的、所属聊天和完成进度；中间按主题排列问题；底部提供“其他补充”“稍后填写”“提交并继续”。“取消问卷”作为独立的次要操作。
4. 用户填写时自动保存草稿。切换标签、聊天或关闭问卷标签均保留内容；聊天卡片可以重新打开同一份问卷。
5. 提交时先校验当前题目和答案，再保存不可变的提交快照。收到宿主接收回执后，页面显示“已提交”，对应 Agent 继续处理。
6. 聊天卡片更新为已回答状态，显示关键答案并允许查看完整记录。已经提交的问卷默认只读，便于解释后续方案依据。

当前前台聊天首次发起时可以自动展示工作区，保留其他类型标签，不强制最大化。窄窗口沿用工作区的展开和返回方式，保留表单中的阅读位置和输入焦点。

## 单一问卷标签

全应用同时最多打开一个问卷标签。有标题时标签显示“问卷: 标题”，没有标题时显示“问卷”；具体问卷标题和所属聊天也显示在正文。再次打开同一问卷只激活已有标签；打开另一份问卷时，在同一标签内切换内容并更新标题。首版不提供问卷标签复制、拖出或独立窗口打开入口。

标签数量与待答问卷数量分别管理。不同聊天和子任务仍可以各有待答请求，但都通过同一个问卷标签查看和填写。新的后台请求不自动替换当前表单。

切换问卷前保存当前草稿并确认保存结果；如果保存失败，保留当前表单与输入，提示重试。每份问卷保留独立草稿，切换回来恢复对应内容。异步加载、保存和提交回执必须核对问卷身份，旧问卷的迟到结果不能覆盖当前页面。

关闭后重新打开仍使用同一个标签入口，工作区恢复不得为不同聊天各复制一个问卷标签。

## 首版题型和答案语义

首版覆盖六类输入：短文本、长文本、单选、多选、开关和数字。文本用于目标与补充，数字可表达数量并标明单位、上下限；单选和多选支持选项说明及“其他，自行填写”。

此处“自定义”包括选择题的自填答案、每题备注和整份问卷的补充说明。自定义控件、脚本和任意页面布局留待后续评估。

所有题目使用稳定题目 ID，选择项使用稳定选项 ID。界面文案可以优化，答案关联不能依靠题号或显示文本猜测。

需要明确区分以下含义：

- 尚未回答：用户还没有对该题表达意见。
- 已回答：保存实际选择或输入，开关的“关闭”和数字的零都属于有效回答。
- 不确定：用户暂时不知道答案，Agent 后续应说明假设或补充调查。
- 由 Agent 决定：用户明确把该项方案选择交给 Agent，并保留相关约束。
- 跳过：该题未提供答案；是否允许跳过由题目定义决定。

“不确定”“由 Agent 决定”和“跳过”仅在题目允许时提供。真正阻碍执行的必需信息不能悄悄用空值或推荐项补齐；用户仍可稍后填写或取消。

推荐项显示“推荐”及原因，初始不计入已回答。若用户此前已明确给出某项信息，可以预填并标注“来自当前对话”，提交时一并确认。开关的初始值可以是未选择，不能把默认关闭解释成用户否定。

## 表单呈现

界面以简便、美观和快速填写为目标，使用当前软件的主题变量与现有控件规范，统一背景、文字、强调色、边框、圆角、字体、图标和交互状态。浅色、暗色及其他已有主题切换后即时对齐，主题变化保留输入、焦点和阅读位置。

正文采用适合阅读的单列布局，宽度参考对话编辑框，随工作区实际可用宽度收缩。顶部紧凑显示标题、目的和进度，中间连续排列题目，底部保留一个主要提交动作。题目之间用留白和标题层级区分，减少重复卡片、边框和常驻说明；低频操作收纳到次要入口。

短问卷直接展示全部问题；较长问卷按主题分节，避免为每题增加一次“下一步”。

题目依次展示问题、必要说明、输入控件和错误提示。选项的标签表达具体结果，可附一行影响说明。多选题可以限制最少和最多选择数量，选择“其他”后才显示自填框。

进度按当前适用题目计算，必需项和可选项分开说明。提交发现错误时聚焦第一个需要修正的位置，并保留全部已填内容。首版支持键盘导航、控件标签、可见焦点、输入法和窄窗口布局。

底部主按钮统一使用“提交并继续”，提交中禁止重复点击。失败时显示可重试原因，保留草稿；成功状态以宿主回执为准。

## 草稿和任务生命周期

每个 Agent 同时最多有一份待答问卷，不同聊天和独立子任务可以各自等待。子任务的问卷可以在父聊天显示提示，打开后明确标记实际所属子任务。

问卷状态区分待填写、提交中、已接收、已取消和已失效；草稿保存情况、任务是否已中断以及继续运行的状态分别记录，不能用一个“完成”标志混在一起。

- 关闭标签只改变显示状态，待答请求和草稿继续保留。
- 点击取消会结束这份待答请求，并告知对应 Agent 用户已取消。Agent 不应立即再次发起同样的问题。
- 用户停止任务或用新任务替换原任务时，对应问卷停止接受提交，已有内容可以查看或复制；迟到的回复不能继续旧任务。删除聊天时按聊天的数据清理规则一并清理问卷与草稿。
- 等待期间暂停当前 Agent 后续推理和工具调用，其他独立聊天可以继续运行。浏览器窗口、会话和运行上下文的保留与释放按各自生命周期处理。
- 问卷默认不限时，不自动提交推荐项，也不因用户离开窗口而替用户作答。
- 应用重启后恢复题目、草稿及待答状态；旧进程中的运行已经结束。用户提交后，按会话历史和已保存任务约束发起继续运行。

草稿按下节要求写入持久存储。提交结果及继续运行请求也需要持久记录，避免接收后退出导致答案已保存、任务却一直未继续。

等待问卷时，聊天输入框仍可编辑；需要发送消息让 Agent 回应时，发送动作明确显示为“发送并切回聊天”。宿主将结束表单等待与接收这条消息作为一次状态切换交回原任务，保留草稿，并使原问卷停止接受提交。这样用户可以讨论题意，消息也不会只排在未完成的问卷后面。将一段自然语言自动拆成多题答案留到后续；没有明确对应关系时不能静默改写表单。

## 与对话编辑框一致的草稿持久化

问卷采用与对话编辑框一致的自动保存、恢复和冲突保护语义，草稿按聊天 ID、问卷 ID 和题目版本独立存储。对话编辑框和问卷各自保留草稿，互不覆盖。可以复用现有保存与版本保护机制，答案按表单结构组织。

- 自动保存覆盖所有用户输入：文本、数字、选择项、开关、其他答案、每题备注和整体补充，并保留未回答、明确清空等状态。
- 输入后自动保存，无需额外点击“保存”。切换问卷、关闭标签、切换聊天及应用正常退出时刷入待保存修改；重新打开、界面重载和重启后恢复最后成功持久保存的草稿。
- 保存状态保持轻量，区分保存中、已保存和保存失败；“已保存”须以持久保存回执为准。保存失败保留当前输入并支持重试，不能把失败当作清空。
- 保存请求按草稿串行处理并校验版本。旧请求、旧页面和迟到回执不能覆盖新输入；主动清空也需要记录新版本，避免旧答案在恢复时重新出现。
- 发生同步冲突时保留两份内容，并沿用对话编辑框的恢复方式处理；无法识别的草稿格式保留原始数据，不写回空表单覆盖。
- 提交前先确认草稿保存成功，再保存本次提交快照并等待接收回执。失败可恢复或按同一提交身份重试；回执只处理对应快照，不能清掉用户在其他问卷或聊天中的新输入。

自动保存草稿不等于提交答案，不会唤醒 Agent。异常退出以最后一次成功保存的版本为准；关闭页面前的内存缓存不能作为持久化完成的依据。

## 题目变更和提交一致性

首版问卷发出后固定题目版本，Agent 不在用户填写过程中修改问题。补问使用新问卷，只询问新信息，保留前一份提交记录。

问卷包含聊天 ID、原任务关联、问卷 ID、题目版本和稳定题目 ID。提交包含答案快照及唯一提交 ID，宿主重新校验归属、状态、版本、答案类型、选项值和必填约束。

同一提交重试返回同一接收结果，不重复唤醒 Agent。即使远程客户端同时访问同一问卷，也需共享已接收和失效状态；两个不同提交竞争时只接收一份。本地界面始终遵守单一问卷标签限制。草稿保存带修订信息，迟到的保存请求不能覆盖较新的内容。

答案一旦被任务接收，查看或重新打开问卷不会再次触发执行。修改已提交答案应形成新的用户输入和新版本，原先执行过的操作不会因编辑记录而自动撤销。

后续支持题目更新时，需要展示变更、保留仍然有效的答案，并让用户确认。条件分支中被隐藏的题目可以保留草稿，但不参与当前必填校验和本次答案提交。

## 现有能力和接入建议

当前单题链路已有等待、回答、提醒和重启后继续的基础，可以复用交互规则，但问卷需要单独的结构化协议。

- [Agent 工具定义](../shared/agent-tools.ts) 的 `agent_ask_user` 明确要求一次一题，回应为单一文本。建议新增 `agent_ask_form`，保留原工具处理轻量询问。
- [共享类型](../shared/types.ts) 的 `AgentAskRequest` 和 `AgentAskResponse` 面向单题。新增问卷定义、草稿、提交快照和回执类型，避免把多选、数字及未回答状态压成一个字符串。
- [Agent 运行时](../electron/modules/agent-runtime.ts) 的 `runAskUserTool` 可作为等待接入参考。问卷工具将结构化答案返回对应任务，并在聊天显示易读摘要。
- [主进程](../electron/main.ts) 的 `pendingAsk`、`resolveAsk`、`replayPersistedAsks` 和 [聊天存储](../electron/modules/chat-store.ts) 已处理单题请求。问卷应有独立持久记录及接收流程，复用会话归属、通知和继续运行机制。
- [提交状态](../shared/decision-submission.ts) 已有等待回执、重复点击防护和失败保留的交互规则。问卷还需增加持久提交 ID、版本检查和宿主侧去重。
- [单题决策草稿](../src/composables/useDecisionDraft.ts) 仅使用内存保存，重启会丢。问卷对齐 [对话编辑框草稿](../src/composables/useComposerDraft.ts) 的版本保存、切换刷入、冲突副本、失败恢复和回执保护机制，并使用独立的问卷存储身份。
- [工作区标签](../shared/file-tabs.ts) 目前包括文件、浏览器和子对话。建议新增 `questionnaire` 类型，在 [工作区容器](../src/components/FileWorkspace.vue) 挂载固定表单组件。标签身份保持全应用唯一；当前按聊天保存的标签记录需要统一恢复和去重，避免生成多个问卷标签。
- [聊天页](../src/pages/ChatPage.vue) 接入问卷卡片、待答数量和子任务提醒，沿用当前会话隔离规则。

现有 `replayPersistedAsks` 只重放等待界面；`continueAfterPersistedAsk` 会记录回答并从历史启动新运行。问卷沿用这一恢复语义，恢复的是任务上下文和用户填写结果。

Agent 输出的题目数据需要校验类型、ID 唯一性和规模限制。无效定义返回可修正错误，不能展示无法提交的半份表单。应用统一渲染控件，题目说明作为受限内容展示。

## 分阶段范围

第一阶段完成可用闭环：与当前软件主题对齐的简洁表单、全应用唯一问卷标签、六类基础输入、推荐项与自填、明确的未回答状态、必填校验、其他补充、聊天入口、待答提醒、与对话编辑框一致的持久草稿、关闭重开、取消失效、提交回执和原任务继续。首版同时完成会话隔离和重启恢复，避免用户集中填写后丢失内容。

第二阶段补充简单条件显示、较长问卷的分组导航、文件和图片附加、日期与范围输入、已提交答案修改及差异展示。先支持“选择某项后显示某题”，再评估更复杂的规则。

第三阶段增加可复用模板，例如需求澄清、项目初始化和执行参数收集，以及用户模板管理、跨任务复用和导出。复用历史答案时显示来源并允许修正，不能悄悄将旧项目偏好应用到新项目。

逐段提交、Agent 在等待期间继续处理不依赖答案的工作、多用户协作和复杂表格题型另行规划；首版继续使用当前 Agent 的阻塞等待模型。

## 验收场景

1. Agent 发起六个问题，覆盖单选、多选、开关、数字和文本；用户提交后，原任务获得类型正确、含题目对应关系的答案。
2. 用户填写一半，切换聊天、关闭标签后重新打开，内容和所属任务保持正确；重启后恢复最后成功保存的草稿。
3. 开关未选择、明确关闭、数字零、跳过、不确定和由 Agent 决定分别保留语义，推荐项不会自动变成用户回答。
4. 提交失败后草稿保留；重复点击、回执迟到、提交后立即退出和远程客户端重复请求均不会重复接收或重复发起继续任务。
5. 用户停止原任务、取消问卷或删除聊天后，旧页面不能提交；不同聊天和子任务的草稿、答案和提醒不会串用。
6. 完成问卷后可以从聊天查看当时提交的答案；仅打开记录不会触发 Agent 执行，后续补问不会重新询问已有答案。
7. 后台问卷不切走用户正在看的页面；工作区达到标签上限时，问卷及草稿仍保留，并给出可恢复的打开提示。
8. 浅色、暗色及其他已有主题下的颜色与控件均和当前软件对齐；填写中切换主题不重置内容。窄窗口、键盘和输入法场景可完成填写，校验失败定位明确。
9. 等待问卷时选择“发送并切回聊天”，Agent 能收到消息并讨论题目；原问卷的草稿保留且不能再提交，不出现两次继续或并行运行原任务的情况。
10. 重复打开同一问卷、从另一聊天打开问卷、关闭后重开以及工作区恢复，整个应用始终最多只有一个问卷标签；切换前保存旧问卷，返回后恢复其草稿，其他问卷不串入内容。
11. 所有输入类型及补充说明均可持久恢复；明确清空后重启仍为空。保存失败、乱序回执、版本冲突和提交失败时，按对话编辑框相同标准保留草稿与恢复副本，不用旧内容覆盖新输入。

## 建议采用的首版默认值

入口名称使用“问卷”，聊天动作使用“打开填写”，提交动作使用“提交并继续”。界面简便美观，跟随当前软件主题；全应用同时一个问卷标签，切换不同问卷时复用；一个 Agent 同时一份待答问卷；三项以上独立问题优先批量询问；发出后固定题目；默认不限时；草稿按对话编辑框相同标准持久保存；关闭标签保留请求；重启后按历史继续任务。

首版优先验证“集中回答能顺利回到原任务”这一完整体验，再增加题型和模板管理。
