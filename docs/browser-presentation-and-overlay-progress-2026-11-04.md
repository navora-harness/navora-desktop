## 已完成的源码变更

### 白屏恢复

在真实旧构建中复现：布局稳定后，仅让原生宿主的几何失效，DOM 矩形不变；View 被隐藏，前端继续使用旧的 lastLayout 去重，无法自行恢复。报告见 [修复前失败记录](../../_planning/browser-presentation-before/failed.json)。此复现证明一条确定的失败链路，不断言现场只有这一种触发条件。

BrowserHostManager 现在通过独立的 `navora:browser.layout-invalidated` 事件通知宿主 renderer，携带 pageId、owner、hostGeneration 与原因。BrowserTabPanel 只接受当前活动页和当前 owner 的新代次，清除几何去重后重新测量提交；旧 owner、旧代次和其它页的通知不触发恢复。它不重新发出页面激活、不重建网页或重载。

窗口显示、还原或获得焦点时，存在有效提交的当前网页直接恢复可见；仍有有效请求时复用既有安全提交。显式隐藏、空布局、被弹层暂停或非当前页不因普通 focus 而被重新显示。需要改变几何时继续遵守忙碌／空闲提交契约，不取消或重放 Agent 输入。

### 标签外观

旧构建的比较确认：同状态标签的底色、文字和描边已经共享；明显差异主要来自独立标题栏使用 chrome 色、工作区使用 header 色。独立标题栏现已改用同主题 header 色，新增和移回按钮使用共享标签／控件变量，取消独立宿主单独覆盖标签描边的控制状态规则。控制状态仍由原有页面工具与无障碍描述提供。

### 已退出截图链的新增入口

- BrowserTabList 标签搜索：使用现有 NativePanel 的原生输入、图标、滚动列表和按钮；稳定动作 ID，查询后移除的旧结果不能再次选择。当前使用 `.5` 已有控件，未来列表行视觉改版继续搁置。超多结果先显示前 180 项，并可搜索完整集合缩小范围；不为所有标签建立独立原生面板。
- ChatResourcesMenu 当前对话更多：复用已有原生 Menu，保留分组、禁用、置顶勾选、查找／浏览器快捷键提示、危险操作确认与现有事件。菜单绑定对话／页面上下文，切换上下文后旧结果不能操作新对话。通用 ActionMenu 同步增加可选勾选、快捷键与上下文失效保护。
- ChatPage 侧栏聊天行更多：每页复用一个菜单调用器，保留原行按钮与修改标题、置顶、导出、删除流程；绑定稳定对话 ID、开关状态和导出条件，关闭、离页或目标失效时取消迟到动作，不给每个聊天行常驻原生实例。
- FilePreviewPanel 文件显示方式、打开文件选项：复用原生 Menu，保留 Markdown／源码切换、系统打开、所在目录与另存为；菜单绑定所属对话、相对路径和当前预览生命周期。切换文件或缓存组件停用后旧动作失效。不在测试中弹出系统保存对话框或打开资源管理器。

上述原生入口不创建覆盖网页的 DOM 副本，不触发 preview 或空布局。远程端、不支持运行时或原生调用失败仍有显式兼容路径；这些兼容路径尚未计作“全部截图替换已清除”。

## 已执行验证

完整构建、类型检查和 477 项源码测试通过。新增 `scripts/ui-browser-presentation.mjs` 使用实际构建的主进程、preload、renderer 和原生 View，隔离临时配置、聊天与网页，不读取用户现有资料。

[修复后专项报告](../../_planning/browser-presentation-after/completed.json) 共 15 项检查，覆盖：

- DOM 矩形不变时的原生失效恢复，及真实窗口连续调整尺寸。
- 单标签独立窗口首次显示、反复显示／还原、从主窗口资源入口再次查看，不切换标签即可恢复。
- 当前 owner／宿主代次隔离，网页实例、草稿、持续 RAF 和控制权保持。
- 六种内置主题的浅色、深色共 12 组最终计算样式，两个现存窗口一致。
- 标签搜索真实原生控件、查询更新与旧结果拒绝；当前对话原生菜单的勾选／快捷键和实际行内查找跳转。
- 侧栏聊天行的导出禁用与真实行内重命名；文件显示方式的原生单选／源码切换和打开选项，均无覆盖 DOM 副本。
- 已切换为文件内容时，宿主获得焦点或还原不会重新显示旧网页盖住文件。
- 本专项的弹层 preview 请求为零。

这些自动检查把窗口放在屏幕外，并对 NativePanel 使用不激活模式；按钮／菜单选择通过真实接口回调注入，不把它们计作物理鼠标、系统输入法、多显示器 DPI 或视频解码验收。发布前仍需按总规划补齐真实可见窗口检查。

## 第三项仍需完成

完整入口清单继续以[统一规划第 3 节](./native-panels-followup-plan-2026-11-04.md#3-修复与迁移清单)为准。本次已迁移标签搜索、对话更多、侧栏聊天行更多及两个文件预览菜单，共五个入口；其余未迁移的 HTML 提示、菜单、对话框和复杂面板仍可能进入截图兼容链。**BrowserTabPanel 中的截图替换总路径尚未删除。**

后续不能只删除截图代码然后让原生网页挡住界面，或隐藏 View 留白充当完成。必须先保持各入口原有交互、资料和编辑能力，再退出对应截图依赖。

按用户安排，定制 Electron 智能体提供以下缺失能力，应用待实际发布的类型／功能探测接入，不预造字段或修改定制内核：

1. 被动原生提示的鼠标穿透及明确的文字约束；用于移除标签 HTML 悬停提示，避免提示吞掉网页真实点击。
2. 多行编辑、组合输入、带修饰键提交与草稿保留；用于悬浮批注及多行资料界面。
3. 持久侧栏所需的树、行操作、拖放、宽度变化与子菜单协调；保留聊天／文件／浏览器／插件资源交互。
4. 按实际入口需要的受限图片预览、按键捕获与可观测焦点状态；用于图片资料／预览及快捷键设置。

普通列表与单行编辑已具备的能力可继续迁移；原生列表行的新视觉与 Menu 横排缩放不作为本轮额外设计要求。新内核发布后核对兼容、完成剩余入口映射，清除常规截图替换及其残留 DOM 检测，再做全量验证、提交推送并编译新版本。
