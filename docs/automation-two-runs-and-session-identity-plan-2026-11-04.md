## 3. R01：分离文字输入、提交及页面效果

### 已确认的代码路径

[原生目标文本适配](../electron/modules/browser-target-text.ts)在提交前已经核对输入值，但进入 Enter 批次时重新将 `effect` 设为 `unknown`、清空 `confirmedCodeUnits`；发送序列为 `rawKeyDown → char(回车) → keyUp`。若第一条已让页面保存并隐藏／移除编辑框，第二条仍带旧 target，原生目标准备可以返回 `STALE_TARGET` 或 `TARGET_NOT_VISIBLE`。

重新发布 `.7` 的 `input_sequence.cc` 已让 keyUp 使用当前页面 frame，不再强行聚焦原节点；当前问题仍可发生在其前面的 char 阶段。两份记录的停止索引和清理回执与这条路径一致。

### 规划

- 保存独立的文字输入回执、提交回执和页面结果回执。已核对的文字长度及输入效果不因后续提交失败而被抹掉。
- `submitDispatched` 区分“Enter 按下已派发”和“页面提交结果已确认”；保持旧字段读取兼容，避免把一次按下解释为完整提交成功。
- 提交导致正常导航、输入框隐藏、节点替换或组件卸载时，转入结果核对阶段。核对同一页面／文档的最新任务文字、状态或表单结果，再判断业务成功、失败或未知。
- 原生错误仍保留。核对成功时可以形成“输入成功、保存成功、后续事件因目标变化停止”的分阶段结果；不能直接将所有 `STALE_TARGET`／`TARGET_NOT_VISIBLE` 改成成功。
- 清理未确认、页面已被用户接管或文档凭据失效时继续阻断。提交状态不明时先观察，不重放整段文字或再次按回车。
- 评估现有 API 能否安全表达 Enter 的完整生命周期；需要原生补强时，要求“触发事件后目标消失”的结构化原因、文档／frame 绑定的释放，以及同一批次内受控的后续事件处理。不能将待发送字符盲目投向另一个新聚焦输入框。

## 4. R02：目标消失后的有界恢复

[运行策略](../shared/agent-progress-policy.ts)的 `verifiedObservation` 要求新快照里找到与旧 target 完全一致的节点，并读到其值、聚焦、可见及只读信息。记录 A 中旧节点已被移除，这个恢复条件无法满足；应用的页面观察与策略层的输入恢复也可能给出不同结论。

规划建立三条恢复路径：

1. **原目标仍在**：核对当前值、文档、编辑能力及清理结果，保留现有严格验证。
2. **原目标已隐藏／被替换／被移除**：通过具备明确范围的原生观察，结合提交阶段回执和最新业务状态解决不确定性。查询返回空只证明当前查询没有命中；只有范围覆盖、文档一致及结果证据充分时才能确认目标消失及操作后果。
3. **证据仍不足**：进行有限补充观察；达到边界后给出具体未确认项和可继续的条件，保留现场。

统一页面控制器与运行策略的恢复原因及状态；向模型返回具体需要的观察范围，而不是始终要求找回旧输入框。恢复完成后使用新的 target／ref 创建新动作，旧输入和旧 Flow 不自动重播。

同一页面、同一未解决输入产生的阻断应合并计数。当前失败指纹包含参数，换 ref 后可能不能累计为同一阻断；不得因此把同一门闸反复试到预算耗尽。保留任务预算、用户接管、权限和输入清理保护。

## 6. I01：用户处理其它工作时的后台输入与焦点隔离（`.8` 已恢复）

**当前状态：2026-11-05 已由用户明确恢复，随 `.8` 完成应用接入。** 以下保留 `.7` 阶段的能力缺口、原搁置决定和场景要求；最新实际验证及未覆盖边界以 [.8 实施记录](./electron-8-automation-implementation-2026-11-05.md)为准。原来的可选开关方案已改为 Agent 持有控制权期间固定开启。

搁置范围也包括最近讨论的开关方案：在 `setVirtualCursorEnabled(true, { blockRealPointer: true, blockRealKeyboard: true })` 的保护模式下，由定制内核额外启用完整输入／焦点隔离。当前已有 `blockRealPointer`、`blockRealKeyboard` 的真实输入过滤语义保持原状，尚未增加该扩展。

**需求澄清：用户指的是切换到其它软件、继续打字、移动真实鼠标等日常工作期间，Agent 仍能独立操作浏览器，不争抢系统焦点。这是后台自动化输入隔离的要求，需要在内核层提供明确保证，应用层完成接入和状态协调。** 点击 Navora 内非 View 区域只是其中一种场景，不能用该场景代替完整需求。

### 现有边界

当前应用的自动接管监听绑定 guest WebContents 的输入事件；纯悬停不算接管。原生虚拟光标输入过滤也检查事件目标是否属于该 View 的原生窗口后才阻断，未见“任何宿主点击都必须接管”的设计。

但以下变化确实可能影响动作：guest 失焦让网页编辑器触发 blur 保存；打开侧栏／设置改变 View 几何；切换网页、隐藏工作区或移动窗口改变显示与坐标条件；显式点击暂停／接管改变控制权。现有 `geometryChanged()` 会使旧操作失效并要求新观察。

**两份导出没有物理输入及焦点轨迹，不能确认其中某次失败由点击非 View 引起。**

### 期望行为

- 用户激活其它应用或其它 Navora 窗口时，后台网页自动化不因系统前台窗口变化而失去目标路由；用户真实键鼠继续作用于正在工作的界面。
- Agent 的键盘内容仅投递到获准的 guest 文档／frame／目标，不能落入用户正在操作的其它应用；用户输入的内容也不能混进 Agent 的网页编辑。
- 点击聊天、输入消息、查看不改变 View 的界面控件，不应自动撤销 Agent 页面租约、暂停整个对话或清空虚拟指针位置。
- 界面切换实际改变 View 大小／缩放时，停止使用旧几何的动作，在新边界就绪后重新观察并安排新动作；保留已经确认的步骤，不重放在途副作用。
- 导航、关闭页面、切换控制权等明确影响目标的用户操作，按真实语义处理；记录来源及原因。
- 原生键盘投递不能抢走用户正在聊天输入框或 NativePanel 中输入的物理键盘内容；guest 虚拟输入与宿主真实输入分别路由。
- 隐藏、最小化及独立窗口需要分别报告能力和状态，不承诺所有页面在任意隐藏状态下均可继续输入。

### 是否需要定制内核

**需要把输入和焦点隔离作为明确的内核交付目标。** 后台自动化不能依赖当前真实前台窗口、系统键盘焦点或真实鼠标位置。仅修改应用的暂停判断、延时或自动调用 focus，不能形成这一保证。

`.7` 已有目标派发基础，但它不等于已完成整个后台隔离契约。应按以下要求核对现有实现，复用已满足的部分，针对缺口定制补齐并验收：

- 每个 WebContents 独立持有虚拟键盘焦点及虚拟指针状态。区分系统前台窗口、宿主真实输入焦点、guest 文档内的虚拟目标焦点。
- 注入键鼠按页面／frame／目标及批次凭据路由，避免将“当前真实聚焦窗口／控件”作为 Agent 输入的最终目的地。
- 输入执行和恢复不通过激活窗口、置前或反复抢系统焦点实现。真实键鼠的保护仅作用于对应 guest，不封锁用户在其它界面工作。
- 用户切换软件或正常失焦不自动解释为接管；明确的暂停、接管、关闭页面和失效文档仍按安全语义停止旧动作。
- 原生回执可区分目标失焦、用户接管、宿主失活、文档替换、页面隐藏及清理未确认，应用不把这些原因混成统一失败。
- 非前台可见页面、被其它窗口遮挡、最小化／隐藏分别声明支持能力并定向验收。能力不足时给出真实状态；不能先声称后台操作成功。

上述为搁置前拟定的交付要求，不代表 `.7` 已经具备所有公开接口，也不是本轮已完成的改动。应用层提交判定、恢复、位置缓存和速度等独立修复继续保留各自状态，不等待本项恢复。

## 7. P02：虚拟光标连续移动与统一位置

### 已确认的应用路径

- [指针运动缓存](../electron/modules/pointer-motion.ts)在没有可复用位置时，视口动作回退到 `{x:0,y:0}`；target 动作回退到本次目标坐标。
- 缓存 scope 包含具体 `backendNodeId`，更换目标后不能直接复用上一个目标的位置。
- [点击和悬停适配](../electron/modules/browser-tools.ts)多处在原生点击／悬停前后调用 `invalidatePointerMotion`，使前一个移动的终点被丢弃。
- 当前公开类型没有可靠的虚拟指针位置读取接口。内核内部虽有 `_getVirtualCursorState`，它不是稳定公开契约，规划不依赖私有接口上线。
- 已核对的内核 `VirtualCursor::Configure` 没有每次将位置归零，位置由实际注入鼠标事件更新。因此应用反复失去轨迹起点是有源码依据的重点；尚未进行现场逐帧验证。

### 规划

- 为每个 WebContents 维护同一坐标系下、带有效标记及代次的最后确认虚拟位置；目标凭据与虚拟位置分别管理。
- 统一以主视口逻辑坐标记录位置，target 局部坐标在真实派发时可靠转换。不同节点或 iframe 的局部坐标不能直接当成同一个空间接续。
- 从原生回执记录最后真正派发的鼠标点。完整动作后延续终点，部分失败后只使用回执已确认的点；回执未知时位置保持未知。
- 首次没有有效位置时，等待第一个真实定位动作后建立位置；不假造从固定角落飞入的装饰轨迹。
- 普通点击、键盘输入和悬停结束不无条件清空位置。导航和目标变化应使旧目标凭据失效；若 View 坐标空间未变，可单独保留已确认的指针位置。
- View 尺寸、缩放、DPI、frame 变换或窗口迁移改变坐标时，按有效转换或重新定位处理，不能仅凭旧缓存继续点击。
- 页面实例、不同窗口和并发子任务分别持有位置。真实系统鼠标位置不能代替 guest 的虚拟指针起点；模型提供的 `from` 也不能覆盖已确认位置而制造跳变。

必要的原生公开契约包括：当前位置是否有效、主视口逻辑坐标、frame／文档／几何代次、最后输入批次与步骤、最后确认鼠标点，以及从当前位置向目标移动的原子能力。接口名称及支持平台在定制规范中另行确定。

## 8. P03：降低默认移动速度

当前默认 `speed_multiplier=1`、120 Hz 输入采样、60 fps 光标显示。[轨迹估时](../shared/pointer-trajectory.ts)使用距离及目标宽度估计总时长，默认 lognormal 曲线还可能将主要位移集中在较短区间。采样密度和绘制帧率不是移动速度。

- 建议先将默认速度调整到现有基线的 **0.6× 左右**，作为待实际效果校准的初值；优先验证 0.55–0.7× 范围，不声称已经完成设备标定。
- 结合移动距离、有效目标宽度、总时长和峰值速度，让中长距离移动更容易看清；短距离保持自然，避免每个微小动作都强制等待相同长时间。
- 优化加速／减速曲线，限制突然冲刺。放慢总时长时保持有效输入采样和绘制，不用降低帧率制造卡顿。
- target 中心点击同样走一致的时序策略；不能只有坐标工具变慢，而普通 selector／ref 点击仍跳跃。
- 设置保留明确的慢／默认／快选择或速度滑杆与预览。“默认”对应新体验；已主动设定的速度不被静默覆盖，缺失字段或旧默认的迁移策略需明确记录。
- 单次工具覆盖有合理范围，并在诊断中记录最终生效参数，便于发现模型显式速度覆盖为何让用户偏好失效。
- 这部分主要在应用层调整轨迹规划与设置即可，除非定向回执证明原生实际执行时序未遵守计划。

## 11. UX01：同一主按钮切换停止与加入队列

- 主工作区、展开工作区和独立浏览器窗口使用同一规则；子菜单也在实际可用范围内自适应布局。窗口移动、改变大小、界面缩放或 DPI 变化后，不复用旧的屏幕坐标。
- Menu 使用窗口内容区相对 DIP，NativePanel 使用屏幕 DIP；界面缩放只转换一次，不重复加窗口原点或乘设备像素比。位置请求绑定真实所属窗口和触发控件。
- 打开、关闭及键盘操作继续沿现有原生菜单行为，网页保持实时显示，不增加截图替换，不改变 Agent 的页面实例或控制权。

本节细化[现有 U05 菜单定位规划](./browser-chrome-interaction-followup-plan-2026-11-04.md)。**本轮已在应用层完成位置自适应**：[公共位置计算](../shared/native-menu-position.ts)供菜单桥和网页右键使用，`bottom-end` 按按钮右沿定位，再在当前窗口内容区内平移约束。

## 15. UX05：链接打开偏好与右键动作

### 设置与默认行为

在 **设置 → 浏览器 → 链接打开方式** 增加简洁选择：

- **软件内新建窗口，默认**：创建新的浏览器页面并放入独立浏览器窗口，不只是在当前窗口增加标签页，更不能覆盖正在自动化的现有页面。
- **软件内新建标签页**：在符合现有归属约束的浏览器窗口／工作区内新建页面；没有合适宿主时走现有创建流程。
- **系统默认浏览器**：明确交给系统默认浏览器。

缺省配置及升级前没有此字段的记录使用“软件内新建窗口”；用户选择自动保存并同步所有窗口。使用现有配置校验与合并机制，保存失败保留可恢复状态。

偏好作用于软件界面中用户点击的普通 HTTP(S) 链接：聊天和子对话正文、来源引用、文件预览中的网页链接等共用受控路由。应用内路由、文内锚点、工作区文件链接、下载／文件打开以及 `mailto` 等独立协议不混入网页偏好。网页内部普通导航、站点自身弹窗和 Agent 工具调用保留各自语义，不因为全局设置而把每一步导航拆成新窗口。

### 链接右键菜单

- **访问链接**：按当前设置打开；需要时用提示说明当前选择，不让菜单中的默认动作与左键不同。
- **复制链接**：复制真实目标地址，不复制显示文字或被省略的地址。
- **在外部浏览器访问**：此次明确使用系统默认浏览器，覆盖当前偏好，但不改变设置。

键盘激活和已有显式新窗口／外部打开操作保持明确语义；右键不触发导航。菜单绑定原始链接及来源，切换聊天后不能读取新的当前地址；协议、来源及权限校验沿可信路由处理，不将任意字符串或危险协议交给系统 Shell。

### 会话与控制权

从聊天等普通界面打开新网页时，复用[公共默认浏览会话解析](./已完成/browser-public-default-session-plan-2026-11-04.md)，页面保留来源聊天、引用及权限归属；公共登录共享不授予其它聊天的页面控制权。普通链接不意外继承当前前台专用会话，也不自动创建新的隔离会话。

没有当前聊天时沿现有明确归属选择流程，不制造隐藏聊天；显式来源页面／opener 或用户选择专用会话时按既有继承规则处理。新窗口保留真实页面实例和现有窗口约束，不导航、关闭或接管 Agent 正在操作的页面；创建失败保留原界面并提示，不静默改为外部打开。

实施前 Markdown HTTP 链接、部分文件预览和全局外部跳转存在分散入口；本轮已统一相关设置、渲染器路由及主进程打开服务。本项主要为应用层工作，不依赖普通新窗口策略的定制内核补强。

## 16. UX06：区分浏览会话、聊天对话与窗口名称

截图中的多个“会话 1”无法说明来源或区别，而“默认会话”又容易被理解为当前聊天。保留既有公共／隔离模型，调整可见名称和层级，不合并真实存储。

- 浏览器资源中的公共节点显示 **“默认浏览会话”**，固定在前；公共属性用紧凑共享图标和提示表达，不再增加一段常驻说明。它仍是原有唯一默认会话，不新建第二个分区。

- 历史重复“会话 1”只在确认是自动占位名称时迁移为稳定的可区分名称；明确由用户设置的重名保留，用次级信息消歧。来源或编号不足时追加稳定短 ID，不能刷新一次换一个名称。
- “聊天对话”用于任务交流及来源；“浏览会话”用于网站登录与隔离环境；“浏览器窗口”用于容器。工具结果、创建／选择菜单、详情及窗口相关文案使用相同区分，不继续用单独的“会话”混指三者。

### 列表与数据边界

资源侧栏继续保持 **浏览会话 → 页面** 两层结构。页面标题为主；“全部对话”范围才在次行显示来源聊天，当前范围不重复标注。会话名过长省略，悬停／详情可查看全名；紧凑类型标记和数量不互相挤压，空状态不堆叠说明。

命名基于独立的稳定 ID 和用户名称字段，不能用展示文字查找会话。改名、编号迁移、筛选、排序、关闭／移窗不改变 session ID、partition、Cookie、页面归属或 Agent 租约；旧工具按 ID 调用继续兼容。默认节点零页仍可见，专用会话不因改名被误识别为公共节点。

本项是[已建立的公共默认会话与资源侧栏](./已完成/browser-public-default-session-plan-2026-11-04.md)的名称和交互补充，不把已完成的数据模型重新列为全部未实现。它也不替代 V01 的子对话图案标识：图案帮助辨认子对话，名称帮助区分真实浏览环境，两者分别保存。

## 18. UX08：标签信息原生面板、复用与标题布局

用户补充了三项明确要求：标签页不配置 HTML `title` 属性；标签信息使用定制原生面板；面板已经显示时，在标签间移动可直接移到下一标签下复用。同时修复标签本身明明有可用宽度却只显示“百…”的问题。

- 主工作区、独立浏览器、独立文件窗口及混合文件／聊天标签共用标签呈现组件。移除标签、状态文字和标签内按钮上的 `title`，调用方不再向根元素透传该属性；完整信息保留在 `aria-label` 和原生信息面板中。
- 每个所属窗口按需创建并复用一个标签信息 NativePanel。首次悬停使用短延迟；面板已经显示时，移到相邻标签直接更新内容和锚点，不重复等待首次延迟，也不为每个标签创建一份面板。
- 跨标签短暂越过间隙允许很短的延迟收起；真正离开标签区域、点击、拖动、切换页面、滚动或打开其它交互菜单时隐藏。隐藏保留实例，所属窗口关闭时销毁；标签卸载不能销毁已经由下一标签使用的共享面板。
- 面板是被动信息提示，使用 `focusMode:none`，不抢网页或输入框焦点；没有取得过焦点的面板关闭后也不能强行恢复旧 guest 焦点。现有公开能力没有明确的透明区域穿透保证时，不声称已支持；鼠标离开标签进入面板区域时按被动提示收起。
- 请求绑定标签身份与代次。先前标签的迟到回包不得覆盖新标签内容、关闭新面板或让位置错误跟随；共享面板保持固定生命周期身份，显示目标单独更新。
- 使用真实 NativePanel 承载文字，退出该提示的 DOM Teleport／整页截图占位路径。无原生面板能力时保留无障碍名称，不恢复系统 title 或用截图替换 View 显示标签提示。
- 根据标签真实宽度分配图标、标题、声音和关闭按钮空间。修正宽度约束、flex 收缩及内联容器尺寸影响，充足空间优先显示标题；多标签和窄窗沿最小可读宽度滚动。完整标题放入提示面板，不能因为还存在副标题／来源就让主标题只剩一个字。

**截图替换审计边界：** 当前真正占位链是 BrowserTabPanel 的覆盖检测 → `workspace.preview`／`capturePage` → `frozenFrame` → 隐藏实时 View。旧 DOM 标签信息层会触发这条链，属于本项直接修复。浮动侧栏、HTML 批注编辑器和部分通用对话框仍可能触发，属于此前保留的复杂迁移范围；本次单独接入标签提示不自动恢复其它搁置工作。正常截图工具、批注证据、用户主动预览和远程画面流不算 View 占位，继续保留。
