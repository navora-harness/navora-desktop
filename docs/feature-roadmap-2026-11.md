# Navora 产品功能路线图

> 规划基线：2026-11-03 · 当前版本：0.3.33
>
> 本文是建议的实施顺序，不是交付承诺。当前实现以 [当前功能与验证边界](./current-state.md) 为准；跨平台插件细节继续以[插件平台规划](./plugin-platform-installation-plan.md)和[Fastls 集成进展](./fastls-integration-progress.md)为准。
>
> 2026-11-03 增补：第 9–15 节细化聊天、文件、插件、浏览器四条产品线及共享基础；新增条目均为 **Planned**。实施优先级以第 5、14、15 节为准，第 3 节继续保留各能力的设计与历史验收记录。

## 1. 规划目标

在现有桌面聊天、浏览器工作区、文件预览、插件工作区和运行归属能力上，按风险和依赖完成以下结果：

1. 把当前已做的大批界面与桌面能力收口为可复现、可发布的版本。
2. 让用户清楚知道任务在做什么、使用了哪些上下文、为什么等待，以及停止后还有哪些工作未结束。
3. 补齐 PDF/表格阅读、插件诊断、浏览器接管反馈及混合独立窗口，形成从提问到查看产物的连续体验。
4. 在权限、状态隔离和失败恢复成立的前提下，扩展 Fastls 网络会话能力。
5. 逐步提升文件编辑与运行恢复能力，先建立所需的最小版本和持久记录协议。

阶段采用“完成门槛”推进。生成过某平台产物、测试中途通过或本机可以运行，都不自动等于该平台正式支持。

## 2. 当前基线

### 已交付或已有实现

- 桌面对话、文件、浏览器、插件与设置工作区；窄区域布局、键盘导航、统一控件、加载和错误状态。
- 浏览器主页、地址建议、会话内历史、快捷网址、下载，以及网页标签在内嵌区和独立窗口之间迁移。
- 网页元素/区域批注、截图和意见版本；草稿跨窗口保存、冲突副本与损坏文件隔离。
- 文件目录、列表/网格、受限文本/Markdown/图片预览、下载归属和文件/网页共用标签。
- 插件 SDK 目标产物、商店 v2、多平台选择与受控 sidecar 基础机制。
- Fastls 0.1.0 的 status、profiles、request 工具及 Windows x64 闭环。五种目标包已生成；Windows 实际验收不代表 macOS/Linux 已认证。
- runId 基础身份、消息序号及部分进程内下载任务归属。

### 尚未完成或需要证据

- 批注检索、筛选和分批阅读已有实现；更大历史规模、真实多显示器拖放与平台窗口差异仍需验收。
- macOS 的运行/签名/公证/隔离属性验证，Linux 实际运行和依赖验证；Windows 强制结束后的 sidecar 进程树回收。
- Fastls 按对话隔离的 Cookie 上下文与安全逐跳重定向。
- 文件通用编辑、保存冲突恢复、PDF 阅读器、CSV/TSV 表格视图；当前只提供受限只读预览。
- 完整持久事件记录、重复事件去重、跨重启来源链、可恢复运行及阶段耗时诊断。
- 静态本地/可切换源商店尚非公共托管发布平台。
- 聊天已有标题/消息搜索、草稿保存和消息队列；精确到命中消息的搜索定位、统一任务状态和可管理的文件上下文附件仍需升级。
- 插件已有安装预检和失败回滚；面向用户的运行诊断、占用中升级策略及可用旧版本恢复入口尚需补齐。文件和网页独立窗口仍分别管理。

源码运行时已切换至 `45.0.0-cloudbypass.3`，原生快照与定向输入见[浏览器 Agent 自动化](./browser-agent-automation.md)。下文 `45.0.0-beta.5` 的性能数据和旧候选包均保留原记录日期；不能直接作为新运行时、新增功能的发布证据。

当前 `electron:install` 脚本只接受 Windows x64，而通用构建及 macOS/Linux 打包入口仍会调用它。因此其他平台目前还存在构建链前置阻塞，需先定义运行时来源、能力降级和按平台选择的安装入口，再做宿主实机验收；不能仅将其描述为缺少测试设备。

## 3. 阶段路线

本节阶段编号用于组织能力主题，不要求全部串行。PDF/表格只读预览和插件诊断可在版本收口后独立推进，无需等待 Fastls 0.2.x；文件编辑与恢复各自依赖的最小基础见第 14 节。

### 阶段 0：当前版本收口与发布候选

**建议窗口：近期，约 1–2 周。建议版本线：0.3.x。**

#### 工作范围

- 冻结本次范围：主窗口与系统标题栏、浏览器/文件标签、菜单焦点、下载、插件工作区、Fastls 当前请求能力。
- 对照代码、`current-state.md`、插件/商店文档和实际验证记录，统一“已实现 / 已测 / 已发布”的说法。
- 用一个隔离配置完成 Windows 候选版本的安装、启动、升级保留、卸载与重新启动检查；保护日常用户配置。
- 针对跨模块交互做一次整合验收：会话切换、窗口切换、文件/网页预览、浏览器接管、取消操作、下载稍后完成、插件失败回滚。
- 只修复阻断发布或显著影响任务完成的问题；新需求记录到后续阶段。

#### 执行记录（2026-11-02）

- **In progress：**0.3.33 源码的类型检查、150 项基础测试、原生浏览器契约、桌面界面回归和浏览器工作区/IPC 端到端均通过；UI 回归覆盖普通及减少动态效果模式，输入更新 P95 约 16–17ms。
- P1 开始前的 Windows x64 NSIS 候选包已在 `release/phase0-candidate-2026-11-02/` 生成，隔离目录安装、首次启动及配置初始化、同版本覆盖安装、卸载均通过；卸载移除了应用目录并保留隔离数据目录。该包不包含后续 P1 改动。
- 目前覆盖安装是同版本重装，不能替代从旧版本升级的迁移验收。候选包尚未签名，不可作为面向用户的正式发布包；P0 在完成真实升级数据验证和签名/分发检查前保持 **In progress**。
- 构建仍提示主 JS 909.61 KiB（gzip 303.53 KiB）、主 CSS 720.43 KiB（gzip 106.62 KiB）超过 500 KiB 提示线；当前不影响测试通过，作为后续性能调查项记录。

#### 完成门槛

- 类型检查、基础测试、原生浏览器契约和必要 UI 回归均通过，测试记录对应同一候选源码状态。
- Windows 首次启动与更新后数据完整；未完成下载、浏览器 Session 和草稿表现符合当前文档。
- 主要发布说明列明已支持、已验证和待平台实测的区别。

#### 暂缓

文件编辑、Fastls Cookie/重定向、商店托管和新的对话工作流不并入此阶段。

### 阶段 1：桌面与浏览器体验补齐

**建议窗口：阶段 0 后约 2–4 周；与平台实机验收并行。建议版本线：0.4.x。**

#### 浏览器批注阅读

**执行状态（2026-11-02）：In progress。** 批注面板已加入按标题/网址/页面文字/意见（包括未保存草稿）检索、状态筛选、最新/最早排序和 20 条分批展开；截图按当前显示批次延迟读取。Windows 浏览器工作区端到端检查覆盖检索、状态筛选、排序、25 条历史分页、键盘移动结果及编辑草稿保留，截图见 `release/ui-browser-workspace/annotation-history-search.png`。当前标签可主动比较创建时与当前网址、标题及所选元素；区域批注保留人工查看截图的提示，不做易误判的像素差异结论。

- 按对话/页面筛选，按状态过滤；提供关键词检索标题、URL 和意见。
- 大量历史批注保持分页或分批加载，不一次读入所有截图。
- 筛选和检索不丢失正在编辑的草稿；同一页面可检查网址、标题、元素唯一性和选区文字变化，区域快照提示人工对照。
- 键盘可完成筛选、结果切换、定位、展开截图和恢复编辑。

#### 多窗口与响应速度

- 完成当前事件驱动状态更新：无活动标注/批注时不对每个标签高频轮询；只对需要等待用户选取或刷新批注的状态进行按需轮询。
- 检查多标签切换、关闭、拖动、窗口大小变化和关闭后重开，确保迟到事件不会切回旧标签或覆盖新布局。
- 固定性能样例和现有 32ms 输入更新 P95 门槛；记录浏览器标签数量、页面类型和运行模式，避免仅以单窗口数据代表真实工作区。
- Windows 实机检查跨显示器拖放、不同 DPI、窗口边缘、系统按钮命中区和小屏幕高度。

**2026-11-02 本机基线：**新增 `npm run test:ui:browser` 的标签切换和窗口缩放采样报告 `release/ui-browser-workspace/browser-workspace-performance.json`。Windows、Electron 45.0.0-beta.5、普通动效、主窗口与独立浏览器窗口同时打开（共 2 个窗口）、单台 175% 缩放显示器、静态本地页面和原生 WebContentsView：2 标签 16 次切换 P95 9.2ms，3 标签 16 次切换 P95 9.2ms；独立窗口交替变更尺寸 12 次，原生 resize 到渲染器下一帧同步的 P95 为 8.94ms，每次均核对渲染器视口与原生客户区尺寸一致。标签采样点不等同于既有 32ms 输入更新指标，也不代表跨机器性能。自动化确认了窗口落在目标工作区且系统按钮命中区有效；本机只有一个显示器，真实跨屏拖放和混合 DPI 仍待实机体验。

#### 平台验收并行线

- 先修复运行时安装入口的 Windows x64 限制：按目标平台选择已支持的运行时，不将 cloudbypass.3 的 Windows 包用于其他系统；未取得等价原生能力的平台显式降级并单独记录。
- macOS：打包启动、原生交通灯、拖动区、文件选择、权限对话框、签名、公证和首次启动隔离提示。
- Linux：打包启动、系统窗口框架、文件选择、缺依赖提示、证书与 noexec 环境。
- Windows：安装目录含空格/中文、标准用户权限、多显示器和强制退出回收 sidecar。
- 每个平台分开记录 Electron 版本、构建产物、硬件环境、结果和未通过项。

#### 完成门槛

- 批注列表在高数量下仍可搜索、过滤、阅读和恢复编辑，草稿冲突策略保持不变。
- 所有受支持平台都有实际宿主验收记录；没有目标设备或签名链的目标继续显示“待验证”。
- 性能回归报告附带工作负载和采样环境，不把单机结果扩写为通用提速承诺。

### 阶段 2：Fastls 会话状态与重定向

**建议窗口：约 3–6 周；需要先完成权限与隔离设计评审。建议版本线：Fastls 0.2.x。**

#### Cookie 上下文

- 提供创建、列出和关闭上下文；上下文由宿主生成身份，并绑定 pluginId、chatId、能力权限和固定代理/指纹设置。
- Cookie jar 只放在宿主管理的私有目录；调用时写 staging 副本，仅在符合提交条件后原子替换正式 jar。
- 同一上下文请求串行化；超时、取消、进程崩溃和响应过大时不静默提交半成品。
- 删除对话、关闭上下文、停用、卸载、更新和退出时清理相应状态。
- 不继承浏览器 Cookie，不共享跨对话 Cookie，不把任意路径或 CLI 参数交给模型。

#### 安全逐跳重定向

- 宿主处理每一跳，不使用 CLI 自动跟随；每跳重新检查 scheme、域名、端口和白名单。
- 限制跳转数量并共用原始调用的总超时预算；检测循环地址和非法 Location。
- 明确 301/302/303/307/308 的方法与正文处理；跨 origin 删除 Authorization、Cookie、Host 等敏感头，返回原 origin 时也不恢复。
- 第一版不开放认证代理、任意 CA、任意文件型指纹配置或无限重试。

#### 完成门槛

- 本地 HTTP/TLS/代理夹具覆盖重复头、Cookie 提交、跳转链、跨域凭据剥离、循环、超时、取消和失败回滚。
- 每个拒绝请求都能证明目标没有收到请求；诊断不泄漏凭据。
- 关闭/停用/更新时进程与临时文件均回收；Windows Job Object/子进程边界有独立验收。

### 阶段 3：文件工作区能力

**建议窗口：约 4–8 周；先做只读预览，再决定编辑范围。**

#### 3A：只读格式扩展

- 增加 PDF 阅读，支持页码、缩放、查找和安全错误提示；有界读取并避免执行嵌入脚本。
- 增加 CSV/TSV 表格视图，列宽/行数受控，保留原文查看和下载/系统打开入口。
- 明确大文件上限、编码识别、超大行、恶意内容和渲染失败时的退路。

**3A 完成门槛：**样例覆盖常见/损坏/超限文件；预览只读，不修改源文件；窄窗口和键盘导航可用。

#### 3B：文本与 Markdown 编辑（需用户价值信号后启动）

- 编辑器先支持 UTF-8 与明确识别的 BOM 编码；保留换行符和文件原始编码信息。
- 保存前校验文件版本；并发变更时展示差异并提供重载、另存或经确认的合并。
- 使用原子替换，写入失败保留原文件；应用退出或关闭标签时统一处理未保存修改。
- 将用户编辑和 Agent 写入纳入同一版本协议，防止静默覆盖。

**3B 完成门槛：**外部进程修改、磁盘写入失败、关闭/崩溃、超限文本和跨对话同名文件都无静默丢失或错误覆盖。

图片批注、裁剪和派生文件排在文本编辑之后；PDF 编辑、Office 原生编辑和任意二进制编辑不列入本路线承诺。

### 阶段 4：运行记录、产物来源与恢复

**建议窗口：阶段 2/3 后约 6–10 周；作为架构性版本单独评审。**

#### 工作范围

- 在已有 runId 基础上，补持久事件序号、幂等去重和启动恢复；记录运行、模型调用、工具等待、权限等待、停止和完成等阶段。
- 明确排队、插入纠正、续跑与子任务之间的父子身份，迟到事件始终回到原运行。
- 给文件产物建立 artifactId、来源 runId、原始/派生关系和内容版本；跨进程下载完成后仍关联到原答复。
- 持久化最终状态和足以恢复的最小信息；重启后先核对副作用状态，避免重复提交请求、下载或文件写入。
- 提供运行耗时诊断：首个模型输出、模型调用、工具执行、用户/权限等待和整轮完成分别统计。

#### 完成门槛

- 对重复、乱序、进程退出、网络中断和晚到下载事件做故障注入。
- 恢复流程不重复副作用；无法安全恢复时明确要求用户继续或重新运行。
- 性能统计区分本地等待和外部模型/站点，不以本机夹具数据宣传线上速度。

## 5. 优先级与排期建议

下面的相对窗口按一名主要开发者估算，平台设备和签名资料可并行准备。macOS/Linux 设备或签名链不可用时，平台阶段顺延并保持“待验证”，不以日历日期替代验收。

### P0：立即

当前版本收口、跨模块回归、文档核对和 Windows 发布候选。目标是降低最近大范围界面及功能改动的发布风险。

### P1：紧接着做

先做聊天任务状态与消息定位、插件诊断、浏览器能力与接管反馈；同一优先级内随后安排 PDF/CSV/TSV 只读预览。现有批注检索进入回归与大历史验收，不作为全新功能重做。多屏/标题栏和新运行时性能继续收口，平台设备准备同步开始。

### P2：随后扩展

推进结构化上下文附件、队列反馈、文件外部变更提示、插件占用中升级及文件/网页混合独立窗口。各项按最小共享协议分别接入，避免合并成一次大型重写。

### P3：按使用需求

文本/Markdown 编辑、Fastls Cookie 与逐跳重定向、浏览器显式休眠依需求立项。编辑先通过版本冲突与恢复门槛，Fastls 先通过凭据隔离与失败回滚门槛；这些能力分别发布，不相互阻塞。

### P4：中期基础建设

完整持久事件、跨重启产物来源与可恢复运行独立评审。最小运行终态记录和文件保存协议按具体功能提前建设；完整事件重放与自动恢复继续作为中期能力。

## 6. 全局验收与发布规则

每个功能状态统一使用以下标签：

- **Planned**：已决定方向，尚未开始。
- **In progress**：正在实现；不作为可交付承诺。
- **Implemented**：代码已落地，但可能未完成完整验收。
- **Verified**：在明确平台、环境和场景通过验收。
- **Released**：进入用户可获取的版本/商店源。

上线前必须明确：当前源码版本、目标平台/架构、运行时版本、测试数据边界、失败恢复路径、权限变化、迁移与回滚方式。安全和数据完整性相关功能必须覆盖取消、超时、重启、并发与损坏输入；无真实目标平台环境时不标记 Verified。

## 7. 不纳入近期承诺

- 用户设备在线 npm 安装、本机自动编译、任意原生模块 ABI 与跨架构模拟。
- Fastls 无限重定向、任意 CLI/文件路径、浏览器 Cookie 自动共享、隐式认证代理和自动重试。
- PDF/Office 编辑、任意二进制编辑、图片对源文件的破坏性标注。
- 把本地静态目录表述为公共插件市场；把五种 ZIP 已生成表述为五个平台已经支持。
- 把 runId、消息序号或内存事件去重描述为完整持久事件日志和断点续跑。

## 8. 规划维护

实现完成后，先更新 [当前功能与验证边界](./current-state.md) 和对应验证记录，再将本路线图状态从 Planned/In progress 改为 Verified/Released。协议或能力边界变化时，同步更新 SDK、宿主和商店文档。计划日期与测试数量保留明确基线日期，避免旧记录被误当作当前状态。

## 9. 下一阶段的产品范围（2026-11-03）

目标体验：用户附加已有资源并发起任务，能看懂当前进度，在浏览器中接管操作，直接阅读生成或下载的文件；插件出错时能找到原因和恢复入口。围绕这条路径分别交付，避免四个模块都增加入口却无法协同完成任务。

以下 C/F/P/B/T 编号是规划任务，状态统一为 **Planned**；文中的数量和时间是建议验收负载或容量估算，不是已测结果。现有能力只作为复用基线：

- **文件：**已有目录、列表/网格、路径搜索、文本/Markdown/图片预览和独立文件窗口。PDF 与 CSV/TSV 表格阅读属于新增；现有 CSV/TSV 仅按文本查看。
- **插件：**已有搜索、商店、启停、导入导出、版本/平台选择、完整性校验和安装事务。新增重点是诊断、运行中变更与可用版本恢复。
- **浏览器：**已有人工接管、批注检索与草稿恢复、主页/历史/快捷访问、下载和窗口迁移；Windows x64 已接入原生跨文档快照与定向输入。新增重点是能力反馈、交回后的重新观察和混合窗口。

首个增量优先选 C01、C03、P01、B01；PDF 与表格视图分别验收后进入后续小版本。聊天上下文管理和混合窗口不必等待完整事件系统，文本编辑与自动恢复须通过各自数据保护门槛。

## 10. 聊天：任务可理解、上下文可管理

### C01 · 统一任务状态与停止反馈 · P1

**用户价值：**离开对话查看文件或插件后，仍能知道任务正在运行、等待授权还是已经结束。

- 由宿主维护运行状态：准备中、模型响应、工具执行、等待用户/授权、正在停止、已完成、已停止、失败、应用退出后中断。浏览器被人工接管作为等待原因单独显示，其他获准工具是否继续遵循实际调度。
- 对话列表、输入区和执行详情读取同一份状态；界面提供返回任务、处理等待和停止入口。状态旁可展示当前阶段耗时，持久终态与阶段开始时间先由 T01 支撑。
- 点击停止立即进入“正在停止”；宿主关闭后续调度入口、传播取消，再汇总工具和下载的实际状态。无法确认已经终止的外部副作用明确保留“状态待确认”。
- “继续任务”先作为用户发起的新运行并记录前序身份；不能将重新提问显示为恢复原工具调用。

**验收：**切换对话/模块不改变真实状态；等待授权不显示为模型卡住；停止后不再发出新工具调用。已开始的请求、原生下载及进程分别报告取消结果，晚到结果仍归原 runId。应用重启将未确认终态显示为中断，不自动续跑。依赖 T01。

### C02 · 上下文附件与发送前检查 · P2

**用户价值：**发送前能看到本次附加的文件、页面和批注，并能逐项查看或移除。

- 复用回形针、`@` 和现有资源选择器，将选择结果整理为可移除附件；文件显示所属对话、相对路径及读取状态，网页显示页面身份，批注保留创建时版本。
- 将“用户选中的资源”与“模型本次实际读取的内容”分别记录。引用附件不等于已经读入全文；无法确认时不显示“已阅读”。
- 发送和队列出队前校验归属、存在性与版本；文件变更时提示采用当前版本或重新选择，页面导航后使旧文档引用失效。关闭页面、删除文件和撤销授权提供对应处理入口。
- 外部文件通过已有授权范围内的导入/复制流程进入工作区；只在确认复制成功后生成引用。粘贴普通路径不能自动扩大读取范围。

**验收：**同名文件、跨对话文件、删除/移动后的引用和排队期间发生的变更不会错读；纯文本模型遇到图片或页面截图时显示真实支持情况；草稿和队列中的附件可随内容一起保存。依赖 T02，兼容旧 BrowserContextRef 和文本文件引用。

### C03 · 搜索命中消息与长对话定位 · P1

**用户价值：**搜索到一个对话后能直接到达包含关键词的那一条消息。

- 在现有标题/消息全文搜索上增加消息级结果，返回 chatId、messageId、可用的 runId 和摘要；支持当前对话内查找及上一个/下一个命中。
- 区分用户提问、最终答复和执行记录；命中折叠记录时按需展开，定位后突出命中片段。离开搜索后保留用户原有折叠偏好和阅读位置。
- 将较大范围检索移出同步渲染热路径，按批返回，可取消过期查询；首版不同时引入语义检索或整套向量索引。

**验收：**建议使用单会话 5,000 条消息、100 个会话合计 50,000 条消息的固定夹具；连续输入不会被旧结果覆盖，定位目标准确。搜索等待与输入响应分别采样，输入更新继续满足现有 P95 32ms 门槛。先测量再决定是否采用虚拟列表；采用后须保持浏览器查找、消息跳转和辅助技术可用。

### C04 · 队列反馈与插入纠正的确定性 · P2

**用户价值：**知道一条消息是在排队、已交给 Agent，还是发送失败。

- 保留已有编辑、删除、暂停、继续和插入，补齐队首状态、阻塞原因及失败项单独重试。排序作为后续增量，仅允许对未提交的条目操作。
- 插入操作显示宿主是否已接收及所归属的 runId；不声称模型已经处理纠正。重复点击和客户端重连复用提交身份，避免产生重复工作。
- 用户停止当前任务后队列暂停，明确说明尚未执行的条目；恢复需用户操作。移除已提交条目与停止运行使用不同操作。
- 将队列接收、运行身份登记和出队边界纳入 T01。重启遇到“已提交但是否启动未知”时保留待确认状态，不自动重发。

**验收：**编辑与出队并发时只接受一个确定结果；停止不会自动拉起下一条；切换对话不丢队列；崩溃窗口中的条目可追溯，不以重复执行换取表面恢复。依赖 T01；结构化附件依赖 C02。

## 11. 文件：先补阅读，再提供受控编辑

### F01 · PDF 阅读器 · P1

- 提供页码跳转、缩放、适合宽度、文本查找及回到来源答复；按可见页渲染，保留独立窗口使用方式。
- 使用宿主校验过的文件引用和有界读取，阅读器与远程网页隔离；不开放任意 `file://` 读取。关闭嵌入脚本、自动附件启动和隐式外部导航。
- 首版建议支持不超过 25 MiB、500 页的 PDF；加密、损坏、超限文件显示具体原因，并提供系统打开/另存入口。扫描 PDF 说明无法文本搜索，OCR 另行评估。

**验收：**普通文本、扫描件、横竖混排、中文、加密、损坏和超限样例；快速翻页与切换文件不串页，关闭标签释放解析与渲染资源，源文件不被修改。容量阈值经目标机器测试后固定，不将示例阈值直接视为兼容承诺。

### F02 · CSV/TSV 表格查看器 · P1

- 提供表格/原文切换、首行表头选项、列宽调整、当前载入范围查找和单元格复制。首版仅查看，不编辑、不计算公式。
- 正确处理引号、转义、字段内换行、空字段及 UTF-8/带 BOM 的 UTF-16；分隔符识别不确定时允许用户选择。单元格按文本呈现，保留以 `= + - @` 开头的原始内容。
- 建议上限 10 MiB、100,000 行、200 列、单字段 64 KiB；解析放入可取消的后台任务，视图按需显示行列，并区分已扫描范围与总数未知。超限时停止并说明已显示范围，保留原文与系统打开入口。

**验收：**带换行字段、不同换行符、极宽表、超长字段、格式错误、公式字符串、编码错误和快速切换文件；不因单个异常文件阻塞聊天输入。列排序和全量筛选后置，避免截断数据产生错误结论。

### F03 · 文件变更、来源与阅读状态 · P2

- 打开中的文件被 Agent 或外部程序修改后显示更新提示；只读视图可刷新，保留最后可读快照和变更说明，不将旧内容标为最新。
- 同一路径删除、替换、权限失效分别显示；文件监听事件先去重合并，重新读取时仍检查真实路径与归属。监听器仅覆盖使用中的工作区，关闭后回收。
- 将现有来源答复/下载关联做成可返回入口，缺少证据时显示工作区文件；第一轮只继承现有来源，不提前声称拥有跨重启完整来源链。
- 保存文件标签的阅读位置、图片缩放和列表视图偏好。版本改变后仅恢复仍有效的位置，文件迁移窗口时使用同一阅读状态记录。

**验收：**Agent 连续写入、外部替换、移动/删除、同名文件、切换窗口与监听丢事件后手动刷新；不跨对话更新错误预览，不增加未授权目录访问。资源身份依赖 T02。

### F04 · 文本/Markdown 编辑首版 · P3，单独准入

- 先支持完整读取且未截断的 UTF-8 文本与 Markdown；保留 BOM/换行信息，其他编码继续只读，后续再扩展。256 KiB 截断预览不能直接进入可保存状态。
- 增加编辑/预览切换、查找替换、保存/另存和未保存提示；跨标签、主/独立窗口、退出共用脏状态与草稿恢复规则。
- 基于 T03 的版本令牌保存；冲突展示当前磁盘内容与用户草稿，提供重载、另存和人工处理，不静默覆盖。Agent 与用户编辑共同接入保存服务。

**准入与验收：**先观察 PDF/表格和现有系统打开入口的实际使用，再决定是否启动；T03 的并发、失败和恢复检查必须先通过。未完成全部写入入口接入、只支持 UI 保存时不开放通用编辑。图片编辑、PDF 编辑和 Office 原生编辑继续后置。

## 12. 插件：可诊断、可变更、可恢复

### P01 · 插件诊断与能力说明 · P1

- 插件详情增加诊断区：安装/加载状态、当前宿主与平台目标、运行方式、注册工具、最近失败阶段及可执行的恢复动作。
- 区分“不兼容”“停用”“加载失败”“所需授权被拒绝”“运行时不可用”“调用失败”。权限展示绑定所选对话或最近调用；未选择上下文时不宣称插件已获得授权。
- 诊断默认使用已存在的状态，不在浏览商店时执行插件。需要探测的本地检查由用户发起，可取消；联网检查仍走已有权限与目标校验。
- 支持复制脱敏诊断，包含宿主/插件版本、目标、错误码及关联调用身份；默认不包含 Cookie、Token、请求正文或用户文件内容。

**验收：**断网、错误架构、最低宿主不满足、摘要错误、停用、权限拒绝、sidecar 启动失败及正常调用分别给出可理解原因；商店离线仍可查看本机状态。沿用已有预检和安装事务，不重复建设另一套安装器。

### P02 · 更新权限变化与运行中变更 · P2

- 安装/更新预览展示版本变化、兼容性和 manifest 能确定的能力变化；动态 `planPermissions` 不能静态确定的部分明确说明，在真实调用时继续授权，不把预览当作永久授权。
- 同一插件的升级、变体更换、重新加载和卸载采用生命周期互斥。显示在用调用；用户可等待完成，或取消后在确认释放时继续，变更期间拒绝新的调用进入。
- 候选包沿用已有 staging、校验和恢复 journal；提交后刷新工具目录，正在执行的运行保留清晰的版本归属。不能跨版本拼接同一次调用的状态。
- sidecar 退出、临时文件回收和 Windows 强制终止后的进程树回收作为独立门槛；不以一次性 CLI 自身超时代替进程归属保障。

**验收：**调用中升级、取消升级、双窗口同时更新、加载失败、卸载后晚到结果和宿主强制退出；失败后原可用版本、启停状态及索引一致。普通进程内 JavaScript 插件不能被安全强杀时，提示需重启再变更；不承诺硬隔离或任意代码超时终止。

### P03 · 恢复到可用版本 · P2，接在 P02 后

- 为最近一次成功安装保留有界的包摘要、来源和版本记录；用户主动选择恢复。首版最多保留一个可恢复包及其容量上限，明确清理入口。
- 恢复仍执行兼容性、包完整性、权限变化和生命周期检查；商店下架或安全撤回的版本不能仅因缓存存在就自动启用。
- 将“安装过程中失败回滚”与“更新成功后的用户主动恢复旧版”分开表达。当前事务备份提交后会清理，不能直接当作版本历史使用。
- 外链开发目录和随附保护插件按各自规则处理；涉及不可逆配置迁移的插件先拒绝直接降级，提供解释和恢复资料。

**验收：**缓存缺失/损坏、旧版本不兼容、恢复过程断电、原版本可用性及来源离线；失败保留当前可用安装。依赖 P02；不将保留插件包等同于自动回滚用户数据。

Fastls 0.2.x 继续按第 3 节阶段 2 的独立门槛实施。按对话选择可见插件工具、批量自动升级、公共市场发布和通用插件沙箱后置；按对话隐藏工具不能替代权限校验。

## 13. 浏览器：操作可解释、工作区可连续使用

### B01 · 能力状态与接管交回反馈 · P1

- 在浏览器详情或帮助中展示实际能力探测结果：原生快照、跨文档覆盖、定向输入及运行时版本；区分 API 存在、当前快照覆盖完整和平台已验证。
- 人工接管保留现有宿主输入锁，清楚显示哪些页面在等待、是否还有非浏览器工作继续；不把页面接管显示为整个 Agent 已暂停。
- 交回 Agent 后先重新观察文档状态，再允许下一次输入；旧 target、批注锚点和选择结果按各自版本校验。重新观察失败时保持待处理，不沿用接管前坐标继续点击。
- 统一导航失败、页面崩溃、覆盖不完整、目标过期和不支持原生系统控件的反馈。`dispatched` 继续只表示派发，交互成功须通过回读确认。

**验收：**接管期间页面导航、表单修改、跨域 iframe、Shadow DOM、页面崩溃、运行停止和后台输入；缺少能力时给出可用的降级或人工入口。复用现有能力探测与原生接口，本项不重复实现跨文档引擎。

### B02 · 文件/网页共用独立窗口 · P2

- 接续[文件与网页统一方案](./workspace-unification-plan.md)阶段二、三，建立类型化混合窗口标签宿主，复用现有 WorkspaceTabItem 和系统窗口控件。
- 首版独立混合窗口仅接收同一所属对话资源；主窗口继续保留现有跨对话预览规则。文件引用与网页 Session/WebContents 各自校验，不按 URL/标题猜身份。
- 迁移网页保留原 WebContents；迁移文件传递受校验的引用和阅读状态。接收确认前保留来源标签，失败回到原位置；用户接管和未保存编辑按各自规则阻止或推迟迁移。
- 统一排序、拖出/拖回、关闭相邻选择、最后一项关闭、移回全部、窗口标题及布局恢复。重启只恢复资源和布局元数据，不声称恢复网页 JS 内存或任务。

**验收：**至少 3 个窗口、文件/网页混合、并发关闭与移回、接收失败、跨对话拒绝和真实跨屏/混合 DPI 拖放；文件归属、网页登录态、批注和下载均正确。依赖 T02 与已有迁移令牌；F03 的阅读状态可随后接入。F04 上线前补未保存编辑的迁移场景。

### B03 · 会话与页面资源管理 · P3

- 先展示会话的页面数量、持久/临时属性、正在使用的任务和最近活动；能够测量时才展示资源占用，并注明进程共享可能导致的统计边界。
- 提供用户主动关闭、释放和清理入口；清理登录态与关闭页面分开确认。隐藏继续保留原页面，不改变现有语义。
- 显式休眠另行评估：仅允许无活动任务、无接管/批注选取、无下载及未保存表单风险的页面进入；无法确认条件时禁用。恢复需要重新加载，明确说明内存状态不会保留。

**验收：**关闭/释放期间任务引用、下载和持久 Session 不混淆；后台页面不抢焦点；多页面等待按实际活动启停轮询。首版不自动休眠或自动清理登录态。

## 14. 共享基础与实施依赖

### T01 · 最小持久运行记录与安全写入 · 支撑 C01/C04

- 在已有 runId、消息序号和持久队列上增加 schemaVersion、运行终态、阶段时间、前序运行身份及队列提交身份；关键接收/终态写入确认后才向客户端报告成功。
- 先补 ChatStore 的同目录临时文件写入、替换、损坏文件隔离与可读备份策略。目前直接覆写整个对话 JSON，不能作为新的恢复保证。磁盘空间不足时保留旧文件并报告未保存。
- 运行登记与队列出队使用可恢复提交记录；发生重启时先分类“未提交 / 已启动 / 状态未知”。未知状态等待用户核对，自动化不得重复有副作用的工作。
- 消息追加序号继续保持原语义。独立 eventId、完整事件重放、跨重启下载恢复属于阶段 4，不用最小终态记录冒充完整事件系统。

### T02 · 类型化资源引用 · 支撑 C02/F03/B02

- 在共享契约中定义带版本的文件、网页和批注引用。文件记录 ownerChatId、工作区身份、规范路径及读取版本；网页保留稳定页面/Session 身份和文档代次；批注保留批注版本。
- 文件元数据版本用于提示“可能变化”，内容摘要只在确有需要时计算；不把 mtime/size 当作内容哈希。文件移动后的自动追踪暂不保证，无法确定同一对象时显示引用失效。
- 对话引用、队列、窗口迁移和预览入口均由宿主解析并检查真实路径、符号链接和所有权；结构化引用不是新增授权。
- 保持旧消息和 BrowserContextRef 可读，通过带版本的新字段渐进迁移。工作区产物身份与插件商店平台包的 artifactId 分开命名，避免混用。

### T03 · 文件版本与保存服务 · F04 的前置门槛

- 统一完整读取、版本令牌、保存请求、冲突结果与草稿恢复。保存前核对完整内容版本；同一实际工作区文件使用同一写入锁，不仅按 chatId 上锁，覆盖共享 workspaceRoot 的场景。
- Agent 文件写入、追加、复制覆盖、移动覆盖、下载最终提交和用户保存分别审计并接入；目标路径在提交时重新校验，取消和版本不符不得覆盖。
- 使用同卷临时文件与原子替换，设计原文件权限、磁盘写满、应用崩溃及恢复路径；未保存草稿与源文件分开保留。
- 应用内写入锁不能约束任意外部程序。对外部替换重读核验，存在无法判断的并发窗口时停止保存并允许另存；明确实际支持的文件系统和冲突边界，不能仅靠 stat 比较宣称全局原子比较交换。

### T04 · 固定负载、诊断与模块拆分 · 贯穿各增量

- 聊天准备/模型/工具/授权等待、解析、标签切换和窗口布局分别记录；模型供应商未返回用量时不伪造 Token 和费用。
- 除保留原有小负载基线，建议增加：2/10/20 网页标签，1/3 个窗口，500 条批注含截图，5,000 条单会话消息与 50,000 条跨会话消息，以及文件上限边界。记录硬件、DPI、运行时和样本数。
- 新运行时先复测旧基线再比较；主包体积、启动可交互时间和空闲 CPU/内存先采样再确定门槛。输入更新沿用 P95 32ms，避免用标签切换耗时代替输入指标。
- 随功能将 ChatPage 的任务状态、上下文、搜索与工作区状态逐步移到独立组件/组合函数；主进程按运行记录、资源解析和插件生命周期形成明确入口。不进行脱离产品任务的大范围重写。

依赖关系：C01/C04 → T01；C02/F03/B02 → T02；F04 → T03（T03 复用 T02 的文件身份）；P03 → P02；F01/F02/P01/C03/B01 可在现有契约上独立起步。完整事件系统不阻塞只读预览，Fastls 也不阻塞插件日常管理。

## 15. 建议执行批次、验收与取舍

按一名主要开发者估算，测试与文档包含在窗口内；外部设备、签名和真实站点问题不包含等待时间。批次是容量预估，实际以最小条目验收为准，每批可拆成多个小版本。四批串行约 9–14 个开发周，后续准入项另计；近期先固定批次 0/1 的范围，批次 2/3 在前一批完成后重估，不将全部条目包装成一次短周期升级。

### 批次 0 · 发布基线收口 · 约 1–2 周

完成原阶段 0，核验真实旧版升级数据、签名/分发边界，并在 cloudbypass.3 上重跑受影响的浏览器和界面回归；建立 T04 的新基线。新功能可在开发分支推进，但发布候选需冻结源码与依赖。

**出口：**同一候选源码、运行时、构建产物和隔离数据的验证记录齐全。平台功能分别标注；Windows 版本不等待无设备平台的“全部支持”承诺，未认证平台继续待验证。

### 批次 1 · 每天可感知的反馈改善 · 约 2–3 周

顺序建议：T01 最小终态/安全写入 → C01；其后 C03、P01、B01 分别交付。此批保持原队列调度、安装和窗口模型，不夹带编辑器或混合宿主重构。

**出口：**任务状态一致、停止有确切反馈、搜索可到消息、插件错误能诊断、浏览器接管交回有可靠反馈。若 T01 超出预算，先发布 C03/P01/B01；C01 依赖部分继续保留 Planned/In progress。

### 批次 2 · 产物阅读与上下文管理 · 约 3–4 周

顺序建议：F01、F02 各自形成可发布单元；T02 → C02/F03；T01 的队列提交记录完善后接入 C04。PDF 或表格解析器评估遇到阻塞时，另一项独立交付，不打包等待。

**出口：**从聊天附件能读 PDF/表格、回到来源、发现文件变更，再将有效文件/页面加入下一轮上下文；队列不自动重发状态未知的工作。超预算先延后 C04 的排序与 F03 的跨窗口阅读位置，保留归属和变更校验。

### 批次 3 · 多窗口与插件变更可靠性 · 约 3–5 周

P02 → P03 与 B02 分成独立小版本；一名开发者顺序处理，不假定全部同时推进。优先完成占用中变更和混合窗口迁移的故障路径，再增加恢复入口与交互细节。

**出口：**插件更新不破坏在用调用，失败保留可用安装；混合窗口迁移不丢标签、会话、草稿或下载归属。遇到容量压力先后置 P03 与完整布局恢复，保留 P02 生命周期互斥和 B02 接收确认。

### 后续按需求准入

F04/T03、Fastls 0.2.x、B03 及阶段 4 分别评审。首轮四模块体验完成后再决定投入，不能将它们塞入上述每批容量；新需求先说明替换哪一项或增加多少容量。

### 贯穿四个模块的整体验收

1. **带资源发起任务：**已有文件、已导航页面和历史批注进入输入区；排队期间资源变化能被发现，失败不悄悄替换上下文。
2. **运行与人工协作：**任务执行时切到浏览器接管并修改表单，交回先重新观察；返回聊天仍能看到正确等待/执行状态。
3. **下载与阅读：**旧运行的下载晚到，仍进入原答复；PDF/表格在本地阅读，文件变化后刷新，不混到新运行。
4. **插件故障与变更：**调用失败能定位插件/版本/阶段；运行中更新有明确策略，取消或加载失败保留原安装。
5. **窗口和恢复：**聊天、文件、网页在主/独立窗口间切换；包含关闭、接收失败、停止与应用重启，未知副作用不自动重复。

每项验收覆盖实际可用的 320/420/760px 内容区、键盘与输入法、减少动态效果、加载失败和权限拒绝。原生窗口、平台安装和跨屏拖放须使用目标设备验证。远程端维持当前支持范围，新增桌面能力没有等价安全入口时明确显示不可用。
